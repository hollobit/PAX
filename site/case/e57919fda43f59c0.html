판정 근거

과기정통부·NIPA가 국산 AI 모델 기반으로 전 국민 무료 범용 AI 챗봇과 행정 처리를 돕는 AI 에이전트를 만드는 '모두의 AI' 사업으로, SKT·카카오·KT 3개 컨소시엄이 선정돼 10월 베타·12월 정식 서비스, 연내 월 이용자 500만 명을 목표한다. 범용 대화형 챗봇은 B1 코파일럿, 행정 처리를 돕는 에이전트는 도구 호출·계획 성격이 강해 B6을 secondary로 뒀다. 메신저 연동·전화·문자 접근성은 A12 접근성 어댑터, 국산 독자모델 운용은 A2.2로 태깅했다. 공고 시점에 구체 아키텍처·보안설계가 공개되지 않아 environment 대부분을 미확인 또는 잠정으로 남긴다.

구현 가이드

주 패턴 B1 코파일럿을 구현할 때

구현 단계

  1. 대상 문서의 서식·필수 항목·문체 규범을 정리해 A9 스킬(프롬프트 템플릿)로 만든다.
  2. 업무 질문·모범 답안·채점 기준으로 C9 평가 세트를 먼저 만들어 모델·프롬프트 선택을 잰다.
  3. E1·E5에 맞는 모델 경로를 정한다. 행정망이면 BYO 대신 A2 내부망 프록시, 민감 자료면 C5 비식별을 앞단에 둔다.
  4. 산출물을 F2 편집 가능 출력과 A10 서식으로 내고, C1 검토 큐에서 담당자가 확정하게 한다.
  5. 수정률·처리시간을 C4로 집계하고, 저위험 유형이 확인되면 C2 자동 확정 분기를 검토한다.

점검표

  • 담당자가 최종 확정한다는 절차가 운영되는가
  • 서식·문체 규범이 A9 스킬로 분리되어 있는가
  • 초안을 이용자가 직접 고칠 수 있는가(F2)
  • 수정 내역이 기록되어 품질 개선에 쓰이는가

환경 조건

E1 행정망이면 BYO 코딩 에이전트를 쓸 수 없어 A2 내부망 프록시가 필요하다. E1 로컬 PC 완결이면 A9 스킬 + A10 어댑터 조합이 된다. E2 해외 상용 API면 직접 호출 대신 A2 게이트웨이를 거친다. E2 모델 중립(BYO)이면 A9 스킬 형태로 배포하고 모델 교체 가능성이 곧 C7이다. E4는 P1이 기본이고, P2로 올라가면 C1 전건 검토 → C2 분기로 바꾼다.

주의할 점

  • 전건 검토가 영원히 남으면 업무 순서는 그대로(First 불가)
  • 상용 API 직접 호출 시 X4 위험
  • 행정망에서는 BYO 불가로 A2 내부망 프록시가 선행되어야 함

기본 배선 예

A9 → B1 (B′5) → C1 → D8.3 · A2.4 → B1 (행정망)

보완이 필요한 필수 부품

이 조합에서 카탈로그가 함께 갖추라고 권하는 부품 가운데 아직 확인되지 않은 것이다.

  • C5 가드레일 필터 개인정보·환각·편향·형식 오류가 프롬프트나 산출물에 들어가지 못하게 시스템이 경계에서 걸러낸다. 비식별 전처리, 출처 검증, 구조적 출력 제약이 대표 변형이다.
  • C9 평가 세트·회귀시험 배포 전에 업무 맥락의 질문·정답·채점 기준을 세트로 만들어, 프롬프트·모델·설정의 모든 변경을 같은 자로 재고 회귀를 잡는다.
  • C7 폴백 스위치 모델·API·도구가 멈추거나 품질이 떨어질 때 대체 모델·규칙 기반 축소·수동 처리로 경로를 바꿔 서비스가 끊기지 않게 한다.
  • F1 출처 표시 답변에 근거 문서·조문·통계표 ID를 붙여 이용자가 원문을 직접 확인할 수 있게 한다. C5 출처 검증의 이용자 면이다.

피해야 할 안티패턴

  • X1 AI 스티커 기존 화면에 요약·챗봇 버튼만 붙이고 업무 순서와 사람·AI의 역할 분담은 그대로 두어, AI가 있어도 업무 산출물이 바뀌지 않는 함정이다. 대처: 먼저 가치 흐름 규칙(R1)으로 사람 또는 국민이 최종으로 받는 핵심 산출물을 정하고, 그 산출물을 AI가 어떤 모양으로 분담할지 B 업무 컴포넌트를 하나 고른다(초안→사람 확정이면 B1, 근거 접지 답변이면 B3, 서류 추출이면 B4). 사람이 확정하는 지점은 C1 검토 큐로, 이용자가 고쳐 확정하는 면은 F2 편집 가능한 출력으로 명시한다. 흐름이 바뀌었는지는 C4 감사 로그·지표의 처리시간·수정률로 잰다. AI 런타임이 전혀 없는 행정정보시스템이라면 AI로 포장하지 말고 R24대로 B0·service_type 0·platform 공란·X1(AI 무관)으로 정직하게 분류한다.
  • X4 단일 모델 인질 상용 API 하나에 전 기능이 묶여 있어, 그 API가 멈추거나 바뀌면 무슨 일이 생기는지 아무도 답하지 못하는 함정이다. 대처: 모델 호출을 A2 모델 서빙 계층 뒤로 숨겨 B 부품이 특정 벤더 API를 직접 부르지 않게 한다. 그 위에 C7 폴백 스위치로 재시도 → 기존 API → 대체 MCP → 대체 모델(A2.2 주권형 로컬 등) → 규칙 기반 축소 → 수동 전환의 경로를 정하고 전환 이력을 C4에 남긴다. 모델 교체가 실제로 안전한지는 C9 평가 세트로 재어 버전을 고정한다. 모델 중립(BYO) 배포라면 A9 스킬 형태로 배포해 모델 교체 가능성 자체를 폴백으로 삼는다.
  • X10 평가 없는 RAG, RAG 없는 튜닝 평가 세트 없이 검색을 붙여 '좋아진 것 같다'로 배포하고, 검색으로 풀릴 문제를 파인튜닝으로 푸는, 진행 경로를 건너뛰는 함정이다. 대처: §7.2 진행 경로를 순서대로 밟는다. B1 직접 프롬프트에서 시작해 두 번째 단계에서 C9 평가 세트(업무 질문·정답·채점 기준)를 먼저 만들고, 이후 A9 규범 스킬·F4, B3 지식 접지(A1 데이터 자산), B3 검색 품질(Hybrid·Rewriting·Reranker), C5 가드레일·F1 순으로 붙이며 매 단계를 C9로 잰다. A2.3 튜닝은 진행 경로의 마지막 단계로, 검색·규범 스킬로 풀리지 않는다는 것이 C9 점수로 확인됐을 때만 한다. 모델·프롬프트·설정 조합은 릴리스처럼 버전 관리한다.

PAX 사례 15건이 이 부품을 쓴다

맥락

여러 시스템·도구(A8 MCP·API·문서)를 오가는 다단계 업무, 데이터 조회·분석 에이전트(유형 5b), 망분리 환경의 로컬 MCP 호스트에 쓴다. 하위 작업이 실제로 분리되거나 AI가 도구를 골라야 할 때만 해당한다.

맞서는 힘(긴장)

  • 자율성 vs 권한 통제(P2 이상에서 C8 필수)
  • 멀티에이전트의 분업 vs 조정 비용·충돌(X11)
  • 도구 출력 활용 vs 도구 출력 속 지시가 명령이 되는 위험(X13)
  • 탐색적 유연성 vs 재생·감사 가능성

해법

목표와 도구 목록(A8 MCP·API)을 받아 AI가 계획을 세우고 도구를 골라 호출하며, 필요하면 하위 전문 에이전트에 위임한다(B′4·B′7·B′8). 단일 에이전트에서 시작해 하위 작업이 분리될 때만 계층·병렬로 승급한다. 도구별 읽기/쓰기 권한과 실행 승인은 C8로, 단계 상태와 되돌림은 C3로, 모든 호출은 C4 추적 로그로 남긴다. 신뢰 불가 입력을 읽는 경우 S5 계획 고정이나 S6 격리로 도구 출력이 새 행동을 끼워 넣지 못하게 하고, 되돌리기 어려운 조치 앞에는 F6 확인을 둔다.

이럴 때 쓴다

  • 한 건의 처리가 여러 시스템 조회·작성·검증에 걸쳐 있고 AI가 도구 순서를 골라야 할 때
  • 하위 작업이 실제로 분리되거나 컨텍스트 창이 부족할 때
  • C8·C3·C4 통제를 함께 갖출 수 있을 때

이럴 때는 쓰지 않는다

  • 단계 순서가 고정된 파이프라인일 때(B′1을 가진 B1·B4)
  • 실제 흐름이 초안 → 사람 확정일 때(B1)
  • 스케줄러·크롤러 수준 자동화일 때(agent_system=true라도 B6 아님)
  • 단일 에이전트가 되기 전에 멀티에이전트부터 만들려 할 때(X11)

얻는 것

  • 여러 시스템을 오가는 업무 흐름 자체를 재설계
  • 도구 교체로 다른 기관이 그래프를 재사용 가능
  • First 지향 구조

점검표

  • 복수 LLM 역할·도구 호출 루프·AI의 계획 선택이 실제로 있는가(R2)
  • 도구별 읽기/쓰기 권한과 실행 승인이 명시되어 있는가
  • 모든 도구 호출이 추적되는가
  • 도구 출력이 새 행동을 촉발하지 못하게 막는 구조가 있는가

구조 — 참여 부품

B1 코파일럿 업무 컴포넌트

사람이 하던 문서·판단 작업 옆에 AI가 초안·요약·검토안을 놓고, 사람이 고쳐서 확정한다.

PAX 사례 111건이 이 부품을 쓴다

맥락

문서·기안·검토의견처럼 산출물 형식이 정해져 있고 최종 확정자가 사람인 업무에 쓴다. BYO 코딩 에이전트와 A9 스킬을 쓰는 스킬 코파일럿이 PAX 자생 도구에 많다.

맞서는 힘(긴장)

  • 초안 속도 vs 전건 검토에 드는 사람 시간
  • 상용 모델 품질 vs 행정망·민감정보 제약(E1·E5)
  • 양식 일관성(A9 규범) vs 사안별 유연성

해법

업무 서식과 참고 자료를 입력으로 받아 모델(A2 또는 BYO 구독)이 초안·근거·신뢰도를 내고, 사람이 편집 가능한 형태(F2)로 받아 고쳐서 확정한다. 보고서 구조·문체·검증 절차는 A9 규범 스킬로 코드 밖에 두고, 공공 문서 형식은 A10 어댑터로 입출력한다. 확정 전 검토는 C1 검토 큐로 운영하고 수정 내역을 C4·C6의 입력으로 남긴다. First로 가려면 저위험 건을 C2로 자동 확정하는 분기를 더한다.

이럴 때 쓴다

  • 산출물 형식이 정해진 문서를 반복 작성할 때
  • 최종 판단과 책임이 사람에게 남아야 할 때(P1 산출물 생성)
  • 유형 ④ 내부 문서·기안, 유형 ⑫ 개발 코파일럿의 기본 조립일 때

이럴 때는 쓰지 않는다

  • 답이 기관 규정·선례 속에 있어 접지와 출처가 핵심일 때(B3)
  • 추출 결과가 사람 확정 없이 다음 판정 단계로 흐를 때(B4)
  • 런타임에 모델이 필요 없는 정형 취합일 때(B0)

얻는 것

  • 문서 작성 시간 단축
  • 책임 소재가 사람에게 명확히 남음
  • 도입이 쉬워 Enabled의 전형 경로

점검표

  • 담당자가 최종 확정한다는 절차가 운영되는가
  • 서식·문체 규범이 A9 스킬로 분리되어 있는가
  • 초안을 이용자가 직접 고칠 수 있는가(F2)
  • 수정 내역이 기록되어 품질 개선에 쓰이는가

구조 — 참여 부품

  • A2 모델 서빙 계층 — 초안 생성 모델 호출(행정망이면 내부망 프록시)
  • A9 업무 규범 스킬 — 서식·문체·검증 절차를 프롬프트 템플릿으로 고정
  • A10 문서 형식 어댑터 — HWPX·엑셀 입출력
  • C1 검토 큐 — 담당자가 초안을 확인·수정·확정
  • 담당자 — 최종 확정자이자 책임자

변형

  • 시스템 내장형: 기관 업무 시스템 안에 초안 기능을 넣은 형태
  • 스킬 코파일럿: BYO 코딩 에이전트 + A9 스킬로 배포되는 형태(PAX Enabled 사례에서 가장 흔한 형태)

맥락

  • 현장 기기 자체에서 돌아야 하면 A5(엣지 런타임)
  • 모델을 재학습했으면 A2.3

얻는 것

  • 호출 비용이 고정비로 바뀜

  • C7의 대체 경로 후보

점검표

  • 모델 선정 근거(평가 세트 비교)가 남아 있는가
  • 반입한 모델·패키지의 무결성 검사 기록이 있는가
  • 대체 로컬 모델 또는 수동 전환 절차가 있는가

A12 접근성·모달리티 어댑터 공통 서비스

맥락

맞서는 힘(긴장)

  • 포용성·접근성 vs 변환 단계 추가에 따른 오류 누적
  • 현장 착용 기기의 편의 vs 기기 비용·개인정보(시야 영상)
  • 쉬운 언어 변환 vs 원문 의미 보존

해법

  • 현장 작업자가 손을 쓸 수 없어 음성·착용 기기가 필요할 때
  • 안내문을 다국어·쉬운 언어·자막으로 내야 할 때

이럴 때는 쓰지 않는다

얻는 것

  • 현장 작업자의 손 자유
  • 채널을 바꿔도 업무 로직 유지

점검표

  • 텍스트 외 접근 경로가 최소 하나 있는가
  • 변환 과정에서 숫자·날짜·기관명 오류를 확인하는 장치가 있는가

F7 한계·신뢰도 안내 상호작용 패턴

AI가 무엇을 못 하는지, 얼마나 확신하는지, 공식 판단이 아님을 이용자가 볼 수 있는 곳에 적어 과신을 막는다.

PAX 사례 63건이 이 부품을 쓴다

맥락

대민 상담·안내(유형 ①), 대조·점검(⑦), 분석·예측(5a·⑩), 비식별 도구(⑬). 대체 경로로 운영 중인 C7 상황.

맞서는 힘(긴장)

  • 정직한 한계 고지 vs 서비스 신뢰도 하락 우려
  • 신뢰도 수치 표시의 정확성 vs 이용자 이해

해법

화면에 사용 한계(대상 범위·미검증 항목·처리 시간), 신뢰도, '공식 판단 아님' 고지를 결과 옆에 배치한다. 저신뢰 결과는 표시를 달리하고, C7 대체 경로로 운영 중이면 품질 저하를 알린다. 고지 문구는 법률 자문·유권해석을 대체하지 않는다는 점을 분명히 적는다.

이럴 때 쓴다

  • 대민 서비스 D1~D7(F1·F2·F7 최소 요건)
  • 유형 ①⑦5a⑩⑬처럼 F7이 필수인 유형
  • C7 대체 경로 운영 중

이럴 때는 쓰지 않는다

  • 유형 ①·⑦에서 model_dependency가 없음(비LLM)이면 필수에서 면제(R7). 단 비LLM 도구도 한계 고지는 권장된다

얻는 것

  • 과신·오인 방지
  • 기관 책임 범위 명확화

점검표

  • 이용자가 '공식 판단이 아님'을 결과 화면에서 읽을 수 있는가
  • 사용 한계가 명시되어 있는가
  • 저신뢰 결과가 구분 표시되는가

구조 — 참여 부품

  • 고지 문구 — 사용 한계·공식 판단 아님
  • 신뢰도 표시 — 결과별 확신 수준
  • C7 폴백 스위치 — 대체 경로 운영 여부 제공

변형

  • 공식 판단 아님 고지: '유권해석 아님'·'참고용' 고지
  • 신뢰도 표시: 결과별 신뢰도·등급 표시
  • 미검증 항목 열거: 검증되지 않은 조건·처리 시간을 명시

참조 구현 예

  • 소방기술민원 답변생성기 — '유권해석 아님' 고지
  • PAX 9998aba2d1f55c24 — 비공식 참고 도구·공식 판단 아님 고지와 원문 연계를 함께 갖춘 자가점검 UI
  • PAX 759835514b4b7ca4 — README가 미검증 항목을 열거하고 '최종 판단은 항상 사람' 고지
  • PAX 6c0fa4c0c3508ff0 — 처리 시간과 라이선스 동의 절차를 정직하게 고지한 온디바이스 비전 도구
  • PAX aef95509b7611c96 — 비LLM 스크리닝 도구가 실제 검토를 대체하지 않음을 화면에 명시
  • PAX 0a2535cadf2d621a — 법률 자문·안전 인증을 대체하지 않는다는 한계 고지

D1 안내·탐색 서비스 블록

국민이 어떤 서비스를 받을 수 있고 어디로 가야 하는지 알려 주는 대민 접점 블록이다. B3 지식 접지나 B0 탐색기가 이 자리에 들어간다.

PAX 사례 99건이 이 부품을 쓴다

맥락

국민·기업이 직접 쓰는 대민 접점. §7.3 유형 ① 대민 상담·안내(D1·D7, P0~P1)의 입구다. 규칙 기반 공공데이터 조회로 안내하는 비LLM 도구도 이 블록에 속한다(R21).

맞서는 힘(긴장)

  • 안내 범위의 폭 vs 답의 정확성
  • 자유 질의의 편의 vs 규정 밖 답을 끌어내려는 입력(S4가 막는 위협)
  • 상시 운영 요구 vs 상용 API 장애(C7)
  • 쉬운 말 vs 법령·공고 원문 충실성

해법

블록은 렌즈이고, 해법은 이 자리에 끼우는 부품 조합이다. 주 부품은 공개(O) 문서에 접지한 B3 대민 자동응답형이나 조건으로 대상 서비스를 좁히는 B0 탐색기다. 답은 F1 출처와 F7 "공식 판단 아님" 고지와 함께 내고, 입력은 F4 구조화 입력으로 받아 조건 누락을 줄인다. 민원인 입력은 신뢰 불가 입력이므로 S4 행동 선택기와 S7 컨텍스트 최소화로 규정 밖 답을 막고, 상시 서비스이므로 C7 폴백을 둔다. 판단이 필요한 질문은 B′2 라우터로 D4 분류·이관이나 담당자에게 넘기고 F11로 이관을 알린다.

이럴 때 쓴다

  • 국민이 받을 수 있는 서비스나 담당 창구를 몰라 헤매는 문제가 있을 때
  • 같은 안내 질문이 반복되고 답이 공개 규정·공고에 있을 때
  • 뒤따르는 신청(D2)의 입구를 정리해 잘못된 접수를 줄이고 싶을 때

이럴 때는 쓰지 않는다

  • 개인별 요건 충족 판정이 필요하면 D3 자격·심사
  • 개인 상황에 맞춘 정보·처방·법령 해석을 주면 D7 상담·처방
  • 이용자가 기관 내부 담당자면 D8.1 탐색·조회

얻는 것

  • 창구를 찾아 헤매는 시간 감소
  • 반복 안내 업무 경감
  • 후속 신청(D2)의 입구 정리

점검표

  • 안내마다 근거 출처가 보이는가
  • "공식 판단 아님" 고지가 화면에 있는가
  • 규정 밖 질문을 사람에게 넘기는 경로가 있는가
  • 평가 세트로 안내 정확도를 재는가
  • 모델 장애 시에도 안내가 멈추지 않는가

구조 — 참여 부품

  • 국민·기업 — 자기 상황을 말하고 받을 서비스와 창구를 찾는 주체
  • B3 지식 접지 상담 — 공개 문서에 접지해 안내 답변을 생성
  • B0 결정적 도구(탐색기) — 조건 선택으로 해당 서비스 목록을 좁힘
  • F1 출처 표시 — 안내의 근거 문서·데이터를 보여 줌
  • F7 한계·신뢰도 안내 — 공식 판단이 아님과 안내 범위를 고지
  • 담당자 — 라우터가 넘긴 판단 필요 질문을 처리

변형

  • 조건 탐색형: B0 탐색기. 나이·가구·지역 같은 조건을 넣으면 받을 수 있는 서비스 목록을 준다(생애주기 혜택 내비게이터).
  • 접지 질의응답형: B3 대민 자동응답형. 자유 질의에 공개 규정·공고로 답하고 예외만 이관한다.
  • 비LLM 공공데이터 안내형: 모델 없이 A1 결정론 조회로 안내한다. 유형 1의 A2 요건을 A1로 대체한다(R21).

참조 구현 예

  • 생애주기 혜택 내비게이터 — 카탈로그 D1 카드의 B3·B0 탐색기 예

D7 상담·처방 서비스 블록

개인 상황에 맞춘 정보·처방·법령 안내를 주는 대민 접점 블록이다. B1 코파일럿이나 B3 지식 접지가 이 자리에 들어간다.

PAX 사례 14건이 이 부품을 쓴다

맥락

국민에게 개인 맞춤 정보·처방·법령 안내를 주는 접점. §7.3 유형 ① 대민 상담·안내(D1·D7)와 유형 ⑪ 추천·매칭(D7·D4)의 무대다.

맞서는 힘(긴장)

  • 맞춤화 정도 vs 오답의 대가
  • 전문가 전건 검토 vs 처리량
  • 민원인이 원하는 답 vs 규정·데이터에서 나오는 답(S4)
  • 쉬운 설명 vs '공식 해석 아님' 고지

해법

답이 데이터·규정에서 나오게 한다. 개인 조건은 F4 구조화 입력으로 받고, B3가 공개 규정·법령에 접지하거나 B1이 전문가 검토용 처방 초안을 만든다. 처방처럼 오답의 대가가 크면 C1 검토 큐로 전문가가 확정하고, 저위험 건만 C2로 자동 확정한다. 답에는 F1 출처와 F7 한계 고지, 추천이면 F9 추천 사유와 F3 대안을 붙인다. 민원인 입력에는 S4 행동 선택기·S7로 규정 밖 답을 막고, 이용자 반응과 전문가 수정은 C6로 되돌린다.

이럴 때 쓴다

  • 개인 조건에 따라 답이 달라지는 정보·처방·법령 안내
  • 전문가 상담 수요가 인력을 넘을 때
  • 일반 안내(D1)로는 무엇을 할지 결정하지 못할 때

이럴 때는 쓰지 않는다

  • 서비스·창구를 찾는 데서 끝나면 D1
  • 지급·승인 같은 자격 판정이면 D3
  • 이용자가 기관 담당자면 D8 하위 블록

얻는 것

  • 전문가 상담 대기 감소
  • 개인 조건에 맞는 행동 제시
  • 전문가 수정의 누적으로 품질 개선

점검표

  • 맞춤 답이 데이터·규정에서 나오는가
  • 오답의 대가가 큰 건에 전문가 확정이 있는가
  • 공식 판단이 아님이 고지되는가
  • 전문가 수정이 개선으로 되돌아오는가

구조 — 참여 부품

  • 국민 — 자기 상황을 말하고 맞춤 안내를 받음
  • B1 직접 프롬프트 코파일럿 — 처방·안내 초안 생성
  • B3 지식 접지 상담 — 법령·조례·규정에 접지한 답변
  • C1 검토 큐 — 전문가가 처방을 확정
  • F7 한계·신뢰도 안내 — 공식 판단이 아님을 고지
  • F9 판정 근거 표시 — 추천·처방 사유를 보여 줌

변형

  • 전문가 확정 처방형: B1이 초안을 만들고 전문가가 전건 검토.
  • 법령·조례 안내형: B3가 법령·조례에 접지해 답함(경기도의회 법·조례 안내).
  • 추천·매칭형: 조건 점수화로 맞춤 프로그램·서비스를 추천(유형 ⑪).

C5 가드레일 필터 운영 컴포넌트

개인정보·환각·편향·형식 오류가 프롬프트나 산출물에 들어가지 못하게 시스템이 경계에서 걸러낸다. 비식별 전처리, 출처 검증, 구조적 출력 제약이 대표 변형이다.

PAX 사례 44건이 이 부품을 쓴다

맥락

외부 모델을 부르거나 대민에 답하는 모든 B 부품. 특히 E2 해외 상용 API, E5 S 이상 데이터, B3 지식 접지 상담, 유형 ① 대민 상담, ④ 기안, ⑥ 콘텐츠, ⑦ 대조·점검, ⑨ 인수인계, ⑬ 비식별·정제 도구.

맞서는 힘(긴장)

  • 차단의 엄격함 vs 과잉 차단으로 인한 유용성 저하
  • 비식별 강도 vs 문맥 보존
  • 결정적 검증의 신뢰성 vs 구현 범위

해법

프롬프트가 기관 밖으로 나가기 전 PII를 마스킹하고 원복 키를 보관하는 비식별 전처리기를 둔다. 응답에는 인용을 원본(법령정보센터·통계표 등)과 대조하는 출처 검증기와, JSON 스키마·허용 목록 같은 구조적 출력 제약을 건다. 근거가 없으면 답하지 않거나 '확인 필요'로 표시한다. 차단 사유는 C4에 남기고, 이용자에게는 F1 출처와 F7 한계 안내로 보인다. 사람이 하는 팩트체크·법무 심의는 C5가 아니라 C1.2에 둔다.

이럴 때 쓴다

  • E2 해외 상용 API로 행정망 본문이 외부로 나갈 때(필수)
  • E5 S 이상 개인정보·민감정보를 다룰 때
  • B3 대민 응답처럼 인용·수치의 정확성이 신뢰의 핵심일 때
  • C5가 필수인 유형 ①④⑥⑦⑨⑪⑬

이럴 때는 쓰지 않는다

  • E1 로컬 PC 완결로 데이터가 밖으로 나가지 않을 때 비식별은 불필요해질 수 있다(§5 매트릭스, 단 출처 검증은 별개)
  • 사람이 수행하는 심의만 있을 때(C1.2로 태그)
  • 적대적 입력 탐지가 목적일 때(S8)

얻는 것

  • 개인정보 외부 유출 차단
  • 환각 인용 감소
  • 상용 API 사용 조건 충족

점검표

  • 외부 전송 전 무엇이 걸러지는지 답할 수 있는가
  • 인용이 원본과 대조되는가
  • 근거 없을 때의 동작이 정해져 있는가
  • 차단 사유가 기록되는가

구조 — 참여 부품

  • 비식별 전처리기 — 외부 전송 전 PII 마스킹과 원복
  • 출처 검증기 — 인용을 원본과 대조해 환각을 걸러냄
  • 출력 제약 — 스키마·허용 목록·금칙어로 출력 형식 제한
  • F1 출처 표시 — 검증된 출처를 이용자에게 보임

변형

  • 로컬 비식별 전처리기: 외부 전송 전 PII 마스킹·원복(PAX에서 독립 부품으로 확인)
  • 출처 검증기: 인용을 법령정보센터·KCI·CrossRef 원본과 대조
  • 구조적 출력 제약·스키마 검증: JSON 스키마·허용 목록으로 출력 범위를 고정(v0.6 식별 신호 추가)

C9 평가 세트·회귀시험 운영 컴포넌트

배포 전에 업무 맥락의 질문·정답·채점 기준을 세트로 만들어, 프롬프트·모델·설정의 모든 변경을 같은 자로 재고 회귀를 잡는다.

PAX 사례 15건이 이 부품을 쓴다

맥락

모델·프롬프트·검색 설정이 바뀌는 모든 AI 부품. 특히 B3 지식 접지(검색 품질은 평가 없이 개선 불가), E2 상용 API(예고 없는 모델 업데이트), 유형 ①④⑤a⑦⑩⑫.

맞서는 힘(긴장)

  • 평가 세트 구축 비용 vs 변경의 안전
  • 사람 라벨의 정확성 vs LLM 심판의 규모
  • 세트 고정(비교 가능성) vs 업무 변화 반영(세트 갱신)

해법

RAG를 붙이거나 모델을 고르기 전에 업무 질문·정답·채점 기준(사람 라벨 + LLM 심판)을 세트로 만든다. 프롬프트·모델·설정 조합을 릴리스처럼 버전 관리하고, 모든 변경마다 같은 세트로 재평가해 점수표와 회귀 실패 목록을 남긴다. 기준을 넘지 못하면 배포하지 않는 게이트를 둔다. 학습 데이터와 평가 세트는 누수 없이 분리한다.

이럴 때 쓴다

  • RAG·튜닝을 붙이기 전(§7.1 4단계, §7.2 진행 경로 2단계)
  • E2 상용 API로 모델 업데이트가 예고 없이 올 때(필수)
  • 폐쇄망 로컬 모델의 교체 시점
  • C6 환류·C7 모델 교체를 하려 할 때(선행 조건)

이럴 때는 쓰지 않는다

  • B0 결정적 도구처럼 비결정적 출력이 없을 때
  • 유형 5a 중 순수 시각화(R10: 면제)

얻는 것

  • 변경의 효과와 회귀를 숫자로 확인
  • 모델 교체·재학습의 안전
  • 모델 선정 근거 확보

점검표

  • 업무 질문·정답·채점 기준 세트가 있는가
  • 프롬프트·모델·설정이 버전 관리되는가
  • 변경마다 재평가한 기록이 있는가
  • 기준 미달 시 배포를 막는 절차가 있는가

구조 — 참여 부품

변형

C7 폴백 스위치 운영 컴포넌트

모델·API·도구가 멈추거나 품질이 떨어질 때 대체 모델·규칙 기반 축소·수동 처리로 경로를 바꿔 서비스가 끊기지 않게 한다.

PAX 사례 12건이 이 부품을 쓴다

맥락

상용 API 또는 단일 모델에 의존하는 모든 B 부품. 특히 E2가 해외 상용 API이거나 B5처럼 상시 가동해야 하는 서비스.

맞서는 힘(긴장)

  • 가용성 vs 비용(대체 경로를 상시 유지하는 비용)
  • 품질 일관성 vs 대체 경로의 품질 저하
  • 자동 전환의 신속성 vs 전환 판단의 오작동 위험

해법

오류율·지연·단가 신호를 감시하다가 임계를 넘으면 재시도 → 기존 API → 대체 MCP → 대체 모델 → 규칙 기반 축소 → 수동 전환 순으로 경로를 바꾼다. 장애 범위는 격리(Bulkhead)로 한 부품에 가두고, 모델 교체는 무중단(Blue-Green)으로 한다. 전환은 C4 감사 로그에 남기고, 복구 후에는 원래 경로로 되돌리는 조건도 함께 정한다. 대체 경로의 품질 저하는 이용자에게 F7 한계 안내로 알린다.

이럴 때 쓴다

  • E2가 해외 상용 API이거나 혼합일 때
  • B5 현장 감지·경보처럼 상시 서비스일 때 필수
  • 대민 자동응답(B3 대민형)처럼 중단 비용이 큰 경우
  • 유형 ① 대민 상담(상시), ③ 현장 감시

이럴 때는 쓰지 않는다

  • B0 결정적 도구처럼 런타임 AI가 없을 때
  • 로컬 완결 도구로 외부 의존이 없을 때
  • 유형 ①·⑦에서 model_dependency가 없음(비LLM)일 때는 필수에서 면제(R7)

얻는 것

  • 핵심 서비스 연속성
  • 벤더 종속 완화(X4 예방)

점검표

  • 대체 경로가 최소 하나 구현되어 있는가
  • 전환 임계와 복귀 조건이 수치로 정의되어 있는가
  • 전환 이력이 로그로 남는가
  • 실증 기간에 전환을 1회 이상 실행한 기록이 있는가

구조 — 참여 부품

  • A2 모델 서빙 계층 — 주 경로와 대체 모델을 함께 노출하는 끼울 자리
  • 상태 감시기 — 오류율·지연을 임계와 비교해 전환을 결정
  • C4 감사 로그·지표 — 전환 시점·사유·복구를 기록
  • 수동 처리 담당자 — 모든 자동 경로가 실패했을 때의 최종 경로

변형

  • 대체 모델 전환: 상용 API 장애 시 다른 상용 모델 또는 로컬 오픈웨이트 모델(A2.2)로 전환
  • 규칙 기반 축소: AI 판정 대신 결정적 규칙·공식 템플릿으로 기능을 줄여 계속 운영(Fail-safe)
  • 수동 전환: 담당자 처리로 되돌리고 접수만 유지
  • 격리(Bulkhead): 장애가 난 부품의 영향 범위를 가둠
  • 무중단 교체(Blue-Green): 모델 업데이트를 병행 운영 후 전환하고 급락 시 이전 안정 모델로 복귀

X1 AI 스티커 안티패턴

기존 화면에 요약·챗봇 버튼만 붙이고 업무 순서와 사람·AI의 역할 분담은 그대로 두어, AI가 있어도 업무 산출물이 바뀌지 않는 함정이다.

맥락

기존 행정정보시스템·업무 포털에 AI 기능을 추가하는 과제, 특히 성과 지표가 'AI 기능 탑재 여부'나 호출 수로 잡힌 과제. R24에 따라 AI 런타임이 전혀 없는 순수 행정정보시스템도 이 태그(AI 무관)로 표기한다.

맞서는 힘(긴장)

  • 빠른 도입 실적 vs 업무 흐름 재설계 비용
  • 기존 시스템 무변경(안정성) vs 산출물 단위의 역할 분담
  • 'AI 탑재' 홍보 효과 vs 실제 처리시간·수정률 개선

해법

먼저 가치 흐름 규칙(R1)으로 사람 또는 국민이 최종으로 받는 핵심 산출물을 정하고, 그 산출물을 AI가 어떤 모양으로 분담할지 B 업무 컴포넌트를 하나 고른다(초안→사람 확정이면 B1, 근거 접지 답변이면 B3, 서류 추출이면 B4). 사람이 확정하는 지점은 C1 검토 큐로, 이용자가 고쳐 확정하는 면은 F2 편집 가능한 출력으로 명시한다. 흐름이 바뀌었는지는 C4 감사 로그·지표의 처리시간·수정률로 잰다. AI 런타임이 전혀 없는 행정정보시스템이라면 AI로 포장하지 말고 R24대로 B0·service_type 0·platform 공란·X1(AI 무관)으로 정직하게 분류한다.

이럴 때 쓴다

  • AI 기능이 추가됐다는 서술은 있으나 처리 단계 수·결재선·담당자 역할이 바뀌었다는 서술이 없다
  • 성과 지표가 AI 호출 수·이용 만족도뿐이고 처리시간·수정률 같은 산출물 지표가 없다
  • 챗봇이 기관 업무 데이터·시스템과 연결되지 않은 범용 대화에 머문다
  • AI 런타임이 전혀 없는 행정정보시스템이 AX 과제로 분류되어 있다(R24)

이럴 때는 쓰지 않는다

  • B1 코파일럿처럼 AI가 초안을 만들고 사람이 확정하는 역할 분담이 실제로 서술된 경우
  • B8 레거시 오버레이처럼 표준 시스템 위에 얹었지만 업무 산출물을 AI가 만들어 내는 경우
  • B0 결정적 도구가 반복 취합 업무를 실제로 줄이고 AI로 포장하지 않은 경우(Ready 부품으로 정직하게 분류된 경우)

얻는 것

  • 기존 시스템을 건드리지 않아 도입이 빠르고 장애 위험이 낮다
  • 'AI 탑재' 실적을 즉시 보고할 수 있다

점검표

  • AI 도입 전후 처리 단계·담당자 역할의 차이를 한 장으로 보여 줄 수 있는가
  • AI가 만드는 산출물과 사람이 확정하는 지점이 명시되어 있는가
  • 처리시간·수정률 같은 산출물 지표가 도입 전 기준선과 함께 있는가
  • AI 런타임이 없는데 AI 과제로 보고하고 있지 않은가

구조 — 참여 부품

  • 덧붙인 AI 기능 — 요약·대화 버튼. 업무 산출물 생산에 역할이 없음
  • B1 코파일럿 — 교정 후 초안→사람 확정으로 산출물 역할을 나누는 대체 부품
  • C1 검토 큐 — 교정 후 사람이 확정하는 지점을 명시
  • C4 감사 로그·지표 — 흐름이 실제로 바뀌었는지 처리시간·수정률로 측정

변형

  • 범용 챗봇 부착형: 업무 데이터와 연결되지 않은 범용 대화창을 포털에 부착
  • AI 무관 행정시스템(R24): AI 런타임이 전혀 없는 순수 행정정보시스템(예: 교육·인증 학습관리시스템). B0·service_type 0·platform 공란과 함께 X1(AI 무관)로 표기

  • 자체 모델 보유 인상 vs 검색으로 충분한 문제

해법

§7.2 진행 경로를 순서대로 밟는다. B1 직접 프롬프트에서 시작해 두 번째 단계에서 C9 평가 세트(업무 질문·정답·채점 기준)를 먼저 만들고, 이후 A9 규범 스킬·F4, B3 지식 접지(A1 데이터 자산), B3 검색 품질(Hybrid·Rewriting·Reranker), C5 가드레일·F1 순으로 붙이며 매 단계를 C9로 잰다. A2.3 튜닝은 진행 경로의 마지막 단계로, 검색·규범 스킬로 풀리지 않는다는 것이 C9 점수로 확인됐을 때만 한다. 모델·프롬프트·설정 조합은 릴리스처럼 버전 관리한다.

이럴 때 쓴다

  • RAG·튜닝을 도입했는데 업무 질문·정답·채점 기준 세트가 없다
  • '답변 품질 향상'을 수치 없이 서술하거나 단발 정확도만 보고한다
  • 자주 바뀌는 규정·매뉴얼 질의를 파인튜닝으로 풀었다
  • 검색 품질(재현율·리랭킹)을 재지 않고 튜닝으로 넘어갔다

이럴 때는 쓰지 않는다

  • C9 세트로 RAG 전후를 비교한 뒤 배포한 경우
  • 검색·스킬로 풀리지 않음을 C9 점수로 확인한 뒤 튜닝한 경우
  • B2·B4처럼 비LLM 학습 모델로 원래 학습이 해법인 경우(RAG가 대안이 아님)

얻는 것

  • RAG·튜닝이라는 눈에 보이는 기술 성과를 빨리 낸다
  • 평가 세트 구축에 현업 시간을 쓰지 않는다

점검표

  • 업무 질문·정답·채점 기준 세트가 있는가
  • RAG 전후 점수 비교가 있는가
  • 튜닝을 선택한 근거가 C9 점수로 설명되는가
  • 모델·프롬프트·설정 조합이 버전 관리되는가

구조 — 참여 부품

  • C9 평가 세트·회귀시험 — 빠진 부품. 모든 변경을 같은 자로 잼
  • B3 지식 접지 — 튜닝 전에 먼저 시도할 검색 기반 접지
  • A2.3 튜닝형 모델 — 진행 경로의 마지막 단계
  • A1 데이터 자산 서비스 — 정답 출처와 검색 코퍼스

변형

  • 평가 없는 RAG: 검색을 붙이고 몇 개 질문을 눈으로 보고 배포
  • RAG 없는 튜닝: 문서 검색으로 풀릴 최신 규정 질의를 파인튜닝으로 해결하려 함
  • 평가 없는 튜닝: 튜닝 전후를 같은 세트로 비교하지 않음

관련 부품
