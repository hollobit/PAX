판정 근거

보도자료 PDF·HWPX 한 건을 올리면 핵심 문구 추출→기획안→정부 디자인 가이드 준수 카드뉴스(한·영)→SNS 캡션→인스타그램 발행까지 15분에 끝내는 웹서비스. 산출물이 카드뉴스·인포그래픽 자체이므로 B7 콘텐츠 생성기. 단계가 고정 순서로 이어져 B′1 순차 파이프라인. PDF·HWPX 입력은 A10, 정부 디자인 가이드 준수를 규범으로 내장한 것은 A9, 공공 깃랩 공개는 A3, 담당관실 실무자 3인 자체 개발은 A7. LLM 사용은 분명하나 모델이 미상이라 LLM(모델 미상), A2.x 미태그. 인스타그램 발행까지 자동이므로 R8 판정 문장(대민 외부 공개 직행)에 따라 P2 시스템 쓰기; 사람 검수 게이트(C1)는 요약에 없어 태그하지 않음. 입력은 기관 보도자료라 신뢰 불가 입력 없음. 실무자 3인 팀 산출물이라 전이 단계는 부서 공유로 보정. 배포·발행에 인터넷이 필요하므로 인터넷망·인터넷 필수로 보정. URL 없음.

구현 단계

  1. 기관 문체·표현 윤리·서식을 A9 스타일 스킬로 정리하고 실패 사례를 규칙으로 추가한다.
  2. 입력 원자료(보도자료 HWPX 등)를 A10으로 받고, 기획 단계(B′8)에서 구성안을 먼저 확정한다.
  3. 형식 기준(길이·필수 항목·규격)을 수치로 정하고 반복 개선(B′6)에 최대 반복을 둔다.
  4. C5 저작권·사실검증과 C1 검수를 발행 전 관문으로 둔다.
  5. F3으로 여러 안과 부분 재생성을 제공하고, 발행 후 반응을 다음 기획에 반영한다.

점검표

  • 기관 스타일 규범이 스킬로 분리되어 있는가
  • 발행 전 사실·저작권 검수가 운영되는가
  • 반복 개선에 최대 반복 횟수가 있는가
  • 이용자가 일부만 다시 만들 수 있는가(F3)

환경 조건

E2 해외 상용 API 의존이 강하다(이미지 생성). E5는 O(공개) 자료가 대부분이라 제약이 적다. E4는 P1이 기본이며, 외부 공개로 직행하면 P2다. 적대적 위협은 참고 링크를 통한 유출 링크 삽입·설명문 인젝션이며 S8 독립 검증기가 필수다(§7.4 유형 ⑥).

주의할 점

  • 사실 오류·저작권 위험
  • 해외 상용 이미지 생성 API 의존(X4)
  • 유출 링크 삽입·설명문 인젝션 위협

보완이 필요한 필수 부품

이 조합에서 카탈로그가 함께 갖추라고 권하는 부품 가운데 아직 확인되지 않은 것이다.

  • C5 가드레일 필터 개인정보·환각·편향·형식 오류가 프롬프트나 산출물에 들어가지 못하게 시스템이 경계에서 걸러낸다. 비식별 전처리, 출처 검증, 구조적 출력 제약이 대표 변형이다.
  • C1 검토 큐 AI 산출물이 다음 단계로 넘어가기 전에 사람이 맞고 틀림을 확인·수정·확정하는 대기열을 두어, 오류가 업무 결과로 흘러가지 않게 한다.
  • F3 결과 대안·부분 재생성 한 요청에 여러 안을 주고 일부만 다시 만들게 해, 첫 결과가 마음에 들지 않을 때 전체를 다시 요청하지 않아도 되게 한다. B′6 반복 개선의 이용자 면이다.

피해야 할 안티패턴

  • X4 단일 모델 인질 상용 API 하나에 전 기능이 묶여 있어, 그 API가 멈추거나 바뀌면 무슨 일이 생기는지 아무도 답하지 못하는 함정이다. 대처: 모델 호출을 A2 모델 서빙 계층 뒤로 숨겨 B 부품이 특정 벤더 API를 직접 부르지 않게 한다. 그 위에 C7 폴백 스위치로 재시도 → 기존 API → 대체 MCP → 대체 모델(A2.2 주권형 로컬 등) → 규칙 기반 축소 → 수동 전환의 경로를 정하고 전환 이력을 C4에 남긴다. 모델 교체가 실제로 안전한지는 C9 평가 세트로 재어 버전을 고정한다. 모델 중립(BYO) 배포라면 A9 스킬 형태로 배포해 모델 교체 가능성 자체를 폴백으로 삼는다.
  • X12 상한 없는 반영 루프 생성자-비평가·반복 개선 루프에 최대 반복을 두지 않아, 품질은 그대로인데 토큰과 지연만 늘어나는 함정이다. 대처: B′5·B′6 루프에 최대 반복(2~3회)을 설정하고, 상한에 도달해도 기준을 못 넘으면 C1 검토 큐로 사람에게 넘긴다. A2 모델 서빙 계층에서 호출당 비용·P95 지연을 지표로 수집하고(C4), S1 단일 진입점에 요청·비용 상한을 둬 폭주를 막는다. 재생성이 필요 없는 판정 구조라면 B′9 결정론 판정 게이트처럼 재생성 없이 기각·강등만 하는 비루프 검증으로 바꾼다. 상한 값은 C9 평가 세트에서 반복 횟수별 점수를 재어 정한다.

해법

기관 인력이 AI 코딩 에이전트·저작도구·오픈소스로 직접 만들되, 처음부터 전이를 전제로 한다. 설정·데이터(연락처·업무분장 등)는 코드 밖 파일로 빼 비개발자도 고치게 하고, 작업 지시서 자체를 코딩 에이전트가 수행할 프롬프트로 설계해 제작 절차를 남긴다. MIT·Apache 등 라이선스를 명시하고 공공 깃랩(A3)이나 혁신24 자료실에 등재해 담당자가 바뀌어도 이어지게 한다. 실사용 건수로 성과를 재 기관 공식으로 올린다.

이럴 때 쓴다

  • 반복 업무를 줄이는 소규모 도구를 빠르게 만들 때
  • 용역 없이 작은 수정을 계속해야 할 때
  • 유형 8 취합·변환 자동화

이럴 때는 쓰지 않는다

  • P2 이상 시스템 쓰기·처분이 걸려 보안 검토·통제 부품이 먼저 필요한데 이를 갖출 수 없을 때
  • 라이선스·저장소·인수인계를 정할 수 없어 전이가 불가능할 때(X9 위험)

얻는 것

  • 제작 속도와 현장 적합성
  • 내부 유지보수 역량 축적
  • 무예산·소예산 제작

점검표

  • 라이선스가 명시되어 있는가
  • 저장소가 개인 PC가 아닌 공유 위치에 있는가
  • 담당자가 바뀌어도 고칠 수 있는 문서·설정 분리가 있는가
  • 실사용 지표가 있는가

A9 업무 규범 스킬 공통 서비스

보고서 구조·문체·서식·검증 절차 같은 업무 규범을 모델 중립 스킬(지침 + 검증기 + 출력 서식)로 패키징해 어떤 모델·에이전트에서든 재사용한다.

해법

규정집·매뉴얼·서식 예시에서 업무 규범을 뽑아 지침(구조·문체·금지 사항), 검증기(형식·인용·수치 검사), 출력 서식(HWPX·DOCX 등)으로 묶은 스킬 패키지로 만든다. 모델 호출 코드와 분리된 파일로 두어 어떤 코딩 에이전트·모델에서도 같은 절차가 돌게 한다(External Configuration). 산출·검증된 수치와 출처만 주입하고 미제공 수치·순위 생성을 금지하는 식으로 생성 범위를 규범으로 좁힌다. 스킬은 버전으로 관리해 규범 유출·변경을 추적하고, C9로 스킬 변경 전후 품질을 잰다.

이럴 때 쓴다

  • 산출물 서식·문체·구조가 정해져 있을 때
  • 출력 품질이 들쭉날쭉할 때(§7.5)
  • BYO 환경에서 모델과 무관하게 같은 절차를 돌려야 할 때
  • 갱신이 잦은 규범을 튜닝 없이 반영해야 할 때

이럴 때는 쓰지 않는다

  • 규범이 문서로 정리되지 않았고 정리할 담당도 없을 때
  • 지식 검색이 필요한 문제(B3 접지가 먼저)
  • 스킬 내용 자체가 민감해 배포할 수 없는데 버전 관리·접근 통제를 둘 수 없을 때

얻는 것

  • 출력 일관성
  • 모델 교체 가능(BYO에서는 교체 가능성이 곧 C7)
  • 타 기관 재사용
  • 튜닝 없이 규범 갱신

점검표

  • 규범이 모델 호출 코드와 분리된 파일로 있는가
  • 검증기가 출력 형식·인용·수치를 실제로 검사하는가
  • 스킬에 버전이 있는가
  • 다른 모델로 바꿔도 같은 서식이 나오는지 확인했는가

A10 문서 형식 어댑터 공통 서비스

HWP·HWPX·엑셀·한셀·PDF 같은 한국 공공 문서 형식을 AI 부품이 읽고(구조화) 쓰게(서식 생성) 하는 변환 계층이다.

해법

입력 쪽에서는 HWPX 압축 구조·PDF에서 조·항·호·별표 계층과 표를 보존해 구조화 텍스트·표로 바꾸고, 머리말·각주 같은 잡음을 걷어 조항 단위로 정규화한다. 출력 쪽에서는 스킬(A9)의 출력 서식을 받아 HWPX·XLSX 기안 서식을 역방향으로 생성한다. 민감 문서는 PC 밖으로 보내지 않도록 로컬에서 변환하고, 파서를 라이브러리·CLI·MCP로 함께 제공하면 다른 부품과 기관이 그대로 쓴다. 형식 변환 정확도는 C9 판정 체계로 잰다.

이럴 때 쓴다

  • 입력이 HWP·HWPX·엑셀·PDF 공공 문서일 때
  • 산출물을 기안·보고 서식으로 내보내야 할 때
  • 유형 2·4·8 조립

이럴 때는 쓰지 않는다

  • 스캔 이미지·음성처럼 인식이 필요한 입력은 B4 인식 파이프라인(OCR·STT)
  • 입출력이 이미 정형 데이터·API인 경우

얻는 것

  • 공공 문서를 AI 입력·출력으로 연결
  • 기관 간 재사용 가능한 공통 부품
  • 로컬 처리로 무반출

점검표

  • 표·조항 계층이 변환 후에도 보존되는가
  • 출력이 기관 기안 서식 그대로 열리는가
  • 민감 문서가 변환 과정에서 PC 밖으로 나가지 않는가
  • 변환 정확도 판정 기록이 있는가

A3 공공 API 제공자 공통 서비스

정부·공공이 운영하는 모델·데이터·개발 도구(범정부 AI 공통기반, 모두의 AI 실험실, 공공데이터포털, 공공 깃랩)를 범정부 Provider로 소비한다.

해법

기반을 새로 만들기 전에 범정부 AI 공통기반(모델), 공공데이터포털·법령 API(데이터), 모두의 AI 실험실·공공 깃랩(개발·실험 환경)에서 먼저 찾아 소비한다. 인증은 GPKI·디지털원패스 같은 연합 신원(Federated Identity)으로 위임하고, 공공 API 응답은 출처·조회 시각과 함께 업무 부품에 넘긴다. 에이전트가 부를 수 있게 하려면 A8 MCP 서버로 감싸고, 결과를 재가공해 기준선으로 고정하면 A1을 더한다. 기관이 만든 도구는 공공 깃랩에 등재해 다음 기관의 Provider가 되게 한다.

이럴 때 쓴다

  • 모델·데이터·개발 환경을 기관이 새로 만들려 할 때 — 먼저 Provider 확인
  • 법령·기준 원문을 최신으로 대조해야 하는 유형 7
  • 여러 부서가 같은 기반을 따로 만들고 있을 때(X3 교정)

이럴 때는 쓰지 않는다

  • 필요한 모델·데이터가 공공 Provider에 없을 때(만들고 레지스트리에 올림)
  • 타 기관 데이터를 계약·키 매핑으로 결합하는 경우는 A4

얻는 것

  • 기관별 중복 구축 방지(X3 교정)
  • 공인된 원천 데이터·모델 사용
  • 등재를 통해 전이 경로 확보

점검표

  • 같은 기반을 기관 안에서 따로 만들지 않았는가
  • 공공 API 응답의 출처·조회 시각이 결과에 남는가
  • API 장애·변경 시 어떻게 되는지 답할 수 있는가
  • 만든 도구가 공공 깃랩 등에 등재되었는가

D8.10 발간·홍보 서비스 블록

보도자료·카드뉴스·포스터·정보지를 기획부터 발행까지 만드는 내부 운영 블록이다. B7 콘텐츠 제작의 업무 블록 버전이다.

해법

B7 콘텐츠 제작을 B′8 계획-실행(기획 → 구성 → 생성 → 편집)과 B′6 반복 개선으로 배선하고, 반복 상한을 둔다. 기관 스타일은 A9 스타일 스킬로 패키징하고, 보도자료 입력은 A10(HWPX)으로 읽는다. 발행 전에는 C5 저작권·사실 검증과 C1 검수를 필수로 두고, 필요하면 C1.2 심의 게이트(법무·표시광고)를 더한다. 출력은 F2 편집 가능(PPTX·피그마 등)과 F3 대안·부분 재생성으로 담당자가 고치게 한다. S8 독립 검증기로 유출 링크·사실 오류를 거른다.

이럴 때 쓴다

  • 보도자료를 여러 발행 형식으로 반복 제작할 때
  • 기관 스타일을 여러 담당자가 일관되게 써야 할 때
  • 외부 디자인 용역 의존을 줄이고 싶을 때

이럴 때는 쓰지 않는다

  • 내부 보고서·공문 첫 판이면 D8.3
  • 발행 없이 자료 요약만 하면 D8.2
  • 국민에게 개인 맞춤 안내를 주면 D7

얻는 것

  • 발행물 제작 시간 단축
  • 기관 스타일 일관성
  • 외부 용역 의존 감소

점검표

  • 발행 전 사람 검수가 필수로 걸려 있는가
  • 사실·저작권 검증 절차가 있는가
  • 결과를 편집 가능한 형식으로 고칠 수 있는가
  • 반복 개선에 상한이 있는가

C5 가드레일 필터 운영 컴포넌트

개인정보·환각·편향·형식 오류가 프롬프트나 산출물에 들어가지 못하게 시스템이 경계에서 걸러낸다. 비식별 전처리, 출처 검증, 구조적 출력 제약이 대표 변형이다.

해법

프롬프트가 기관 밖으로 나가기 전 PII를 마스킹하고 원복 키를 보관하는 비식별 전처리기를 둔다. 응답에는 인용을 원본(법령정보센터·통계표 등)과 대조하는 출처 검증기와, JSON 스키마·허용 목록 같은 구조적 출력 제약을 건다. 근거가 없으면 답하지 않거나 '확인 필요'로 표시한다. 차단 사유는 C4에 남기고, 이용자에게는 F1 출처와 F7 한계 안내로 보인다. 사람이 하는 팩트체크·법무 심의는 C5가 아니라 C1.2에 둔다.

이럴 때 쓴다

  • E2 해외 상용 API로 행정망 본문이 외부로 나갈 때(필수)
  • E5 S 이상 개인정보·민감정보를 다룰 때
  • B3 대민 응답처럼 인용·수치의 정확성이 신뢰의 핵심일 때
  • C5가 필수인 유형 ①④⑥⑦⑨⑪⑬

이럴 때는 쓰지 않는다

  • E1 로컬 PC 완결로 데이터가 밖으로 나가지 않을 때 비식별은 불필요해질 수 있다(§5 매트릭스, 단 출처 검증은 별개)
  • 사람이 수행하는 심의만 있을 때(C1.2로 태그)
  • 적대적 입력 탐지가 목적일 때(S8)

얻는 것

  • 개인정보 외부 유출 차단
  • 환각 인용 감소
  • 상용 API 사용 조건 충족

점검표

  • 외부 전송 전 무엇이 걸러지는지 답할 수 있는가
  • 인용이 원본과 대조되는가
  • 근거 없을 때의 동작이 정해져 있는가
  • 차단 사유가 기록되는가

C1 검토 큐 운영 컴포넌트

AI 산출물이 다음 단계로 넘어가기 전에 사람이 맞고 틀림을 확인·수정·확정하는 대기열을 두어, 오류가 업무 결과로 흘러가지 않게 한다.

해법

AI 산출물에 신뢰도·근거를 붙여 검토 대기열에 올리고, 검토자가 승인·수정·반려 중 하나를 고르게 한다. 수정·반려 내역은 C4 감사 로그에 남겨 수정률을 집계하고 C6 환류의 입력으로 쓴다. 검토 화면은 원문 위치·근거를 함께 보여 줘 확인 비용을 줄인다. 전건 검토로 시작하되, 수정률 실측이 쌓이면 C2 위험도 라우터로 저위험 건을 자동 종결하는 단계로 옮긴다.

이럴 때 쓴다

  • AI 산출물이 공문·처분·대민 안내로 그대로 이어질 때
  • E4가 P1 이상이고 되돌리는 데 사람 시간이 많이 드는 조치가 있을 때
  • 서비스 유형 ② 접수·심사, ④ 기안 코파일럿, ⑥ 콘텐츠 제작, ⑦ 대조·점검, ⑩ 위험 예측, ⑪ 추천·매칭, ⑫ 개발 코파일럿처럼 C1이 필수인 유형

이럴 때는 쓰지 않는다

  • B0 결정적 도구처럼 런타임 AI 산출물이 없을 때
  • 쉽게 되돌릴 수 있고 저위험인 조치를 이미 C2로 자동 종결하도록 실측 근거를 갖춘 구간(전건 검토를 영원히 남기지 않는다)

얻는 것

  • 오류가 업무 결과로 나가기 전에 차단
  • 책임 소재가 명확해짐
  • 수정 내역이 C4 지표와 C6 환류의 원천 데이터가 됨

점검표

  • AI 산출물이 확정 전 상태로 머무는 지점이 명시되어 있는가
  • 검토자와 승인·수정·반려 선택지가 정해져 있는가
  • 검토 결정과 수정 내역이 로그로 남는가
  • 실증 기간의 검토·수정 건수가 기록되어 있는가
  • 전건 검토에서 분기로 옮길 조건이 정해져 있는가

관련 부품

C2 다음 단계 — 전건 검토에서 위험도 분기로 승급 · C1.2 변형 — 제3자 전문가 심의 게이트 · F2 이용자 쪽 대응 — 검토자가 직접 고치는 화면 · F6 이용자 쪽 대응 — 에이전트 행동 실행 전 확인 · C4 기록처 — 검토 결정·수정 내역 · C6 후속 — 수정 내역이 환류의 입력

F3 결과 대안·부분 재생성 상호작용 패턴

한 요청에 여러 안을 주고 일부만 다시 만들게 해, 첫 결과가 마음에 들지 않을 때 전체를 다시 요청하지 않아도 되게 한다. B′6 반복 개선의 이용자 면이다.

해법

한 요청에 복수의 안을 제시하고, 이용자가 고른 안의 일부(문단·장면·항목)만 선택해 다시 생성하게 한다. 재생성은 나머지 부분의 맥락을 유지한 채 수행한다. 반복 횟수에는 상한을 두어 비용 폭주를 막는다.

이럴 때 쓴다

  • 콘텐츠·문안처럼 정답이 하나가 아닌 산출물
  • 유형 ⑥ 콘텐츠 제작, ⑪ 추천·매칭(F3 필수), ④ 기안

이럴 때는 쓰지 않는다

  • 판정·조회처럼 답이 하나여야 하는 업무
  • 재생성이 결과를 흔들어 일관성을 해치는 공식 판단

얻는 것

  • 첫 결과 불만족 흡수
  • 맞은 부분을 보존한 채 수정

점검표

  • 복수 안 또는 부분 재생성이 가능한가
  • 재생성 시 나머지 맥락이 유지되는가
  • 반복 상한이 있는가

관련 부품

B′6 시스템 쪽 대응 — 반복 개선 · F2 짝 — 대안 선택 후 직접 편집 · B7 끼울 자리 — 콘텐츠 생성기 · F8 짝 — 이전 결과로 되돌리기

X4 단일 모델 인질 안티패턴

상용 API 하나에 전 기능이 묶여 있어, 그 API가 멈추거나 바뀌면 무슨 일이 생기는지 아무도 답하지 못하는 함정이다.

해법

모델 호출을 A2 모델 서빙 계층 뒤로 숨겨 B 부품이 특정 벤더 API를 직접 부르지 않게 한다. 그 위에 C7 폴백 스위치로 재시도 → 기존 API → 대체 MCP → 대체 모델(A2.2 주권형 로컬 등) → 규칙 기반 축소 → 수동 전환의 경로를 정하고 전환 이력을 C4에 남긴다. 모델 교체가 실제로 안전한지는 C9 평가 세트로 재어 버전을 고정한다. 모델 중립(BYO) 배포라면 A9 스킬 형태로 배포해 모델 교체 가능성 자체를 폴백으로 삼는다.

이럴 때 쓴다

  • E2가 해외 상용 API인데 C7 폴백이 없다(분류기준 검증 경고 조건)
  • 'API가 멈추면 어떻게 되는가'에 대한 서술이 없다
  • 모델 버전 고정·교체 시험 기록이 없다
  • A2 게이트웨이 없이 B 부품이 벤더 API를 직접 호출한다

이럴 때는 쓰지 않는다

  • B0 결정적 도구처럼 런타임 AI가 없는 경우
  • 로컬 완결 도구로 외부 의존이 없는 경우
  • 모델 중립(BYO) 배포로 A9 스킬 형태라 이용자가 모델을 바꿀 수 있는 경우
  • 상용 API를 쓰되 A2 게이트웨이와 C7 대체 경로가 구현된 경우

얻는 것

  • 가장 성능 좋은 모델을 가장 빨리 쓴다
  • 게이트웨이·대체 모델 유지 비용이 없다

점검표

  • 모든 모델 호출이 A2 한 곳을 지나는가
  • 대체 경로가 하나 이상 구현되어 있는가
  • 대체 모델의 품질이 C9로 측정되어 있는가
  • 모델 버전이 고정되어 있고 교체가 릴리스처럼 관리되는가

관련 부품

C7 대체 — 장애 시 이어 가는 폴백 경로 · A2 끼울 자리 — 벤더 API를 숨기는 모델 서빙 계층 · A2.2 대체 모델 후보 — 주권형 로컬 · C9 선행 — 대체 모델 품질 확인과 버전 고정 · A9 BYO 배포에서의 대응 — 스킬 형태면 모델 교체 가능

참고 자료

Gulli ch.12 Exception Handling · Microservice Circuit Breaker · PAX Native 관문 4

X12 상한 없는 반영 루프 안티패턴

생성자-비평가·반복 개선 루프에 최대 반복을 두지 않아, 품질은 그대로인데 토큰과 지연만 늘어나는 함정이다.

해법

B′5·B′6 루프에 최대 반복(2~3회)을 설정하고, 상한에 도달해도 기준을 못 넘으면 C1 검토 큐로 사람에게 넘긴다. A2 모델 서빙 계층에서 호출당 비용·P95 지연을 지표로 수집하고(C4), S1 단일 진입점에 요청·비용 상한을 둬 폭주를 막는다. 재생성이 필요 없는 판정 구조라면 B′9 결정론 판정 게이트처럼 재생성 없이 기각·강등만 하는 비루프 검증으로 바꾼다. 상한 값은 C9 평가 세트에서 반복 횟수별 점수를 재어 정한다.

이럴 때 쓴다

  • B′5·B′6 루프의 종료 조건이 '통과할 때까지'뿐이고 최대 반복이 없다
  • 호출당 비용·지연 지표가 없다
  • 반복 횟수별 품질 변화를 잰 기록이 없다
  • 비용·지연 폭주가 관측되었다

이럴 때는 쓰지 않는다

  • 최대 반복(2~3회)과 상한 도달 시 처리 경로가 정해진 경우
  • B′9처럼 재생성 없이 기각·강등만 하는 비루프 검증
  • 반복이 사람의 수동 요청(F3 부분 재생성)으로만 일어나는 경우

얻는 것

  • 구현이 단순하고 '품질이 나올 때까지 돈다'는 설명이 쉽다
  • 가끔 추가 반복으로 품질이 오른다

점검표

  • 모든 루프에 최대 반복이 있는가
  • 상한 도달 시 사람에게 넘기는 경로가 있는가
  • 지난달 호출당 비용과 P95 지연을 말할 수 있는가
  • 상한 값이 C9 측정으로 정해졌는가

관련 부품

B′5 교정 대상 — 반복 상한 2~3회 · B′6 교정 대상 — 최대 반복 필수 · B′9 대안 — 재생성 없는 비루프 검증 · A2 기록처 — 호출당 비용·지연 지표 · S1 끼울 자리 — 요청·비용 상한(denial-of-wallet 방어)
