판정 근거

소방기술민원 관련 법령·유사 민원·참고자료를 검색해 참고용 답변 초안을 생성하는 RAG 서비스로, 관리자용 요청·승인·적재 절차가 있어 C1을 present로 판정했다. '공식 유권해석이나 법적 판단을 제공하지 않는다'는 명시적 고지가 F7, 근거 법령·유사 민원 인용이 F1에 해당한다. GPT API를 호출하는 해외 상용 API 의존인데 평가 데이터셋·회귀 테스트나 폴백 전환 근거가 보고서에 없어 C9·C7을 planned로 낮췄다. 평가 없는 RAG(X10)로 안티패턴을 태그했다.

구현 가이드

주 패턴 B3 지식 접지 상담을 구현할 때

구현 단계

  1. 대표 질문·정답·채점 기준으로 C9 평가 세트를 먼저 만든다.
  2. A1로 코퍼스를 정리하고 데이터 등급(E5)과 공개 범위를 메타로 붙인다. 등급 문서가 섞이면 S2 권한 인식 검색을 둔다.
  3. E1에 맞게 임베딩·벡터DB·모델 위치를 정한다(폐쇄망이면 전부 로컬, A2.2·A2.4).
  4. 근거 밖 답변 금지·출처 상시 표시·근거 없으면 이관하는 규칙을 C5·F1·B′2로 구현한다.
  5. 검색 품질 3패턴을 하나씩 붙이며 C9로 재고, 문서 갱신 주기를 C6으로 운영한다.

점검표

  • 답마다 출처가 표시되는가
  • 근거가 없을 때 답하지 않고 이관하는가
  • 평가 세트로 검색·답변 품질을 재고 있는가
  • 코퍼스 갱신 주기와 책임자가 정해져 있는가

환경 조건

E1 폐쇄망·행정망이면 임베딩·벡터DB·모델 전부 로컬(A2.2 주권형 또는 A2.4 내부망 프록시 + 로컬 임베딩). E2 해외 상용 API면 C5 비식별 전처리와 C7 폴백이 필수다. E4는 P0~P1이 기본이다. 신뢰 불가 입력(민원 입력·공개 웹)을 읽고 P2 이상이면 S6 문서별 격리와 S2가 필요하다. 대민형은 S4·S7이 권장된다(§7.4).

주의할 점

  • 평가 없이 붙이면 품질을 알 수 없음(X10)
  • 코퍼스 갱신이 멈추면 오답이 됨
  • 부서마다 따로 만들면 중복(X3)
  • 대민형은 인젝션·유출 위협에 노출

기본 배선 예

A1 → A2.2 → B3 (B′7 · B′2) → F1 · B3 → C2 → 담당자 이관

피해야 할 안티패턴

  • X10 평가 없는 RAG, RAG 없는 튜닝 (이 사례에서 확인) 평가 세트 없이 검색을 붙여 '좋아진 것 같다'로 배포하고, 검색으로 풀릴 문제를 파인튜닝으로 푸는, 진행 경로를 건너뛰는 함정이다. 대처: §7.2 진행 경로를 순서대로 밟는다. B1 직접 프롬프트에서 시작해 두 번째 단계에서 C9 평가 세트(업무 질문·정답·채점 기준)를 먼저 만들고, 이후 A9 규범 스킬·F4, B3 지식 접지(A1 데이터 자산), B3 검색 품질(Hybrid·Rewriting·Reranker), C5 가드레일·F1 순으로 붙이며 매 단계를 C9로 잰다. A2.3 튜닝은 진행 경로의 마지막 단계로, 검색·규범 스킬로 풀리지 않는다는 것이 C9 점수로 확인됐을 때만 한다. 모델·프롬프트·설정 조합은 릴리스처럼 버전 관리한다.
  • X3 부서마다 챗봇 같은 기관의 과제들이 각자 모델·벡터DB·프롬프트를 따로 만들어, 공유할 수 있는 기반 부품을 부서 수만큼 중복 구축하는 함정이다. 대처: §7.1의 두 번째 단계대로 기반 부품은 새로 만들지 말고 Provider에서 먼저 가져온다. 모델 호출은 A2 모델 서빙 계층(범정부 AI 공통기반 또는 기관 게이트웨이) 뒤로 모으고, S1 단일 진입점에서 인증·요청 상한·비용 상한·감사 기록을 일괄 적용한다. 공공 API·공공 클라우드·공공 깃랩은 A3 공공 API 제공자로 쓴다. 부서별 차이는 모델을 따로 두지 말고 A9 업무 규범 스킬과 부서 코퍼스(A1)로 표현하며, 부서·등급별 코퍼스 분리가 필요하면 S2 권한 인식 검색으로 푼다. 없어서 새로 만든 부품은 §13 참조 구현 레지스트리에 올린다.

이 사례에 쓰인 패턴

B3 지식 접지 상담 업무 컴포넌트

기관 규정·매뉴얼·사례 문서에 접지(RAG)해 질문에 답하고, 답마다 출처를 붙이며, 근거가 없으면 답하지 않고 담당자에게 넘긴다.

해법

기관 문서를 A1 자산으로 정리해 임베딩·색인하고, 질문이 오면 검색한 근거 범위 안에서만 모델이 답하게 한다. 답에는 출처(F1)를 상시 붙이고, 근거가 없으면 '확인 불가'로 답하거나 담당자·소관기관으로 이관한다(B′2). 검색 품질은 Hybrid Retriever·Query Rewriting·Reranker로 높이되, 변경마다 C9 평가 세트로 잰다. 대민형은 한계 안내(F7)와 폴백(C7)을 두고, 문서 갱신 주기를 C6으로 정한다.

이럴 때 쓴다

  • 같은 질문이 반복되고 답의 근거가 기관 문서에 있을 때
  • 답변에 조문·문서 출처를 반드시 붙여야 할 때
  • 유형 ① 대민 상담·안내, 유형 ⑦ 법령 접지 점검

이럴 때는 쓰지 않는다

  • 평가 세트가 없어 검색 품질을 잴 수 없을 때(먼저 C9, X10)
  • 질문 유형이 몇 개로 정해져 행동 선택기(S4)나 규칙 조회로 충분할 때
  • 문서를 요약해 초안을 쓰는 것이 핵심이면(B1)

얻는 것

  • 답변에 근거를 댈 수 있음
  • 반복 질의 처리 시간 단축
  • 범정부 엔진 + 기관별 코퍼스로 공유 가능

점검표

  • 답마다 출처가 표시되는가
  • 근거가 없을 때 답하지 않고 이관하는가
  • 평가 세트로 검색·답변 품질을 재고 있는가
  • 코퍼스 갱신 주기와 책임자가 정해져 있는가

관련 부품

A2.1 모델 서빙 · 상용 API 호출 공통 서비스

GPT·Gemini·Claude·HyperCLOVA X·Upstage 등 상용 모델 API를 서빙 계층을 거쳐 호출해 자체 인프라 없이 최신 모델 성능을 쓴다.

해법

업무 코드는 서빙 계층만 부르고, 서빙 계층이 상용 API를 호출한다. 행정망 본문이 나가는 경로 앞에는 C5 비식별 전처리를 두고, 대체 모델을 등록해 C7 폴백을 건다(§5 매트릭스 E2 해외 상용 API 행). 모델 버전을 고정하고 모델·프롬프트·설정 조합을 릴리스처럼 관리해 업데이트 전후를 C9로 비교한다. 비용이 문제면 라우팅·캐싱으로 큰 모델 호출을 줄인다. E5가 S 이상이면 이 변형 단독으로는 안 되고 A2.4 내부망 프록시를 거친다.

이럴 때 쓴다

  • 인터넷망·클라우드 환경이고 데이터 등급이 O이거나 비식별 후 전송 가능할 때
  • PoC 초기에 모델 성능을 빠르게 확인해야 할 때
  • 자체 GPU·운영 인력이 없을 때

이럴 때는 쓰지 않는다

  • E1이 폐쇄망이면 조립 오류(A2.2·A2.4로)
  • E5가 S 이상인데 내부망 프록시가 없을 때(A2.4 필수)
  • 상시 서비스인데 대체 경로를 둘 수 없을 때

얻는 것

  • 인프라 없이 최신 모델 성능
  • 빠른 PoC
  • 벤더의 지속적 개선

점검표

  • 업무 코드가 상용 API를 직접 부르지 않는가
  • 외부로 나가는 프롬프트에서 무엇이 걸러지는지 답할 수 있는가
  • API 장애 시 대체 경로가 있는가
  • 모델 버전과 호출당 비용·지연이 기록되는가

관련 부품

C7 필수 짝 — 상용 API 의존이면 폴백 필수 · C5 선행 — 외부 전송 전 비식별 · A2.4 대안 — 행정망·민감 등급일 때 중계 경유 · C9 짝 — 모델 업데이트 회귀시험

A1 데이터 자산 서비스 공통 서비스

흩어진 업무 기록을 정제·라벨링해 AI 부품이 붙여 쓸 수 있는 데이터셋·라벨·데이터 사전 형태의 기준선으로 제공한다.

해법

원천 기록을 수집→정제(중복·결측 처리)→라벨링→정의 문서화 순으로 가공하고, 결과를 정제 데이터셋·라벨·데이터 사전의 세 산출물로 고정해 제공한다. 'N건→M건 정제'처럼 정제 전후 규모와 기준을 기록하고, 변수·테이블·인터페이스 정의서로 소비 부품이 같은 정의를 쓰게 한다. 기준선은 버전으로 관리해 C9 평가 세트의 정답 출처와 C6 재학습의 입력으로 재사용한다. 데이터 경계는 부품별로 두고(DB per Service), 타 기관 데이터와의 결합은 A4로 분리한다.

이럴 때 쓴다

  • 예측·추천기(B2)나 비전 모델(A2.5)을 학습·재학습할 때
  • 지식 접지(B3)의 코퍼스를 구축할 때
  • 평가 세트(C9)의 정답 출처가 필요할 때
  • 서비스 유형 5a-agg·9·10·11처럼 A1이 필수인 조립

이럴 때는 쓰지 않는다

  • 공공 API 응답을 가공 없이 조회만 할 때(A3)
  • 정제·정의 없이 파일을 올려 바로 검색하는 경우(태그 대상 아님)
  • 타 기관 데이터 결합이 핵심일 때는 A4를 함께 태그해 계약·키 매핑을 따로 드러낸다

얻는 것

  • 모델 교체와 무관하게 남는 기관 자산
  • C9·C6·B3가 같은 기준선을 재사용
  • 데이터 사전이 기관 간 표준 확산의 단위가 됨

점검표

  • 정제 전후 규모와 정제 기준이 기록되어 있는가
  • 데이터 사전(정의·단위·출처)이 있는가
  • 기준선에 버전이 있고 평가용 분할이 학습용과 분리되어 있는가
  • 데이터 등급(E5)에 맞는 가명·비식별 처리가 적용되었는가

관련 부품

C1 검토 큐 운영 컴포넌트

AI 산출물이 다음 단계로 넘어가기 전에 사람이 맞고 틀림을 확인·수정·확정하는 대기열을 두어, 오류가 업무 결과로 흘러가지 않게 한다.

해법

AI 산출물에 신뢰도·근거를 붙여 검토 대기열에 올리고, 검토자가 승인·수정·반려 중 하나를 고르게 한다. 수정·반려 내역은 C4 감사 로그에 남겨 수정률을 집계하고 C6 환류의 입력으로 쓴다. 검토 화면은 원문 위치·근거를 함께 보여 줘 확인 비용을 줄인다. 전건 검토로 시작하되, 수정률 실측이 쌓이면 C2 위험도 라우터로 저위험 건을 자동 종결하는 단계로 옮긴다.

이럴 때 쓴다

  • AI 산출물이 공문·처분·대민 안내로 그대로 이어질 때
  • E4가 P1 이상이고 되돌리는 데 사람 시간이 많이 드는 조치가 있을 때
  • 서비스 유형 ② 접수·심사, ④ 기안 코파일럿, ⑥ 콘텐츠 제작, ⑦ 대조·점검, ⑩ 위험 예측, ⑪ 추천·매칭, ⑫ 개발 코파일럿처럼 C1이 필수인 유형

이럴 때는 쓰지 않는다

  • B0 결정적 도구처럼 런타임 AI 산출물이 없을 때
  • 쉽게 되돌릴 수 있고 저위험인 조치를 이미 C2로 자동 종결하도록 실측 근거를 갖춘 구간(전건 검토를 영원히 남기지 않는다)

얻는 것

  • 오류가 업무 결과로 나가기 전에 차단
  • 책임 소재가 명확해짐
  • 수정 내역이 C4 지표와 C6 환류의 원천 데이터가 됨

점검표

  • AI 산출물이 확정 전 상태로 머무는 지점이 명시되어 있는가
  • 검토자와 승인·수정·반려 선택지가 정해져 있는가
  • 검토 결정과 수정 내역이 로그로 남는가
  • 실증 기간의 검토·수정 건수가 기록되어 있는가
  • 전건 검토에서 분기로 옮길 조건이 정해져 있는가

관련 부품

C2 다음 단계 — 전건 검토에서 위험도 분기로 승급 · C1.2 변형 — 제3자 전문가 심의 게이트 · F2 이용자 쪽 대응 — 검토자가 직접 고치는 화면 · F6 이용자 쪽 대응 — 에이전트 행동 실행 전 확인 · C4 기록처 — 검토 결정·수정 내역 · C6 후속 — 수정 내역이 환류의 입력

C5 가드레일 필터 운영 컴포넌트

개인정보·환각·편향·형식 오류가 프롬프트나 산출물에 들어가지 못하게 시스템이 경계에서 걸러낸다. 비식별 전처리, 출처 검증, 구조적 출력 제약이 대표 변형이다.

해법

프롬프트가 기관 밖으로 나가기 전 PII를 마스킹하고 원복 키를 보관하는 비식별 전처리기를 둔다. 응답에는 인용을 원본(법령정보센터·통계표 등)과 대조하는 출처 검증기와, JSON 스키마·허용 목록 같은 구조적 출력 제약을 건다. 근거가 없으면 답하지 않거나 '확인 필요'로 표시한다. 차단 사유는 C4에 남기고, 이용자에게는 F1 출처와 F7 한계 안내로 보인다. 사람이 하는 팩트체크·법무 심의는 C5가 아니라 C1.2에 둔다.

이럴 때 쓴다

  • E2 해외 상용 API로 행정망 본문이 외부로 나갈 때(필수)
  • E5 S 이상 개인정보·민감정보를 다룰 때
  • B3 대민 응답처럼 인용·수치의 정확성이 신뢰의 핵심일 때
  • C5가 필수인 유형 ①④⑥⑦⑨⑪⑬

이럴 때는 쓰지 않는다

  • E1 로컬 PC 완결로 데이터가 밖으로 나가지 않을 때 비식별은 불필요해질 수 있다(§5 매트릭스, 단 출처 검증은 별개)
  • 사람이 수행하는 심의만 있을 때(C1.2로 태그)
  • 적대적 입력 탐지가 목적일 때(S8)

얻는 것

  • 개인정보 외부 유출 차단
  • 환각 인용 감소
  • 상용 API 사용 조건 충족

점검표

  • 외부 전송 전 무엇이 걸러지는지 답할 수 있는가
  • 인용이 원본과 대조되는가
  • 근거 없을 때의 동작이 정해져 있는가
  • 차단 사유가 기록되는가

관련 부품

C7 폴백 스위치 운영 컴포넌트

모델·API·도구가 멈추거나 품질이 떨어질 때 대체 모델·규칙 기반 축소·수동 처리로 경로를 바꿔 서비스가 끊기지 않게 한다.

해법

오류율·지연·단가 신호를 감시하다가 임계를 넘으면 재시도 → 기존 API → 대체 MCP → 대체 모델 → 규칙 기반 축소 → 수동 전환 순으로 경로를 바꾼다. 장애 범위는 격리(Bulkhead)로 한 부품에 가두고, 모델 교체는 무중단(Blue-Green)으로 한다. 전환은 C4 감사 로그에 남기고, 복구 후에는 원래 경로로 되돌리는 조건도 함께 정한다. 대체 경로의 품질 저하는 이용자에게 F7 한계 안내로 알린다.

이럴 때 쓴다

  • E2가 해외 상용 API이거나 혼합일 때
  • B5 현장 감지·경보처럼 상시 서비스일 때 필수
  • 대민 자동응답(B3 대민형)처럼 중단 비용이 큰 경우
  • 유형 ① 대민 상담(상시), ③ 현장 감시

이럴 때는 쓰지 않는다

  • B0 결정적 도구처럼 런타임 AI가 없을 때
  • 로컬 완결 도구로 외부 의존이 없을 때
  • 유형 ①·⑦에서 model_dependency가 없음(비LLM)일 때는 필수에서 면제(R7)

얻는 것

  • 핵심 서비스 연속성
  • 벤더 종속 완화(X4 예방)

점검표

  • 대체 경로가 최소 하나 구현되어 있는가
  • 전환 임계와 복귀 조건이 수치로 정의되어 있는가
  • 전환 이력이 로그로 남는가
  • 실증 기간에 전환을 1회 이상 실행한 기록이 있는가

관련 부품

C9 평가 세트·회귀시험 운영 컴포넌트

배포 전에 업무 맥락의 질문·정답·채점 기준을 세트로 만들어, 프롬프트·모델·설정의 모든 변경을 같은 자로 재고 회귀를 잡는다.

해법

RAG를 붙이거나 모델을 고르기 전에 업무 질문·정답·채점 기준(사람 라벨 + LLM 심판)을 세트로 만든다. 프롬프트·모델·설정 조합을 릴리스처럼 버전 관리하고, 모든 변경마다 같은 세트로 재평가해 점수표와 회귀 실패 목록을 남긴다. 기준을 넘지 못하면 배포하지 않는 게이트를 둔다. 학습 데이터와 평가 세트는 누수 없이 분리한다.

이럴 때 쓴다

  • RAG·튜닝을 붙이기 전(§7.1 4단계, §7.2 진행 경로 2단계)
  • E2 상용 API로 모델 업데이트가 예고 없이 올 때(필수)
  • 폐쇄망 로컬 모델의 교체 시점
  • C6 환류·C7 모델 교체를 하려 할 때(선행 조건)

이럴 때는 쓰지 않는다

  • B0 결정적 도구처럼 비결정적 출력이 없을 때
  • 유형 5a 중 순수 시각화(R10: 면제)

얻는 것

  • 변경의 효과와 회귀를 숫자로 확인
  • 모델 교체·재학습의 안전
  • 모델 선정 근거 확보

점검표

  • 업무 질문·정답·채점 기준 세트가 있는가
  • 프롬프트·모델·설정이 버전 관리되는가
  • 변경마다 재평가한 기록이 있는가
  • 기준 미달 시 배포를 막는 절차가 있는가

관련 부품

F1 출처 표시 상호작용 패턴

답변에 근거 문서·조문·통계표 ID를 붙여 이용자가 원문을 직접 확인할 수 있게 한다. C5 출처 검증의 이용자 면이다.

해법

답변의 각 주장에 근거 문서·조문 번호·통계표 ID·원문 위치를 붙이고, 원문으로 바로 이동하는 링크를 제공한다. 출처의 갱신 시각과 이용 조건을 함께 보여 오래된 자료를 현재로 오인하지 않게 한다. 표시되는 출처는 C5 출처 검증을 통과한 것이어야 한다.

이럴 때 쓴다

  • B3 지식 접지 응답 전반
  • 대민 서비스 D1~D7(F1·F2·F7이 최소 요건)
  • 유형 ①⑤b⑦⑨처럼 F1이 필수인 유형

이럴 때는 쓰지 않는다

  • 모델의 판정 근거(요인·BBox·사유 코드)를 보여 주려는 경우(F9)
  • B0 결정적 도구로 원천 데이터를 그대로 보여 주는 경우(출처가 곧 화면)

얻는 것

  • 이용자 신뢰 확보
  • 원문 대조로 오류 발견
  • 공식 판단 여부를 이용자가 스스로 확인

점검표

  • 모든 답변에 출처가 붙는가
  • 출처가 원본과 대조되는가
  • 갱신 시각이 보이는가
  • 이용자가 원문을 바로 열 수 있는가

F7 한계·신뢰도 안내 상호작용 패턴

AI가 무엇을 못 하는지, 얼마나 확신하는지, 공식 판단이 아님을 이용자가 볼 수 있는 곳에 적어 과신을 막는다.

해법

화면에 사용 한계(대상 범위·미검증 항목·처리 시간), 신뢰도, '공식 판단 아님' 고지를 결과 옆에 배치한다. 저신뢰 결과는 표시를 달리하고, C7 대체 경로로 운영 중이면 품질 저하를 알린다. 고지 문구는 법률 자문·유권해석을 대체하지 않는다는 점을 분명히 적는다.

이럴 때 쓴다

  • 대민 서비스 D1~D7(F1·F2·F7 최소 요건)
  • 유형 ①⑦5a⑩⑬처럼 F7이 필수인 유형
  • C7 대체 경로 운영 중

이럴 때는 쓰지 않는다

  • 유형 ①·⑦에서 model_dependency가 없음(비LLM)이면 필수에서 면제(R7). 단 비LLM 도구도 한계 고지는 권장된다

얻는 것

  • 과신·오인 방지
  • 기관 책임 범위 명확화

점검표

  • 이용자가 '공식 판단이 아님'을 결과 화면에서 읽을 수 있는가
  • 사용 한계가 명시되어 있는가
  • 저신뢰 결과가 구분 표시되는가

관련 부품

D7 상담·처방 서비스 블록

개인 상황에 맞춘 정보·처방·법령 안내를 주는 대민 접점 블록이다. B1 코파일럿이나 B3 지식 접지가 이 자리에 들어간다.

해법

답이 데이터·규정에서 나오게 한다. 개인 조건은 F4 구조화 입력으로 받고, B3가 공개 규정·법령에 접지하거나 B1이 전문가 검토용 처방 초안을 만든다. 처방처럼 오답의 대가가 크면 C1 검토 큐로 전문가가 확정하고, 저위험 건만 C2로 자동 확정한다. 답에는 F1 출처와 F7 한계 고지, 추천이면 F9 추천 사유와 F3 대안을 붙인다. 민원인 입력에는 S4 행동 선택기·S7로 규정 밖 답을 막고, 이용자 반응과 전문가 수정은 C6로 되돌린다.

이럴 때 쓴다

  • 개인 조건에 따라 답이 달라지는 정보·처방·법령 안내
  • 전문가 상담 수요가 인력을 넘을 때
  • 일반 안내(D1)로는 무엇을 할지 결정하지 못할 때

이럴 때는 쓰지 않는다

  • 서비스·창구를 찾는 데서 끝나면 D1
  • 지급·승인 같은 자격 판정이면 D3
  • 이용자가 기관 담당자면 D8 하위 블록

얻는 것

  • 전문가 상담 대기 감소
  • 개인 조건에 맞는 행동 제시
  • 전문가 수정의 누적으로 품질 개선

점검표

  • 맞춤 답이 데이터·규정에서 나오는가
  • 오답의 대가가 큰 건에 전문가 확정이 있는가
  • 공식 판단이 아님이 고지되는가
  • 전문가 수정이 개선으로 되돌아오는가

관련 부품

X10 평가 없는 RAG, RAG 없는 튜닝 안티패턴

평가 세트 없이 검색을 붙여 '좋아진 것 같다'로 배포하고, 검색으로 풀릴 문제를 파인튜닝으로 푸는, 진행 경로를 건너뛰는 함정이다.

해법

§7.2 진행 경로를 순서대로 밟는다. B1 직접 프롬프트에서 시작해 두 번째 단계에서 C9 평가 세트(업무 질문·정답·채점 기준)를 먼저 만들고, 이후 A9 규범 스킬·F4, B3 지식 접지(A1 데이터 자산), B3 검색 품질(Hybrid·Rewriting·Reranker), C5 가드레일·F1 순으로 붙이며 매 단계를 C9로 잰다. A2.3 튜닝은 진행 경로의 마지막 단계로, 검색·규범 스킬로 풀리지 않는다는 것이 C9 점수로 확인됐을 때만 한다. 모델·프롬프트·설정 조합은 릴리스처럼 버전 관리한다.

이럴 때 쓴다

  • RAG·튜닝을 도입했는데 업무 질문·정답·채점 기준 세트가 없다
  • '답변 품질 향상'을 수치 없이 서술하거나 단발 정확도만 보고한다
  • 자주 바뀌는 규정·매뉴얼 질의를 파인튜닝으로 풀었다
  • 검색 품질(재현율·리랭킹)을 재지 않고 튜닝으로 넘어갔다

이럴 때는 쓰지 않는다

  • C9 세트로 RAG 전후를 비교한 뒤 배포한 경우
  • 검색·스킬로 풀리지 않음을 C9 점수로 확인한 뒤 튜닝한 경우
  • B2·B4처럼 비LLM 학습 모델로 원래 학습이 해법인 경우(RAG가 대안이 아님)

얻는 것

  • RAG·튜닝이라는 눈에 보이는 기술 성과를 빨리 낸다
  • 평가 세트 구축에 현업 시간을 쓰지 않는다

점검표

  • 업무 질문·정답·채점 기준 세트가 있는가
  • RAG 전후 점수 비교가 있는가
  • 튜닝을 선택한 근거가 C9 점수로 설명되는가
  • 모델·프롬프트·설정 조합이 버전 관리되는가

관련 부품

C9 대체 — RAG·튜닝보다 먼저 만들 평가 세트 · B3 선행 — 튜닝 전에 시도할 지식 접지 · A2.3 순서 — 진행 경로의 마지막 단계 · A9 대안 — 튜닝 대신 규범 스킬로 푸는 경로 · X11 이웃 안티패턴 — 같은 진행 경로 위반

X3 부서마다 챗봇 안티패턴

같은 기관의 과제들이 각자 모델·벡터DB·프롬프트를 따로 만들어, 공유할 수 있는 기반 부품을 부서 수만큼 중복 구축하는 함정이다.

해법

§7.1의 두 번째 단계대로 기반 부품은 새로 만들지 말고 Provider에서 먼저 가져온다. 모델 호출은 A2 모델 서빙 계층(범정부 AI 공통기반 또는 기관 게이트웨이) 뒤로 모으고, S1 단일 진입점에서 인증·요청 상한·비용 상한·감사 기록을 일괄 적용한다. 공공 API·공공 클라우드·공공 깃랩은 A3 공공 API 제공자로 쓴다. 부서별 차이는 모델을 따로 두지 말고 A9 업무 규범 스킬과 부서 코퍼스(A1)로 표현하며, 부서·등급별 코퍼스 분리가 필요하면 S2 권한 인식 검색으로 푼다. 없어서 새로 만든 부품은 §13 참조 구현 레지스트리에 올린다.

이럴 때 쓴다

  • 같은 기관의 두 과제 이상이 각자 모델 계약·API 키·벡터DB를 갖는다
  • 범정부 AI 공통기반·공공 API를 쓰지 않은 이유가 서술되지 않는다
  • 공통 규정·매뉴얼 코퍼스를 과제마다 따로 임베딩한다
  • 모델 호출 비용을 기관 단위로 집계할 수 없다

이럴 때는 쓰지 않는다

  • 데이터 등급(E5)이나 망 조건(E1) 때문에 공통 기반을 쓸 수 없고 그 사유가 서술된 경우
  • A2 게이트웨이를 공유하면서 부서별 코퍼스·스킬만 따로 둔 경우(정상 조립)
  • 개인이 만든 단일 도구로 기관 내 중복 과제가 없는 경우

얻는 것

  • 부서가 협의 없이 빠르게 만든다
  • 부서 요구에 딱 맞는 맞춤 구성을 갖는다

점검표

  • 기관의 모든 모델 호출이 하나의 게이트웨이를 지나는가
  • 부서별 API 키 직접 호출이 남아 있지 않은가
  • 공통 기반을 쓰지 않은 과제는 그 사유(E1·E5)가 적혀 있는가
  • 부서별 차이가 모델이 아니라 스킬·코퍼스로 표현되어 있는가

관련 부품
