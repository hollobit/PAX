판정 근거

온나라 문서 화면에서 조직도 조회와 여러 부서 문서의 기간별 통합 검색·중복 제거·CSV 저장을 제공하는 크롬·엣지 사이드바. AI 없이 표준 시스템 위에 확장으로 덧입혔으므로 B8 레거시 오버레이(비LLM 변형). 실무자 자체 제작 A7. 온나라는 행정망이므로 행정망·폐쇄망 가능, 내부 문서 메타를 다루니 S(민감). CSV 저장은 산출물 생성(P1). URL 없음.

구현 가이드

주 패턴 B8 레거시 오버레이을 구현할 때

구현 단계

  1. 대상 화면과 반복 조작을 정하고, 확장이 읽을 DOM 요소와 파일을 목록으로 적는다.
  2. 권한을 P0~P1에 묶고, 쓰기 조작이 필요하면 C3 되돌림과 F6 확인을 먼저 설계한다.
  3. 요약을 붙이면 로컬 모델(A2.2)로 처리해 문서가 PC 밖으로 나가지 않게 하고 C5를 둔다.
  4. 화면 텍스트를 신뢰 불가 입력으로 보고 S3 구역 분리를 적용한다.
  5. 시스템 개편 시 점검 절차와, 정식 API·MCP가 열리면 걷어낼 조건을 문서로 남긴다.

점검표

  • 권한이 읽기·산출물 생성(P0~P1)에 묶여 있는가
  • 문서가 PC 밖으로 나가지 않는가
  • 시스템 개편 시 점검 절차가 있는가
  • 정식 연계가 열리면 걷어낼 조건이 적혀 있는가

환경 조건

E1 행정망이 필수 조건이다. E2는 로컬 오픈웨이트(온나라 sAIde: Ollama). E4는 P0~P1에 묶어야 하며, P2 이상이면 C3 되돌림이 필요하나 DOM 조작은 원자성이 없다. 신뢰 불가 입력 + P2 이상이면 DOM 텍스트를 전부 신뢰 불가로 보고 S4 행동 선택기가 필요하다(§5 매트릭스).

주의할 점

  • DOM 의존으로 시스템 개편에 취약(전이 차단: 레거시 미연동)
  • DOM 조작은 원자성이 없어 쓰기 시 되돌림이 어려움
  • 화면 텍스트를 통한 인젝션 위험
  • 개인 도구가 담당자와 함께 사라질 위험(X9)

기본 배선 예

B8 → A2.2 (로컬 요약) → A10 → D8.2 · A8 (정식 MCP가 열리면 B8 대체)

보완이 필요한 필수 부품

이 조합에서 카탈로그가 함께 갖추라고 권하는 부품 가운데 아직 확인되지 않은 것이다.

  • A10 문서 형식 어댑터 HWP·HWPX·엑셀·한셀·PDF 같은 한국 공공 문서 형식을 AI 부품이 읽고(구조화) 쓰게(서식 생성) 하는 변환 계층이다.

피해야 할 안티패턴

  • X9 담당자와 함께 사라지는 도구 개인이 만든 도구가 부서에 퍼졌지만 라이선스·저장소·인수인계가 없어, 만든 사람의 인사이동과 함께 멈추는 함정이다. 대처: 도구가 부서에 퍼지기 시작하면 A7 산출물에 MIT·Apache 등 라이선스를 명시하고, 코드를 개인 PC가 아니라 A3 공공 깃랩 같은 공용 저장소에 등재한다. 업무 규범·프롬프트는 A9 업무 규범 스킬로 패키징해 다른 담당자가 그대로 쓸 수 있게 하고, 설치·설정·데이터 경로를 담은 인수인계 문서를 둔다. 도구를 참조 구현 레지스트리(§13)에 올려 소유를 개인에서 조직으로 옮긴다. transition.blocker에 '담당자 이동'이 적힌 과제는 이 조치를 먼저 한다.

이 사례에 쓰인 패턴

B8 레거시 오버레이 업무 컴포넌트

API가 닫힌 표준 업무 시스템(온나라·나이스·K-에듀파인·업무포털) 화면 위에 브라우저 확장·사이드패널로 검색·요약 기능을 덧입힌다. 시스템 자체는 고치지 않는다.

PAX 사례 13건이 이 부품을 쓴다

맥락

행정망의 표준 업무 시스템을 쓰는 담당자가 개인·부서 단위로 만든 도구가 여기에 든다. 문서가 PC 밖으로 나가면 안 되므로 로컬 모델과 짝을 이룬다. PAX 557건에서 13건이 확인됐다.

맞서는 힘(긴장)

  • 즉시 도입 vs 시스템 개편에 따른 취약성(DOM 의존)
  • 사용자 세션 공유의 편의 vs 권한 경계
  • 요약 기능 추가 vs 문서 외부 유출 금지

해법

브라우저 확장·사이드패널이 담당자 로그인 세션 안에서 화면 DOM과 다운로드 파일을 읽어 통합 검색, 일괄 다운로드, 원클릭 이동을 제공한다. 요약·분석이 필요하면 로컬 오픈웨이트 모델(A2.2)로 처리해 문서가 PC 밖으로 나가지 않게 한다. 권한은 P0~P1(읽기·산출물)에 묶고, 쓰기 조작이 있으면 C3 되돌림을 둔다. 화면 텍스트는 모두 신뢰 불가 입력으로 보고 S3·S4를 적용하며, 표준 시스템에 정식 API·MCP(A8)가 열리면 이 부품을 걷어낸다.

이럴 때 쓴다

  • API가 닫힌 표준 시스템 위에서 반복 조회·다운로드가 병목일 때
  • 행정망에서 문서를 PC 밖으로 내보낼 수 없을 때
  • 정식 연계가 열리기 전 과도기 도구가 필요할 때

이럴 때는 쓰지 않는다

  • 표준 시스템에 정식 API·MCP가 이미 있을 때(A8로 연결)
  • 화면 조작으로 시스템에 쓰기를 해야 하는데 되돌림을 보장할 수 없을 때
  • 독립 화면에서 파일을 처리하는 도구일 때(B0)

얻는 것

  • 표준 시스템을 고치지 않고 즉시 도입
  • 행정망에서 로컬 완결 가능
  • 현장 반복 조작 제거

점검표

  • 권한이 읽기·산출물 생성(P0~P1)에 묶여 있는가
  • 문서가 PC 밖으로 나가지 않는가
  • 시스템 개편 시 점검 절차가 있는가
  • 정식 연계가 열리면 걷어낼 조건이 적혀 있는가

구조 — 참여 부품

  • 브라우저 확장·사이드패널 — 화면 위에 기능을 덧입힘
  • A2.2 주권형 온프레미스 모델 — PC 안에서 요약·분석
  • A10 문서 형식 어댑터 — 첨부 파싱
  • C5 가드레일 필터 — 민감정보 처리
  • 표준 업무 시스템 — 손대지 않는 원 시스템

변형

  • 검색·이동형: AI 없이 통합 검색·원클릭 이동·일괄 다운로드를 제공한다(Ready)
  • 로컬 모델 요약형: 사이드패널에 로컬 모델 요약·분석을 붙인다(Enabled)

A7 자체 제작 환경 공통 서비스

외부 용역 없이 기관 인력이 저작도구·AI 코딩 에이전트로 도구를 직접 만들고 고치는 제작 환경이다.

PAX 사례 317건이 이 부품을 쓴다

맥락

업무 담당자가 AI 코딩 도구·저작도구·오픈소스로 직접 만드는 과제에 쓴다. 유형 8(취합·변환 자동화)에서는 필수 기반이다. PAX 557건에서 A7이 붙고 BYO 모델을 쓰는 사례는 29건이다.

맞서는 힘(긴장)

  • 제작 속도·현장 적합성 vs 유지보수 연속성
  • 개인 역량 의존 vs 조직 인수인계
  • 무예산 제작 vs 보안 검토·기관 공식화 절차

해법

기관 인력이 AI 코딩 에이전트·저작도구·오픈소스로 직접 만들되, 처음부터 전이를 전제로 한다. 설정·데이터(연락처·업무분장 등)는 코드 밖 파일로 빼 비개발자도 고치게 하고, 작업 지시서 자체를 코딩 에이전트가 수행할 프롬프트로 설계해 제작 절차를 남긴다. MIT·Apache 등 라이선스를 명시하고 공공 깃랩(A3)이나 혁신24 자료실에 등재해 담당자가 바뀌어도 이어지게 한다. 실사용 건수로 성과를 재 기관 공식으로 올린다.

이럴 때 쓴다

  • 반복 업무를 줄이는 소규모 도구를 빠르게 만들 때
  • 용역 없이 작은 수정을 계속해야 할 때
  • 유형 8 취합·변환 자동화

이럴 때는 쓰지 않는다

  • P2 이상 시스템 쓰기·처분이 걸려 보안 검토·통제 부품이 먼저 필요한데 이를 갖출 수 없을 때
  • 라이선스·저장소·인수인계를 정할 수 없어 전이가 불가능할 때(X9 위험)

얻는 것

  • 내부 유지보수 역량 축적
  • 무예산·소예산 제작

점검표

  • 라이선스가 명시되어 있는가
  • 저장소가 개인 PC가 아닌 공유 위치에 있는가

  • 실사용 지표가 있는가

구조 — 참여 부품

  • A3 공공 깃랩·자료실 — 등재처 — 담당자 이동 후에도 이어지게

D8.1 탐색·조회 서비스 블록

데이터·법령·공고·선례·타 지역 사례를 찾아 담당자 화면에 놓는 내부 운영 블록이다. B0 탐색·시각화, MCP 도구 제공, B3가 전형 부품이다.

PAX 사례 176건이 이 부품을 쓴다

맥락

기관 내부 담당자가 자료를 찾아 보는 업무. §7.3 유형 ⑤b 데이터 에이전트(D8.1, P0)와 ⑤a 분석 대시보드·브리핑(D8.1, P0~P1)의 무대. PAX 176건(주 부품 B0 80%, B3 10%).

맞서는 힘(긴장)

  • 검색 편의 vs 출처·기준 시점 확인
  • 자연어 질의 vs 질의 조작·도구 출력 인젝션
  • 대시보드 고정 화면 vs 에이전트의 유연한 질의
  • MCP 서버 수 vs 실제 업무 호출(X8)

해법

답이 원천 데이터에서 나오게 한다. 공공데이터·통계는 A8 MCP 서버나 A3 공공 API로 도구화하고, 호스트 쪽 에이전트는 B′7 ReAct 도구 루프로 조회하되 C8로 읽기 전용에 묶는다. 결과에는 F1 출처(통계표 ID)와 조회 시점을 붙이고, 도구 호출은 C4로 추적한다. 도구 출력이 새 지시가 되지 않도록 S5 계획 후 실행과 S1 비용 상한을 둔다. 에이전트가 필요 없으면 B0 대시보드·검색기로 끝내고(5a-agg), LLM이 해설을 붙이면 5a-brief로 C9·F9를 더한다(R19). MCP 서버만 만드는 사례는 5b-server로 A8·S11만 필수다(R18).

이럴 때 쓴다

  • 담당자가 흩어진 데이터·법령·공고·선례를 찾느라 시간을 쓸 때
  • 공공데이터·통계를 자연어로 조회해야 할 때
  • 다른 지역·기관 사례를 모아 봐야 할 때

이럴 때는 쓰지 않는다

  • 찾은 문서에서 할 일·핵심을 뽑으면 D8.2
  • 규정·기준과 대조해 확인 대상을 고르면 D8.4
  • 국민이 서비스를 찾으면 D1

얻는 것

  • 자료 찾는 시간 절감
  • 출처·시점이 붙은 근거 확보
  • 공공데이터 MCP의 재사용

점검표

  • 결과마다 원천 출처와 기준 시점이 보이는가
  • 도구 권한이 읽기 전용으로 묶여 있는가
  • 도구 호출 순서를 나중에 볼 수 있는가
  • MCP 서버가 실제 업무에서 호출되는지 재는가

구조 — 참여 부품

  • 담당자 — 자료를 찾고 결과를 업무에 씀
  • A8 MCP 서버·호스트 — 공공데이터·통계를 도구로 노출
  • B0 결정적 도구(탐색·시각화) — 검색기·대시보드
  • B6 도구 호출 에이전트 — 로컬 MCP 호스트로 조회·차트 생성
  • C8 권한 경계 — 읽기 전용 제한
  • F1 출처 표시 — 통계표 ID·출처·시점 표시

변형

  • 검색·대시보드형(비LLM): B0 탐색·시각화. 유형 5a-agg(필수 A1·F2·C4, R19).
  • 브리핑형: LLM이 조회 결과를 요약·해설. 유형 5a-brief(필수 A2.1|A2.2|A2.6·F9·C9, R19).
  • MCP 서버 제공형: 공공데이터·법령을 MCP로 노출하는 서버 자체. 5b-server(필수 A8·S11, R18).
  • 데이터 에이전트형: 로컬 MCP 호스트가 도구를 불러 조회·차트 생성. 5b-host(필수 C4·F1·S5|S6, R18).

참조 구현 예

  • 망분리 환경용 로컬 AI 에이전트 + KOSIS 공식 MCP — 카탈로그 D8.1 카드·§9 조립 예시, 유형 ⑤b 참조 구현
  • Korean Stats MCP — 카탈로그 D8.1 카드 예: KOSIS 통계를 자연어로, 출처 자동 인용

D8.5 취합·정산 서비스 블록

부서별 자료를 모으고 엑셀·한셀을 합치고 정산하는 내부 운영 블록이다. 서무의 핵심 반복 업무이며 B0 문서·엑셀 자동화와 A10이 전형 부품이다.

PAX 사례 36건이 이 부품을 쓴다

맥락

부서별 제출 파일을 모으고 합치고 정산하는 업무. §7.3 유형 ⑧ 취합·변환 자동화(D8.5 · D8.9, P1). PAX 36건(주 부품 B0 89%, B1 6%). 업무 영역별 PAX 건수(557건 태깅): 회계·정산 13, 문서·기안 8, 공통·범용 4, 데이터·통계 3, 감사·법무 2, 계약·조달 2, 시설·안전 2, 인사·복무 1, 기획·정책 1.

맞서는 힘(긴장)

  • 자동화 속도 vs 원본 훼손·정산 오류
  • 폐쇄망 설치형의 편의 vs 배포·갱신 관리
  • 개인 제작 도구의 민첩성 vs 인사이동 시 소멸(X9)
  • 제출 파일 자동 처리 vs 파일 속 매크로·지시 위협

해법

B0 문서·엑셀 자동화로 B′1 순차 배선(수집 → 양식 정규화 → 병합 → 정산 → 서류 생성)을 만든다. 파일은 A10 어댑터로 엑셀·한셀·HWPX를 읽고 쓴다. 원본은 보존하고 결과만 새로 만들어 C3로 원복할 수 있게 하고, F8로 처리 이력을 되돌릴 수 있게 한다. 제출 파일은 S11 파일 검사와 S9 격리 실행을 거친다. 기관 인력이 직접 만들었다면 A7 자체 제작 환경의 라이선스·저장소를 명시해 X9를 피하고, 기관으로 전이할 때 C4 처리 로그를 둔다.

이럴 때 쓴다

  • 부서별 파일을 모아 합치는 반복 업무
  • 규칙이 분명한 정산·서류 생성
  • 폐쇄망에서 설치형으로 돌려야 할 때

이럴 때는 쓰지 않는다

  • 파일 형식 변환·양식 생성만 하면 D8.9(우선순위 낮지만 동작이 다름)
  • 합친 자료를 기준과 대조해 확인 대상을 고르면 D8.4
  • 모은 자료를 담당자에게 배분하면 D8.6(우선순위 높음)

얻는 것

  • 서무 반복 업무 절감
  • 폐쇄망에서 바로 쓰는 설치형
  • 정산 규칙의 일관 적용

점검표

  • 원본이 보존되고 결과를 되돌릴 수 있는가
  • 제출 파일 속 매크로가 실행되지 않는가
  • 라이선스·저장소가 명시되어 있는가
  • 정산 결과를 검산할 방법이 있는가

구조 — 참여 부품

  • 서무 담당자 — 자료를 모으고 결과를 확인
  • B0 결정적 도구(문서·엑셀 자동화) — 수집·병합·정산 순차 처리
  • A10 문서 형식 어댑터 — 엑셀·한셀·HWPX 읽기·쓰기
  • A7 자체 제작 환경 — 기관 인력이 직접 만든 도구
  • C3 상태 머신·롤백 — 원본 보존과 원복

변형

  • 엑셀·한셀 취합형: 부서별 파일을 양식 정규화 후 병합(GatherFlow, 폐쇄망).
  • 서류 일괄 생성형: 정산 결과로 신청서·명세서·복명서 일괄 생성(출장 여비 서류 자동화).
  • LLM 보조 정리형: 비정형 항목 정리에 B1을 부분 사용.

PAX 사례 136건이 이 부품을 쓴다

맥락

문서를 입력으로 받거나 기안·보고서·취합본을 산출하는 과제라면 거의 다 쓴다. 유형 2·4·8에서는 필수 기반이고 유형 6·7에서도 쓰인다. E1 로컬 PC 조건에서 도는 경우가 많다.

맞서는 힘(긴장)

  • 형식 충실도(표·각주·조항 구조 보존) vs 파서 구현 비용
  • 로컬 처리(무반출) vs 클라우드 변환 도구의 편의
  • 기관별 서식 다양성 vs 공통 어댑터 재사용

해법

입력 쪽에서는 HWPX 압축 구조·PDF에서 조·항·호·별표 계층과 표를 보존해 구조화 텍스트·표로 바꾸고, 머리말·각주 같은 잡음을 걷어 조항 단위로 정규화한다. 출력 쪽에서는 스킬(A9)의 출력 서식을 받아 HWPX·XLSX 기안 서식을 역방향으로 생성한다. 민감 문서는 PC 밖으로 보내지 않도록 로컬에서 변환하고, 파서를 라이브러리·CLI·MCP로 함께 제공하면 다른 부품과 기관이 그대로 쓴다. 형식 변환 정확도는 C9 판정 체계로 잰다.

이럴 때 쓴다

  • 입력이 HWP·HWPX·엑셀·PDF 공공 문서일 때
  • 산출물을 기안·보고 서식으로 내보내야 할 때
  • 유형 2·4·8 조립

이럴 때는 쓰지 않는다

  • 스캔 이미지·음성처럼 인식이 필요한 입력은 B4 인식 파이프라인(OCR·STT)
  • 입출력이 이미 정형 데이터·API인 경우

얻는 것

  • 공공 문서를 AI 입력·출력으로 연결
  • 기관 간 재사용 가능한 공통 부품
  • 로컬 처리로 무반출

점검표

  • 표·조항 계층이 변환 후에도 보존되는가
  • 출력이 기관 기안 서식 그대로 열리는가
  • 민감 문서가 변환 과정에서 PC 밖으로 나가지 않는가
  • 변환 정확도 판정 기록이 있는가

구조 — 참여 부품

  • 입력 파서 — 조·항·호·표 구조를 보존해 구조화
  • 서식 생성기 — 구조화 결과를 HWPX·엑셀 서식으로 출력
  • A9 업무 규범 스킬 — 출력 서식 규범 제공
  • B3 지식 접지 상담 — 구조화된 규정을 색인해 검색

변형

  • 규정 구조 파서: HWP/HWPX·PDF 규정을 조항 단위로 정규화한다.
  • 엑셀·한셀 취합: 폐쇄망에서 엑셀·한셀 파일을 취합한다(GatherFlow).
  • 서식 출력: HWPX 직무기술서·보도자료 등 공공 서식으로 역방향 생성한다(NCS JD, ReleasePick 입력).
  • 완결형 문서 엔진: HWP/HWPX 파싱·조판·렌더링·편집·PDF 출력을 자체 구현하고 MCP·CLI로 제공한다(PAX e18d5e018e0cd10d).
  • AI 친화 병행 등록: 기관이 발간자료를 마크다운으로 함께 등록하도록 표준화한다(PAX 17329009668eb397).

참조 구현 예

  • PAX GatherFlow — 엑셀·한셀 취합(폐쇄망)(§6 A10 카드)
  • PAX 7ad16f34cfb6cca7 — HWP·HWPX·PDF에서 신구대비표 초안을 로컬 생성(§13 A10)
  • PAX e18d5e018e0cd10d — HWP/HWPX 파싱·조판·렌더링·편집·PDF 출력 + MCP·CLI(§13 A10)

관련 부품

A9 짝 — 스킬 출력 서식 · B4 경계 — 인식이 필요한 입력 · A12 대칭 — 사람 쪽 모달리티 어댑터 · A7 짝 — 유형 8 필수 · B0 소비처 — 문서·엑셀 자동화

X9 담당자와 함께 사라지는 도구 안티패턴

개인이 만든 도구가 부서에 퍼졌지만 라이선스·저장소·인수인계가 없어, 만든 사람의 인사이동과 함께 멈추는 함정이다.

맥락

A7 자체 제작 환경으로 태깅된 도구(PAX 557건 중 317건, 57%), 특히 개인 사용에서 부서 공유로 막 퍼지기 시작한 바이브코딩 도구.

맞서는 힘(긴장)

  • 개인의 빠른 제작 vs 조직의 유지보수 책임
  • 비공식 공유의 편의 vs 라이선스·저장소 절차
  • 현장 맞춤 vs 다른 담당자가 이해할 수 있는 구조

해법

도구가 부서에 퍼지기 시작하면 A7 산출물에 MIT·Apache 등 라이선스를 명시하고, 코드를 개인 PC가 아니라 A3 공공 깃랩 같은 공용 저장소에 등재한다. 업무 규범·프롬프트는 A9 업무 규범 스킬로 패키징해 다른 담당자가 그대로 쓸 수 있게 하고, 설치·설정·데이터 경로를 담은 인수인계 문서를 둔다. 도구를 참조 구현 레지스트리(§13)에 올려 소유를 개인에서 조직으로 옮긴다. transition.blocker에 '담당자 이동'이 적힌 과제는 이 조치를 먼저 한다.

이럴 때 쓴다

  • 개인이 만든 도구를 부서원 여러 명이 쓰는데 라이선스 표기가 없다
  • 원본 코드가 개인 PC·개인 계정에만 있다
  • 인수인계 문서·설치 절차가 없다
  • transition.blocker가 '담당자 이동'이다

이럴 때는 쓰지 않는다

  • 개인만 쓰는 도구로 부서에 퍼지지 않은 경우(개인 사용 단계는 정상)
  • A7로 만들었지만 라이선스 명시·공용 저장소 등재·인수인계가 갖춰진 경우
  • 기관 정보화 부서가 넘겨받아 운영 중인 경우

얻는 것

  • 현장 담당자가 필요한 도구를 빠르게 만든다
  • 공식 절차 없이 바로 퍼진다

점검표

  • 라이선스가 명시되어 있는가
  • 원본이 공용 저장소에 있는가
  • 만든 사람 없이 후임이 설치·실행할 수 있는 문서가 있는가
  • 개인 구독·개인 키에 의존하지 않는가

구조 — 참여 부품

  • A7 자체 제작 환경 — 도구가 태어난 곳. 라이선스 명시가 전이 조건
  • A3 공공 API 제공자(공공 깃랩) — 개인 저장소를 대체하는 공용 등재처
  • A9 업무 규범 스킬 — 암묵적 업무 규범을 패키지로 남김
  • 후임 담당자 — 인수인계 문서로 도구를 이어받는 사람

변형

  • 라이선스 미명시: 코드는 공개했지만 라이선스가 없어 타 기관이 가져다 쓸 수 없음
  • 개인 저장소형: 개인 PC·개인 계정에만 원본이 있음
  • 개인 구독 의존형: 개인 AI 구독·API 키로 돌아가 담당자가 떠나면 호출이 끊김

관련 부품
