업무 패턴 B8 레거시 오버레이 변형: 지명 분류 오버레이

서비스 유형 7 대조·점검 도우미 · 전이 단계 부서 공유 · 판정 카탈로그 v0.6

환경 축 배포:로컬 PC 네트워크:로컬 완결 모델:없음(비LLM) 런타임:브라우저만 권한:P0 읽기 전용

판정 근거

전남광주통합특별시로 합쳐진 지역 목록을 광주권 5개 구와 전남권 22개 시·군으로 다시 갈라 보여 주는 Chrome/Edge 확장이다. 주소정보누리집·리치고 등 API가 닫힌 기존 화면 위에 정규식 기반 규칙으로 분류 표지를 덧입히므로 B8 레거시 오버레이로 판정했고, 광주권/전남권 분류 로직은 라우터 성격이라 B′2를 붙였다. AI를 쓰지 않는 규칙 기반 판정이며 화면을 읽기만 해 permission_scope는 P0.

구현 가이드

주 패턴 B8 레거시 오버레이을 구현할 때

구현 단계

  1. 대상 화면과 반복 조작을 정하고, 확장이 읽을 DOM 요소와 파일을 목록으로 적는다.
  2. 권한을 P0~P1에 묶고, 쓰기 조작이 필요하면 C3 되돌림과 F6 확인을 먼저 설계한다.
  3. 요약을 붙이면 로컬 모델(A2.2)로 처리해 문서가 PC 밖으로 나가지 않게 하고 C5를 둔다.
  4. 화면 텍스트를 신뢰 불가 입력으로 보고 S3 구역 분리를 적용한다.
  5. 시스템 개편 시 점검 절차와, 정식 API·MCP가 열리면 걷어낼 조건을 문서로 남긴다.

점검표

  • 권한이 읽기·산출물 생성(P0~P1)에 묶여 있는가
  • 문서가 PC 밖으로 나가지 않는가
  • 시스템 개편 시 점검 절차가 있는가
  • 정식 연계가 열리면 걷어낼 조건이 적혀 있는가

환경 조건

E1 행정망이 필수 조건이다. E2는 로컬 오픈웨이트(온나라 sAIde: Ollama). E4는 P0~P1에 묶어야 하며, P2 이상이면 C3 되돌림이 필요하나 DOM 조작은 원자성이 없다. 신뢰 불가 입력 + P2 이상이면 DOM 텍스트를 전부 신뢰 불가로 보고 S4 행동 선택기가 필요하다(§5 매트릭스).

주의할 점

  • DOM 의존으로 시스템 개편에 취약(전이 차단: 레거시 미연동)
  • DOM 조작은 원자성이 없어 쓰기 시 되돌림이 어려움
  • 화면 텍스트를 통한 인젝션 위험
  • 개인 도구가 담당자와 함께 사라질 위험(X9)

기본 배선 예

B8 → A2.2 (로컬 요약) → A10 → D8.2 · A8 (정식 MCP가 열리면 B8 대체)

보완이 필요한 필수 부품

이 조합에서 카탈로그가 함께 갖추라고 권하는 부품 가운데 아직 확인되지 않은 것이다.

  • A3 공공 API 제공자 정부·공공이 운영하는 모델·데이터·개발 도구(범정부 AI 공통기반, 모두의 AI 실험실, 공공데이터포털, 공공 깃랩)를 범정부 Provider로 소비한다.
  • C1 검토 큐 AI 산출물이 다음 단계로 넘어가기 전에 사람이 맞고 틀림을 확인·수정·확정하는 대기열을 두어, 오류가 업무 결과로 흘러가지 않게 한다.
  • C5 가드레일 필터 개인정보·환각·편향·형식 오류가 프롬프트나 산출물에 들어가지 못하게 시스템이 경계에서 걸러낸다. 비식별 전처리, 출처 검증, 구조적 출력 제약이 대표 변형이다.

B8 레거시 오버레이 업무 컴포넌트

API가 닫힌 표준 업무 시스템(온나라·나이스·K-에듀파인·업무포털) 화면 위에 브라우저 확장·사이드패널로 검색·요약 기능을 덧입힌다. 시스템 자체는 고치지 않는다.

PAX 사례 13건이 이 부품을 쓴다

맥락

행정망의 표준 업무 시스템을 쓰는 담당자가 개인·부서 단위로 만든 도구가 여기에 든다. 문서가 PC 밖으로 나가면 안 되므로 로컬 모델과 짝을 이룬다. PAX 557건에서 13건이 확인됐다.

맞서는 힘(긴장)

  • 즉시 도입 vs 시스템 개편에 따른 취약성(DOM 의존)
  • 사용자 세션 공유의 편의 vs 권한 경계
  • 요약 기능 추가 vs 문서 외부 유출 금지

해법

브라우저 확장·사이드패널이 담당자 로그인 세션 안에서 화면 DOM과 다운로드 파일을 읽어 통합 검색, 일괄 다운로드, 원클릭 이동을 제공한다. 요약·분석이 필요하면 로컬 오픈웨이트 모델(A2.2)로 처리해 문서가 PC 밖으로 나가지 않게 한다. 권한은 P0~P1(읽기·산출물)에 묶고, 쓰기 조작이 있으면 C3 되돌림을 둔다. 화면 텍스트는 모두 신뢰 불가 입력으로 보고 S3·S4를 적용하며, 표준 시스템에 정식 API·MCP(A8)가 열리면 이 부품을 걷어낸다.

이럴 때 쓴다

  • API가 닫힌 표준 시스템 위에서 반복 조회·다운로드가 병목일 때
  • 행정망에서 문서를 PC 밖으로 내보낼 수 없을 때
  • 정식 연계가 열리기 전 과도기 도구가 필요할 때

이럴 때는 쓰지 않는다

  • 표준 시스템에 정식 API·MCP가 이미 있을 때(A8로 연결)
  • 화면 조작으로 시스템에 쓰기를 해야 하는데 되돌림을 보장할 수 없을 때
  • 독립 화면에서 파일을 처리하는 도구일 때(B0)

얻는 것

  • 표준 시스템을 고치지 않고 즉시 도입
  • 행정망에서 로컬 완결 가능
  • 현장 반복 조작 제거

점검표

  • 권한이 읽기·산출물 생성(P0~P1)에 묶여 있는가
  • 문서가 PC 밖으로 나가지 않는가
  • 시스템 개편 시 점검 절차가 있는가
  • 정식 연계가 열리면 걷어낼 조건이 적혀 있는가

구조 — 참여 부품

  • 브라우저 확장·사이드패널 — 화면 위에 기능을 덧입힘
  • A2.2 주권형 온프레미스 모델 — PC 안에서 요약·분석
  • A10 문서 형식 어댑터 — 첨부 파싱
  • C5 가드레일 필터 — 민감정보 처리
  • 표준 업무 시스템 — 손대지 않는 원 시스템

변형

  • 검색·이동형: AI 없이 통합 검색·원클릭 이동·일괄 다운로드를 제공한다(Ready)

B′2 라우터·디스패처 제어 흐름

요청의 의도·유형·난이도를 읽어 전문 경로·모델·도구·담당자로 보내는 배선이다. 모든 건을 같은 경로로 보내는 낭비를 막는다.

PAX 사례 23건이 이 부품을 쓴다

맥락

대민 상담(B3)의 예외 이관, 규칙 선필터로 LLM 호출 줄이기, 폐쇄망 모델과 외부 모델 사이의 모델 라우팅, 여러 MCP를 한 서버에서 경로별로 제공하는 구성에 쓴다. C2 위험도 라우터의 내부 원형이고, D4 분류·이관을 기술로 구현한 실체다.

맞서는 힘(긴장)

  • 경로 분리의 효율 vs 라우팅 오류라는 새 위험
  • 규칙 라우팅의 예측 가능성 vs 모델 라우팅의 유연성
  • 외부 모델 분기의 품질 vs 경계 통제(E1·E5)

해법

요청을 분류하는 단계(규칙·경량 모델·LLM)를 앞에 두고, 분류 결과마다 처리 경로(규칙 판정, LLM 판정, 담당자 이관, 판단 불필요)를 정한다. 경로별 처리 비율을 C4로 실측해 라우팅 품질을 보고, 분류가 불확실한 건은 사람에게 보낸다(C2·F11). 모델 라우팅은 A2 서빙 계층의 기능으로 두고 외부 모델로 나가는 분기에는 C5 비식별을 건다. 보안이 필요한 대민 접점에서는 LLM이 미리 정한 행동 중 선택만 하게 제약해 S4로 만든다.

이럴 때 쓴다

  • 요청 유형마다 처리 비용·방법이 뚜렷이 다를 때
  • 답할 수 없는 건을 담당자로 이관해야 할 때(유형 ① 대민 상담)
  • LLM 호출 비용을 줄여야 할 때

이럴 때는 쓰지 않는다

  • 요청 유형이 하나뿐일 때
  • 분류 오류의 비용이 큰데 분류 품질을 잴 방법이 없을 때
  • 라우팅 대신 규칙으로 판정 모델 호출 대상 자체를 좁히는 구조일 때(B′10)

얻는 것

  • 호출 비용 절감
  • 답할 수 없는 건의 이관
  • 경로별 전문화

점검표

  • 경로별 처리 비율을 실측하는가
  • 분류가 불확실할 때 사람에게 가는 경로가 있는가
  • 외부 모델로 나가는 분기에 비식별이 걸려 있는가

구조 — 참여 부품

  • 분류기 — 의도·유형·난이도 판별(규칙 또는 모델)
  • 전문 경로 — 유형별 처리 모델·도구·규칙
  • C2 위험도 라우터 — 위험도·신뢰도 기반 사람 이관
  • C4 감사 로그·지표 — 경로별 처리 비율 실측

변형

  • 의도 라우팅: 질문 의도로 전문 에이전트·도구에 배정
  • 모델 라우팅: 기본은 폐쇄망 사내 모델, 필요할 때만 외부 모델로 분기(InfoQ Intelligent Model Routing)
  • 결정론 우선·LLM 선택 확대: 기본은 결정론 경로, 규칙 결과가 얕을 때만 LLM 경로로 분기
  • 경로 라우팅 통합 서버: 여러 공공데이터 MCP를 한 서버에서 경로별로 제공

참조 구현 예

  • PAX 9d56d423296a3238 — 5개 공공데이터 MCP를 한 서버에서 경로 라우팅(§13)
  • PAX 7c989a8fe8dda878 — 결정론 우선·LLM 선택 확대 라우팅(§13)

D8.1 탐색·조회 서비스 블록

데이터·법령·공고·선례·타 지역 사례를 찾아 담당자 화면에 놓는 내부 운영 블록이다. B0 탐색·시각화, MCP 도구 제공, B3가 전형 부품이다.

PAX 사례 176건이 이 부품을 쓴다

맥락

기관 내부 담당자가 자료를 찾아 보는 업무. §7.3 유형 ⑤b 데이터 에이전트(D8.1, P0)와 ⑤a 분석 대시보드·브리핑(D8.1, P0~P1)의 무대. PAX 176건(주 부품 B0 80%, B3 10%).

맞서는 힘(긴장)

  • 검색 편의 vs 출처·기준 시점 확인
  • 자연어 질의 vs 질의 조작·도구 출력 인젝션
  • 대시보드 고정 화면 vs 에이전트의 유연한 질의
  • MCP 서버 수 vs 실제 업무 호출(X8)

해법

답이 원천 데이터에서 나오게 한다. 공공데이터·통계는 A8 MCP 서버나 A3 공공 API로 도구화하고, 호스트 쪽 에이전트는 B′7 ReAct 도구 루프로 조회하되 C8로 읽기 전용에 묶는다. 결과에는 F1 출처(통계표 ID)와 조회 시점을 붙이고, 도구 호출은 C4로 추적한다. 도구 출력이 새 지시가 되지 않도록 S5 계획 후 실행과 S1 비용 상한을 둔다. 에이전트가 필요 없으면 B0 대시보드·검색기로 끝내고(5a-agg), LLM이 해설을 붙이면 5a-brief로 C9·F9를 더한다(R19). MCP 서버만 만드는 사례는 5b-server로 A8·S11만 필수다(R18).

이럴 때 쓴다

  • 담당자가 흩어진 데이터·법령·공고·선례를 찾느라 시간을 쓸 때
  • 공공데이터·통계를 자연어로 조회해야 할 때
  • 다른 지역·기관 사례를 모아 봐야 할 때

이럴 때는 쓰지 않는다

  • 찾은 문서에서 할 일·핵심을 뽑으면 D8.2
  • 규정·기준과 대조해 확인 대상을 고르면 D8.4
  • 국민이 서비스를 찾으면 D1

얻는 것

  • 자료 찾는 시간 절감
  • 출처·시점이 붙은 근거 확보
  • 공공데이터 MCP의 재사용

점검표

  • 결과마다 원천 출처와 기준 시점이 보이는가
  • 도구 권한이 읽기 전용으로 묶여 있는가
  • 도구 호출 순서를 나중에 볼 수 있는가
  • MCP 서버가 실제 업무에서 호출되는지 재는가

구조 — 참여 부품

  • 담당자 — 자료를 찾고 결과를 업무에 씀
  • A8 MCP 서버·호스트 — 공공데이터·통계를 도구로 노출
  • B0 결정적 도구(탐색·시각화) — 검색기·대시보드
  • B6 도구 호출 에이전트 — 로컬 MCP 호스트로 조회·차트 생성
  • C8 권한 경계 — 읽기 전용 제한
  • F1 출처 표시 — 통계표 ID·출처·시점 표시

변형

  • 검색·대시보드형(비LLM): B0 탐색·시각화. 유형 5a-agg(필수 A1·F2·C4, R19).
  • 브리핑형: LLM이 조회 결과를 요약·해설. 유형 5a-brief(필수 A2.1|A2.2|A2.6·F9·C9, R19).
  • MCP 서버 제공형: 공공데이터·법령을 MCP로 노출하는 서버 자체. 5b-server(필수 A8·S11, R18).
  • 데이터 에이전트형: 로컬 MCP 호스트가 도구를 불러 조회·차트 생성. 5b-host(필수 C4·F1·S5|S6, R18).

A3 공공 API 제공자 공통 서비스

정부·공공이 운영하는 모델·데이터·개발 도구(범정부 AI 공통기반, 모두의 AI 실험실, 공공데이터포털, 공공 깃랩)를 범정부 Provider로 소비한다.

PAX 사례 154건이 이 부품을 쓴다

맥락

모델·공공데이터·법령 원문·개발 환경을 공공 플랫폼에서 가져올 수 있다면 어느 과제든 해당한다. §7.1 2단계 '기반 부품은 새로 만들지 말고 Provider에서 먼저 찾는다'가 바로 이 부품을 가리킨다. 유형 7(대조·점검)에서는 법령·기준 출처를 대는 필수 기반이다.

맞서는 힘(긴장)

  • 공통 Provider 재사용 vs 기관 고유 요구 반영
  • 공공 API 가용성·갱신 주기 vs 서비스 신뢰성
  • 인가·검증 절차의 통제 vs 에이전트 루프의 병목(PAX 공공API 진단)

해법

기반을 새로 만들기 전에 범정부 AI 공통기반(모델), 공공데이터포털·법령 API(데이터), 모두의 AI 실험실·공공 깃랩(개발·실험 환경)에서 먼저 찾아 소비한다. 인증은 GPKI·디지털원패스 같은 연합 신원(Federated Identity)으로 위임하고, 공공 API 응답은 출처·조회 시각과 함께 업무 부품에 넘긴다. 에이전트가 부를 수 있게 하려면 A8 MCP 서버로 감싸고, 결과를 재가공해 기준선으로 고정하면 A1을 더한다. 기관이 만든 도구는 공공 깃랩에 등재해 다음 기관의 Provider가 되게 한다.

이럴 때 쓴다

  • 모델·데이터·개발 환경을 기관이 새로 만들려 할 때 — 먼저 Provider 확인
  • 법령·기준 원문을 최신으로 대조해야 하는 유형 7
  • 여러 부서가 같은 기반을 따로 만들고 있을 때(X3 교정)

이럴 때는 쓰지 않는다

  • 필요한 모델·데이터가 공공 Provider에 없을 때(만들고 레지스트리에 올림)
  • 타 기관 데이터를 계약·키 매핑으로 결합하는 경우는 A4

얻는 것

  • 기관별 중복 구축 방지(X3 교정)
  • 공인된 원천 데이터·모델 사용
  • 등재를 통해 전이 경로 확보

점검표

  • 같은 기반을 기관 안에서 따로 만들지 않았는가
  • 공공 API 응답의 출처·조회 시각이 결과에 남는가
  • API 장애·변경 시 어떻게 되는지 답할 수 있는가
  • 만든 도구가 공공 깃랩 등에 등재되었는가

구조 — 참여 부품

  • 공공 Provider — 범정부 AI 공통기반·공공데이터포털·모두의 AI 실험실·공공 깃랩
  • 연합 신원 인증 — GPKI·디지털원패스 등으로 호출 주체를 확인
  • 소비 부품(B·A2·A8) — Provider를 직접 만들지 않고 가져다 씀
  • S1 AI 게이트웨이·단일 진입점 — 공공 인증을 위임받아 호출을 통제

변형

  • 공공 모델 Provider: 범정부 AI 공통기반(HCX-GOV-THINK) 위에서 모델을 소비한다. 온나라 AI 문서 분배기가 공통기반 RAG 위에서 돈다.
  • 공공 데이터·법령 Provider: 공공데이터포털 OpenAPI·법제처 API 등을 실서비스 파이프라인에 상시 연동한다.
  • 개발·실험 환경 Provider: 모두의 AI 실험실·공공 깃랩에서 개발하고 결과물을 등재한다.

참조 구현 예

  • PAX 온나라 AI 문서 분배기 — 범정부 공통기반 RAG 위에서 접수 문서 배분(§6 A3 카드)
  • PAX ef389de4efadc258 — 법제처 API로 매일 최신성 검증(§13 A3)
  • PAX 3d07b6da99f5e1ed — 직제·시행규칙을 법령 API로 파싱·결합, 시행일 스냅샷 비교(§13 A3)

관련 부품

A2.4 짝 — 공통기반 모델을 내부망에서 경유 · A8 감싸는 층 — 공공 API를 MCP 도구로 · S1 인증 위임 — 공공 인증을 단일 진입점에 · A7 등재처 — 자체 제작 도구를 공공 깃랩에 · A4 경계 — 계약 기반 결합

C1 검토 큐 운영 컴포넌트

AI 산출물이 다음 단계로 넘어가기 전에 사람이 맞고 틀림을 확인·수정·확정하는 대기열을 두어, 오류가 업무 결과로 흘러가지 않게 한다.

PAX 사례 46건이 이 부품을 쓴다

맥락

AI 산출물이 공문·처분·대민 안내·기록으로 이어지는 모든 B 부품(B1 코파일럿, B4 인식 파이프라인, B2 예측기, B7 콘텐츠 생성기 등). 이용자 본인이 최종 확정자인 자기서비스형 도구도 포함한다(R16).

맞서는 힘(긴장)

  • 정확성·책임성 vs 처리 속도(전건 검토는 자동화 이득을 깎는다)
  • 검토자의 숙련 vs 자동화 편향(AI 결과를 그대로 승인하는 경향)
  • 전건 검토의 안전 vs 위험도별 분기(C2)로 가야 하는 효율 압력

해법

AI 산출물에 신뢰도·근거를 붙여 검토 대기열에 올리고, 검토자가 승인·수정·반려 중 하나를 고르게 한다. 수정·반려 내역은 C4 감사 로그에 남겨 수정률을 집계하고 C6 환류의 입력으로 쓴다. 검토 화면은 원문 위치·근거를 함께 보여 줘 확인 비용을 줄인다. 전건 검토로 시작하되, 수정률 실측이 쌓이면 C2 위험도 라우터로 저위험 건을 자동 종결하는 단계로 옮긴다.

이럴 때 쓴다

  • AI 산출물이 공문·처분·대민 안내로 그대로 이어질 때
  • E4가 P1 이상이고 되돌리는 데 사람 시간이 많이 드는 조치가 있을 때
  • 서비스 유형 ② 접수·심사, ④ 기안 코파일럿, ⑥ 콘텐츠 제작, ⑦ 대조·점검, ⑩ 위험 예측, ⑪ 추천·매칭, ⑫ 개발 코파일럿처럼 C1이 필수인 유형

이럴 때는 쓰지 않는다

  • B0 결정적 도구처럼 런타임 AI 산출물이 없을 때
  • 쉽게 되돌릴 수 있고 저위험인 조치를 이미 C2로 자동 종결하도록 실측 근거를 갖춘 구간(전건 검토를 영원히 남기지 않는다)

얻는 것

  • 오류가 업무 결과로 나가기 전에 차단
  • 책임 소재가 명확해짐
  • 수정 내역이 C4 지표와 C6 환류의 원천 데이터가 됨

점검표

  • AI 산출물이 확정 전 상태로 머무는 지점이 명시되어 있는가
  • 검토자와 승인·수정·반려 선택지가 정해져 있는가
  • 검토 결정과 수정 내역이 로그로 남는가
  • 실증 기간의 검토·수정 건수가 기록되어 있는가
  • 전건 검토에서 분기로 옮길 조건이 정해져 있는가

구조 — 참여 부품

  • 검토 대기열 — AI 산출물을 확정 전 상태로 보관하고 검토자에게 배정
  • 검토자(담당자 또는 이용자 본인) — 승인·수정·반려를 결정하는 최종 책임자
  • F2 편집 가능한 출력 — 검토자가 산출물을 직접 고치는 화면
  • C4 감사 로그·지표 — 검토 결정과 수정 내역을 적재해 수정률로 집계

변형

  • 전건 검토형: 모든 AI 산출물을 담당자가 확인·확정
  • 예외 검수형: 정상 건은 일괄 승인하고 저신뢰 항목만 개별 검수하는 검수 UI
  • 파이프라인 내장 관문형: 멀티에이전트·다단계 파이프라인의 각 관문에 승인·보완·재작성 선택지를 둠
  • 자기서비스형: 이용자 본인이 최종 확정자인 HITL. 실제 운영 중이면 C1 present(R16)
  • 심의 게이트: 팩트체크·법무·윤리처럼 제3자 전문가가 수행하는 승인 게이트

참조 구현 예

  • PAX 9dc1a7081bc869b1 — 광진구 — 담당자·팀장 최종 판단 책임 등 4대 관리 원칙 명문화

관련 부품

C5 가드레일 필터 운영 컴포넌트

개인정보·환각·편향·형식 오류가 프롬프트나 산출물에 들어가지 못하게 시스템이 경계에서 걸러낸다. 비식별 전처리, 출처 검증, 구조적 출력 제약이 대표 변형이다.

PAX 사례 44건이 이 부품을 쓴다

맥락

외부 모델을 부르거나 대민에 답하는 모든 B 부품. 특히 E2 해외 상용 API, E5 S 이상 데이터, B3 지식 접지 상담, 유형 ① 대민 상담, ④ 기안, ⑥ 콘텐츠, ⑦ 대조·점검, ⑨ 인수인계, ⑬ 비식별·정제 도구.

맞서는 힘(긴장)

  • 차단의 엄격함 vs 과잉 차단으로 인한 유용성 저하
  • 비식별 강도 vs 문맥 보존
  • 결정적 검증의 신뢰성 vs 구현 범위

해법

프롬프트가 기관 밖으로 나가기 전 PII를 마스킹하고 원복 키를 보관하는 비식별 전처리기를 둔다. 응답에는 인용을 원본(법령정보센터·통계표 등)과 대조하는 출처 검증기와, JSON 스키마·허용 목록 같은 구조적 출력 제약을 건다. 근거가 없으면 답하지 않거나 '확인 필요'로 표시한다. 차단 사유는 C4에 남기고, 이용자에게는 F1 출처와 F7 한계 안내로 보인다. 사람이 하는 팩트체크·법무 심의는 C5가 아니라 C1.2에 둔다.

이럴 때 쓴다

  • E2 해외 상용 API로 행정망 본문이 외부로 나갈 때(필수)
  • E5 S 이상 개인정보·민감정보를 다룰 때
  • B3 대민 응답처럼 인용·수치의 정확성이 신뢰의 핵심일 때
  • C5가 필수인 유형 ①④⑥⑦⑨⑪⑬

이럴 때는 쓰지 않는다

  • E1 로컬 PC 완결로 데이터가 밖으로 나가지 않을 때 비식별은 불필요해질 수 있다(§5 매트릭스, 단 출처 검증은 별개)
  • 사람이 수행하는 심의만 있을 때(C1.2로 태그)
  • 적대적 입력 탐지가 목적일 때(S8)

얻는 것

  • 개인정보 외부 유출 차단
  • 환각 인용 감소
  • 상용 API 사용 조건 충족

점검표

  • 외부 전송 전 무엇이 걸러지는지 답할 수 있는가
  • 인용이 원본과 대조되는가
  • 근거 없을 때의 동작이 정해져 있는가
  • 차단 사유가 기록되는가

구조 — 참여 부품

  • 비식별 전처리기 — 외부 전송 전 PII 마스킹과 원복
  • 출처 검증기 — 인용을 원본과 대조해 환각을 걸러냄
  • 출력 제약 — 스키마·허용 목록·금칙어로 출력 형식 제한
  • F1 출처 표시 — 검증된 출처를 이용자에게 보임

변형

  • 로컬 비식별 전처리기: 외부 전송 전 PII 마스킹·원복(PAX에서 독립 부품으로 확인)
  • 출처 검증기: 인용을 법령정보센터·KCI·CrossRef 원본과 대조
  • 구조적 출력 제약·스키마 검증: JSON 스키마·허용 목록으로 출력 범위를 고정(v0.6 식별 신호 추가)
  • 근거 재대조형 환각 검증: 추출값의 근거 문장을 원문에서 재대조해 '문서확인/AI추정/문서에없음'으로 재분류

참조 구현 예

  • PAX Korean Stats MCP — KOSIS 통계 출처 자동 인용

X9 담당자와 함께 사라지는 도구 안티패턴

개인이 만든 도구가 부서에 퍼졌지만 라이선스·저장소·인수인계가 없어, 만든 사람의 인사이동과 함께 멈추는 함정이다.

맥락

A7 자체 제작 환경으로 태깅된 도구(PAX 557건 중 317건, 57%), 특히 개인 사용에서 부서 공유로 막 퍼지기 시작한 바이브코딩 도구.

맞서는 힘(긴장)

  • 개인의 빠른 제작 vs 조직의 유지보수 책임
  • 비공식 공유의 편의 vs 라이선스·저장소 절차
  • 현장 맞춤 vs 다른 담당자가 이해할 수 있는 구조

해법

도구가 부서에 퍼지기 시작하면 A7 산출물에 MIT·Apache 등 라이선스를 명시하고, 코드를 개인 PC가 아니라 A3 공공 깃랩 같은 공용 저장소에 등재한다. 업무 규범·프롬프트는 A9 업무 규범 스킬로 패키징해 다른 담당자가 그대로 쓸 수 있게 하고, 설치·설정·데이터 경로를 담은 인수인계 문서를 둔다. 도구를 참조 구현 레지스트리(§13)에 올려 소유를 개인에서 조직으로 옮긴다. transition.blocker에 '담당자 이동'이 적힌 과제는 이 조치를 먼저 한다.

이럴 때 쓴다

  • 개인이 만든 도구를 부서원 여러 명이 쓰는데 라이선스 표기가 없다
  • 원본 코드가 개인 PC·개인 계정에만 있다
  • 인수인계 문서·설치 절차가 없다
  • transition.blocker가 '담당자 이동'이다

이럴 때는 쓰지 않는다

  • 개인만 쓰는 도구로 부서에 퍼지지 않은 경우(개인 사용 단계는 정상)
  • A7로 만들었지만 라이선스 명시·공용 저장소 등재·인수인계가 갖춰진 경우
  • 기관 정보화 부서가 넘겨받아 운영 중인 경우

얻는 것

  • 현장 담당자가 필요한 도구를 빠르게 만든다
  • 공식 절차 없이 바로 퍼진다

점검표

  • 라이선스가 명시되어 있는가
  • 원본이 공용 저장소에 있는가
  • 만든 사람 없이 후임이 설치·실행할 수 있는 문서가 있는가
  • 개인 구독·개인 키에 의존하지 않는가

구조 — 참여 부품

  • A7 자체 제작 환경 — 도구가 태어난 곳. 라이선스 명시가 전이 조건
  • A3 공공 API 제공자(공공 깃랩) — 개인 저장소를 대체하는 공용 등재처
  • A9 업무 규범 스킬 — 암묵적 업무 규범을 패키지로 남김
  • 후임 담당자 — 인수인계 문서로 도구를 이어받는 사람

변형

  • 라이선스 미명시: 코드는 공개했지만 라이선스가 없어 타 기관이 가져다 쓸 수 없음
  • 개인 저장소형: 개인 PC·개인 계정에만 원본이 있음
  • 개인 구독 의존형: 개인 AI 구독·API 키로 돌아가 담당자가 떠나면 호출이 끊김

관련 부품
