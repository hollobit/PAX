판정 근거

담당 시설사업의 설계도면을 GPT-6 Astra(해외 상용, A2.1)로 3차원 모델로 바꿔 입주 현황·주차 동선·인근 건물을 재현한 실무 적용기. 최종 산출물이 3D 모델 자체이므로 B7 콘텐츠 생성기(변형 '생성형 3D 모델링'), 도면을 읽는 단계는 있으나 판정으로 이어지지 않아 B4로 보지 않음. 부서 내부 검토 자료로 쓰였다는 서술에 따라 D8.4 대조·점검, 전이 단계는 부서 공유. 서비스 유형은 2D→3D 변환에 맞는 것이 없어 0 기타. 도구는 별도 시스템 없이 생성형 AI 서비스를 직접 쓴 것으로 보여 runtime은 AI 도구 설정(잠정), 인터넷 필수. 설계도면의 민감도는 미확인. case_url 없음(URL 미확인).

구현 가이드

주 패턴 B7 콘텐츠 생성기을 구현할 때

구현 단계

  1. 기관 문체·표현 윤리·서식을 A9 스타일 스킬로 정리하고 실패 사례를 규칙으로 추가한다.
  2. 입력 원자료(보도자료 HWPX 등)를 A10으로 받고, 기획 단계(B′8)에서 구성안을 먼저 확정한다.
  3. 형식 기준(길이·필수 항목·규격)을 수치로 정하고 반복 개선(B′6)에 최대 반복을 둔다.
  4. C5 저작권·사실검증과 C1 검수를 발행 전 관문으로 둔다.
  5. F3으로 여러 안과 부분 재생성을 제공하고, 발행 후 반응을 다음 기획에 반영한다.

점검표

  • 기관 스타일 규범이 스킬로 분리되어 있는가
  • 발행 전 사실·저작권 검수가 운영되는가
  • 반복 개선에 최대 반복 횟수가 있는가
  • 이용자가 일부만 다시 만들 수 있는가(F3)

환경 조건

E2 해외 상용 API 의존이 강하다(이미지 생성). E5는 O(공개) 자료가 대부분이라 제약이 적다. E4는 P1이 기본이며, 외부 공개로 직행하면 P2다. 적대적 위협은 참고 링크를 통한 유출 링크 삽입·설명문 인젝션이며 S8 독립 검증기가 필수다(§7.4 유형 ⑥).

주의할 점

  • 사실 오류·저작권 위험
  • 해외 상용 이미지 생성 API 의존(X4)
  • 유출 링크 삽입·설명문 인젝션 위협

기본 배선 예

A10 → B7 (B′8 · B′6) → C5 → C1 → D8.10

피해야 할 안티패턴

  • X4 단일 모델 인질 상용 API 하나에 전 기능이 묶여 있어, 그 API가 멈추거나 바뀌면 무슨 일이 생기는지 아무도 답하지 못하는 함정이다. 대처: 모델 호출을 A2 모델 서빙 계층 뒤로 숨겨 B 부품이 특정 벤더 API를 직접 부르지 않게 한다. 그 위에 C7 폴백 스위치로 재시도 → 기존 API → 대체 MCP → 대체 모델(A2.2 주권형 로컬 등) → 규칙 기반 축소 → 수동 전환의 경로를 정하고 전환 이력을 C4에 남긴다. 모델 교체가 실제로 안전한지는 C9 평가 세트로 재어 버전을 고정한다. 모델 중립(BYO) 배포라면 A9 스킬 형태로 배포해 모델 교체 가능성 자체를 폴백으로 삼는다.
  • X12 상한 없는 반영 루프 생성자-비평가·반복 개선 루프에 최대 반복을 두지 않아, 품질은 그대로인데 토큰과 지연만 늘어나는 함정이다. 대처: B′5·B′6 루프에 최대 반복(2~3회)을 설정하고, 상한에 도달해도 기준을 못 넘으면 C1 검토 큐로 사람에게 넘긴다. A2 모델 서빙 계층에서 호출당 비용·P95 지연을 지표로 수집하고(C4), S1 단일 진입점에 요청·비용 상한을 둬 폭주를 막는다. 재생성이 필요 없는 판정 구조라면 B′9 결정론 판정 게이트처럼 재생성 없이 기각·강등만 하는 비루프 검증으로 바꾼다. 상한 값은 C9 평가 세트에서 반복 횟수별 점수를 재어 정한다.

A2.1 모델 서빙 · 상용 API 호출 공통 서비스

GPT·Gemini·Claude·HyperCLOVA X·Upstage 등 상용 모델 API를 서빙 계층을 거쳐 호출해 자체 인프라 없이 최신 모델 성능을 쓴다.

PAX 사례 88건이 이 부품을 쓴다

맥락

E2는 해외 상용 API(또는 국산 상용 모델 API), E1은 인터넷망·클라우드다. E5 등급이 O이거나 비식별 후 전송해도 되는 업무에 맞는다. 대민 상담(B3)·코파일럿(B1)·콘텐츠 생성(B7)에서 흔하다.

맞서는 힘(긴장)

  • 모델 성능·도입 속도 vs 데이터 반출·주권
  • 종량 과금의 초기 저비용 vs 호출량 증가 시 비용 예측 어려움
  • 벤더의 모델 개선 vs 예고 없는 품질 회귀
  • 단일 API의 단순함 vs 장애 시 서비스 중단

해법

업무 코드는 서빙 계층만 부르고, 서빙 계층이 상용 API를 호출한다. 행정망 본문이 나가는 경로 앞에는 C5 비식별 전처리를 두고, 대체 모델을 등록해 C7 폴백을 건다(§5 매트릭스 E2 해외 상용 API 행). 모델 버전을 고정하고 모델·프롬프트·설정 조합을 릴리스처럼 관리해 업데이트 전후를 C9로 비교한다. 비용이 문제면 라우팅·캐싱으로 큰 모델 호출을 줄인다. E5가 S 이상이면 이 변형 단독으로는 안 되고 A2.4 내부망 프록시를 거친다.

이럴 때 쓴다

  • 인터넷망·클라우드 환경이고 데이터 등급이 O이거나 비식별 후 전송 가능할 때
  • PoC 초기에 모델 성능을 빠르게 확인해야 할 때
  • 자체 GPU·운영 인력이 없을 때

이럴 때는 쓰지 않는다

  • E1이 폐쇄망이면 조립 오류(A2.2·A2.4로)
  • E5가 S 이상인데 내부망 프록시가 없을 때(A2.4 필수)
  • 상시 서비스인데 대체 경로를 둘 수 없을 때

얻는 것

  • 인프라 없이 최신 모델 성능
  • 빠른 PoC
  • 벤더의 지속적 개선

점검표

  • 업무 코드가 상용 API를 직접 부르지 않는가
  • 외부로 나가는 프롬프트에서 무엇이 걸러지는지 답할 수 있는가
  • API 장애 시 대체 경로가 있는가
  • 모델 버전과 호출당 비용·지연이 기록되는가

구조 — 참여 부품

  • A2 서빙 계층 — 업무 코드 대신 상용 API를 호출하고 버전·사용량을 기록
  • C5 가드레일(비식별 전처리) — 외부 전송 전 민감정보 제거
  • 상용 모델 API — 기관 밖에서 추론을 수행
  • C7 폴백 스위치 — API 장애·품질 저하 시 대체 모델·수동 처리로 전환

변형

  • 국산 상용 API: HyperCLOVA X·Upstage 등 국내 사업자 API. 망·등급 조건은 해외와 같이 따진다.
  • 구조화 호출: function calling·JSON Schema로 출력 형식을 고정해 부른다. 판정은 규칙 엔진에 남긴다.

D8.4 대조·점검 서비스 블록

법령·규정·서식·인용·근태·보안 기준과 대조해 확인할 대상을 먼저 골라 주는 내부 운영 블록이다. "최종 판단은 사람"이 가장 자주 붙는다.

PAX 사례 81건이 이 부품을 쓴다

맥락

기관 내부 문서·자료를 기준과 대조하는 업무. §7.3 유형 ⑦ 대조·점검 도우미(D8.4, P0~P1)와 유형 ⑩ 위험 예측·표적 선별(D6·D3·D8.4)의 무대. PAX 81건(주 부품 B0 73%, B1 12%), 감사·법무 25건·문서·기안 12건.

맞서는 힘(긴장)

  • 점검 범위 확대 vs 오탐으로 인한 확인 부담
  • 규칙 점검의 결정성 vs LLM 대조의 유연성
  • 점검 대상이 점검기를 속이는 위협 vs 자동 점검
  • 출처 대조의 엄격성 vs 원문 접근 권한(공공 API 인가)

해법

기준이 규칙으로 옮겨지면 B0 규칙 점검기로, 해석이 필요하면 B3 법령 접지로 대조한다. 기준 원문은 A3 공공 API(법령·판례)에서 가져와 C5 출처 검증으로 인용이 실제 원문과 일치하는지 확인한다. 결과는 판정이 아니라 "확인할 대상 목록"으로 내고, C1으로 "최종 판단은 사람"을 명시하며, F7 한계와 F1 출처를 붙인다. 점검 대상 문서·코드가 점검기를 속이지 못하게 대상별 격리(S6)나 고정 규칙 실행(S4)을 쓰고, 코드 점검이면 S9 샌드박스를 둔다. C9 평가 세트로 누락률을 잰다.

이럴 때 쓴다

  • 문서·자료를 법령·규정·서식과 한 줄씩 대조하는 업무
  • 인용·근거가 원문과 맞는지 확인해야 할 때
  • 점검 대상이 많아 확인 대상을 먼저 좁혀야 할 때

이럴 때는 쓰지 않는다

  • 국민 신청 건의 자격 판정이면 D3
  • 현장 시설을 관측해 점검하면 D6
  • 대조 없이 자료를 찾아 보여 주면 D8.1

얻는 것

  • 사람 판단을 확인 대상에 집중
  • 인용 오류의 사전 차단

점검표

  • 결과가 판정이 아닌 확인 대상으로 표시되는가
  • 근거 원문 출처가 연결되는가

  • 모델 업데이트의 성능 향상 vs 예고 없는 동작 변화

해법

모델 호출을 A2 모델 서빙 계층 뒤로 숨겨 B 부품이 특정 벤더 API를 직접 부르지 않게 한다. 그 위에 C7 폴백 스위치로 재시도 → 기존 API → 대체 MCP → 대체 모델(A2.2 주권형 로컬 등) → 규칙 기반 축소 → 수동 전환의 경로를 정하고 전환 이력을 C4에 남긴다. 모델 교체가 실제로 안전한지는 C9 평가 세트로 재어 버전을 고정한다. 모델 중립(BYO) 배포라면 A9 스킬 형태로 배포해 모델 교체 가능성 자체를 폴백으로 삼는다.

이럴 때 쓴다

  • E2가 해외 상용 API인데 C7 폴백이 없다(분류기준 검증 경고 조건)
  • 'API가 멈추면 어떻게 되는가'에 대한 서술이 없다
  • 모델 버전 고정·교체 시험 기록이 없다
  • A2 게이트웨이 없이 B 부품이 벤더 API를 직접 호출한다

이럴 때는 쓰지 않는다

  • B0 결정적 도구처럼 런타임 AI가 없는 경우
  • 로컬 완결 도구로 외부 의존이 없는 경우
  • 모델 중립(BYO) 배포로 A9 스킬 형태라 이용자가 모델을 바꿀 수 있는 경우
  • 상용 API를 쓰되 A2 게이트웨이와 C7 대체 경로가 구현된 경우

얻는 것

  • 가장 성능 좋은 모델을 가장 빨리 쓴다
  • 게이트웨이·대체 모델 유지 비용이 없다

점검표

  • 모든 모델 호출이 A2 한 곳을 지나는가
  • 대체 경로가 하나 이상 구현되어 있는가
  • 대체 모델의 품질이 C9로 측정되어 있는가
  • 모델 버전이 고정되어 있고 교체가 릴리스처럼 관리되는가

구조 — 참여 부품

  • A2 모델 서빙 계층 — 벤더 API를 숨기는 끼울 자리
  • C7 폴백 스위치 — 장애 시 대체 경로로 전환
  • C9 평가 세트·회귀시험 — 대체 모델의 품질을 같은 자로 확인
  • 단일 상용 API — 모든 기능이 묶인 의존 대상

변형

  • 직접 호출형: 게이트웨이 없이 코드 곳곳에서 벤더 SDK를 직접 호출
  • 벤더 내장형: 벤더 제품 안에 모델이 박혀 교체 자체가 불가능(A2.6 블랙박스와 결합)
  • 버전 미고정형: 모델 버전을 고정하지 않아 업데이트가 예고 없이 동작을 바꿈

관련 부품

C7 대체 — 장애 시 이어 가는 폴백 경로 · A2 끼울 자리 — 벤더 API를 숨기는 모델 서빙 계층 · A2.2 대체 모델 후보 — 주권형 로컬 · C9 선행 — 대체 모델 품질 확인과 버전 고정 · A9 BYO 배포에서의 대응 — 스킬 형태면 모델 교체 가능

참고 자료

Gulli ch.12 Exception Handling · Microservice Circuit Breaker · PAX Native 관문 4

X12 상한 없는 반영 루프 안티패턴

생성자-비평가·반복 개선 루프에 최대 반복을 두지 않아, 품질은 그대로인데 토큰과 지연만 늘어나는 함정이다.

맥락

B′5·B′6을 쓰는 B1·B7·B3 과제, 특히 상용 API 과금 환경이나 자원이 제한된 폐쇄망 로컬 모델 환경.

맞서는 힘(긴장)

  • 한 번 더 돌리면 나아질 것이라는 기대 vs 수렴 보장 없음
  • 품질 기준 도달 vs 비용·지연 상한
  • 완전 자동 vs 수렴 실패 시 사람에게 넘김

해법

B′5·B′6 루프에 최대 반복(2~3회)을 설정하고, 상한에 도달해도 기준을 못 넘으면 C1 검토 큐로 사람에게 넘긴다. A2 모델 서빙 계층에서 호출당 비용·P95 지연을 지표로 수집하고(C4), S1 단일 진입점에 요청·비용 상한을 둬 폭주를 막는다. 재생성이 필요 없는 판정 구조라면 B′9 결정론 판정 게이트처럼 재생성 없이 기각·강등만 하는 비루프 검증으로 바꾼다. 상한 값은 C9 평가 세트에서 반복 횟수별 점수를 재어 정한다.

이럴 때 쓴다

  • B′5·B′6 루프의 종료 조건이 '통과할 때까지'뿐이고 최대 반복이 없다
  • 호출당 비용·지연 지표가 없다
  • 반복 횟수별 품질 변화를 잰 기록이 없다
  • 비용·지연 폭주가 관측되었다

이럴 때는 쓰지 않는다

  • 최대 반복(2~3회)과 상한 도달 시 처리 경로가 정해진 경우
  • B′9처럼 재생성 없이 기각·강등만 하는 비루프 검증
  • 반복이 사람의 수동 요청(F3 부분 재생성)으로만 일어나는 경우

얻는 것

  • 구현이 단순하고 '품질이 나올 때까지 돈다'는 설명이 쉽다
  • 가끔 추가 반복으로 품질이 오른다

점검표

  • 모든 루프에 최대 반복이 있는가
  • 상한 도달 시 사람에게 넘기는 경로가 있는가
  • 지난달 호출당 비용과 P95 지연을 말할 수 있는가
  • 상한 값이 C9 측정으로 정해졌는가

구조 — 참여 부품

  • B′5 생성자-비평가 — 반복 상한 2~3회가 필요한 루프
  • B′6 반복 개선 — 수렴 보장이 없어 최대 반복이 필수인 루프
  • A2 모델 서빙 계층 — 호출당 비용·지연 지표의 수집 지점
  • C1 검토 큐 — 상한 도달 시 사람에게 넘기는 출구

변형

  • 통과까지 반복: 비평 통과를 종료 조건으로만 두고 횟수 상한이 없음
  • 도달 불가 목표: 반복 개선의 수치 목표가 현실적으로 도달 불가능
  • 중첩 루프: 여러 에이전트가 각자 반성 루프를 돌려 반복이 곱해짐

관련 부품

B′5 교정 대상 — 반복 상한 2~3회 · B′6 교정 대상 — 최대 반복 필수 · B′9 대안 — 재생성 없는 비루프 검증 · A2 기록처 — 호출당 비용·지연 지표 · S1 끼울 자리 — 요청·비용 상한(denial-of-wallet 방어)
