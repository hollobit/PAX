판정 근거

토지이음·임야대장·기상청 일사량·인허가 조건·한전 계통연계 용량 등 5종 공공데이터를 결합해 태양광 설치 가능성과 예상 수익을 규칙적으로 계산해 보여주는 도구로, LLM 사용 근거가 없어 B0 결정적 도구로 판정했다. 여러 기관 데이터를 연계한 점은 A4, 공공데이터 API 호출은 A3에 해당한다. LX 해커톤 결선작으로 지속 운영 여부가 불확실해 transition을 구현·미배포로 두었다.

구현 가이드

주 패턴 B0 결정적 도구을 구현할 때

구현 단계

  1. 반복 업무의 입력 파일·서식과 원하는 산출물을 나열하고, 처리 규칙을 사람이 읽을 수 있는 조건→결과 표로 먼저 적는다.
  2. HWP·HWPX·엑셀 입출력은 A10 어댑터로 분리하고, 공공 깃랩(A3) 등에 있는 기존 어댑터를 먼저 찾는다.
  3. AI 코딩 도구(A7)로 규칙 코드와 화면을 만들고, 런타임에 모델·외부 API를 부르지 않는지 네트워크 의존을 점검한다.
  4. 대표 입력 세트로 같은 입력에 같은 결과가 나오는지 확인하고 규칙 표와 코드의 대응을 문서로 남긴다.
  5. 부서 공유 이상으로 옮길 때 라이선스·저장소 위치·처리 로그(C4)·원복 경로(C3)를 갖춰 담당자 이동에 대비한다.

점검표

  • 런타임에 LLM·ML 호출이 전혀 없는가
  • 규칙 표가 코드와 별도로 문서화되어 있는가
  • 같은 입력에 같은 결과가 나오는지 확인했는가
  • 라이선스와 저장소 위치가 명시되어 인수인계가 가능한가

환경 조건

E2 = 없음(비LLM). E1 로컬 완결이 다수이며 폐쇄망 이식이 가장 쉬운 부품이다. E4는 대개 P0~P1이다. 로컬 PC 완결이면 C5 비식별 부담은 줄지만 C4 로그가 사라지므로 기관으로 전이할 때 다시 장착한다(§5 매트릭스).

주의할 점

  • 비정형 입력에 취약
  • 규칙 유지보수가 사람에게 남음
  • 개인 제작 도구가 담당자 이동과 함께 멈출 위험(X9)
  • AX 단계는 Ready에 머묾

기본 배선 예

A7 → B0 → A10 (HWPX 출력) · B0 → C4 (처리 로그, 기관 전이 시)

보완이 필요한 필수 부품

이 조합에서 카탈로그가 함께 갖추라고 권하는 부품 가운데 아직 확인되지 않은 것이다.

  • A2 모델 서빙 계층 업무 부품이 모델을 직접 부르지 않고 서빙 계층을 거쳐 부르게 해 모델을 바꿔 끼우고 라우팅·캐싱·버전 고정·폴백을 한 자리에서 다룬다. A2.0~A2.6을 묶는 부모 항목이다.
  • C5 가드레일 필터 개인정보·환각·편향·형식 오류가 프롬프트나 산출물에 들어가지 못하게 시스템이 경계에서 걸러낸다. 비식별 전처리, 출처 검증, 구조적 출력 제약이 대표 변형이다.
  • C9 평가 세트·회귀시험 배포 전에 업무 맥락의 질문·정답·채점 기준을 세트로 만들어, 프롬프트·모델·설정의 모든 변경을 같은 자로 재고 회귀를 잡는다.

피해야 할 안티패턴

  • X6 데모웨어 (이 사례에서 확인) 시연은 있으나 실데이터·권한·망 환경이 없어 현장에 놓을 수 없는 PoC. 접점과 환경 조건을 먼저 못 박는 단계를 건너뛴 결과다. 대처: §7.1 첫 단계대로 서비스 블록(D)과 환경 조건 E1~E5(배포망·모델 의존·실행 형태·권한 범위·데이터 등급)를 먼저 기록하고, 그 조건에서 돌아가는 부품으로 조립한다. 원천 기록을 정제한 A1 데이터 자산으로 실데이터 기준선을 만들고, 타 기관 데이터가 필요하면 A4 데이터 연계 서비스로 계약·연계를 확보한다. 운영 망이 폐쇄망·행정망이면 A2.2 주권형 로컬이나 A2.4 내부망 프록시로 모델 경로를 맞추고, E4 권한에 맞춰 C1~C8 통제 부품을 장착한다. 실증 데이터가 실사용인지 샘플인지를 명시한다(R28 data_realism 제안).
  • X9 담당자와 함께 사라지는 도구 개인이 만든 도구가 부서에 퍼졌지만 라이선스·저장소·인수인계가 없어, 만든 사람의 인사이동과 함께 멈추는 함정이다. 대처: 도구가 부서에 퍼지기 시작하면 A7 산출물에 MIT·Apache 등 라이선스를 명시하고, 코드를 개인 PC가 아니라 A3 공공 깃랩 같은 공용 저장소에 등재한다. 업무 규범·프롬프트는 A9 업무 규범 스킬로 패키징해 다른 담당자가 그대로 쓸 수 있게 하고, 설치·설정·데이터 경로를 담은 인수인계 문서를 둔다. 도구를 참조 구현 레지스트리(§13)에 올려 소유를 개인에서 조직으로 옮긴다. transition.blocker에 '담당자 이동'이 적힌 과제는 이 조치를 먼저 한다.
  • X1 AI 스티커 기존 화면에 요약·챗봇 버튼만 붙이고 업무 순서와 사람·AI의 역할 분담은 그대로 두어, AI가 있어도 업무 산출물이 바뀌지 않는 함정이다. 대처: 먼저 가치 흐름 규칙(R1)으로 사람 또는 국민이 최종으로 받는 핵심 산출물을 정하고, 그 산출물을 AI가 어떤 모양으로 분담할지 B 업무 컴포넌트를 하나 고른다(초안→사람 확정이면 B1, 근거 접지 답변이면 B3, 서류 추출이면 B4). 사람이 확정하는 지점은 C1 검토 큐로, 이용자가 고쳐 확정하는 면은 F2 편집 가능한 출력으로 명시한다. 흐름이 바뀌었는지는 C4 감사 로그·지표의 처리시간·수정률로 잰다. AI 런타임이 전혀 없는 행정정보시스템이라면 AI로 포장하지 말고 R24대로 B0·service_type 0·platform 공란·X1(AI 무관)으로 정직하게 분류한다.

PAX 사례 413건이 이 부품을 쓴다

맥락

AI 코딩 도구(A7)로 기관 인력이 직접 만든 자생 도구가 대부분이다(PAX 557건 가운데 주 부품이 B0인 사례 390건, 70%). 로컬 PC 완결이나 폐쇄망 이식이 필요한 업무, 판정 재현성이 감사에서 중요한 업무에도 맞는다. model_dependency가 '없음(비LLM)'으로 확인될 때만 해당한다.

맞서는 힘(긴장)

  • 재현성·설명 가능성 vs 비정형 입력을 다루는 유연성
  • 로컬 완결의 보안 이점 vs 기관 전이 시 처리 로그(C4)와 인수인계가 사라지는 문제
  • 규칙을 코드에 넣는 단순함 vs 규정이 바뀔 때마다 사람이 규칙을 고쳐야 하는 유지 부담

해법

업무 절차를 입력 형식(A10 어댑터)과 처리 규칙으로 나누고, AI 코딩 도구(A7)는 개발 시점에만 써서 규칙 코드와 화면을 만든다. 런타임에는 모델을 호출하지 않으므로 같은 입력에 같은 결과가 나오고 인터넷 없이 로컬에서 돈다. 판정이 필요한 경우에도 결정적 규칙 엔진이 낸다. 비정형 입력을 다뤄야 하는 단계가 생기면 그 단계만 B1·B3로 승격하고 결정적 부분은 전처리로 남긴다. 부서 밖으로 옮길 때는 라이선스·저장소·처리 로그를 함께 갖춘다.

이럴 때 쓴다

  • 입력이 정형(엑셀·서식)이고 처리 결과를 규칙으로 정의할 수 있을 때
  • 파일이 PC 밖으로 나가면 안 되거나 폐쇄망·로컬 완결이 필요할 때
  • 판정 재현성이 필요해 같은 입력에 늘 같은 결과가 나와야 할 때(규칙 점검기, 결정론 점수 엔진)
  • LLM 도입 전에 데이터·기준선을 정비하는 단계일 때

이럴 때는 쓰지 않는다

  • 비정형 문서의 요약·초안처럼 규칙으로 산출물을 정의할 수 없을 때(B1)
  • 질문이 다양해 규정·선례 접지가 필요한 상담일 때(B3)
  • 학습 모델의 수치·등급 예측이 핵심 산출물일 때(B2)

얻는 것

  • 재현성과 감사 가능성
  • 폐쇄망·로컬 이식이 가장 쉬움
  • 모델 호출 비용과 모델 장애 위험이 없음
  • B1·B3의 전처리 부품으로 승격할 자산

점검표

  • 런타임에 LLM·ML 호출이 전혀 없는가
  • 규칙 표가 코드와 별도로 문서화되어 있는가
  • 같은 입력에 같은 결과가 나오는지 확인했는가
  • 라이선스와 저장소 위치가 명시되어 인수인계가 가능한가

구조 — 참여 부품

B′1 순차 파이프라인 제어 흐름

한 단계의 출력을 다음 단계의 입력으로 넘기는 고정 순서 배선이다. 한 프롬프트에 많은 일을 몰아 시켜 품질이 떨어지는 문제를 막는다.

PAX 사례 109건이 이 부품을 쓴다

맥락

B4 인식 파이프라인의 기본 배선이며, B1·B0·B5 안에서도 흔하다. 단계 순서가 업무 절차로 미리 정해져 있고 AI가 순서를 고를 필요가 없을 때 쓴다.

맞서는 힘(긴장)

  • 디버깅·출처 추적의 쉬움 vs 병렬화 불가로 인한 지연
  • 단계 분리의 품질 이점 vs 단계가 늘수록 오류 누적
  • 고정 순서의 예측 가능성 vs 예외 경로 처리의 경직성

해법

업무 절차를 단계로 나누고 각 단계의 입력·출력 형식을 정해 앞 단계 출력을 다음 단계에 넘긴다. 단계 사이에 형식 검증(스키마)을 두어 오류가 번지기 전에 멈추고, 멈춘 건은 C1 검토 큐나 C3 재처리로 보낸다. 판정·산수 단계는 가능한 한 규칙(B′9)으로 두고 모델은 추출·서술 단계만 맡긴다. 단계 순서를 AI가 바꿔야 한다면 B′8이나 B′7로 옮긴다.

이럴 때 쓴다

  • 업무 절차가 고정 순서로 정해져 있을 때
  • 각 단계를 따로 검증·추적해야 할 때(유형 ② 접수·심사, ⑧ 취합·변환)
  • 단일 에이전트에서 시작하는 첫 배선일 때

이럴 때는 쓰지 않는다

  • 하위 작업이 서로 독립이라 동시에 돌려야 지연이 줄 때(B′3)
  • 입력에 따라 AI가 다음 도구를 골라야 할 때(B′7)
  • 긴 업무를 계획부터 세워야 할 때(B′8)

얻는 것

  • 디버깅과 출처 추적이 쉬움
  • 단계별 품질 검증 가능
  • 구현이 가장 단순

점검표

  • 단계마다 입력·출력 형식이 정의되어 있는가
  • 단계 사이 검증에서 실패하면 멈추는가
  • 단계별 중간 결과를 추적할 수 있는가

구조 — 참여 부품

  • 단계 간 형식 검증 — 다음 단계로 넘기기 전 스키마 확인

PAX 사례 154건이 이 부품을 쓴다

맥락

모델·공공데이터·법령 원문·개발 환경을 공공 플랫폼에서 가져올 수 있다면 어느 과제든 해당한다. §7.1 2단계 '기반 부품은 새로 만들지 말고 Provider에서 먼저 찾는다'가 바로 이 부품을 가리킨다. 유형 7(대조·점검)에서는 법령·기준 출처를 대는 필수 기반이다.

맞서는 힘(긴장)

  • 공통 Provider 재사용 vs 기관 고유 요구 반영
  • 공공 API 가용성·갱신 주기 vs 서비스 신뢰성
  • 인가·검증 절차의 통제 vs 에이전트 루프의 병목(PAX 공공API 진단)

해법

기반을 새로 만들기 전에 범정부 AI 공통기반(모델), 공공데이터포털·법령 API(데이터), 모두의 AI 실험실·공공 깃랩(개발·실험 환경)에서 먼저 찾아 소비한다. 인증은 GPKI·디지털원패스 같은 연합 신원(Federated Identity)으로 위임하고, 공공 API 응답은 출처·조회 시각과 함께 업무 부품에 넘긴다. 에이전트가 부를 수 있게 하려면 A8 MCP 서버로 감싸고, 결과를 재가공해 기준선으로 고정하면 A1을 더한다. 기관이 만든 도구는 공공 깃랩에 등재해 다음 기관의 Provider가 되게 한다.

이럴 때 쓴다

  • 모델·데이터·개발 환경을 기관이 새로 만들려 할 때 — 먼저 Provider 확인
  • 법령·기준 원문을 최신으로 대조해야 하는 유형 7
  • 여러 부서가 같은 기반을 따로 만들고 있을 때(X3 교정)

이럴 때는 쓰지 않는다

  • 필요한 모델·데이터가 공공 Provider에 없을 때(만들고 레지스트리에 올림)
  • 타 기관 데이터를 계약·키 매핑으로 결합하는 경우는 A4

얻는 것

  • 기관별 중복 구축 방지(X3 교정)
  • 공인된 원천 데이터·모델 사용
  • 등재를 통해 전이 경로 확보

점검표

  • 같은 기반을 기관 안에서 따로 만들지 않았는가
  • 공공 API 응답의 출처·조회 시각이 결과에 남는가
  • API 장애·변경 시 어떻게 되는지 답할 수 있는가
  • 만든 도구가 공공 깃랩 등에 등재되었는가

구조 — 참여 부품

  • 공공 Provider — 범정부 AI 공통기반·공공데이터포털·모두의 AI 실험실·공공 깃랩
  • 연합 신원 인증 — GPKI·디지털원패스 등으로 호출 주체를 확인
  • 소비 부품(B·A2·A8) — Provider를 직접 만들지 않고 가져다 씀
  • S1 AI 게이트웨이·단일 진입점 — 공공 인증을 위임받아 호출을 통제

변형

  • 공공 모델 Provider: 범정부 AI 공통기반(HCX-GOV-THINK) 위에서 모델을 소비한다. 온나라 AI 문서 분배기가 공통기반 RAG 위에서 돈다.
  • 공공 데이터·법령 Provider: 공공데이터포털 OpenAPI·법제처 API 등을 실서비스 파이프라인에 상시 연동한다.
  • 개발·실험 환경 Provider: 모두의 AI 실험실·공공 깃랩에서 개발하고 결과물을 등재한다.

참조 구현 예

  • PAX ef389de4efadc258 — 법제처 API로 매일 최신성 검증(§13 A3)
  • PAX 3d07b6da99f5e1ed — 직제·시행규칙을 법령 API로 파싱·결합, 시행일 스냅샷 비교(§13 A3)

A4 데이터 연계 서비스 공통 서비스

타 기관 데이터를 연계 계약과 표준 인터페이스·키 매핑으로 결합해 한 기관의 데이터로는 풀 수 없는 문제의 기준선을 만든다.

PAX 사례 11건이 이 부품을 쓴다

맥락

타 기관·민간 데이터를 결합해야 하는 과제에 쓴다. 유형 5a·10·11의 기반이다(§7.3). 전이 차단 요인 '기관 간 협약'(R8)에 바로 걸린다.

맞서는 힘(긴장)

  • 결합 데이터의 가치 vs 개인정보·기업비밀 보호
  • 계약·협의 기간 vs 과제 일정
  • 실시간 연계 vs 연계 기관 시스템 부담

해법

연계 계약(또는 협약)과 키 매핑 규칙을 먼저 확정하고, 표준 인터페이스로 결합한다. 식별자가 민감하면 가명키·키맵 분리 보관으로 결합하고, 원본·마스킹·제출용 데이터를 분리한다. 결합 결과는 A1 기준선처럼 정의서(결합키·변수 정의)로 문서화한다. 상대 기관이 원자료 제공에 난색을 보이면 그룹핑·집계 수준으로 협의안을 만들고, 기존 전산망을 재활용해 자동 전송한다.

이럴 때 쓴다

  • 한 기관 데이터로는 예측·판정 근거가 부족할 때
  • 타 기관 데이터로 신청 정보의 누락·불일치를 교차 확인할 때
  • 관할이 갈린 다부처 데이터를 하나의 파이프라인으로 묶을 때

이럴 때는 쓰지 않는다

  • 공개 API를 조회만 하면 A3
  • 자기 기관 기록만 정제하면 A1
  • 계약 없이 '연계 예정'만 있으면 태그하지 않는다(계획서 단계)

얻는 것

  • 단일 기관으로 불가능한 판정 근거 확보
  • 재사용 가능한 연계 설계(키·정의서)
  • 가점 ➋ 대상

점검표

  • 연계 계약·협약이 체결되었는가
  • 결합키·변수 정의서가 있는가
  • 키맵과 원본이 분리 보관되는가
  • 연계 중단 시 서비스가 어떻게 되는지 정해져 있는가

구조 — 참여 부품

  • 연계 기관 — 데이터를 제공하고 계약 조건을 정함
  • 키 매핑·가명결합 절차 — 공통 연계키로 레코드를 잇고 식별자를 보호
  • A1 데이터 자산 서비스 — 결합 결과를 기준선으로 정의·버전 관리
  • C5 가드레일(비식별) — 결합 전후 민감정보 처리

변형

  • 가명결합형: 이중 식별축 가명키와 원본/마스킹/제출용·키맵 분리 보관으로 여러 기관 데이터를 결합한다.
  • 시공간 결합형: 기관 시설 좌표·행정구역에 기상청 등 공공 API 값을 최근접·구역 단위로 맞춘다.
  • 동의 기반 마이데이터형: 공통 연계키로 공공·민간 데이터를 당사자 동의로 결합한다.
  • 협의·전산망 재활용형: 제공 기관의 우려를 집계 수준 협의안으로 풀고 기존 전산망으로 자동 전송한다.

F1 출처 표시 상호작용 패턴

답변에 근거 문서·조문·통계표 ID를 붙여 이용자가 원문을 직접 확인할 수 있게 한다. C5 출처 검증의 이용자 면이다.

PAX 사례 87건이 이 부품을 쓴다

맥락

B3 지식 접지 상담, A8 공공데이터 MCP, 법령·통계·규정을 인용하는 모든 응답. 유형 ① 대민 상담, ⑤b 데이터 에이전트, ⑦ 대조·점검, ⑨ 인수인계(원문 위치).

맞서는 힘(긴장)

  • 출처 상세도 vs 화면 복잡도
  • 출처 표시 vs 실제 검증(표시만 하고 검증하지 않으면 잘못된 신뢰)
  • 원문 링크의 신선도 vs 유지 비용

해법

답변의 각 주장에 근거 문서·조문 번호·통계표 ID·원문 위치를 붙이고, 원문으로 바로 이동하는 링크를 제공한다. 출처의 갱신 시각과 이용 조건을 함께 보여 오래된 자료를 현재로 오인하지 않게 한다. 표시되는 출처는 C5 출처 검증을 통과한 것이어야 한다.

이럴 때 쓴다

  • B3 지식 접지 응답 전반
  • 대민 서비스 D1~D7(F1·F2·F7이 최소 요건)
  • 유형 ①⑤b⑦⑨처럼 F1이 필수인 유형

이럴 때는 쓰지 않는다

  • 모델의 판정 근거(요인·BBox·사유 코드)를 보여 주려는 경우(F9)
  • B0 결정적 도구로 원천 데이터를 그대로 보여 주는 경우(출처가 곧 화면)

얻는 것

  • 이용자 신뢰 확보
  • 원문 대조로 오류 발견
  • 공식 판단 여부를 이용자가 스스로 확인

점검표

  • 모든 답변에 출처가 붙는가
  • 출처가 원본과 대조되는가
  • 갱신 시각이 보이는가
  • 이용자가 원문을 바로 열 수 있는가

구조 — 참여 부품

  • C5 가드레일 필터 — 출처 검증
  • 이용자 — 원문을 열어 대조

변형

  • 문서·조문 인용: 근거 문서명과 조문 번호를 답변에 붙임
  • 통계표 ID 인용: 통계 답변에 통계표 ID를 자동 인용(KOSIS MCP 방식)
  • 출처·신선도 표시: 출처에 갱신 시각과 이용 조건을 함께 표시

참조 구현 예

  • PAX Korean Stats MCP — KOSIS 통계를 자연어로, 출처 자동 인용
  • PAX 224e2d82d9369735 — 모든 출처에 갱신 시각과 이용 조건을 함께 저장한 출처·신선도 표시
  • PAX 9998aba2d1f55c24 — 항목별 법령·처분사례 원문 연계(F1)

D1 안내·탐색 서비스 블록

국민이 어떤 서비스를 받을 수 있고 어디로 가야 하는지 알려 주는 대민 접점 블록이다. B3 지식 접지나 B0 탐색기가 이 자리에 들어간다.

PAX 사례 99건이 이 부품을 쓴다

맥락

국민·기업이 직접 쓰는 대민 접점. §7.3 유형 ① 대민 상담·안내(D1·D7, P0~P1)의 입구다. 규칙 기반 공공데이터 조회로 안내하는 비LLM 도구도 이 블록에 속한다(R21).

맞서는 힘(긴장)

  • 안내 범위의 폭 vs 답의 정확성
  • 자유 질의의 편의 vs 규정 밖 답을 끌어내려는 입력(S4가 막는 위협)
  • 상시 운영 요구 vs 상용 API 장애(C7)
  • 쉬운 말 vs 법령·공고 원문 충실성

해법

블록은 렌즈이고, 해법은 이 자리에 끼우는 부품 조합이다. 주 부품은 공개(O) 문서에 접지한 B3 대민 자동응답형이나 조건으로 대상 서비스를 좁히는 B0 탐색기다. 답은 F1 출처와 F7 "공식 판단 아님" 고지와 함께 내고, 입력은 F4 구조화 입력으로 받아 조건 누락을 줄인다. 민원인 입력은 신뢰 불가 입력이므로 S4 행동 선택기와 S7 컨텍스트 최소화로 규정 밖 답을 막고, 상시 서비스이므로 C7 폴백을 둔다. 판단이 필요한 질문은 B′2 라우터로 D4 분류·이관이나 담당자에게 넘기고 F11로 이관을 알린다.

이럴 때 쓴다

  • 국민이 받을 수 있는 서비스나 담당 창구를 몰라 헤매는 문제가 있을 때
  • 같은 안내 질문이 반복되고 답이 공개 규정·공고에 있을 때
  • 뒤따르는 신청(D2)의 입구를 정리해 잘못된 접수를 줄이고 싶을 때

이럴 때는 쓰지 않는다

  • 개인별 요건 충족 판정이 필요하면 D3 자격·심사
  • 개인 상황에 맞춘 정보·처방·법령 해석을 주면 D7 상담·처방
  • 이용자가 기관 내부 담당자면 D8.1 탐색·조회

얻는 것

  • 창구를 찾아 헤매는 시간 감소
  • 반복 안내 업무 경감
  • 후속 신청(D2)의 입구 정리

점검표

  • 안내마다 근거 출처가 보이는가
  • "공식 판단 아님" 고지가 화면에 있는가
  • 규정 밖 질문을 사람에게 넘기는 경로가 있는가
  • 평가 세트로 안내 정확도를 재는가
  • 모델 장애 시에도 안내가 멈추지 않는가

구조 — 참여 부품

  • 국민·기업 — 자기 상황을 말하고 받을 서비스와 창구를 찾는 주체
  • B3 지식 접지 상담 — 공개 문서에 접지해 안내 답변을 생성
  • B0 결정적 도구(탐색기) — 조건 선택으로 해당 서비스 목록을 좁힘
  • F1 출처 표시 — 안내의 근거 문서·데이터를 보여 줌
  • F7 한계·신뢰도 안내 — 공식 판단이 아님과 안내 범위를 고지
  • 담당자 — 라우터가 넘긴 판단 필요 질문을 처리

변형

  • 조건 탐색형: B0 탐색기. 나이·가구·지역 같은 조건을 넣으면 받을 수 있는 서비스 목록을 준다(생애주기 혜택 내비게이터).
  • 접지 질의응답형: B3 대민 자동응답형. 자유 질의에 공개 규정·공고로 답하고 예외만 이관한다.
  • 비LLM 공공데이터 안내형: 모델 없이 A1 결정론 조회로 안내한다. 유형 1의 A2 요건을 A1로 대체한다(R21).

참조 구현 예

  • 생애주기 혜택 내비게이터 — 카탈로그 D1 카드의 B3·B0 탐색기 예

X6 데모웨어 안티패턴

시연은 있으나 실데이터·권한·망 환경이 없어 현장에 놓을 수 없는 PoC. 접점과 환경 조건을 먼저 못 박는 단계를 건너뛴 결과다.

맥락

운영(시범 운영 포함) 기간이 짧은 기관 시범 과제, 특히 행정망·폐쇄망에서 운영해야 하는데 인터넷 클라우드에서 개발·시연한 과제, 샘플·목업 데이터로만 시범 운영한 과제.

맞서는 힘(긴장)

  • 시연 일정 vs 실데이터·보안검토 소요 시간
  • 개발 편의(인터넷 클라우드) vs 운영 망 조건(행정망·폐쇄망)
  • 화려한 시연 vs 권한 범위에 맞춘 통제 부품

해법

§7.1 첫 단계대로 서비스 블록(D)과 환경 조건 E1~E5(배포망·모델 의존·실행 형태·권한 범위·데이터 등급)를 먼저 기록하고, 그 조건에서 돌아가는 부품으로 조립한다. 원천 기록을 정제한 A1 데이터 자산으로 실데이터 기준선을 만들고, 타 기관 데이터가 필요하면 A4 데이터 연계 서비스로 계약·연계를 확보한다. 운영 망이 폐쇄망·행정망이면 A2.2 주권형 로컬이나 A2.4 내부망 프록시로 모델 경로를 맞추고, E4 권한에 맞춰 C1~C8 통제 부품을 장착한다. 실증 데이터가 실사용인지 샘플인지를 명시한다(R28 data_realism 제안).

이럴 때 쓴다

  • E1~E5가 '미확인'이거나 보고서에 기재되지 않았다
  • 실증 데이터가 샘플·목업·시뮬레이션이고 실사용 데이터 계획이 없다
  • 운영 망과 시연 망이 다르고 반입 계획이 없다
  • 시연 영상·화면은 있으나 현장 사용자·사용 건수가 없다

이럴 때는 쓰지 않는다

  • 실데이터·운영 망에서 시범운영했지만 규모가 작은 경우
  • 샘플 데이터로 시작했으나 E 조건을 기록하고 실데이터 전환 경로가 구현된 경우
  • 개인정보 때문에 합성 데이터를 쓰되 운영 환경과 권한은 실제와 같은 경우

얻는 것

  • 보안검토·데이터 승인 없이 빠르게 시연한다
  • 개발 환경이 편하다

점검표

  • E1~E5가 모두 기재되어 있는가
  • 실증 데이터가 실사용 데이터인가, 아니면 그 사실이 명시되어 있는가
  • 운영 망에서 한 번이라도 돌아갔는가
  • E4 권한에 맞는 통제 부품이 장착되어 있는가

구조 — 참여 부품

  • A1 데이터 자산 서비스 — 실데이터 정제·기준선 확보
  • A4 데이터 연계 서비스 — 타 기관 데이터의 계약·연계
  • E 환경 조건 기록 — 배포망·모델 의존·실행 형태·권한·등급을 먼저 못 박음
  • A2.4 내부망 프록시 — 행정망에서 상용 모델을 쓰는 경로

변형

  • 샘플 데이터형: 목업·공개 샘플·시뮬레이션 데이터로만 시범 운영
  • 망 불일치형: 운영은 행정망·폐쇄망인데 개발·시연은 인터넷 클라우드
  • 권한 부재형: 운영 시스템 쓰기·연계 권한 없이 화면만 시연

관련 부품

A2 모델 서빙 계층 공통 서비스

업무 부품이 모델을 직접 부르지 않고 서빙 계층을 거쳐 부르게 해 모델을 바꿔 끼우고 라우팅·캐싱·버전 고정·폴백을 한 자리에서 다룬다. A2.0~A2.6을 묶는 부모 항목이다.

맥락

런타임에 모델(LLM·VLM·비전·ML)을 부르는 모든 B 부품. E2 모델 의존 값이 곧 어떤 하위 변형을 쓸지를 정하고, E1 배포망과 E5 데이터 등급이 허용 범위를 좁힌다. B0 결정적 도구처럼 런타임 AI가 없으면 해당하지 않는다.

맞서는 힘(긴장)

  • 모델 교체 가능성 vs 추상화 계층을 운영하는 비용
  • 모델 성능 vs 데이터 주권(E1·E5)
  • 비용 통제(라우팅·캐싱·배칭) vs 지연
  • 벤더 고유 기능 활용 vs 종속

해법

업무 부품과 모델 사이에 서빙 계층을 두고 모든 호출을 이 층으로 보낸다. 계층은 모델 버전을 고정하고 사용량·지연 로그를 C4로 넘기며, 대체 모델을 함께 등록해 C7이 전환할 자리를 만든다. 지능형 모델 라우팅(경량 모델이 복잡도를 보고 큰 모델로 넘김)·프롬프트 캐싱·동적 배칭은 모두 이 계층이 있어야 가능한 비용 통제다. 하위 변형은 모델이 어디서 도는가로 고른다: 기관 밖 상용 API면 A2.1(행정망·민감 등급이면 A2.4), 오픈웨이트를 기관 안에서 돌리면 A2.2, 재학습했으면 A2.3, 비LLM 자체 학습이면 A2.5, 장비·솔루션에 내장돼 있으면 A2.6, 알 수 없거나 이용자가 가져오면 A2.0이다.

이럴 때 쓴다

  • 업무 부품이 런타임에 모델을 한 번이라도 부를 때
  • 상용 API에 의존해 C7 폴백을 끼워야 할 때(E2 해외 상용 API)
  • 호출당 비용·지연을 관리해야 할 때(라우팅·캐싱)
  • 모델 업데이트 후 품질 회귀를 막아야 할 때(버전 고정 + C9)

이럴 때는 쓰지 않는다

  • B0 결정적 도구처럼 런타임에 모델을 부르지 않을 때
  • 모델이 아니라 도구·데이터를 감싸는 층이 필요할 때(A8·A3)

얻는 것

  • 모델 교체와 C7 폴백이 가능해짐
  • 라우팅·캐싱으로 비용 통제
  • 버전 고정으로 회귀시험 가능
  • 민감정보 반출 통제 지점 확보

점검표

  • 업무 코드가 특정 모델 API를 직접 호출하지 않는가
  • 모델 버전이 고정·기록되는가
  • 대체 모델 또는 대체 경로가 계층에 등록되어 있는가
  • 선택한 변형이 E1·E5 조건과 모순되지 않는가

구조 — 참여 부품

  • 업무 컴포넌트(B) — 모델을 직접 부르지 않고 서빙 계층의 인터페이스만 호출
  • 라우터·캐시 — 요청 복잡도에 따라 모델을 고르고 반복 요청을 캐싱·배칭
  • 모델 풀(A2.0~A2.6) — 실제로 추론하는 모델들. 주 경로와 대체 경로를 함께 등록
  • C4 감사 로그·지표 — 호출별 사용량·지연·모델 버전 기록처
  • C7 폴백 스위치 — 장애·품질 저하 시 모델 풀 안에서 경로 전환

변형

  • 모델 미상: LLM 사용은 확인되지만 모델명이 없거나 이용자 구독 모델(BYO)에 얹혀 있다. v0.7에서 추가했다.
  • 상용 API 호출: GPT·Gemini·Claude·HyperCLOVA X·Upstage 등 상용 모델 API를 부른다.
  • 주권형 온프레미스: 오픈웨이트 모델을 자체 서버·폐쇄망·로컬 PC에서 돌린다(Ollama·vLLM).
  • 튜닝형: 파인튜닝·LoRA·재학습으로 만든 자체 모델이다. 진행 경로의 마지막 단계에 놓인다.
  • 내부망 프록시: 행정망·내부망에서 상용 모델을 기관 게이트웨이·사설 엔드포인트·범정부 공통기반을 거쳐 부른다.
  • 비LLM 학습 모델: XGBoost·LightGBM·YOLO·U-Net 등 기관이 직접 학습한 모델을 서빙한다.
  • 벤더 블랙박스: 장비·상용 제품에 내장돼 있어 기관이 모델을 보지도 바꾸지도 못한다.

C5 가드레일 필터 운영 컴포넌트

개인정보·환각·편향·형식 오류가 프롬프트나 산출물에 들어가지 못하게 시스템이 경계에서 걸러낸다. 비식별 전처리, 출처 검증, 구조적 출력 제약이 대표 변형이다.

PAX 사례 44건이 이 부품을 쓴다

맥락

외부 모델을 부르거나 대민에 답하는 모든 B 부품. 특히 E2 해외 상용 API, E5 S 이상 데이터, B3 지식 접지 상담, 유형 ① 대민 상담, ④ 기안, ⑥ 콘텐츠, ⑦ 대조·점검, ⑨ 인수인계, ⑬ 비식별·정제 도구.

맞서는 힘(긴장)

  • 차단의 엄격함 vs 과잉 차단으로 인한 유용성 저하
  • 비식별 강도 vs 문맥 보존
  • 결정적 검증의 신뢰성 vs 구현 범위

해법

프롬프트가 기관 밖으로 나가기 전 PII를 마스킹하고 원복 키를 보관하는 비식별 전처리기를 둔다. 응답에는 인용을 원본(법령정보센터·통계표 등)과 대조하는 출처 검증기와, JSON 스키마·허용 목록 같은 구조적 출력 제약을 건다. 근거가 없으면 답하지 않거나 '확인 필요'로 표시한다. 차단 사유는 C4에 남기고, 이용자에게는 F1 출처와 F7 한계 안내로 보인다. 사람이 하는 팩트체크·법무 심의는 C5가 아니라 C1.2에 둔다.

이럴 때 쓴다

  • E2 해외 상용 API로 행정망 본문이 외부로 나갈 때(필수)
  • E5 S 이상 개인정보·민감정보를 다룰 때
  • B3 대민 응답처럼 인용·수치의 정확성이 신뢰의 핵심일 때
  • C5가 필수인 유형 ①④⑥⑦⑨⑪⑬

이럴 때는 쓰지 않는다

  • E1 로컬 PC 완결로 데이터가 밖으로 나가지 않을 때 비식별은 불필요해질 수 있다(§5 매트릭스, 단 출처 검증은 별개)
  • 사람이 수행하는 심의만 있을 때(C1.2로 태그)
  • 적대적 입력 탐지가 목적일 때(S8)

얻는 것

  • 개인정보 외부 유출 차단
  • 환각 인용 감소
  • 상용 API 사용 조건 충족

점검표

  • 외부 전송 전 무엇이 걸러지는지 답할 수 있는가
  • 인용이 원본과 대조되는가
  • 근거 없을 때의 동작이 정해져 있는가
  • 차단 사유가 기록되는가

구조 — 참여 부품

  • 비식별 전처리기 — 외부 전송 전 PII 마스킹과 원복
  • 출처 검증기 — 인용을 원본과 대조해 환각을 걸러냄
  • 출력 제약 — 스키마·허용 목록·금칙어로 출력 형식 제한

C9 평가 세트·회귀시험 운영 컴포넌트

배포 전에 업무 맥락의 질문·정답·채점 기준을 세트로 만들어, 프롬프트·모델·설정의 모든 변경을 같은 자로 재고 회귀를 잡는다.

PAX 사례 15건이 이 부품을 쓴다

맥락

모델·프롬프트·검색 설정이 바뀌는 모든 AI 부품. 특히 B3 지식 접지(검색 품질은 평가 없이 개선 불가), E2 상용 API(예고 없는 모델 업데이트), 유형 ①④⑤a⑦⑩⑫.

맞서는 힘(긴장)

  • 평가 세트 구축 비용 vs 변경의 안전
  • 사람 라벨의 정확성 vs LLM 심판의 규모
  • 세트 고정(비교 가능성) vs 업무 변화 반영(세트 갱신)

해법

RAG를 붙이거나 모델을 고르기 전에 업무 질문·정답·채점 기준(사람 라벨 + LLM 심판)을 세트로 만든다. 프롬프트·모델·설정 조합을 릴리스처럼 버전 관리하고, 모든 변경마다 같은 세트로 재평가해 점수표와 회귀 실패 목록을 남긴다. 기준을 넘지 못하면 배포하지 않는 게이트를 둔다. 학습 데이터와 평가 세트는 누수 없이 분리한다.

이럴 때 쓴다

  • RAG·튜닝을 붙이기 전(§7.1 4단계, §7.2 진행 경로 2단계)
  • E2 상용 API로 모델 업데이트가 예고 없이 올 때(필수)
  • 폐쇄망 로컬 모델의 교체 시점
  • C6 환류·C7 모델 교체를 하려 할 때(선행 조건)

이럴 때는 쓰지 않는다

  • B0 결정적 도구처럼 비결정적 출력이 없을 때
  • 유형 5a 중 순수 시각화(R10: 면제)

얻는 것

  • 변경의 효과와 회귀를 숫자로 확인
  • 모델 교체·재학습의 안전
  • 모델 선정 근거 확보

점검표

  • 업무 질문·정답·채점 기준 세트가 있는가
  • 프롬프트·모델·설정이 버전 관리되는가
  • 변경마다 재평가한 기록이 있는가
  • 기준 미달 시 배포를 막는 절차가 있는가

구조 — 참여 부품

  • A1 데이터 자산 서비스 — 정답의 출처
  • A2 모델 서빙 계층 — 평가 대상 모델의 버전 고정
  • 채점기 — 사람 라벨과 LLM 심판으로 점수 산출

  • C4 감사 로그·지표 — 운영 지표와 평가 점수 대조

변형

X9 담당자와 함께 사라지는 도구 안티패턴

개인이 만든 도구가 부서에 퍼졌지만 라이선스·저장소·인수인계가 없어, 만든 사람의 인사이동과 함께 멈추는 함정이다.

맥락

A7 자체 제작 환경으로 태깅된 도구(PAX 557건 중 317건, 57%), 특히 개인 사용에서 부서 공유로 막 퍼지기 시작한 바이브코딩 도구.

맞서는 힘(긴장)

  • 개인의 빠른 제작 vs 조직의 유지보수 책임
  • 비공식 공유의 편의 vs 라이선스·저장소 절차
  • 현장 맞춤 vs 다른 담당자가 이해할 수 있는 구조

해법

도구가 부서에 퍼지기 시작하면 A7 산출물에 MIT·Apache 등 라이선스를 명시하고, 코드를 개인 PC가 아니라 A3 공공 깃랩 같은 공용 저장소에 등재한다. 업무 규범·프롬프트는 A9 업무 규범 스킬로 패키징해 다른 담당자가 그대로 쓸 수 있게 하고, 설치·설정·데이터 경로를 담은 인수인계 문서를 둔다. 도구를 참조 구현 레지스트리(§13)에 올려 소유를 개인에서 조직으로 옮긴다. transition.blocker에 '담당자 이동'이 적힌 과제는 이 조치를 먼저 한다.

이럴 때 쓴다

  • 개인이 만든 도구를 부서원 여러 명이 쓰는데 라이선스 표기가 없다
  • 원본 코드가 개인 PC·개인 계정에만 있다
  • 인수인계 문서·설치 절차가 없다
  • transition.blocker가 '담당자 이동'이다

이럴 때는 쓰지 않는다

  • 개인만 쓰는 도구로 부서에 퍼지지 않은 경우(개인 사용 단계는 정상)
  • A7로 만들었지만 라이선스 명시·공용 저장소 등재·인수인계가 갖춰진 경우
  • 기관 정보화 부서가 넘겨받아 운영 중인 경우

얻는 것

  • 현장 담당자가 필요한 도구를 빠르게 만든다
  • 공식 절차 없이 바로 퍼진다

점검표

  • 라이선스가 명시되어 있는가
  • 원본이 공용 저장소에 있는가
  • 만든 사람 없이 후임이 설치·실행할 수 있는 문서가 있는가
  • 개인 구독·개인 키에 의존하지 않는가

구조 — 참여 부품

  • A7 자체 제작 환경 — 도구가 태어난 곳. 라이선스 명시가 전이 조건
  • A3 공공 API 제공자(공공 깃랩) — 개인 저장소를 대체하는 공용 등재처
  • A9 업무 규범 스킬 — 암묵적 업무 규범을 패키지로 남김
  • 후임 담당자 — 인수인계 문서로 도구를 이어받는 사람

변형

  • 라이선스 미명시: 코드는 공개했지만 라이선스가 없어 타 기관이 가져다 쓸 수 없음
  • 개인 저장소형: 개인 PC·개인 계정에만 원본이 있음
  • 개인 구독 의존형: 개인 AI 구독·API 키로 돌아가 담당자가 떠나면 호출이 끊김

맞서는 힘(긴장)

  • 빠른 도입 실적 vs 업무 흐름 재설계 비용
  • 기존 시스템 무변경(안정성) vs 산출물 단위의 역할 분담
  • 'AI 탑재' 홍보 효과 vs 실제 처리시간·수정률 개선

해법

먼저 가치 흐름 규칙(R1)으로 사람 또는 국민이 최종으로 받는 핵심 산출물을 정하고, 그 산출물을 AI가 어떤 모양으로 분담할지 B 업무 컴포넌트를 하나 고른다(초안→사람 확정이면 B1, 근거 접지 답변이면 B3, 서류 추출이면 B4). 사람이 확정하는 지점은 C1 검토 큐로, 이용자가 고쳐 확정하는 면은 F2 편집 가능한 출력으로 명시한다. 흐름이 바뀌었는지는 C4 감사 로그·지표의 처리시간·수정률로 잰다. AI 런타임이 전혀 없는 행정정보시스템이라면 AI로 포장하지 말고 R24대로 B0·service_type 0·platform 공란·X1(AI 무관)으로 정직하게 분류한다.

이럴 때 쓴다

  • AI 기능이 추가됐다는 서술은 있으나 처리 단계 수·결재선·담당자 역할이 바뀌었다는 서술이 없다
  • 성과 지표가 AI 호출 수·이용 만족도뿐이고 처리시간·수정률 같은 산출물 지표가 없다
  • 챗봇이 기관 업무 데이터·시스템과 연결되지 않은 범용 대화에 머문다
  • AI 런타임이 전혀 없는 행정정보시스템이 AX 과제로 분류되어 있다(R24)

이럴 때는 쓰지 않는다

  • B1 코파일럿처럼 AI가 초안을 만들고 사람이 확정하는 역할 분담이 실제로 서술된 경우
  • B8 레거시 오버레이처럼 표준 시스템 위에 얹었지만 업무 산출물을 AI가 만들어 내는 경우
  • B0 결정적 도구가 반복 취합 업무를 실제로 줄이고 AI로 포장하지 않은 경우(Ready 부품으로 정직하게 분류된 경우)

얻는 것

  • 기존 시스템을 건드리지 않아 도입이 빠르고 장애 위험이 낮다
  • 'AI 탑재' 실적을 즉시 보고할 수 있다

점검표

  • AI 도입 전후 처리 단계·담당자 역할의 차이를 한 장으로 보여 줄 수 있는가
  • AI가 만드는 산출물과 사람이 확정하는 지점이 명시되어 있는가
  • 처리시간·수정률 같은 산출물 지표가 도입 전 기준선과 함께 있는가
  • AI 런타임이 없는데 AI 과제로 보고하고 있지 않은가

구조 — 참여 부품

  • 덧붙인 AI 기능 — 요약·대화 버튼. 업무 산출물 생산에 역할이 없음
  • B1 코파일럿 — 교정 후 초안→사람 확정으로 산출물 역할을 나누는 대체 부품
  • C1 검토 큐 — 교정 후 사람이 확정하는 지점을 명시
  • C4 감사 로그·지표 — 흐름이 실제로 바뀌었는지 처리시간·수정률로 측정

변형

  • 요약 버튼형: 기존 화면에 '요약' 버튼만 추가하고 결재·처리 단계는 그대로
  • 범용 챗봇 부착형: 업무 데이터와 연결되지 않은 범용 대화창을 포털에 부착
  • AI 무관 행정시스템(R24): AI 런타임이 전혀 없는 순수 행정정보시스템(예: 교육·인증 학습관리시스템). B0·service_type 0·platform 공란과 함께 X1(AI 무관)로 표기

관련 부품

B1 대체 — 초안→사람 확정으로 산출물 역할을 나누는 교정 목표 · C1 교정에 끼울 자리 — 사람이 확정하는 지점 · B0 정직한 분류 — AI 런타임이 없으면 B0 Ready 부품으로(R24) · C4 기록처 — 흐름 변화의 증거(처리시간·수정률) · X8 이웃 안티패턴 — 개수·탑재를 성과로 세는 같은 뿌리
