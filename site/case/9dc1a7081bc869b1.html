판정 근거

광진구가 소속 공무원이 직접 개발한 AI 도구 6종(코닥·법령·통계·건축·표준주소실록·애니씽)을 전 직원 업무에 투입했다. 법령·통계·건축 도구는 기관 자체 AI 서비스 '광진GPT'(A2.4 내부망 프록시)와 연동해 원문과 출처를 함께 제시하는 지식접지 상담(B3)이 대표 PoC이고, 문서 요약·재작성(코닥, B1)과 주소 정리·문서 검색(B0)은 secondary다. 개인정보 입력 금지, 원문·출처 확인 의무, 담당자·팀장의 최종 판단 책임, 전용 문의 창구라는 4대 관리 원칙이 명문화돼 C1(검토 큐) present, 개인정보 입력 금지 정책은 C5 implemented로 본다. 행안부 지방정부 AI 우수사례 발표대회에 서울시 대표로 선정돼 기관 공식으로 판정한다.

구현 가이드

주 패턴 B3 지식 접지 상담을 구현할 때

구현 단계

  1. 대표 질문·정답·채점 기준으로 C9 평가 세트를 먼저 만든다.
  2. A1로 코퍼스를 정리하고 데이터 등급(E5)과 공개 범위를 메타로 붙인다. 등급 문서가 섞이면 S2 권한 인식 검색을 둔다.
  3. E1에 맞게 임베딩·벡터DB·모델 위치를 정한다(폐쇄망이면 전부 로컬, A2.2·A2.4).
  4. 근거 밖 답변 금지·출처 상시 표시·근거 없으면 이관하는 규칙을 C5·F1·B′2로 구현한다.
  5. 검색 품질 3패턴을 하나씩 붙이며 C9로 재고, 문서 갱신 주기를 C6으로 운영한다.

점검표

  • 답마다 출처가 표시되는가
  • 근거가 없을 때 답하지 않고 이관하는가
  • 평가 세트로 검색·답변 품질을 재고 있는가
  • 코퍼스 갱신 주기와 책임자가 정해져 있는가

환경 조건

E1 폐쇄망·행정망이면 임베딩·벡터DB·모델 전부 로컬(A2.2 주권형 또는 A2.4 내부망 프록시 + 로컬 임베딩). E2 해외 상용 API면 C5 비식별 전처리와 C7 폴백이 필수다. E4는 P0~P1이 기본이다. 신뢰 불가 입력(민원 입력·공개 웹)을 읽고 P2 이상이면 S6 문서별 격리와 S2가 필요하다. 대민형은 S4·S7이 권장된다(§7.4).

주의할 점

  • 평가 없이 붙이면 품질을 알 수 없음(X10)
  • 코퍼스 갱신이 멈추면 오답이 됨
  • 부서마다 따로 만들면 중복(X3)
  • 대민형은 인젝션·유출 위협에 노출

  • X3 부서마다 챗봇 같은 기관의 과제들이 각자 모델·벡터DB·프롬프트를 따로 만들어, 공유할 수 있는 기반 부품을 부서 수만큼 중복 구축하는 함정이다. 대처: §7.1의 두 번째 단계대로 기반 부품은 새로 만들지 말고 Provider에서 먼저 가져온다. 모델 호출은 A2 모델 서빙 계층(범정부 AI 공통기반 또는 기관 게이트웨이) 뒤로 모으고, S1 단일 진입점에서 인증·요청 상한·비용 상한·감사 기록을 일괄 적용한다. 공공 API·공공 클라우드·공공 깃랩은 A3 공공 API 제공자로 쓴다. 부서별 차이는 모델을 따로 두지 말고 A9 업무 규범 스킬과 부서 코퍼스(A1)로 표현하며, 부서·등급별 코퍼스 분리가 필요하면 S2 권한 인식 검색으로 푼다. 없어서 새로 만든 부품은 §13 참조 구현 레지스트리에 올린다.

B1 코파일럿 업무 컴포넌트

사람이 하던 문서·판단 작업 옆에 AI가 초안·요약·검토안을 놓고, 사람이 고쳐서 확정한다.

PAX 사례 111건이 이 부품을 쓴다

맥락

문서·기안·검토의견처럼 산출물 형식이 정해져 있고 최종 확정자가 사람인 업무에 쓴다. BYO 코딩 에이전트와 A9 스킬을 쓰는 스킬 코파일럿이 PAX 자생 도구에 많다.

맞서는 힘(긴장)

  • 초안 속도 vs 전건 검토에 드는 사람 시간
  • 상용 모델 품질 vs 행정망·민감정보 제약(E1·E5)
  • 양식 일관성(A9 규범) vs 사안별 유연성

해법

업무 서식과 참고 자료를 입력으로 받아 모델(A2 또는 BYO 구독)이 초안·근거·신뢰도를 내고, 사람이 편집 가능한 형태(F2)로 받아 고쳐서 확정한다. 보고서 구조·문체·검증 절차는 A9 규범 스킬로 코드 밖에 두고, 공공 문서 형식은 A10 어댑터로 입출력한다. 확정 전 검토는 C1 검토 큐로 운영하고 수정 내역을 C4·C6의 입력으로 남긴다. First로 가려면 저위험 건을 C2로 자동 확정하는 분기를 더한다.

이럴 때 쓴다

  • 산출물 형식이 정해진 문서를 반복 작성할 때
  • 최종 판단과 책임이 사람에게 남아야 할 때(P1 산출물 생성)
  • 유형 ④ 내부 문서·기안, 유형 ⑫ 개발 코파일럿의 기본 조립일 때

이럴 때는 쓰지 않는다

  • 답이 기관 규정·선례 속에 있어 접지와 출처가 핵심일 때(B3)
  • 추출 결과가 사람 확정 없이 다음 판정 단계로 흐를 때(B4)
  • 런타임에 모델이 필요 없는 정형 취합일 때(B0)

얻는 것

  • 문서 작성 시간 단축
  • 책임 소재가 사람에게 명확히 남음
  • 도입이 쉬워 Enabled의 전형 경로

점검표

  • 담당자가 최종 확정한다는 절차가 운영되는가
  • 서식·문체 규범이 A9 스킬로 분리되어 있는가
  • 초안을 이용자가 직접 고칠 수 있는가(F2)
  • 수정 내역이 기록되어 품질 개선에 쓰이는가

구조 — 참여 부품

  • A2 모델 서빙 계층 — 초안 생성 모델 호출(행정망이면 내부망 프록시)
  • A9 업무 규범 스킬 — 서식·문체·검증 절차를 프롬프트 템플릿으로 고정
  • A10 문서 형식 어댑터 — HWPX·엑셀 입출력
  • C1 검토 큐 — 담당자가 초안을 확인·수정·확정
  • 담당자 — 최종 확정자이자 책임자

변형

  • 시스템 내장형: 기관 업무 시스템 안에 초안 기능을 넣은 형태

B0 결정적 도구 업무 컴포넌트

AI 코딩으로 만들었지만 런타임에는 AI를 부르지 않고 규칙과 원문 발췌만으로 같은 입력에 같은 결과를 내는 취합·변환·검색·시각화 도구다.

PAX 사례 413건이 이 부품을 쓴다

맥락

AI 코딩 도구(A7)로 기관 인력이 직접 만든 자생 도구가 대부분이다(PAX 557건 가운데 주 부품이 B0인 사례 390건, 70%). 로컬 PC 완결이나 폐쇄망 이식이 필요한 업무, 판정 재현성이 감사에서 중요한 업무에도 맞는다. model_dependency가 '없음(비LLM)'으로 확인될 때만 해당한다.

맞서는 힘(긴장)

  • 재현성·설명 가능성 vs 비정형 입력을 다루는 유연성
  • 로컬 완결의 보안 이점 vs 기관 전이 시 처리 로그(C4)와 인수인계가 사라지는 문제
  • 규칙을 코드에 넣는 단순함 vs 규정이 바뀔 때마다 사람이 규칙을 고쳐야 하는 유지 부담

해법

업무 절차를 입력 형식(A10 어댑터)과 처리 규칙으로 나누고, AI 코딩 도구(A7)는 개발 시점에만 써서 규칙 코드와 화면을 만든다. 런타임에는 모델을 호출하지 않으므로 같은 입력에 같은 결과가 나오고 인터넷 없이 로컬에서 돈다. 판정이 필요한 경우에도 결정적 규칙 엔진이 낸다. 비정형 입력을 다뤄야 하는 단계가 생기면 그 단계만 B1·B3로 승격하고 결정적 부분은 전처리로 남긴다. 부서 밖으로 옮길 때는 라이선스·저장소·처리 로그를 함께 갖춘다.

이럴 때 쓴다

  • 입력이 정형(엑셀·서식)이고 처리 결과를 규칙으로 정의할 수 있을 때
  • 파일이 PC 밖으로 나가면 안 되거나 폐쇄망·로컬 완결이 필요할 때
  • 판정 재현성이 필요해 같은 입력에 늘 같은 결과가 나와야 할 때(규칙 점검기, 결정론 점수 엔진)
  • LLM 도입 전에 데이터·기준선을 정비하는 단계일 때

이럴 때는 쓰지 않는다

  • 비정형 문서의 요약·초안처럼 규칙으로 산출물을 정의할 수 없을 때(B1)
  • 질문이 다양해 규정·선례 접지가 필요한 상담일 때(B3)
  • 학습 모델의 수치·등급 예측이 핵심 산출물일 때(B2)

얻는 것

  • 재현성과 감사 가능성
  • 폐쇄망·로컬 이식이 가장 쉬움
  • 모델 호출 비용과 모델 장애 위험이 없음
  • B1·B3의 전처리 부품으로 승격할 자산

점검표

  • 런타임에 LLM·ML 호출이 전혀 없는가
  • 규칙 표가 코드와 별도로 문서화되어 있는가
  • 같은 입력에 같은 결과가 나오는지 확인했는가
  • 라이선스와 저장소 위치가 명시되어 인수인계가 가능한가

구조 — 참여 부품

  • A7 자체 제작 환경 — 개발 시점에 AI 코딩으로 규칙 코드와 화면을 만드는 곳
  • A10 문서 형식 어댑터 — HWP·HWPX·엑셀 입출력
  • 규칙 엔진 — 조건→결과 표에 따라 결정적으로 취합·판정·정렬
  • 담당자 — 결과를 받아 쓰고 규칙 변경을 요청

변형

  • 문서·엑셀 자동화: 부서별 제출 파일 취합·병합·서식 변환(카드 기본 변형)
  • 데이터 탐색·시각화: 공공데이터·내부 데이터를 지도·차트·대시보드로 보여 준다(카드 기본 변형)
  • 전문 검색: 키워드·색인 기반 원문 검색(카드 기본 변형)
  • MCP 도구 제공: MCP 서버만 있는 사례다. 서버 자체는 결정적 도구이고 AI는 호스트 쪽에 있다(§10.3, A8 동시 태깅)
  • 도구 허브·링크 큐레이션: 흩어진 업무 도구·링크를 한 화면에 모은다(R15)
  • 데스크톱 유틸리티·RPA·매크로: PC 반복 조작 자동화(R15)
  • 규칙 편성·최적화: TSP·스케줄링 등 비학습 알고리즘으로 배정·동선을 편성한다(R15)
  • 알림·컨텍스트 복귀 도구: 마감·할 일 알림, 작업 맥락 복귀(R15)
  • 실시간 현황판: 다중 역할별 화면 분리 현황판(R15)
  • 업무 절차·법적 근거 흐름도 정리: 절차와 근거 조문을 흐름도로 정리(R15)
  • 결정적 재식별·엔티티 매칭: 규칙 기반 동일 개체 판별·병합(R15)
  • 결정론 점수 엔진: 규칙 점수화로 순위·등급을 낸다. 유형 5a·11에서 A2.5의 대안으로 인정된다(R10, §7.3 ⑪)
  • AI 무관 행정정보시스템(취급 기준): AI 런타임이 전혀 없는 순수 행정시스템도 B0으로 태깅하고 X1을 명시하며, 통계에서는 각주로 처리한다(R24)

B3 지식 접지 상담 업무 컴포넌트

기관 규정·매뉴얼·사례 문서에 접지(RAG)해 질문에 답하고, 답마다 출처를 붙이며, 근거가 없으면 답하지 않고 담당자에게 넘긴다.

PAX 사례 48건이 이 부품을 쓴다

맥락

규정·매뉴얼·FAQ·사례가 문서로 쌓인 기관에서 내부 검색·검수, 대민 자동응답, 폐쇄망 로컬 검색에 쓴다. PAX 557건에서 주 부품이 B3인 사례는 31건으로 B0·B1 다음이다. 유형 ① 대민 상담·안내의 기본 조립이기도 하다.

맞서는 힘(긴장)

  • 답변 범위 vs 환각 위험(근거 밖 답변 금지)
  • 대민 자동응답의 효율 vs 예외 건 이관 필요
  • 검색 품질 개선 vs 평가 세트 없이는 개선을 잴 수 없음
  • 폐쇄망 요구 vs 로컬 임베딩·모델 품질

해법

기관 문서를 A1 자산으로 정리해 임베딩·색인하고, 질문이 오면 검색한 근거 범위 안에서만 모델이 답하게 한다. 답에는 출처(F1)를 상시 붙이고, 근거가 없으면 '확인 불가'로 답하거나 담당자·소관기관으로 이관한다(B′2). 검색 품질은 Hybrid Retriever·Query Rewriting·Reranker로 높이되, 변경마다 C9 평가 세트로 잰다. 대민형은 한계 안내(F7)와 폴백(C7)을 두고, 문서 갱신 주기를 C6으로 정한다.

이럴 때 쓴다

  • 같은 질문이 반복되고 답의 근거가 기관 문서에 있을 때
  • 답변에 조문·문서 출처를 반드시 붙여야 할 때
  • 유형 ① 대민 상담·안내, 유형 ⑦ 법령 접지 점검

이럴 때는 쓰지 않는다

  • 평가 세트가 없어 검색 품질을 잴 수 없을 때(먼저 C9, X10)
  • 질문 유형이 몇 개로 정해져 행동 선택기(S4)나 규칙 조회로 충분할 때
  • 문서를 요약해 초안을 쓰는 것이 핵심이면(B1)

얻는 것

  • 답변에 근거를 댈 수 있음
  • 반복 질의 처리 시간 단축
  • 범정부 엔진 + 기관별 코퍼스로 공유 가능

점검표

  • 답마다 출처가 표시되는가
  • 근거가 없을 때 답하지 않고 이관하는가
  • 평가 세트로 검색·답변 품질을 재고 있는가
  • 코퍼스 갱신 주기와 책임자가 정해져 있는가

구조 — 참여 부품

  • A1 데이터 자산 서비스 — 코퍼스 정제·등급 메타
  • A2 모델 서빙 계층 — 임베딩·생성 모델(폐쇄망이면 로컬)
  • 검색기 — 벡터·키워드 검색, 재작성·재순위
  • C5 가드레일 필터 — 출처 검증·근거 밖 답변 차단
  • F1 출처 표시 — 근거 문서·조문을 답에 표시
  • 담당자 — 내부형 검수, 대민형 예외 건 처리

변형

  • 내부 검수형: 직원이 쓰고 답을 검수(Enabled)
  • 대민 자동응답형: 국민에게 직접 답하고 예외만 이관(이관 분기가 있으면 First)
  • 폐쇄망 로컬 RAG: 내부망 LLM + 로컬 임베딩·벡터DB
  • 검색 품질 하위 항목: Hybrid Retriever(벡터+키워드)·Query Rewriting·Reranker. 태깅 시 variant에 기재(Fowler)
  • 그래프 RAG: A6 지식그래프를 검색에 결합(rag_type = Graph)

B′2 라우터·디스패처 제어 흐름

요청의 의도·유형·난이도를 읽어 전문 경로·모델·도구·담당자로 보내는 배선이다. 모든 건을 같은 경로로 보내는 낭비를 막는다.

PAX 사례 23건이 이 부품을 쓴다

맥락

대민 상담(B3)의 예외 이관, 규칙 선필터로 LLM 호출 줄이기, 폐쇄망 모델과 외부 모델 사이의 모델 라우팅, 여러 MCP를 한 서버에서 경로별로 제공하는 구성에 쓴다. C2 위험도 라우터의 내부 원형이고, D4 분류·이관을 기술로 구현한 실체다.

맞서는 힘(긴장)

  • 경로 분리의 효율 vs 라우팅 오류라는 새 위험
  • 규칙 라우팅의 예측 가능성 vs 모델 라우팅의 유연성
  • 외부 모델 분기의 품질 vs 경계 통제(E1·E5)

해법

요청을 분류하는 단계(규칙·경량 모델·LLM)를 앞에 두고, 분류 결과마다 처리 경로(규칙 판정, LLM 판정, 담당자 이관, 판단 불필요)를 정한다. 경로별 처리 비율을 C4로 실측해 라우팅 품질을 보고, 분류가 불확실한 건은 사람에게 보낸다(C2·F11). 모델 라우팅은 A2 서빙 계층의 기능으로 두고 외부 모델로 나가는 분기에는 C5 비식별을 건다. 보안이 필요한 대민 접점에서는 LLM이 미리 정한 행동 중 선택만 하게 제약해 S4로 만든다.

이럴 때 쓴다

  • 요청 유형마다 처리 비용·방법이 뚜렷이 다를 때
  • 답할 수 없는 건을 담당자로 이관해야 할 때(유형 ① 대민 상담)
  • LLM 호출 비용을 줄여야 할 때

이럴 때는 쓰지 않는다

  • 요청 유형이 하나뿐일 때
  • 분류 오류의 비용이 큰데 분류 품질을 잴 방법이 없을 때
  • 라우팅 대신 규칙으로 판정 모델 호출 대상 자체를 좁히는 구조일 때(B′10)

얻는 것

  • 호출 비용 절감
  • 답할 수 없는 건의 이관
  • 경로별 전문화

점검표

  • 경로별 처리 비율을 실측하는가
  • 분류가 불확실할 때 사람에게 가는 경로가 있는가
  • 외부 모델로 나가는 분기에 비식별이 걸려 있는가

구조 — 참여 부품

  • 분류기 — 의도·유형·난이도 판별(규칙 또는 모델)
  • 전문 경로 — 유형별 처리 모델·도구·규칙
  • C2 위험도 라우터 — 위험도·신뢰도 기반 사람 이관
  • C4 감사 로그·지표 — 경로별 처리 비율 실측

변형

  • 의도 라우팅: 질문 의도로 전문 에이전트·도구에 배정
  • 모델 라우팅: 기본은 폐쇄망 사내 모델, 필요할 때만 외부 모델로 분기(InfoQ Intelligent Model Routing)
  • 결정론 우선·LLM 선택 확대: 기본은 결정론 경로, 규칙 결과가 얕을 때만 LLM 경로로 분기
  • 경로 라우팅 통합 서버: 여러 공공데이터 MCP를 한 서버에서 경로별로 제공

  • PAX 9d56d423296a3238 — 5개 공공데이터 MCP를 한 서버에서 경로 라우팅(§13)

A2.4 모델 서빙 · 내부망 프록시 공통 서비스

행정망·내부망에서 상용 모델을 쓰도록 호출을 기관 게이트웨이·사설 엔드포인트·범정부 공통기반으로 중계해 반출과 접근을 통제한다.

PAX 사례 4건이 이 부품을 쓴다

맥락

E1은 행정망·내부망·사내망, E2는 상용 모델, E5는 S 이상이다. §5 매트릭스는 E5가 S 이상인 해외 상용 API 사용, 폐쇄망 B3, 행정망 B1(BYO 코딩 에이전트 불가)에 이 변형을 필수로 둔다.

맞서는 힘(긴장)

  • 상용 모델 성능 vs 망 분리·반출 통제
  • 중계 계층 구축·운영 비용 vs 부서별 직접 호출의 난립(X3)
  • 통제 강화(로깅·차단) vs 지연 증가

해법

업무 부품이 인터넷에 직접 나가지 않고 기관 AI 게이트웨이·클라우드 VPC 사설 엔드포인트·범정부 AI 공통기반을 경유해 상용 모델을 부르게 한다. 중계 계층에서 비식별(C5), 호출 기록(C4), 허용 모델 목록과 불용 모델 자동 제외를 적용한다. 같은 계층에 다중 모델 후보를 두면 C7 전환 자리가 되고, 인증·요청 상한·비용 상한을 걸면 S1 단일 진입점을 겸한다. 범정부 공통기반을 쓰면 A3 Provider 소비로도 기록한다.

이럴 때 쓴다

  • E5가 S 이상인데 상용 모델을 써야 할 때(§5 필수)
  • 행정망 업무 PC에서 AI를 붙여야 할 때
  • 부서별 API 키 직접 호출을 한 진입점으로 모아야 할 때

이럴 때는 쓰지 않는다

  • 인터넷망이고 데이터 등급이 O라 중계가 필요 없을 때(A2.1)
  • 완전 폐쇄망이라 외부 모델에 닿을 경로 자체가 없을 때(A2.2)

얻는 것

  • 행정망에서 상용 모델 성능 사용
  • 반출·접근 통제 지점 일원화
  • 부서별 직접 호출 난립(X3) 방지
  • C7·S1을 같은 자리에 장착 가능

점검표

  • 업무 PC·서버가 상용 API에 직접 나가는 경로가 남아 있지 않은가
  • 중계 전 무엇이 걸러지는지 문서로 답할 수 있는가
  • 중계 호출이 기록되는가
  • 허용 모델 목록과 불용 모델 제외 기준이 있는가

구조 — 참여 부품

  • 내부망 업무 부품 — 인터넷에 직접 나가지 않고 중계 계층만 호출
  • 기관 AI 게이트웨이·사설 엔드포인트 — 호출을 중계하고 허용 모델·반출 정책을 적용
  • C5 가드레일(비식별) — 중계 전 민감정보 제거
  • A3 공공 API 제공자 — 범정부 AI 공통기반을 경유할 때의 Provider
  • C4 감사 로그·지표 — 중계 호출 기록

변형

  • 사내 AI 게이트웨이 경유: 직접 API 호출을 사내 게이트웨이로 돌려 외부 노출을 통제하고 다중 모델 후보를 관리한다.
  • 클라우드 사설 엔드포인트: 상용 LLM을 VPC 안 사설 엔드포인트로만 불러 공용 인터넷을 지나지 않는다.
  • 범정부 공통기반 경유: 행망 자원풀에서 범정부 초거대 AI 공통기반 플랫폼으로 연결하고, 내부망 브라우저 확장이 공통기반을 거친다(PAX 50ab356bb2ee3f4d).

A1 데이터 자산 서비스 공통 서비스

흩어진 업무 기록을 정제·라벨링해 AI 부품이 붙여 쓸 수 있는 데이터셋·라벨·데이터 사전 형태의 기준선으로 제공한다.

PAX 사례 110건이 이 부품을 쓴다

맥락

학습 모델(A2.5·B2), 지식 접지(B3)의 코퍼스, 평가 세트(C9)의 정답 출처가 필요한 과제라면 모두 이 부품을 쓴다. 서비스 유형 5a·9·10·11에서는 필수 기반이다. 비LLM 규칙 기반 대민 안내에서는 A2를 거치지 않고 결정론 조회의 대상이 된다(R21).

맞서는 힘(긴장)

  • 정제 품질 vs 구축 기간·라벨링 인력 비용
  • 과제 전용 가공(빠름) vs 기관 공통 기준선(재사용)
  • 데이터 활용 범위 vs 데이터 등급(E5) 보호
  • 기준선 고정(재현성) vs 원천 갱신 반영

해법

원천 기록을 수집→정제(중복·결측 처리)→라벨링→정의 문서화 순으로 가공하고, 결과를 정제 데이터셋·라벨·데이터 사전의 세 산출물로 고정해 제공한다. 'N건→M건 정제'처럼 정제 전후 규모와 기준을 기록하고, 변수·테이블·인터페이스 정의서로 소비 부품이 같은 정의를 쓰게 한다. 기준선은 버전으로 관리해 C9 평가 세트의 정답 출처와 C6 재학습의 입력으로 재사용한다. 데이터 경계는 부품별로 두고(DB per Service), 타 기관 데이터와의 결합은 A4로 분리한다.

이럴 때 쓴다

  • 예측·추천기(B2)나 비전 모델(A2.5)을 학습·재학습할 때
  • 지식 접지(B3)의 코퍼스를 구축할 때
  • 평가 세트(C9)의 정답 출처가 필요할 때
  • 서비스 유형 5a-agg·9·10·11처럼 A1이 필수인 조립

이럴 때는 쓰지 않는다

  • 공공 API 응답을 가공 없이 조회만 할 때(A3)
  • 정제·정의 없이 파일을 올려 바로 검색하는 경우(태그 대상 아님)
  • 타 기관 데이터 결합이 핵심일 때는 A4를 함께 태그해 계약·키 매핑을 따로 드러낸다

얻는 것

  • 모델 교체와 무관하게 남는 기관 자산
  • C9·C6·B3가 같은 기준선을 재사용
  • 데이터 사전이 기관 간 표준 확산의 단위가 됨

점검표

  • 정제 전후 규모와 정제 기준이 기록되어 있는가
  • 데이터 사전(정의·단위·출처)이 있는가
  • 기준선에 버전이 있고 평가용 분할이 학습용과 분리되어 있는가
  • 데이터 등급(E5)에 맞는 가명·비식별 처리가 적용되었는가

구조 — 참여 부품

  • 원천 시스템·기록 — 가공 전 업무 기록을 내주는 출처
  • 정제·라벨링 파이프라인 — 중복 제거·결측 처리·라벨 부여·품질관리를 수행
  • 데이터 사전 — 정의·단위·출처를 문서로 고정해 소비 부품이 같은 뜻으로 쓰게 함
  • C9 평가 세트·회귀시험 — 기준선을 정답 출처로 사용
  • A2.5 비LLM 학습 모델 — 기준선으로 학습·재학습하는 소비 부품

변형

  • 학습데이터 구축형: 영상·이미지 등을 수집해 품질관리 단계(중복 제거·재라벨링·학습/검증/평가 분리)를 거쳐 학습 기준선으로 만든다.
  • RAG 코퍼스 정본화형: 법령·규정 원문을 현행 시행본 기준으로 정본화하고 조문 구조·메타데이터를 부여해 색인한다.
  • 지표 표준화형: 여러 자료원의 지표를 도메인별로 표준화하고 정의·단위·분모·결측·원본 링크를 메타데이터로 관리한다.
  • 자동 피처 파이프라인형: 수집→정제→파생 변수 생성→자동 검증→담당자 승인을 주기 실행하고 승인만 사람에게 남긴다.

C1 검토 큐 운영 컴포넌트

AI 산출물이 다음 단계로 넘어가기 전에 사람이 맞고 틀림을 확인·수정·확정하는 대기열을 두어, 오류가 업무 결과로 흘러가지 않게 한다.

PAX 사례 46건이 이 부품을 쓴다

맥락

AI 산출물이 공문·처분·대민 안내·기록으로 이어지는 모든 B 부품(B1 코파일럿, B4 인식 파이프라인, B2 예측기, B7 콘텐츠 생성기 등). 이용자 본인이 최종 확정자인 자기서비스형 도구도 포함한다(R16).

맞서는 힘(긴장)

  • 정확성·책임성 vs 처리 속도(전건 검토는 자동화 이득을 깎는다)
  • 검토자의 숙련 vs 자동화 편향(AI 결과를 그대로 승인하는 경향)
  • 전건 검토의 안전 vs 위험도별 분기(C2)로 가야 하는 효율 압력

해법

AI 산출물에 신뢰도·근거를 붙여 검토 대기열에 올리고, 검토자가 승인·수정·반려 중 하나를 고르게 한다. 수정·반려 내역은 C4 감사 로그에 남겨 수정률을 집계하고 C6 환류의 입력으로 쓴다. 검토 화면은 원문 위치·근거를 함께 보여 줘 확인 비용을 줄인다. 전건 검토로 시작하되, 수정률 실측이 쌓이면 C2 위험도 라우터로 저위험 건을 자동 종결하는 단계로 옮긴다.

이럴 때 쓴다

  • AI 산출물이 공문·처분·대민 안내로 그대로 이어질 때
  • E4가 P1 이상이고 되돌리는 데 사람 시간이 많이 드는 조치가 있을 때
  • 서비스 유형 ② 접수·심사, ④ 기안 코파일럿, ⑥ 콘텐츠 제작, ⑦ 대조·점검, ⑩ 위험 예측, ⑪ 추천·매칭, ⑫ 개발 코파일럿처럼 C1이 필수인 유형

이럴 때는 쓰지 않는다

  • B0 결정적 도구처럼 런타임 AI 산출물이 없을 때
  • 쉽게 되돌릴 수 있고 저위험인 조치를 이미 C2로 자동 종결하도록 실측 근거를 갖춘 구간(전건 검토를 영원히 남기지 않는다)

얻는 것

  • 오류가 업무 결과로 나가기 전에 차단
  • 책임 소재가 명확해짐
  • 수정 내역이 C4 지표와 C6 환류의 원천 데이터가 됨

점검표

  • AI 산출물이 확정 전 상태로 머무는 지점이 명시되어 있는가
  • 검토자와 승인·수정·반려 선택지가 정해져 있는가
  • 검토 결정과 수정 내역이 로그로 남는가
  • 실증 기간의 검토·수정 건수가 기록되어 있는가
  • 전건 검토에서 분기로 옮길 조건이 정해져 있는가

구조 — 참여 부품

  • 검토 대기열 — AI 산출물을 확정 전 상태로 보관하고 검토자에게 배정
  • 검토자(담당자 또는 이용자 본인) — 승인·수정·반려를 결정하는 최종 책임자
  • F2 편집 가능한 출력 — 검토자가 산출물을 직접 고치는 화면
  • C4 감사 로그·지표 — 검토 결정과 수정 내역을 적재해 수정률로 집계

변형

  • 전건 검토형: 모든 AI 산출물을 담당자가 확인·확정
  • 예외 검수형: 정상 건은 일괄 승인하고 저신뢰 항목만 개별 검수하는 검수 UI
  • 파이프라인 내장 관문형: 멀티에이전트·다단계 파이프라인의 각 관문에 승인·보완·재작성 선택지를 둠
  • 자기서비스형: 이용자 본인이 최종 확정자인 HITL. 실제 운영 중이면 C1 present(R16)
  • 심의 게이트: 팩트체크·법무·윤리처럼 제3자 전문가가 수행하는 승인 게이트

C5 가드레일 필터 운영 컴포넌트

맥락

D8.1 탐색·조회 서비스 블록

데이터·법령·공고·선례·타 지역 사례를 찾아 담당자 화면에 놓는 내부 운영 블록이다. B0 탐색·시각화, MCP 도구 제공, B3가 전형 부품이다.

맥락

기관 내부 담당자가 자료를 찾아 보는 업무. §7.3 유형 ⑤b 데이터 에이전트(D8.1, P0)와 ⑤a 분석 대시보드·브리핑(D8.1, P0~P1)의 무대. PAX 176건(주 부품 B0 80%, B3 10%).

  • 검색 편의 vs 출처·기준 시점 확인

  • 대시보드 고정 화면 vs 에이전트의 유연한 질의
  • MCP 서버 수 vs 실제 업무 호출(X8)

해법

답이 원천 데이터에서 나오게 한다. 공공데이터·통계는 A8 MCP 서버나 A3 공공 API로 도구화하고, 호스트 쪽 에이전트는 B′7 ReAct 도구 루프로 조회하되 C8로 읽기 전용에 묶는다. 결과에는 F1 출처(통계표 ID)와 조회 시점을 붙이고, 도구 호출은 C4로 추적한다. 도구 출력이 새 지시가 되지 않도록 S5 계획 후 실행과 S1 비용 상한을 둔다. 에이전트가 필요 없으면 B0 대시보드·검색기로 끝내고(5a-agg), LLM이 해설을 붙이면 5a-brief로 C9·F9를 더한다(R19). MCP 서버만 만드는 사례는 5b-server로 A8·S11만 필수다(R18).

이럴 때 쓴다

  • 담당자가 흩어진 데이터·법령·공고·선례를 찾느라 시간을 쓸 때

  • 규정·기준과 대조해 확인 대상을 고르면 D8.4
  • 국민이 서비스를 찾으면 D1

  • 도구 권한이 읽기 전용으로 묶여 있는가

맥락

  • 요약 속도 vs 누락·오독
  • 표준 시스템 무수정 vs 연동 안정성(B8 오버레이는 정식 연동 시 소멸)
  • 외부에서 온 공문·첨부(간접 인젝션) vs 자동 요약

  • 첨부까지 열어 봐야 핵심을 알 수 있을 때

이럴 때는 쓰지 않는다

  • 요약을 넘어 보고서·공문 첫 판을 만들면 D8.3(우선순위가 더 높음)
  • 문서를 담당자에게 배분하면 D8.6
  • 문서를 찾는 것이 목적이면 D8.1

얻는 것

  • 문서 읽기 시간 절감
  • 기한 누락 방지
  • 표준 시스템 무수정 도입

점검표

  • 요약마다 원문 위치가 연결되는가
  • 문서가 허용된 망 밖으로 나가지 않는가
  • 외부 공문 속 지시가 요약·행동을 바꾸지 못하는가
  • 요약 확인 절차가 서술되어 있는가

구조 — 참여 부품

  • 담당자 — 요약 카드를 확인하고 할 일을 처리
  • B8 레거시 오버레이 — 표준 시스템 화면 위 사이드패널
  • A10 문서 형식 어댑터 — HWPX·PDF 첨부를 읽음
  • B1 직접 프롬프트 코파일럿 — 요약·할 일·기한 추출
  • A2 모델 서빙 계층 — 로컬·내부망 프록시 모델 제공
  • C1 검토 큐 — 요약 확인 절차

변형

  • 사이드패널 오버레이형: 표준 시스템 화면 위 브라우저 사이드바(B8, 온나라 sAIde).
  • 문서 리소스 추출형: 문서에서 항목·자원을 정형으로 뽑음(B4).
  • 할 일 카드형: 공문 → 할 일 카드(D-day). 알림을 보내면 D5와 함께.

A9 업무 규범 스킬 공통 서비스

보고서 구조·문체·서식·검증 절차 같은 업무 규범을 모델 중립 스킬(지침 + 검증기 + 출력 서식)로 패키징해 어떤 모델·에이전트에서든 재사용한다.

PAX 사례 54건이 이 부품을 쓴다

맥락

기안·보고서·콘텐츠처럼 서식과 문체가 정해진 산출물을 만드는 B1·B7, BYO 코딩 에이전트 환경(E2 모델 중립), 개발 코파일럿에서 쓴다. 유형 4·6·12에서는 필수 기반이고, §7.2 진행 경로에서는 3단계에 놓인다.

맞서는 힘(긴장)

  • 규범 고정(일관성) vs 담당자 재량
  • 모델 중립(이식성) vs 특정 모델 최적화
  • 규범 공개·재사용 vs 프롬프트·규범 유출
  • 가중치에 넣기(튜닝) vs 문서로 주입하기

해법

규정집·매뉴얼·서식 예시에서 업무 규범을 뽑아 지침(구조·문체·금지 사항), 검증기(형식·인용·수치 검사), 출력 서식(HWPX·DOCX 등)으로 묶은 스킬 패키지로 만든다. 모델 호출 코드와 분리된 파일로 두어 어떤 코딩 에이전트·모델에서도 같은 절차가 돌게 한다(External Configuration). 산출·검증된 수치와 출처만 주입하고 미제공 수치·순위 생성을 금지하는 식으로 생성 범위를 규범으로 좁힌다. 스킬은 버전으로 관리해 규범 유출·변경을 추적하고, C9로 스킬 변경 전후 품질을 잰다.

이럴 때 쓴다

  • 산출물 서식·문체·구조가 정해져 있을 때
  • 출력 품질이 들쭉날쭉할 때(§7.5)
  • BYO 환경에서 모델과 무관하게 같은 절차를 돌려야 할 때
  • 갱신이 잦은 규범을 튜닝 없이 반영해야 할 때

이럴 때는 쓰지 않는다

  • 규범이 문서로 정리되지 않았고 정리할 담당도 없을 때
  • 지식 검색이 필요한 문제(B3 접지가 먼저)
  • 스킬 내용 자체가 민감해 배포할 수 없는데 버전 관리·접근 통제를 둘 수 없을 때

얻는 것

  • 출력 일관성
  • 모델 교체 가능(BYO에서는 교체 가능성이 곧 C7)
  • 타 기관 재사용
  • 튜닝 없이 규범 갱신

점검표

  • 규범이 모델 호출 코드와 분리된 파일로 있는가
  • 검증기가 출력 형식·인용·수치를 실제로 검사하는가
  • 스킬에 버전이 있는가
  • 다른 모델로 바꿔도 같은 서식이 나오는지 확인했는가

구조 — 참여 부품

  • 규범 원천(규정집·매뉴얼·서식) — 스킬로 옮길 업무 규범의 출처
  • 스킬 패키지 — 지침·검증기·출력 서식을 모델 밖 파일로 묶음
  • 코딩 에이전트·모델(BYO) — 스킬을 불러 규범대로 산출
  • A10 문서 형식 어댑터 — 출력 서식을 HWPX·DOCX로 내보냄
  • C9 평가 세트 — 스킬 변경 전후 품질 비교

변형

  • 보고서·문서 규범 스킬: gov-report-skill(기획보고서 7대 항목), 원페이퍼 스킬(A4 한 쪽·DOCX 검증).
  • 스타일·콘텐츠 스킬: Public Cardnews(6개 스타일), 제작 가이드·검수 체크리스트를 묶은 제작 스킬 패키지.
  • 검증 스킬: paper-verify(인용 검증)처럼 검증 절차 자체를 패키징한다.
  • 규정집→스킬 변환: book-to-skill은 PDF 규정집을 에이전트 스킬로 자동 변환한다(A9+A10 조합).
  • 지식 가이드 In-Context 주입: 파인튜닝 대신 추출·판정 기준을 문서형 가이드로 증류해 주입한다.

참조 구현 예

A10 문서 형식 어댑터 공통 서비스

HWP·HWPX·엑셀·한셀·PDF 같은 한국 공공 문서 형식을 AI 부품이 읽고(구조화) 쓰게(서식 생성) 하는 변환 계층이다.

PAX 사례 136건이 이 부품을 쓴다

맥락

문서를 입력으로 받거나 기안·보고서·취합본을 산출하는 과제라면 거의 다 쓴다. 유형 2·4·8에서는 필수 기반이고 유형 6·7에서도 쓰인다. E1 로컬 PC 조건에서 도는 경우가 많다.

맞서는 힘(긴장)

  • 형식 충실도(표·각주·조항 구조 보존) vs 파서 구현 비용
  • 로컬 처리(무반출) vs 클라우드 변환 도구의 편의
  • 기관별 서식 다양성 vs 공통 어댑터 재사용

해법

입력 쪽에서는 HWPX 압축 구조·PDF에서 조·항·호·별표 계층과 표를 보존해 구조화 텍스트·표로 바꾸고, 머리말·각주 같은 잡음을 걷어 조항 단위로 정규화한다. 출력 쪽에서는 스킬(A9)의 출력 서식을 받아 HWPX·XLSX 기안 서식을 역방향으로 생성한다. 민감 문서는 PC 밖으로 보내지 않도록 로컬에서 변환하고, 파서를 라이브러리·CLI·MCP로 함께 제공하면 다른 부품과 기관이 그대로 쓴다. 형식 변환 정확도는 C9 판정 체계로 잰다.

이럴 때 쓴다

  • 입력이 HWP·HWPX·엑셀·PDF 공공 문서일 때
  • 산출물을 기안·보고 서식으로 내보내야 할 때
  • 유형 2·4·8 조립

이럴 때는 쓰지 않는다

  • 스캔 이미지·음성처럼 인식이 필요한 입력은 B4 인식 파이프라인(OCR·STT)
  • 입출력이 이미 정형 데이터·API인 경우

얻는 것

  • 공공 문서를 AI 입력·출력으로 연결
  • 기관 간 재사용 가능한 공통 부품
  • 로컬 처리로 무반출

점검표

  • 표·조항 계층이 변환 후에도 보존되는가
  • 출력이 기관 기안 서식 그대로 열리는가
  • 민감 문서가 변환 과정에서 PC 밖으로 나가지 않는가
  • 변환 정확도 판정 기록이 있는가

구조 — 참여 부품

  • 입력 파서 — 조·항·호·표 구조를 보존해 구조화
  • 서식 생성기 — 구조화 결과를 HWPX·엑셀 서식으로 출력
  • A9 업무 규범 스킬 — 출력 서식 규범 제공
  • B3 지식 접지 상담 — 구조화된 규정을 색인해 검색

변형

  • 규정 구조 파서: HWP/HWPX·PDF 규정을 조항 단위로 정규화한다.
  • 엑셀·한셀 취합: 폐쇄망에서 엑셀·한셀 파일을 취합한다(GatherFlow).
  • 서식 출력: HWPX 직무기술서·보도자료 등 공공 서식으로 역방향 생성한다(NCS JD, ReleasePick 입력).
  • 완결형 문서 엔진: HWP/HWPX 파싱·조판·렌더링·편집·PDF 출력을 자체 구현하고 MCP·CLI로 제공한다(PAX e18d5e018e0cd10d).
  • AI 친화 병행 등록: 기관이 발간자료를 마크다운으로 함께 등록하도록 표준화한다(PAX 17329009668eb397).

참조 구현 예

  • PAX GatherFlow — 엑셀·한셀 취합(폐쇄망)(§6 A10 카드)
  • PAX 7ad16f34cfb6cca7 — HWP·HWPX·PDF에서 신구대비표 초안을 로컬 생성(§13 A10)

F2 편집 가능한 출력 상호작용 패턴

생성물을 이용자가 직접 고쳐 확정하게 한다. 통제감의 실체이며, 수정 내역은 C4 지표와 C6 환류의 입력이 된다.

PAX 사례 50건이 이 부품을 쓴다

맥락

B1 코파일럿(필수 면), B7 콘텐츠 생성기, B4 인식 결과 확정. 유형 ② 접수·심사, ④ 기안 코파일럿, ⑫ 개발 코파일럿, 5a-agg(R19), 2b 시민 제출 준비(R20).

맞서는 힘(긴장)

  • 편집 자유도 vs 원본 추적(무엇을 고쳤는지)
  • 편집 가능한 공공 서식(HWPX 등) 출력 vs 구현 비용

해법

생성물을 이용자가 바로 고칠 수 있는 형식(편집 화면, HWPX·PPTX 등 네이티브 파일)으로 내고, 이용자가 고친 뒤 확정하게 한다. AI 원안과 수정본의 차이를 기록해 C4 수정률과 C6 환류 입력으로 쓴다. 문서 형식 출력은 A10 어댑터가 받친다.

이럴 때 쓴다

  • B1 코파일럿 전반(필수 면)
  • 대민 서비스 D1~D7(F1·F2·F7이 최소 요건)
  • 유형 ②④⑫, 5a-agg, 2b처럼 F2가 필수인 유형

이럴 때는 쓰지 않는다

  • 이용자가 결과를 수정하면 안 되는 판정 결과(판정은 C1 확정 절차로 다룸)
  • 조회 결과만 보여 주는 P0 도구

얻는 것

  • 이용자 통제감
  • 수정 내역이 품질 지표·환류 데이터가 됨
  • 공공 서식 재작업 감소

점검표

  • 산출물을 이용자가 직접 고칠 수 있는가
  • 원안과 수정본 차이가 기록되는가
  • 공공 서식 형식으로 편집 가능한가

구조 — 참여 부품

  • 편집 화면·네이티브 파일 — 이용자가 직접 고치는 면
  • A10 문서 형식 어댑터 — HWPX·PPTX 등 편집 가능한 형식 출력
  • C4 감사 로그·지표 — 수정 내역 기록

변형

  • 화면 내 편집: 생성 결과를 화면에서 바로 수정·확정
  • 네이티브 파일 출력: PPTX·HWPX·피그마 등 이어서 고칠 수 있는 형식으로 산출

참조 구현 예

X3 부서마다 챗봇 안티패턴

같은 기관의 과제들이 각자 모델·벡터DB·프롬프트를 따로 만들어, 공유할 수 있는 기반 부품을 부서 수만큼 중복 구축하는 함정이다.

맥락

한 기관 안에서 여러 부서가 동시에 대민·내부 챗봇, 문서 검색, 요약 도구를 추진하는 경우. 특히 각 과제가 상용 API를 직접 호출하는 경우.

맞서는 힘(긴장)

  • 부서의 빠른 자율 구축 vs 기관 전체의 중복 비용
  • 부서별 맞춤(코퍼스·문체) vs 공통 모델·게이트웨이
  • 과제 단위 예산·성과 vs 공통 기반 등재·유지 책임

해법

§7.1의 두 번째 단계대로 기반 부품은 새로 만들지 말고 Provider에서 먼저 가져온다. 모델 호출은 A2 모델 서빙 계층(범정부 AI 공통기반 또는 기관 게이트웨이) 뒤로 모으고, S1 단일 진입점에서 인증·요청 상한·비용 상한·감사 기록을 일괄 적용한다. 공공 API·공공 클라우드·공공 깃랩은 A3 공공 API 제공자로 쓴다. 부서별 차이는 모델을 따로 두지 말고 A9 업무 규범 스킬과 부서 코퍼스(A1)로 표현하며, 부서·등급별 코퍼스 분리가 필요하면 S2 권한 인식 검색으로 푼다. 없어서 새로 만든 부품은 §13 참조 구현 레지스트리에 올린다.

이럴 때 쓴다

  • 같은 기관의 두 과제 이상이 각자 모델 계약·API 키·벡터DB를 갖는다
  • 범정부 AI 공통기반·공공 API를 쓰지 않은 이유가 서술되지 않는다
  • 공통 규정·매뉴얼 코퍼스를 과제마다 따로 임베딩한다
  • 모델 호출 비용을 기관 단위로 집계할 수 없다

이럴 때는 쓰지 않는다

  • 데이터 등급(E5)이나 망 조건(E1) 때문에 공통 기반을 쓸 수 없고 그 사유가 서술된 경우
  • A2 게이트웨이를 공유하면서 부서별 코퍼스·스킬만 따로 둔 경우(정상 조립)
  • 개인이 만든 단일 도구로 기관 내 중복 과제가 없는 경우

얻는 것

  • 부서가 협의 없이 빠르게 만든다
  • 부서 요구에 딱 맞는 맞춤 구성을 갖는다

점검표

  • 기관의 모든 모델 호출이 하나의 게이트웨이를 지나는가
  • 부서별 API 키 직접 호출이 남아 있지 않은가
  • 공통 기반을 쓰지 않은 과제는 그 사유(E1·E5)가 적혀 있는가
  • 부서별 차이가 모델이 아니라 스킬·코퍼스로 표현되어 있는가

구조 — 참여 부품

  • A2 모델 서빙 계층 — 교정 후 모든 부서 호출이 모이는 공통 자리
  • A3 공공 API 제공자 — 범정부 AI 공통기반·공공 깃랩 등 Provider
  • S1 AI 게이트웨이·단일 진입점 — 부서별 API 키 직접 호출을 대체하는 인증·상한·기록 지점
  • A9 업무 규범 스킬 — 부서별 차이를 모델이 아니라 스킬로 표현

변형

  • 부서별 API 키 직접 호출: 각 과제가 상용 API 키를 따로 받아 직접 호출. S1 부재의 전형
  • 벡터DB 중복: 같은 규정·매뉴얼을 부서마다 따로 임베딩해 따로 검색
  • 프롬프트 사일로: 같은 공문 규범을 부서마다 다른 프롬프트로 재작성

X10 평가 없는 RAG, RAG 없는 튜닝 안티패턴

평가 세트 없이 검색을 붙여 '좋아진 것 같다'로 배포하고, 검색으로 풀릴 문제를 파인튜닝으로 푸는, 진행 경로를 건너뛰는 함정이다.

맥락

B3 지식 접지·B1 코파일럿에 RAG를 붙이거나 A2.3 튜닝형 모델을 만드는 과제, 특히 규정·매뉴얼 기반 질의응답.

맞서는 힘(긴장)

  • 눈에 보이는 기술 성과 vs 지루한 평가 세트 구축
  • 빠른 배포 vs 변경마다 재는 자
  • 자체 모델 보유 인상 vs 검색으로 충분한 문제

해법

§7.2 진행 경로를 순서대로 밟는다. B1 직접 프롬프트에서 시작해 두 번째 단계에서 C9 평가 세트(업무 질문·정답·채점 기준)를 먼저 만들고, 이후 A9 규범 스킬·F4, B3 지식 접지(A1 데이터 자산), B3 검색 품질(Hybrid·Rewriting·Reranker), C5 가드레일·F1 순으로 붙이며 매 단계를 C9로 잰다. A2.3 튜닝은 진행 경로의 마지막 단계로, 검색·규범 스킬로 풀리지 않는다는 것이 C9 점수로 확인됐을 때만 한다. 모델·프롬프트·설정 조합은 릴리스처럼 버전 관리한다.

이럴 때 쓴다

  • RAG·튜닝을 도입했는데 업무 질문·정답·채점 기준 세트가 없다
  • '답변 품질 향상'을 수치 없이 서술하거나 단발 정확도만 보고한다
  • 자주 바뀌는 규정·매뉴얼 질의를 파인튜닝으로 풀었다
  • 검색 품질(재현율·리랭킹)을 재지 않고 튜닝으로 넘어갔다

이럴 때는 쓰지 않는다

  • C9 세트로 RAG 전후를 비교한 뒤 배포한 경우
  • 검색·스킬로 풀리지 않음을 C9 점수로 확인한 뒤 튜닝한 경우
  • B2·B4처럼 비LLM 학습 모델로 원래 학습이 해법인 경우(RAG가 대안이 아님)

얻는 것

  • RAG·튜닝이라는 눈에 보이는 기술 성과를 빨리 낸다
  • 평가 세트 구축에 현업 시간을 쓰지 않는다

점검표

  • 업무 질문·정답·채점 기준 세트가 있는가
  • RAG 전후 점수 비교가 있는가
  • 튜닝을 선택한 근거가 C9 점수로 설명되는가
  • 모델·프롬프트·설정 조합이 버전 관리되는가

구조 — 참여 부품

  • C9 평가 세트·회귀시험 — 빠진 부품. 모든 변경을 같은 자로 잼
  • B3 지식 접지 — 튜닝 전에 먼저 시도할 검색 기반 접지
  • A2.3 튜닝형 모델 — 진행 경로의 마지막 단계
  • A1 데이터 자산 서비스 — 정답 출처와 검색 코퍼스

변형

  • 평가 없는 RAG: 검색을 붙이고 몇 개 질문을 눈으로 보고 배포
  • RAG 없는 튜닝: 문서 검색으로 풀릴 최신 규정 질의를 파인튜닝으로 해결하려 함
  • 평가 없는 튜닝: 튜닝 전후를 같은 세트로 비교하지 않음
