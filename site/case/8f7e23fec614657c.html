판정 근거

한국어 문서의 개인정보를 탐지하는 100MB급 경량 모델. 비정형 텍스트를 인식해 PII 개체로 구조화하므로 B4(텍스트 개체 인식), 자체 학습 비LLM 모델 서빙이라 A2.5(국산 독자모델). 문서 반출 전 로컬 점검 용도가 S13 로컬 비식별 게이트 그 자체라 present. 미탐지 사례를 다음 학습에 반영받는 구조가 C6이며 주기·실행 기록이 없어 implemented. 개인정보를 다루니 S(민감). 일부 공무원 개별 배포→정식 공개라 부서 공유. URL 없음.

구현 가이드

주 패턴 B4 인식 파이프라인을 구현할 때

구현 단계

  1. 입력 종류와 추출할 필드, 필드별 기준정보(대장·코드표)를 정의한다.
  2. 인식 단계는 정형 출력(JSON 스키마)만 내게 하고, 판정·산수는 규칙 단계로 분리한다(B′9).
  3. 신뢰도 임계와 보류 조건을 정해 C1 검토 큐로 보내고, C3로 재처리 경로를 둔다.
  4. E5 민감 서류면 행정망 + 로컬 모델로 두고, 제출 서류를 읽는 P2 이상 구성은 S6 문서별 격리를 둔다.
  5. C9 시험 세트로 필드별 정확도를 재고 C4로 보류율·수정률을 집계한다.

점검표

  • 인식과 판정이 서로 다른 단계로 분리되어 있는가
  • 저신뢰 건이 보류되어 사람에게 가는가
  • 오인식 건을 되돌리는 경로가 있는가(C3)
  • 필드별 정확도를 잰 시험 세트가 있는가

환경 조건

E5 민감 서류면 E1 행정망 + A2 로컬(Whisper 로컬 등). E4는 P1~P2이며, 건별 검수 없이 운영 DB로 직행하면 P2, 승인·반려에 직결되면 P3다. 제출 서류는 신뢰 불가 입력이므로 P2 이상이면 S6 문서별 격리 + 규칙 집계가 필수다(§7.4 유형 ②).

주의할 점

  • 오인식이 판정으로 번질 위험(C3 필수)
  • 민감 서류는 로컬 모델 제약
  • 제출 서류 속 숨은 지시로 판정이 조작될 위협

기본 배선 예

A10 → B4 (B′1 → B′9) → C1 → D3 · B4 → C3 (재처리)

보완이 필요한 필수 부품

이 조합에서 카탈로그가 함께 갖추라고 권하는 부품 가운데 아직 확인되지 않은 것이다.

  • A3 공공 API 제공자 정부·공공이 운영하는 모델·데이터·개발 도구(범정부 AI 공통기반, 모두의 AI 실험실, 공공데이터포털, 공공 깃랩)를 범정부 Provider로 소비한다.
  • C1 검토 큐 AI 산출물이 다음 단계로 넘어가기 전에 사람이 맞고 틀림을 확인·수정·확정하는 대기열을 두어, 오류가 업무 결과로 흘러가지 않게 한다.
  • C5 가드레일 필터 개인정보·환각·편향·형식 오류가 프롬프트나 산출물에 들어가지 못하게 시스템이 경계에서 걸러낸다. 비식별 전처리, 출처 검증, 구조적 출력 제약이 대표 변형이다.
  • F7 한계·신뢰도 안내 AI가 무엇을 못 하는지, 얼마나 확신하는지, 공식 판단이 아님을 이용자가 볼 수 있는 곳에 적어 과신을 막는다.

피해야 할 안티패턴

  • X13 도구 출력이 지시가 되는 에이전트 검색 결과·첨부·API 응답을 읽은 모델이 그 안의 문장을 새 명령으로 받아 도구를 부르는 구조를, 탐지 필터 하나로 지키려는 함정이다. 대처: 과제의 AI가 읽는 입력 중 기관 밖에서 작성된 것을 untrusted_inputs로 나열하고, §4.2 신뢰 불가 입력 규칙대로 S4 행동 선택기(미리 정한 행동 중 선택만, 결과가 LLM으로 돌아가지 않음), S5 계획 후 실행(외부 데이터를 읽기 전에 도구 호출 계획을 고정), S6 격리 LLM(도구 있는 LLM은 외부 데이터를 읽지 않고, 읽는 LLM은 도구가 없음) 중 하나를 갖춘다. S3 컨텍스트 방화벽과 S8 독립 검증기는 보조로 붙이되 S8만으로는 규칙을 충족하지 못한다. C8 승인 게이트도 신뢰 불가 입력 규칙의 대체 통제로 인정되지 않는다(R6). 그 전 단계에서는 E4를 P0~P1 읽기·산출물 범위에 묶어 두는 것이 곧 보안이다.
  • X16 기준을 노출하는 위조 탐지 진위 판정 근거를 이용자 화면에 그대로 보여 줘 위조범이 탐지 기준을 역추적하게 만드는 함정이다. F9 근거 표시가 적대적 접점에서는 취약점이 된다. 대처: F9 판정 근거·기여도 표시를 역할별로 나눈다. 이용자 화면에는 '정상/위조의심'만 노출하고, 의심 부위·사유 코드·기여도 같은 세부 근거는 관리자 화면에만 보여 준다(근거 은닉, anti-oracle — 카탈로그가 S 계층 후보로 둔 반대편 부품). 관리자 화면 접근은 C8 권한 경계로 제한하고, '위조의심' 건은 C1 검토 큐에서 담당자가 세부 근거를 보고 확정한다. 이용자에게는 F7 한계·신뢰도 안내로 추가 확인 절차를 알리고, 반복 제출·판정 이력은 C4·S10에 남겨 역추적 시도를 탐지할 근거로 삼는다.

이 사례에 쓰인 패턴

B4 인식 파이프라인 업무 컴포넌트

서류·음성·영상·도면 같은 비정형 입력을 인식 → 구조화 → 판정으로 연쇄 처리해 사람이 옮겨 적던 단계를 없앤다.

해법

인식(OCR·STT·비전·VLM)은 정형 필드만 내게 하고, 기준정보와의 대조·요건 판정은 규칙 단계가 맡는다(B′1 + B′9). 저신뢰·불일치 건은 보류해 C1 검토 큐로 보내고, 오인식은 C3 상태 머신으로 되돌린다. 공공 문서 형식은 A10으로 받으며 OCR·STT 엔진은 A2 공통 후보를 쓴다. 제출 서류처럼 신뢰 불가 입력을 읽고 시스템 쓰기가 있으면 문서별 격리(S6)로 서류 속 지시가 판정을 바꾸지 못하게 한다.

이럴 때 쓴다

  • 비정형 입력을 사람이 옮겨 적는 단계가 업무의 병목일 때
  • 추출값이 규칙 판정·다음 처리로 이어질 수 있을 때
  • 유형 ② 접수·심사 자동화의 기본 조립일 때

이럴 때는 쓰지 않는다

  • 추출 결과가 초안으로 멈추고 사람이 확정할 때(B1)
  • 추출 뒤 질의응답이 핵심 산출물일 때(B3)
  • 상시 관측 스트림 감시가 핵심일 때(B5)

얻는 것

  • 옮겨 적기 단계 제거
  • 판정 기준이 규칙으로 남아 설명 가능
  • OCR·STT 엔진을 범정부 공통으로 공유 가능

점검표

  • 인식과 판정이 서로 다른 단계로 분리되어 있는가
  • 저신뢰 건이 보류되어 사람에게 가는가
  • 오인식 건을 되돌리는 경로가 있는가(C3)
  • 필드별 정확도를 잰 시험 세트가 있는가

관련 부품

B′1 기본 배선 — 순차 파이프라인 · B′9 배선 — 인식은 추출만, 판정은 규칙 · C3 First 관문 — 오인식 되돌림 · S6 보안 짝 — 제출 서류별 격리 처리 · F9 이용자 쪽 대응 — 판정 근거 표시(위조 탐지는 관리자에게만)

A2.5 모델 서빙 · 비LLM 학습 모델 공통 서비스

XGBoost·LightGBM·YOLO·U-Net처럼 기관이 직접 학습한 비LLM 예측·비전 모델을 서빙하고 재학습·버전 롤백이 붙을 자리를 제공한다.

해법

학습한 모델을 서빙 계층에 버전과 함께 올려 업무 부품이 점수·등급·탐지 결과만 받게 한다. 서빙 계층은 모델 버전과 드리프트 지표를 함께 내보내 C4에 기록하고, 재학습 파이프라인(C6)이 새 버전을 올리는 자리와 이전 안정판으로 되돌리는 자리(모델 버전 롤백, C7 변형)를 둔다. 재학습 버전은 C9 독립 시험세트에서 이전 버전을 넘을 때만 배포한다. 판정 근거는 F9로 이용자에게 보인다.

이럴 때 쓴다

  • 기관이 자체 데이터로 비LLM 모델을 학습해 운영할 때
  • 유형 5a-brief가 아닌 분석·위험 예측(유형 10)·현장 감시(유형 3) 조립
  • 재학습과 버전 롤백이 필요한 예측·탐지 서비스

이럴 때는 쓰지 않는다

  • LLM을 튜닝했으면 A2.3
  • 벤더 장비·솔루션에 내장돼 기관이 모델을 못 바꾸면 A2.6
  • 학습 없는 규칙 점수 엔진이면 B0(R10 대안)

얻는 것

  • 비LLM 과제가 A2 계층에 정식 자리를 가짐
  • 재학습·버전 롤백으로 운영 개선
  • C6·C7을 끼울 자리 확보

점검표

  • 모델 버전과 학습 데이터 버전이 짝지어 기록되는가
  • 독립 시험세트가 학습 데이터와 분리되어 있는가
  • 이전 안정판으로 되돌릴 수 있는가
  • 재학습 버전 배포 기준이 수치로 있는가

관련 부품

사용 결과(수정·이의·오탐 기록)가 정해진 주기와 트리거로 재학습·기준 개정에 되돌아오게 해, 배포 후에도 성능과 기준이 개선되게 한다.

해법

C4의 수정·이의·오탐 기록을 입력으로, 재학습 또는 기준 개정의 주기(예: 6개월)와 트리거(예: 일치율 임계 미만)를 수치로 정한다. 개정 전에는 C9 평가 세트로 재검증해 기준을 넘는 경우에만 배포하고, 개정 이력을 남긴다. 반영 범위에 상한을 두고 평가 기간에는 루프를 동결하는 조건도 정한다. 이용자 쪽에서는 F10 피드백이 입력이 된다.

이럴 때 쓴다

  • C4에 수정·오탐 기록이 쌓이는 학습 모델 기반 부품
  • 데이터 분포가 시간에 따라 바뀌는 감지·예측 업무
  • 유형 ③⑤a⑩⑪처럼 C6가 필수인 유형

이럴 때는 쓰지 않는다

  • B0 결정적 도구처럼 학습·개정할 모델·기준이 없을 때
  • C4 기록과 C9 평가 세트가 없어 반영 결과를 검증할 수 없을 때(먼저 C4·C9)

얻는 것

  • 배포 후 성능 개선
  • 현장 기준 변화 반영
  • Native 단계 진입 근거

점검표

  • 주기·트리거가 수치로 정해져 있는가
  • 환류 입력 데이터가 C4에서 나오는가
  • 개정 전 재검증 절차가 있는가
  • 실증 기간에 완결된 사이클이 1회 이상 기록되었는가

S13 로컬 비식별 게이트 보안 패턴

외부로 전송하기 전에 단말·현장 서버의 소형 모델로 개인정보를 탐지·마스킹해 비식별 결과만 내보낸다. v0.6 후보 부품으로, 카드 없이 R4 한 줄 정의와 §13 레지스트리로만 등재되어 있다.

해법

데이터가 단말·현장 서버를 떠나기 직전에 소형 PII 탐지 모델(A2.5 자체 학습 모델 등)을 돌려 얼굴·개인정보를 마스킹하고, 비식별된 결과와 통계·이벤트만 전송한다. 원본은 현장에서 처리·종결하거나 원본과 분리해 보관한다. 탐지 누락에 대비해 수동 보완 절차를 두고, 외부 연결이 실패하면 로컬 처리로 되돌린다. 오프라인 모드를 강제하면 게이트를 우회한 전송을 막을 수 있다. ^[inferred]

이럴 때 쓴다

  • 현장 영상·음성을 클라우드·중앙 서버로 보내는 감시 과제
  • 공공문서를 외부 LLM(E2 해외 상용 API)에 보내기 전
  • 비식별·정제 도구(유형 13)
  • E5 S 등급 데이터를 A2.4 없이 외부로 보내야 할 때의 보완

이럴 때는 쓰지 않는다

  • 데이터를 아예 외부로 보내지 않아도 되면 S12가 더 강함
  • 이미 서버 쪽 비식별(C5)만으로 충분한 내부 전송
  • 탐지 누락이 허용되지 않는데 수동 보완 경로가 없을 때 — 게이트만으로는 부족

얻는 것

  • 외부 모델·클라우드를 쓰면서 원문 유출 축소
  • 전송 데이터량 감소
  • 원본을 현장에 남겨 데이터 주권 유지

점검표

  • 게이트를 거치지 않는 외부 전송 경로가 없는가
  • 탐지율 목표와 실측치가 있는가
  • 누락 시 수동 보완 절차가 있는가
  • 원본이 외부로 나가지 않거나 분리 보관되는가

D8.8 보호·정제 서비스 블록

공유·전송 전에 개인정보를 비식별하고, 생성 코드를 보안 기준으로 점검하고, 파일을 이중 보관하는 내부 운영 블록이다. C5의 업무 블록 버전이다.

해법

보호 조치를 자료가 기관 밖이나 모델로 나가기 직전에 둔다. 개인정보는 C5 비식별 전처리기로 거르되, 가능하면 단말에서 처리해 PII가 서버에 닿지 않게 하는 S12 데이터 비도달 설계나 S13 로컬 비식별 게이트(온디바이스 소형 모델)를 쓴다. 규칙으로 잡히는 항목은 B0 결정적 탐지로, 문맥이 필요한 항목만 소형 모델로 처리한다. 생성 코드 점검은 공공 보안 기준을 규칙 세트로 만들어 1차 린터로 돌리고 S9 샌드박스에서 실행한다. 결과에는 F7 한계("1차 점검", 누락 가능성)를 명시하고 C9로 탐지 누락률을 잰다.

이럴 때 쓴다

  • 자료를 외부·AI로 보내기 전에 개인정보를 가려야 할 때
  • 직접 만든 코드의 보안 기준 준수를 점검해야 할 때
  • 보호 조치가 반복 업무로 담당자 시간을 쓸 때

이럴 때는 쓰지 않는다

  • 비식별이 다른 도구의 내부 단계일 뿐이면 그 도구의 블록에 두고 C5만 태그
  • 규정·서식 대조가 목적이면 D8.4
  • 인수인계가 목적이면 D8.7(우선순위 높음)

얻는 것

  • 외부 모델 활용의 전제 조건 확보
  • 담당자 수작업 마스킹 절감
  • 보안 기준 1차 점검의 일상화

점검표

  • PII가 서버·외부 모델에 닿기 전에 걸러지는가
  • 탐지 누락률을 재는가
  • "1차 점검" 한계가 고지되는가
  • 점검 규칙의 출처(보안 기준)가 명시되어 있는가

A3 공공 API 제공자 공통 서비스

정부·공공이 운영하는 모델·데이터·개발 도구(범정부 AI 공통기반, 모두의 AI 실험실, 공공데이터포털, 공공 깃랩)를 범정부 Provider로 소비한다.

해법

기반을 새로 만들기 전에 범정부 AI 공통기반(모델), 공공데이터포털·법령 API(데이터), 모두의 AI 실험실·공공 깃랩(개발·실험 환경)에서 먼저 찾아 소비한다. 인증은 GPKI·디지털원패스 같은 연합 신원(Federated Identity)으로 위임하고, 공공 API 응답은 출처·조회 시각과 함께 업무 부품에 넘긴다. 에이전트가 부를 수 있게 하려면 A8 MCP 서버로 감싸고, 결과를 재가공해 기준선으로 고정하면 A1을 더한다. 기관이 만든 도구는 공공 깃랩에 등재해 다음 기관의 Provider가 되게 한다.

이럴 때 쓴다

  • 모델·데이터·개발 환경을 기관이 새로 만들려 할 때 — 먼저 Provider 확인
  • 법령·기준 원문을 최신으로 대조해야 하는 유형 7
  • 여러 부서가 같은 기반을 따로 만들고 있을 때(X3 교정)

이럴 때는 쓰지 않는다

  • 필요한 모델·데이터가 공공 Provider에 없을 때(만들고 레지스트리에 올림)
  • 타 기관 데이터를 계약·키 매핑으로 결합하는 경우는 A4

얻는 것

  • 기관별 중복 구축 방지(X3 교정)
  • 공인된 원천 데이터·모델 사용
  • 등재를 통해 전이 경로 확보

점검표

  • 같은 기반을 기관 안에서 따로 만들지 않았는가
  • 공공 API 응답의 출처·조회 시각이 결과에 남는가
  • API 장애·변경 시 어떻게 되는지 답할 수 있는가
  • 만든 도구가 공공 깃랩 등에 등재되었는가

C1 검토 큐 운영 컴포넌트

AI 산출물이 다음 단계로 넘어가기 전에 사람이 맞고 틀림을 확인·수정·확정하는 대기열을 두어, 오류가 업무 결과로 흘러가지 않게 한다.

해법

AI 산출물에 신뢰도·근거를 붙여 검토 대기열에 올리고, 검토자가 승인·수정·반려 중 하나를 고르게 한다. 수정·반려 내역은 C4 감사 로그에 남겨 수정률을 집계하고 C6 환류의 입력으로 쓴다. 검토 화면은 원문 위치·근거를 함께 보여 줘 확인 비용을 줄인다. 전건 검토로 시작하되, 수정률 실측이 쌓이면 C2 위험도 라우터로 저위험 건을 자동 종결하는 단계로 옮긴다.

이럴 때 쓴다

  • AI 산출물이 공문·처분·대민 안내로 그대로 이어질 때
  • E4가 P1 이상이고 되돌리는 데 사람 시간이 많이 드는 조치가 있을 때
  • 서비스 유형 ② 접수·심사, ④ 기안 코파일럿, ⑥ 콘텐츠 제작, ⑦ 대조·점검, ⑩ 위험 예측, ⑪ 추천·매칭, ⑫ 개발 코파일럿처럼 C1이 필수인 유형

이럴 때는 쓰지 않는다

  • B0 결정적 도구처럼 런타임 AI 산출물이 없을 때
  • 쉽게 되돌릴 수 있고 저위험인 조치를 이미 C2로 자동 종결하도록 실측 근거를 갖춘 구간(전건 검토를 영원히 남기지 않는다)

얻는 것

  • 오류가 업무 결과로 나가기 전에 차단
  • 책임 소재가 명확해짐
  • 수정 내역이 C4 지표와 C6 환류의 원천 데이터가 됨

점검표

  • AI 산출물이 확정 전 상태로 머무는 지점이 명시되어 있는가
  • 검토자와 승인·수정·반려 선택지가 정해져 있는가
  • 검토 결정과 수정 내역이 로그로 남는가
  • 실증 기간의 검토·수정 건수가 기록되어 있는가
  • 전건 검토에서 분기로 옮길 조건이 정해져 있는가

관련 부품

C5 가드레일 필터 운영 컴포넌트

개인정보·환각·편향·형식 오류가 프롬프트나 산출물에 들어가지 못하게 시스템이 경계에서 걸러낸다. 비식별 전처리, 출처 검증, 구조적 출력 제약이 대표 변형이다.

해법

프롬프트가 기관 밖으로 나가기 전 PII를 마스킹하고 원복 키를 보관하는 비식별 전처리기를 둔다. 응답에는 인용을 원본(법령정보센터·통계표 등)과 대조하는 출처 검증기와, JSON 스키마·허용 목록 같은 구조적 출력 제약을 건다. 근거가 없으면 답하지 않거나 '확인 필요'로 표시한다. 차단 사유는 C4에 남기고, 이용자에게는 F1 출처와 F7 한계 안내로 보인다. 사람이 하는 팩트체크·법무 심의는 C5가 아니라 C1.2에 둔다.

이럴 때 쓴다

  • E2 해외 상용 API로 행정망 본문이 외부로 나갈 때(필수)
  • E5 S 이상 개인정보·민감정보를 다룰 때
  • B3 대민 응답처럼 인용·수치의 정확성이 신뢰의 핵심일 때
  • C5가 필수인 유형 ①④⑥⑦⑨⑪⑬

이럴 때는 쓰지 않는다

  • E1 로컬 PC 완결로 데이터가 밖으로 나가지 않을 때 비식별은 불필요해질 수 있다(§5 매트릭스, 단 출처 검증은 별개)
  • 사람이 수행하는 심의만 있을 때(C1.2로 태그)
  • 적대적 입력 탐지가 목적일 때(S8)

얻는 것

  • 개인정보 외부 유출 차단
  • 환각 인용 감소

F7 한계·신뢰도 안내 상호작용 패턴

AI가 무엇을 못 하는지, 얼마나 확신하는지, 공식 판단이 아님을 이용자가 볼 수 있는 곳에 적어 과신을 막는다.

해법

화면에 사용 한계(대상 범위·미검증 항목·처리 시간), 신뢰도, '공식 판단 아님' 고지를 결과 옆에 배치한다. 저신뢰 결과는 표시를 달리하고, C7 대체 경로로 운영 중이면 품질 저하를 알린다. 고지 문구는 법률 자문·유권해석을 대체하지 않는다는 점을 분명히 적는다.

이럴 때 쓴다

  • 대민 서비스 D1~D7(F1·F2·F7 최소 요건)
  • 유형 ①⑦5a⑩⑬처럼 F7이 필수인 유형
  • C7 대체 경로 운영 중

이럴 때는 쓰지 않는다

  • 유형 ①·⑦에서 model_dependency가 없음(비LLM)이면 필수에서 면제(R7). 단 비LLM 도구도 한계 고지는 권장된다

얻는 것

  • 과신·오인 방지
  • 기관 책임 범위 명확화

점검표

  • 이용자가 '공식 판단이 아님'을 결과 화면에서 읽을 수 있는가
  • 사용 한계가 명시되어 있는가
  • 저신뢰 결과가 구분 표시되는가

관련 부품

X13 도구 출력이 지시가 되는 에이전트 안티패턴

검색 결과·첨부·API 응답을 읽은 모델이 그 안의 문장을 새 명령으로 받아 도구를 부르는 구조를, 탐지 필터 하나로 지키려는 함정이다.

해법

과제의 AI가 읽는 입력 중 기관 밖에서 작성된 것을 untrusted_inputs로 나열하고, §4.2 신뢰 불가 입력 규칙대로 S4 행동 선택기(미리 정한 행동 중 선택만, 결과가 LLM으로 돌아가지 않음), S5 계획 후 실행(외부 데이터를 읽기 전에 도구 호출 계획을 고정), S6 격리 LLM(도구 있는 LLM은 외부 데이터를 읽지 않고, 읽는 LLM은 도구가 없음) 중 하나를 갖춘다. S3 컨텍스트 방화벽과 S8 독립 검증기는 보조로 붙이되 S8만으로는 규칙을 충족하지 못한다. C8 승인 게이트도 신뢰 불가 입력 규칙의 대체 통제로 인정되지 않는다(R6). 그 전 단계에서는 E4를 P0~P1 읽기·산출물 범위에 묶어 두는 것이 곧 보안이다.

이럴 때 쓴다

  • E4가 P2 이상이고 untrusted_inputs가 비어 있지 않은데 S4·S5·S6이 모두 없다(신뢰 불가 입력 규칙 위반)
  • 외부 문서를 읽는 LLM이 같은 컨텍스트에서 쓰기 도구를 호출할 수 있다
  • 인젝션 대책이 탐지 필터·프롬프트 경고문뿐이다
  • 읽은 텍스트 중 어떤 것이 어떤 도구를 부를 수 있는지 답하지 못한다

이럴 때는 쓰지 않는다

  • E4가 P0~P1로 읽기·산출물 생성에만 묶여 도구 호출·시스템 쓰기가 없는 경우(S4·S5·S6 판정 전제 불충족, R6)
  • S4·S5·S6 중 하나가 구조적으로 갖춰진 경우(보안 목적 서술이 없어도 구조가 일치하면 충족)
  • AI가 읽는 입력이 모두 기관 내부에서 작성된 경우

얻는 것

  • 단일 LLM 범용 에이전트로 구조가 단순하다
  • 새 입력·새 도구를 자유롭게 붙인다

점검표

  • untrusted_inputs가 나열되어 있는가
  • 신뢰 불가 입력을 읽은 LLM이 쓰기 도구를 직접 부를 수 없는가
  • S4·S5·S6 중 하나가 구조로 구현되어 있는가
  • S8 탐지를 유일한 방어로 두지 않았는가

관련 부품

X16 기준을 노출하는 위조 탐지 안티패턴

진위 판정 근거를 이용자 화면에 그대로 보여 줘 위조범이 탐지 기준을 역추적하게 만드는 함정이다. F9 근거 표시가 적대적 접점에서는 취약점이 된다.

해법

F9 판정 근거·기여도 표시를 역할별로 나눈다. 이용자 화면에는 '정상/위조의심'만 노출하고, 의심 부위·사유 코드·기여도 같은 세부 근거는 관리자 화면에만 보여 준다(근거 은닉, anti-oracle — 카탈로그가 S 계층 후보로 둔 반대편 부품). 관리자 화면 접근은 C8 권한 경계로 제한하고, '위조의심' 건은 C1 검토 큐에서 담당자가 세부 근거를 보고 확정한다. 이용자에게는 F7 한계·신뢰도 안내로 추가 확인 절차를 알리고, 반복 제출·판정 이력은 C4·S10에 남겨 역추적 시도를 탐지할 근거로 삼는다.

이럴 때 쓴다

  • 진위·위조 판정 결과와 함께 세부 근거(의심 부위·사유 코드·점수)가 제출자 화면에 표시된다
  • 제출자가 근거를 보고 수정해 반복 재제출할 수 있다
  • 이용자 중 탐지 회피 동기를 가진 적대자가 있을 수 있다
  • 관리자와 이용자의 판정 화면이 같다

이럴 때는 쓰지 않는다

  • 내부 담당자만 쓰는 판독 도구로 제출자에게 결과가 노출되지 않는 경우
  • 이용자가 적대자가 아닌 접점(예: 내부 품질 점검, 자기 서류 오류 안내)에서 F9로 근거를 보여 주는 경우 — 이때 F9는 정상 부품이다
  • 이용자에게 '정상/위조의심'만 보여 주고 세부 근거는 관리자 화면에 둔 경우

얻는 것

  • 투명성·설명 가능성 요구를 쉽게 충족한다
  • 선의의 이용자가 오류를 스스로 고칠 수 있다

점검표

  • 제출자 화면에 세부 판정 근거가 노출되지 않는가
  • 세부 근거가 관리자 화면에서만 보이고 접근이 제한되는가
  • 위조의심 건을 사람이 확정하는가
  • 반복 재제출 이력이 기록되는가
