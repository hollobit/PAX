판정 근거

의원 요구자료를 문항별로 나눠 주관·협조 부서에 배정(B′2)하고, 과거 회신·현안 자료를 근거로 붙이며(B3 secondary), 로컬 모델이 있으면 근거 기반 회신 초안(B1)을, 없으면 검색·발췌만으로 동작한다. 최종 산출물은 사람이 확정한 제출 묶음이라 R1상 B1 주 부품으로 보되, AI 없는 경로도 완결되므로 B0를 secondary, 그 축소 경로를 C7 implemented로 태그했다. 회신 버전 관리·대조는 C3 implemented와 F8, 근거 연결은 F1, 회신 편집은 F2. 수치와 최종안의 사람 확정은 C1 implemented(합성 사례 검증 중인 프로토타입이라 present 아님). 인증·권한·기관별 데이터 격리 미구현을 스스로 밝혀 S2는 planned, 파일럿 전이라 구현·미배포에 blocker 보안검토. 유형은 R23 기준 판정 목적이 아닌 취합·전달이라 8. case_url이 없어 README·소개 페이지를 읽지 못했다(URL 미확인, 원장 요약·PAX 평가만으로 판정).

구현 가이드

주 패턴 B1 코파일럿을 구현할 때

구현 단계

  1. 대상 문서의 서식·필수 항목·문체 규범을 정리해 A9 스킬(프롬프트 템플릿)로 만든다.
  2. 업무 질문·모범 답안·채점 기준으로 C9 평가 세트를 먼저 만들어 모델·프롬프트 선택을 잰다.
  3. E1·E5에 맞는 모델 경로를 정한다. 행정망이면 BYO 대신 A2 내부망 프록시, 민감 자료면 C5 비식별을 앞단에 둔다.
  4. 산출물을 F2 편집 가능 출력과 A10 서식으로 내고, C1 검토 큐에서 담당자가 확정하게 한다.
  5. 수정률·처리시간을 C4로 집계하고, 저위험 유형이 확인되면 C2 자동 확정 분기를 검토한다.

점검표

  • 담당자가 최종 확정한다는 절차가 운영되는가
  • 서식·문체 규범이 A9 스킬로 분리되어 있는가
  • 초안을 이용자가 직접 고칠 수 있는가(F2)
  • 수정 내역이 기록되어 품질 개선에 쓰이는가

환경 조건

E1 행정망이면 BYO 코딩 에이전트를 쓸 수 없어 A2 내부망 프록시가 필요하다. E1 로컬 PC 완결이면 A9 스킬 + A10 어댑터 조합이 된다. E2 해외 상용 API면 직접 호출 대신 A2 게이트웨이를 거친다. E2 모델 중립(BYO)이면 A9 스킬 형태로 배포하고 모델 교체 가능성이 곧 C7이다. E4는 P1이 기본이고, P2로 올라가면 C1 전건 검토 → C2 분기로 바꾼다.

주의할 점

  • 전건 검토가 영원히 남으면 업무 순서는 그대로(First 불가)
  • 상용 API 직접 호출 시 X4 위험
  • 행정망에서는 BYO 불가로 A2 내부망 프록시가 선행되어야 함

피해야 할 안티패턴

  • X1 AI 스티커 기존 화면에 요약·챗봇 버튼만 붙이고 업무 순서와 사람·AI의 역할 분담은 그대로 두어, AI가 있어도 업무 산출물이 바뀌지 않는 함정이다. 대처: 먼저 가치 흐름 규칙(R1)으로 사람 또는 국민이 최종으로 받는 핵심 산출물을 정하고, 그 산출물을 AI가 어떤 모양으로 분담할지 B 업무 컴포넌트를 하나 고른다(초안→사람 확정이면 B1, 근거 접지 답변이면 B3, 서류 추출이면 B4). 사람이 확정하는 지점은 C1 검토 큐로, 이용자가 고쳐 확정하는 면은 F2 편집 가능한 출력으로 명시한다. 흐름이 바뀌었는지는 C4 감사 로그·지표의 처리시간·수정률로 잰다. AI 런타임이 전혀 없는 행정정보시스템이라면 AI로 포장하지 말고 R24대로 B0·service_type 0·platform 공란·X1(AI 무관)으로 정직하게 분류한다.
  • X4 단일 모델 인질 상용 API 하나에 전 기능이 묶여 있어, 그 API가 멈추거나 바뀌면 무슨 일이 생기는지 아무도 답하지 못하는 함정이다. 대처: 모델 호출을 A2 모델 서빙 계층 뒤로 숨겨 B 부품이 특정 벤더 API를 직접 부르지 않게 한다. 그 위에 C7 폴백 스위치로 재시도 → 기존 API → 대체 MCP → 대체 모델(A2.2 주권형 로컬 등) → 규칙 기반 축소 → 수동 전환의 경로를 정하고 전환 이력을 C4에 남긴다. 모델 교체가 실제로 안전한지는 C9 평가 세트로 재어 버전을 고정한다. 모델 중립(BYO) 배포라면 A9 스킬 형태로 배포해 모델 교체 가능성 자체를 폴백으로 삼는다.
  • X10 평가 없는 RAG, RAG 없는 튜닝 평가 세트 없이 검색을 붙여 '좋아진 것 같다'로 배포하고, 검색으로 풀릴 문제를 파인튜닝으로 푸는, 진행 경로를 건너뛰는 함정이다. 대처: §7.2 진행 경로를 순서대로 밟는다. B1 직접 프롬프트에서 시작해 두 번째 단계에서 C9 평가 세트(업무 질문·정답·채점 기준)를 먼저 만들고, 이후 A9 규범 스킬·F4, B3 지식 접지(A1 데이터 자산), B3 검색 품질(Hybrid·Rewriting·Reranker), C5 가드레일·F1 순으로 붙이며 매 단계를 C9로 잰다. A2.3 튜닝은 진행 경로의 마지막 단계로, 검색·규범 스킬로 풀리지 않는다는 것이 C9 점수로 확인됐을 때만 한다. 모델·프롬프트·설정 조합은 릴리스처럼 버전 관리한다.

B3 지식 접지 상담 업무 컴포넌트

기관 규정·매뉴얼·사례 문서에 접지(RAG)해 질문에 답하고, 답마다 출처를 붙이며, 근거가 없으면 답하지 않고 담당자에게 넘긴다.

PAX 사례 48건이 이 부품을 쓴다

맥락

규정·매뉴얼·FAQ·사례가 문서로 쌓인 기관에서 내부 검색·검수, 대민 자동응답, 폐쇄망 로컬 검색에 쓴다. PAX 557건에서 주 부품이 B3인 사례는 31건으로 B0·B1 다음이다. 유형 ① 대민 상담·안내의 기본 조립이기도 하다.

맞서는 힘(긴장)

  • 답변 범위 vs 환각 위험(근거 밖 답변 금지)
  • 대민 자동응답의 효율 vs 예외 건 이관 필요
  • 검색 품질 개선 vs 평가 세트 없이는 개선을 잴 수 없음
  • 폐쇄망 요구 vs 로컬 임베딩·모델 품질

해법

기관 문서를 A1 자산으로 정리해 임베딩·색인하고, 질문이 오면 검색한 근거 범위 안에서만 모델이 답하게 한다. 답에는 출처(F1)를 상시 붙이고, 근거가 없으면 '확인 불가'로 답하거나 담당자·소관기관으로 이관한다(B′2). 검색 품질은 Hybrid Retriever·Query Rewriting·Reranker로 높이되, 변경마다 C9 평가 세트로 잰다. 대민형은 한계 안내(F7)와 폴백(C7)을 두고, 문서 갱신 주기를 C6으로 정한다.

이럴 때 쓴다

  • 같은 질문이 반복되고 답의 근거가 기관 문서에 있을 때
  • 답변에 조문·문서 출처를 반드시 붙여야 할 때
  • 유형 ① 대민 상담·안내, 유형 ⑦ 법령 접지 점검

이럴 때는 쓰지 않는다

  • 평가 세트가 없어 검색 품질을 잴 수 없을 때(먼저 C9, X10)
  • 질문 유형이 몇 개로 정해져 행동 선택기(S4)나 규칙 조회로 충분할 때
  • 문서를 요약해 초안을 쓰는 것이 핵심이면(B1)

얻는 것

  • 답변에 근거를 댈 수 있음
  • 반복 질의 처리 시간 단축
  • 범정부 엔진 + 기관별 코퍼스로 공유 가능

점검표

  • 답마다 출처가 표시되는가
  • 근거가 없을 때 답하지 않고 이관하는가
  • 평가 세트로 검색·답변 품질을 재고 있는가
  • 코퍼스 갱신 주기와 책임자가 정해져 있는가

구조 — 참여 부품

  • A1 데이터 자산 서비스 — 코퍼스 정제·등급 메타
  • A2 모델 서빙 계층 — 임베딩·생성 모델(폐쇄망이면 로컬)
  • 검색기 — 벡터·키워드 검색, 재작성·재순위
  • C5 가드레일 필터 — 출처 검증·근거 밖 답변 차단
  • F1 출처 표시 — 근거 문서·조문을 답에 표시
  • 담당자 — 내부형 검수, 대민형 예외 건 처리

변형

  • 내부 검수형: 직원이 쓰고 답을 검수(Enabled)
  • 대민 자동응답형: 국민에게 직접 답하고 예외만 이관(이관 분기가 있으면 First)
  • 폐쇄망 로컬 RAG: 내부망 LLM + 로컬 임베딩·벡터DB
  • 검색 품질 하위 항목: Hybrid Retriever(벡터+키워드)·Query Rewriting·Reranker. 태깅 시 variant에 기재(Fowler)
  • 그래프 RAG: A6 지식그래프를 검색에 결합(rag_type = Graph)

B0 결정적 도구 업무 컴포넌트

AI 코딩으로 만들었지만 런타임에는 AI를 부르지 않고 규칙과 원문 발췌만으로 같은 입력에 같은 결과를 내는 취합·변환·검색·시각화 도구다.

PAX 사례 413건이 이 부품을 쓴다

맥락

AI 코딩 도구(A7)로 기관 인력이 직접 만든 자생 도구가 대부분이다(PAX 557건 가운데 주 부품이 B0인 사례 390건, 70%). 로컬 PC 완결이나 폐쇄망 이식이 필요한 업무, 판정 재현성이 감사에서 중요한 업무에도 맞는다. model_dependency가 '없음(비LLM)'으로 확인될 때만 해당한다.

맞서는 힘(긴장)

  • 재현성·설명 가능성 vs 비정형 입력을 다루는 유연성
  • 로컬 완결의 보안 이점 vs 기관 전이 시 처리 로그(C4)와 인수인계가 사라지는 문제
  • 규칙을 코드에 넣는 단순함 vs 규정이 바뀔 때마다 사람이 규칙을 고쳐야 하는 유지 부담

해법

업무 절차를 입력 형식(A10 어댑터)과 처리 규칙으로 나누고, AI 코딩 도구(A7)는 개발 시점에만 써서 규칙 코드와 화면을 만든다. 런타임에는 모델을 호출하지 않으므로 같은 입력에 같은 결과가 나오고 인터넷 없이 로컬에서 돈다. 판정이 필요한 경우에도 결정적 규칙 엔진이 낸다. 비정형 입력을 다뤄야 하는 단계가 생기면 그 단계만 B1·B3로 승격하고 결정적 부분은 전처리로 남긴다. 부서 밖으로 옮길 때는 라이선스·저장소·처리 로그를 함께 갖춘다.

이럴 때 쓴다

  • 입력이 정형(엑셀·서식)이고 처리 결과를 규칙으로 정의할 수 있을 때
  • 파일이 PC 밖으로 나가면 안 되거나 폐쇄망·로컬 완결이 필요할 때
  • 판정 재현성이 필요해 같은 입력에 늘 같은 결과가 나와야 할 때(규칙 점검기, 결정론 점수 엔진)
  • LLM 도입 전에 데이터·기준선을 정비하는 단계일 때

이럴 때는 쓰지 않는다

  • 비정형 문서의 요약·초안처럼 규칙으로 산출물을 정의할 수 없을 때(B1)
  • 질문이 다양해 규정·선례 접지가 필요한 상담일 때(B3)
  • 학습 모델의 수치·등급 예측이 핵심 산출물일 때(B2)

얻는 것

  • 재현성과 감사 가능성
  • 폐쇄망·로컬 이식이 가장 쉬움
  • 모델 호출 비용과 모델 장애 위험이 없음
  • B1·B3의 전처리 부품으로 승격할 자산

점검표

  • 런타임에 LLM·ML 호출이 전혀 없는가
  • 규칙 표가 코드와 별도로 문서화되어 있는가
  • 같은 입력에 같은 결과가 나오는지 확인했는가
  • 라이선스와 저장소 위치가 명시되어 인수인계가 가능한가

구조 — 참여 부품

  • A7 자체 제작 환경 — 개발 시점에 AI 코딩으로 규칙 코드와 화면을 만드는 곳
  • A10 문서 형식 어댑터 — HWP·HWPX·엑셀 입출력
  • 규칙 엔진 — 조건→결과 표에 따라 결정적으로 취합·판정·정렬

B1 코파일럿 업무 컴포넌트

맥락

  • 초안 속도 vs 전건 검토에 드는 사람 시간
  • 상용 모델 품질 vs 행정망·민감정보 제약(E1·E5)

해법

이럴 때 쓴다

B′1 순차 파이프라인 제어 흐름

한 단계의 출력을 다음 단계의 입력으로 넘기는 고정 순서 배선이다. 한 프롬프트에 많은 일을 몰아 시켜 품질이 떨어지는 문제를 막는다.

PAX 사례 109건이 이 부품을 쓴다

맥락

B4 인식 파이프라인의 기본 배선이며, B1·B0·B5 안에서도 흔하다. 단계 순서가 업무 절차로 미리 정해져 있고 AI가 순서를 고를 필요가 없을 때 쓴다.

맞서는 힘(긴장)

  • 디버깅·출처 추적의 쉬움 vs 병렬화 불가로 인한 지연
  • 단계 분리의 품질 이점 vs 단계가 늘수록 오류 누적
  • 고정 순서의 예측 가능성 vs 예외 경로 처리의 경직성

해법

업무 절차를 단계로 나누고 각 단계의 입력·출력 형식을 정해 앞 단계 출력을 다음 단계에 넘긴다. 단계 사이에 형식 검증(스키마)을 두어 오류가 번지기 전에 멈추고, 멈춘 건은 C1 검토 큐나 C3 재처리로 보낸다. 판정·산수 단계는 가능한 한 규칙(B′9)으로 두고 모델은 추출·서술 단계만 맡긴다. 단계 순서를 AI가 바꿔야 한다면 B′8이나 B′7로 옮긴다.

이럴 때 쓴다

  • 업무 절차가 고정 순서로 정해져 있을 때
  • 각 단계를 따로 검증·추적해야 할 때(유형 ② 접수·심사, ⑧ 취합·변환)
  • 단일 에이전트에서 시작하는 첫 배선일 때

이럴 때는 쓰지 않는다

  • 하위 작업이 서로 독립이라 동시에 돌려야 지연이 줄 때(B′3)
  • 입력에 따라 AI가 다음 도구를 골라야 할 때(B′7)
  • 긴 업무를 계획부터 세워야 할 때(B′8)

얻는 것

  • 디버깅과 출처 추적이 쉬움
  • 단계별 품질 검증 가능
  • 구현이 가장 단순

점검표

  • 단계마다 입력·출력 형식이 정의되어 있는가
  • 단계 사이 검증에서 실패하면 멈추는가
  • 단계별 중간 결과를 추적할 수 있는가

구조 — 참여 부품

  • 단계 처리기 — 각 단계에서 추출·변환·작성 수행
  • 단계 간 형식 검증 — 다음 단계로 넘기기 전 스키마 확인
  • C3 상태 머신·롤백 — 실패 단계 재처리

B′2 라우터·디스패처 제어 흐름

요청의 의도·유형·난이도를 읽어 전문 경로·모델·도구·담당자로 보내는 배선이다. 모든 건을 같은 경로로 보내는 낭비를 막는다.

PAX 사례 23건이 이 부품을 쓴다

맥락

대민 상담(B3)의 예외 이관, 규칙 선필터로 LLM 호출 줄이기, 폐쇄망 모델과 외부 모델 사이의 모델 라우팅, 여러 MCP를 한 서버에서 경로별로 제공하는 구성에 쓴다. C2 위험도 라우터의 내부 원형이고, D4 분류·이관을 기술로 구현한 실체다.

맞서는 힘(긴장)

  • 경로 분리의 효율 vs 라우팅 오류라는 새 위험
  • 규칙 라우팅의 예측 가능성 vs 모델 라우팅의 유연성
  • 외부 모델 분기의 품질 vs 경계 통제(E1·E5)

해법

요청을 분류하는 단계(규칙·경량 모델·LLM)를 앞에 두고, 분류 결과마다 처리 경로(규칙 판정, LLM 판정, 담당자 이관, 판단 불필요)를 정한다. 경로별 처리 비율을 C4로 실측해 라우팅 품질을 보고, 분류가 불확실한 건은 사람에게 보낸다(C2·F11). 모델 라우팅은 A2 서빙 계층의 기능으로 두고 외부 모델로 나가는 분기에는 C5 비식별을 건다. 보안이 필요한 대민 접점에서는 LLM이 미리 정한 행동 중 선택만 하게 제약해 S4로 만든다.

이럴 때 쓴다

  • 요청 유형마다 처리 비용·방법이 뚜렷이 다를 때
  • 답할 수 없는 건을 담당자로 이관해야 할 때(유형 ① 대민 상담)
  • LLM 호출 비용을 줄여야 할 때

이럴 때는 쓰지 않는다

  • 요청 유형이 하나뿐일 때
  • 분류 오류의 비용이 큰데 분류 품질을 잴 방법이 없을 때
  • 라우팅 대신 규칙으로 판정 모델 호출 대상 자체를 좁히는 구조일 때(B′10)

얻는 것

  • 호출 비용 절감
  • 답할 수 없는 건의 이관
  • 경로별 전문화

점검표

  • 경로별 처리 비율을 실측하는가
  • 분류가 불확실할 때 사람에게 가는 경로가 있는가
  • 외부 모델로 나가는 분기에 비식별이 걸려 있는가

구조 — 참여 부품

  • 분류기 — 의도·유형·난이도 판별(규칙 또는 모델)
  • 전문 경로 — 유형별 처리 모델·도구·규칙
  • C2 위험도 라우터 — 위험도·신뢰도 기반 사람 이관
  • C4 감사 로그·지표 — 경로별 처리 비율 실측

A2.2 모델 서빙 · 주권형 온프레미스 공통 서비스

오픈웨이트 모델을 기관 서버·폐쇄망·로컬 PC 안에서 Ollama·vLLM 등으로 구동해 데이터를 기관 밖으로 내보내지 않고 추론한다.

PAX 사례 54건이 이 부품을 쓴다

맥락

E1은 폐쇄망·행정망·로컬 PC, E2는 해외 오픈웨이트(로컬) 또는 국산 오픈웨이트, E5는 S 이상이다. 폐쇄망 B3·B6·B8, 유형 3(현장 폐쇄망 서버 추론), 유형 12 개발 코파일럿은 이 변형을 기본으로 쓴다.

맞서는 힘(긴장)

  • 데이터 주권 vs 상용 최신 모델 대비 성능
  • GPU·서버 고정비 vs 종량 과금
  • 모델 운영·갱신 역량 vs 외부 의존 제거
  • 저사양 장비 구동 vs 모델 크기

해법

오픈웨이트 모델을 기관 안에 설치하고 서빙 계층(Ollama·vLLM·LM Studio 등)으로 업무 부품에 노출한다. 임베딩 모델도 로컬로 두어 B3 검색까지 망 안에서 끝낸다(§5 E1 폐쇄망 행 '로컬 임베딩'). 모델 선정은 C9 평가 세트로 상용·온프레미스 후보를 같은 조건에서 비교해 정한다. 폐쇄망에서 C7 경로는 수동 전환·다른 로컬 모델로 제한되므로 둘 이상의 로컬 모델이나 수동 절차를 미리 둔다. 모델·패키지 반입은 S11 인제스천 검증을 거친다.

이럴 때 쓴다

  • E1이 폐쇄망·행정망이거나 문서가 PC 밖으로 나가면 안 될 때
  • E5가 S 이상인데 내부망 프록시(A2.4)를 쓸 수 없을 때
  • 현장 폐쇄망 서버에서 추론해야 하는 유형 3
  • C7의 대체 경로로 로컬 모델을 둘 때

이럴 때는 쓰지 않는다

  • 추론 인프라·운영 인력을 확보할 수 없을 때
  • 현장 기기 자체에서 돌아야 하면 A5(엣지 런타임)
  • 모델을 재학습했으면 A2.3

얻는 것

  • 데이터가 기관 밖으로 나가지 않음
  • 호출 비용이 고정비로 바뀜
  • 폐쇄망에서도 LLM 사용 가능
  • C7의 대체 경로 후보

점검표

  • 추론·임베딩 어디에서도 데이터가 망 밖으로 나가지 않는가
  • 모델 선정 근거(평가 세트 비교)가 남아 있는가
  • 반입한 모델·패키지의 무결성 검사 기록이 있는가
  • 대체 로컬 모델 또는 수동 전환 절차가 있는가

구조 — 참여 부품

  • A2 서빙 계층 — 로컬 모델을 업무 부품에 노출
  • 오픈웨이트 모델·로컬 임베딩 — 기관 안에서 추론·색인
  • GPU 서버 또는 워크스테이션 — 추론 인프라
  • S11 인제스천·공급망 검증 — 폐쇄망 반입 모델·패키지 검사

변형

  • 기관 서버형: vLLM 등으로 기관 GPU 서버에서 다수 이용자에게 서빙한다.

  • 범정부 공통기반 내부망 설치형: 국산 독자모델·오픈웨이트를 공통기반 내부망에 직접 설치해 여러 부처에 제공한다(PAX 행정안전부 사례).

A10 문서 형식 어댑터 공통 서비스

HWP·HWPX·엑셀·한셀·PDF 같은 한국 공공 문서 형식을 AI 부품이 읽고(구조화) 쓰게(서식 생성) 하는 변환 계층이다.

PAX 사례 136건이 이 부품을 쓴다

맥락

문서를 입력으로 받거나 기안·보고서·취합본을 산출하는 과제라면 거의 다 쓴다. 유형 2·4·8에서는 필수 기반이고 유형 6·7에서도 쓰인다. E1 로컬 PC 조건에서 도는 경우가 많다.

맞서는 힘(긴장)

  • 형식 충실도(표·각주·조항 구조 보존) vs 파서 구현 비용
  • 로컬 처리(무반출) vs 클라우드 변환 도구의 편의
  • 기관별 서식 다양성 vs 공통 어댑터 재사용

해법

입력 쪽에서는 HWPX 압축 구조·PDF에서 조·항·호·별표 계층과 표를 보존해 구조화 텍스트·표로 바꾸고, 머리말·각주 같은 잡음을 걷어 조항 단위로 정규화한다. 출력 쪽에서는 스킬(A9)의 출력 서식을 받아 HWPX·XLSX 기안 서식을 역방향으로 생성한다. 민감 문서는 PC 밖으로 보내지 않도록 로컬에서 변환하고, 파서를 라이브러리·CLI·MCP로 함께 제공하면 다른 부품과 기관이 그대로 쓴다. 형식 변환 정확도는 C9 판정 체계로 잰다.

이럴 때 쓴다

  • 입력이 HWP·HWPX·엑셀·PDF 공공 문서일 때
  • 산출물을 기안·보고 서식으로 내보내야 할 때
  • 유형 2·4·8 조립

이럴 때는 쓰지 않는다

  • 스캔 이미지·음성처럼 인식이 필요한 입력은 B4 인식 파이프라인(OCR·STT)
  • 입출력이 이미 정형 데이터·API인 경우

얻는 것

  • 공공 문서를 AI 입력·출력으로 연결
  • 기관 간 재사용 가능한 공통 부품
  • 로컬 처리로 무반출

점검표

  • 표·조항 계층이 변환 후에도 보존되는가
  • 출력이 기관 기안 서식 그대로 열리는가
  • 민감 문서가 변환 과정에서 PC 밖으로 나가지 않는가
  • 변환 정확도 판정 기록이 있는가

구조 — 참여 부품

  • 입력 파서 — 조·항·호·표 구조를 보존해 구조화

  • B3 지식 접지 상담 — 구조화된 규정을 색인해 검색

변형

C1 검토 큐 운영 컴포넌트

AI 산출물이 다음 단계로 넘어가기 전에 사람이 맞고 틀림을 확인·수정·확정하는 대기열을 두어, 오류가 업무 결과로 흘러가지 않게 한다.

PAX 사례 46건이 이 부품을 쓴다

맥락

AI 산출물이 공문·처분·대민 안내·기록으로 이어지는 모든 B 부품(B1 코파일럿, B4 인식 파이프라인, B2 예측기, B7 콘텐츠 생성기 등). 이용자 본인이 최종 확정자인 자기서비스형 도구도 포함한다(R16).

맞서는 힘(긴장)

  • 정확성·책임성 vs 처리 속도(전건 검토는 자동화 이득을 깎는다)
  • 검토자의 숙련 vs 자동화 편향(AI 결과를 그대로 승인하는 경향)
  • 전건 검토의 안전 vs 위험도별 분기(C2)로 가야 하는 효율 압력

해법

AI 산출물에 신뢰도·근거를 붙여 검토 대기열에 올리고, 검토자가 승인·수정·반려 중 하나를 고르게 한다. 수정·반려 내역은 C4 감사 로그에 남겨 수정률을 집계하고 C6 환류의 입력으로 쓴다. 검토 화면은 원문 위치·근거를 함께 보여 줘 확인 비용을 줄인다. 전건 검토로 시작하되, 수정률 실측이 쌓이면 C2 위험도 라우터로 저위험 건을 자동 종결하는 단계로 옮긴다.

이럴 때 쓴다

  • AI 산출물이 공문·처분·대민 안내로 그대로 이어질 때
  • E4가 P1 이상이고 되돌리는 데 사람 시간이 많이 드는 조치가 있을 때
  • 서비스 유형 ② 접수·심사, ④ 기안 코파일럿, ⑥ 콘텐츠 제작, ⑦ 대조·점검, ⑩ 위험 예측, ⑪ 추천·매칭, ⑫ 개발 코파일럿처럼 C1이 필수인 유형

이럴 때는 쓰지 않는다

  • B0 결정적 도구처럼 런타임 AI 산출물이 없을 때
  • 쉽게 되돌릴 수 있고 저위험인 조치를 이미 C2로 자동 종결하도록 실측 근거를 갖춘 구간(전건 검토를 영원히 남기지 않는다)

얻는 것

  • 오류가 업무 결과로 나가기 전에 차단
  • 책임 소재가 명확해짐
  • 수정 내역이 C4 지표와 C6 환류의 원천 데이터가 됨

점검표

  • AI 산출물이 확정 전 상태로 머무는 지점이 명시되어 있는가
  • 검토자와 승인·수정·반려 선택지가 정해져 있는가
  • 검토 결정과 수정 내역이 로그로 남는가
  • 실증 기간의 검토·수정 건수가 기록되어 있는가
  • 전건 검토에서 분기로 옮길 조건이 정해져 있는가

구조 — 참여 부품

  • 검토 대기열 — AI 산출물을 확정 전 상태로 보관하고 검토자에게 배정
  • 검토자(담당자 또는 이용자 본인) — 승인·수정·반려를 결정하는 최종 책임자
  • F2 편집 가능한 출력 — 검토자가 산출물을 직접 고치는 화면
  • C4 감사 로그·지표 — 검토 결정과 수정 내역을 적재해 수정률로 집계

변형

  • 전건 검토형: 모든 AI 산출물을 담당자가 확인·확정
  • 예외 검수형: 정상 건은 일괄 승인하고 저신뢰 항목만 개별 검수하는 검수 UI
  • 파이프라인 내장 관문형: 멀티에이전트·다단계 파이프라인의 각 관문에 승인·보완·재작성 선택지를 둠
  • 자기서비스형: 이용자 본인이 최종 확정자인 HITL. 실제 운영 중이면 C1 present(R16)
  • 심의 게이트: 팩트체크·법무·윤리처럼 제3자 전문가가 수행하는 승인 게이트

C3 상태 머신·롤백 운영 컴포넌트

건이 끝났음을 시스템이 알게 하고, 잘못 처리된 건을 되돌리는 경로(롤백·재처리·이의제기)를 제공한다. 여러 시스템에 걸친 처리는 보상 트랜잭션으로 되돌린다.

C7 폴백 스위치 운영 컴포넌트

모델·API·도구가 멈추거나 품질이 떨어질 때 대체 모델·규칙 기반 축소·수동 처리로 경로를 바꿔 서비스가 끊기지 않게 한다.

PAX 사례 12건이 이 부품을 쓴다

맥락

상용 API 또는 단일 모델에 의존하는 모든 B 부품. 특히 E2가 해외 상용 API이거나 B5처럼 상시 가동해야 하는 서비스.

맞서는 힘(긴장)

  • 가용성 vs 비용(대체 경로를 상시 유지하는 비용)
  • 품질 일관성 vs 대체 경로의 품질 저하
  • 자동 전환의 신속성 vs 전환 판단의 오작동 위험

해법

오류율·지연·단가 신호를 감시하다가 임계를 넘으면 재시도 → 기존 API → 대체 MCP → 대체 모델 → 규칙 기반 축소 → 수동 전환 순으로 경로를 바꾼다. 장애 범위는 격리(Bulkhead)로 한 부품에 가두고, 모델 교체는 무중단(Blue-Green)으로 한다. 전환은 C4 감사 로그에 남기고, 복구 후에는 원래 경로로 되돌리는 조건도 함께 정한다. 대체 경로의 품질 저하는 이용자에게 F7 한계 안내로 알린다.

이럴 때 쓴다

  • E2가 해외 상용 API이거나 혼합일 때
  • B5 현장 감지·경보처럼 상시 서비스일 때 필수
  • 대민 자동응답(B3 대민형)처럼 중단 비용이 큰 경우
  • 유형 ① 대민 상담(상시), ③ 현장 감시

이럴 때는 쓰지 않는다

  • B0 결정적 도구처럼 런타임 AI가 없을 때
  • 로컬 완결 도구로 외부 의존이 없을 때
  • 유형 ①·⑦에서 model_dependency가 없음(비LLM)일 때는 필수에서 면제(R7)

얻는 것

  • 핵심 서비스 연속성
  • 벤더 종속 완화(X4 예방)

점검표

  • 대체 경로가 최소 하나 구현되어 있는가
  • 전환 임계와 복귀 조건이 수치로 정의되어 있는가
  • 전환 이력이 로그로 남는가
  • 실증 기간에 전환을 1회 이상 실행한 기록이 있는가

구조 — 참여 부품

  • A2 모델 서빙 계층 — 주 경로와 대체 모델을 함께 노출하는 끼울 자리
  • 상태 감시기 — 오류율·지연을 임계와 비교해 전환을 결정
  • C4 감사 로그·지표 — 전환 시점·사유·복구를 기록
  • 수동 처리 담당자 — 모든 자동 경로가 실패했을 때의 최종 경로

변형

  • 대체 모델 전환: 상용 API 장애 시 다른 상용 모델 또는 로컬 오픈웨이트 모델(A2.2)로 전환

S2 권한 인식 검색 보안 패턴

검색·생성 전에 요청자의 권한으로 문서 단위 접근을 판정해, 모델이 볼 수 없는 문서는 검색 결과에도 나타나지 않게 한다.

PAX 사례 2건이 이 부품을 쓴다

맥락

B3 지식 접지를 부서·등급이 섞인 코퍼스 위에 올리는 경우(전북AI 유형 내부망 RAG), 인수인계·지식 보존(유형 ⑨)처럼 전임자 파일 더미를 코퍼스화하는 경우, 대민 챗봇이 내부 문서와 공개 문서를 함께 보는 경우. 카탈로그 등재 상태는 후보.

맞서는 힘(긴장)

  • 답변 범위의 풍부함 vs 권한 밖 문서의 요약 노출
  • 문서 메타(등급·부서) 정비 비용 vs 필터 정확도
  • 검색 성능 vs 요청마다 권한 판정하는 지연

해법

요청자 신원·역할과 문서 메타(E5 등급·부서·소유자)를 대조해 허용 문서 집합을 먼저 만든 뒤, 그 집합 안에서만 검색하고 생성한다. 권한 판정은 서버 측에서 하고 모델이나 프롬프트에 맡기지 않는다. 문서 메타는 A1 문서 자산 단계에서 정비하고, 인용(출처)도 같은 권한 검사를 거치게 한다. 가장 단순한 형태는 대민 챗봇 코퍼스에 공개(O) 문서만 두는 것이다.

이럴 때 쓴다

  • 부서 간 문서를 한 코퍼스에 넣는 내부망 RAG
  • 인수인계·지식 보존(유형 ⑨)의 필수 부품(C5와 함께)
  • 대민 상담(유형 ①)에서 공개 문서만 쓰도록 강제할 때(권장)
  • 내부 문서·기안 코파일럿(유형 ④)에서 등급 문서 요약 유출이 우려될 때(권장)

이럴 때는 쓰지 않는다

  • 코퍼스 전체가 공개(O) 문서이고 이용자 구분이 없을 때 — 이미 공개 문서 한정형을 충족
  • 개인 PC에서 본인 문서만 검색하는 로컬 도구
  • 검색 단계가 없는 생성·변환 도구

얻는 것

  • 등급 문서의 요약 노출을 설계로 차단(증명 가능)
  • 권한 상승 경로 제거
  • 기관 내 코퍼스 통합이 가능해짐

점검표

  • 권한 판정이 모델·프롬프트가 아닌 서버 측 필터에서 이루어지는가
  • 모든 문서에 등급·부서 메타가 있는가
  • 권한 밖 문서가 인용·출처 표시에도 나타나지 않는가
  • 권한별 접근 시험이 자동화되어 있는가

구조 — 참여 부품

  • A1 데이터 자산 서비스 — 문서별 등급·부서 메타 정비
  • 권한 판정기 — 요청자 역할과 문서 메타를 대조해 허용 집합 산출(서버 측)
  • B3 지식 접지 — 허용 집합 안에서만 검색·생성
  • A3 공공 인증 — 요청자 신원 제공

D8.5 취합·정산 서비스 블록

부서별 자료를 모으고 엑셀·한셀을 합치고 정산하는 내부 운영 블록이다. 서무의 핵심 반복 업무이며 B0 문서·엑셀 자동화와 A10이 전형 부품이다.

PAX 사례 36건이 이 부품을 쓴다

맥락

부서별 제출 파일을 모으고 합치고 정산하는 업무. §7.3 유형 ⑧ 취합·변환 자동화(D8.5 · D8.9, P1). PAX 36건(주 부품 B0 89%, B1 6%). 업무 영역별 PAX 건수(557건 태깅): 회계·정산 13, 문서·기안 8, 공통·범용 4, 데이터·통계 3, 감사·법무 2, 계약·조달 2, 시설·안전 2, 인사·복무 1, 기획·정책 1.

맞서는 힘(긴장)

  • 자동화 속도 vs 원본 훼손·정산 오류
  • 폐쇄망 설치형의 편의 vs 배포·갱신 관리
  • 개인 제작 도구의 민첩성 vs 인사이동 시 소멸(X9)
  • 제출 파일 자동 처리 vs 파일 속 매크로·지시 위협

해법

B0 문서·엑셀 자동화로 B′1 순차 배선(수집 → 양식 정규화 → 병합 → 정산 → 서류 생성)을 만든다. 파일은 A10 어댑터로 엑셀·한셀·HWPX를 읽고 쓴다. 원본은 보존하고 결과만 새로 만들어 C3로 원복할 수 있게 하고, F8로 처리 이력을 되돌릴 수 있게 한다. 제출 파일은 S11 파일 검사와 S9 격리 실행을 거친다. 기관 인력이 직접 만들었다면 A7 자체 제작 환경의 라이선스·저장소를 명시해 X9를 피하고, 기관으로 전이할 때 C4 처리 로그를 둔다.

이럴 때 쓴다

  • 부서별 파일을 모아 합치는 반복 업무
  • 규칙이 분명한 정산·서류 생성
  • 폐쇄망에서 설치형으로 돌려야 할 때

이럴 때는 쓰지 않는다

  • 파일 형식 변환·양식 생성만 하면 D8.9(우선순위 낮지만 동작이 다름)
  • 합친 자료를 기준과 대조해 확인 대상을 고르면 D8.4
  • 모은 자료를 담당자에게 배분하면 D8.6(우선순위 높음)

얻는 것

  • 서무 반복 업무 절감
  • 폐쇄망에서 바로 쓰는 설치형
  • 정산 규칙의 일관 적용

점검표

  • 원본이 보존되고 결과를 되돌릴 수 있는가
  • 제출 파일 속 매크로가 실행되지 않는가
  • 라이선스·저장소가 명시되어 있는가
  • 정산 결과를 검산할 방법이 있는가

구조 — 참여 부품

  • 서무 담당자 — 자료를 모으고 결과를 확인
  • B0 결정적 도구(문서·엑셀 자동화) — 수집·병합·정산 순차 처리

  • A7 자체 제작 환경 — 기관 인력이 직접 만든 도구
  • C3 상태 머신·롤백 — 원본 보존과 원복

변형

D8.6 분배·이관 서비스 블록

접수된 문서·민원을 담당자·부서로 보내는 내부 운영 블록이다. 대민 Triage(D4)의 내부 버전이며 C2 라우터가 붙는 첫 자리다.

PAX 사례 7건이 이 부품을 쓴다

맥락

기관이 접수한 문서·민원을 내부 담당자·부서에 배분하는 업무. §7.3 유형 ② 접수·심사 자동화의 참조 구현(온나라 AI 문서 분배기)이 여기 있다. PAX 7건(주 부품 B0 71%, B1·B4 각 14%). 판정 목적(승인·반려)이 있으면 유형 2, 형식·경로 변환·전달만이면 유형 8(R23). 업무 영역별 PAX 건수(557건 태깅): 문서·기안 2, 공통·범용 2, 인사·복무 1, 민원 1, 감사·법무 1.

맞서는 힘(긴장)

  • 자동 배분 속도 vs 오배분 비용
  • 업무 분장 변경 vs 분류 체계 고정
  • 공통기반 모델 활용 vs 문서 등급·반출 제약
  • 자동 배정 vs 담당자·팀장의 배정 권한

해법

접수 문서를 A10으로 읽고 B4가 핵심 항목을 추출한 뒤, B′2 라우터가 업무 분장에 비춰 담당자를 추천한다. C2 위험도 라우터로 신뢰도가 높은 건만 자동 배정하고 나머지는 배정 권한자에게 C1 확인을 받는다. 업무 분장표는 B3로 접지해 근거를 보여 주고, 배분·재배분 기록은 C4에 남겨 C6로 분류 기준을 고친다. 운영 시스템에 배정을 직접 쓰면 P2이므로 C8·C3를 둔다. 행정망에서는 범정부 AI 공통기반(A3·A2.4)을 경유한다.

이럴 때 쓴다

  • 접수 대기 문서를 읽고 담당자를 정하는 반복 업무
  • 오배분·재배분이 잦을 때
  • 업무 분장이 복잡해 배정 권한자의 판단 부담이 클 때

이럴 때는 쓰지 않는다

  • 국민 민원을 부서로 보내고 국민에게 이관을 알리면 D4
  • 배분 없이 요약만 하면 D8.2
  • 요건 판정이 목적이면 D3(대민) 또는 D8.4(내부)

얻는 것

  • 배분 시간 단축
  • 재배분 감소
  • 배분 기록으로 업무 분장 문제 발견

점검표

  • 자동 배정 임계가 수치로 정해져 있는가
  • 배분 근거(업무 분장 조항)가 보이는가
  • 재배분률을 재는가
  • 잘못된 배정을 되돌릴 수 있는가

구조 — 참여 부품

  • A10 문서 형식 어댑터 — 접수 문서·첨부를 읽음
  • B4 인식 파이프라인 — 문서의 핵심 항목 추출
  • B′2 라우터 원형 — 업무 분장에 비춰 담당자 선택
  • C2 위험도 라우터 — 자동 배정 / 확인 요청 분기
  • 배정 권한자(팀장·서무) — 추천 배정을 확인
  • C4 감사 로그·지표 — 배분·재배분 기록

변형

  • 배정 추천형: 담당자 후보를 추천하고 배정 권한자가 확정.
  • 자동 배정형: C2 임계 이상은 자동 배정(P2).
  • 목록 요약 보조형: 등록대장 목록에서 요약·분석을 붙여 배분 판단을 돕는다(온나라 sAIde, D8.2와 경계).

A7 자체 제작 환경 공통 서비스

외부 용역 없이 기관 인력이 저작도구·AI 코딩 에이전트로 도구를 직접 만들고 고치는 제작 환경이다.

PAX 사례 317건이 이 부품을 쓴다

맥락

업무 담당자가 AI 코딩 도구·저작도구·오픈소스로 직접 만드는 과제에 쓴다. 유형 8(취합·변환 자동화)에서는 필수 기반이다. PAX 557건에서 A7이 붙고 BYO 모델을 쓰는 사례는 29건이다.

맞서는 힘(긴장)

  • 제작 속도·현장 적합성 vs 유지보수 연속성
  • 개인 역량 의존 vs 조직 인수인계
  • 무예산 제작 vs 보안 검토·기관 공식화 절차

해법

기관 인력이 AI 코딩 에이전트·저작도구·오픈소스로 직접 만들되, 처음부터 전이를 전제로 한다. 설정·데이터(연락처·업무분장 등)는 코드 밖 파일로 빼 비개발자도 고치게 하고, 작업 지시서 자체를 코딩 에이전트가 수행할 프롬프트로 설계해 제작 절차를 남긴다. MIT·Apache 등 라이선스를 명시하고 공공 깃랩(A3)이나 혁신24 자료실에 등재해 담당자가 바뀌어도 이어지게 한다. 실사용 건수로 성과를 재 기관 공식으로 올린다.

이럴 때 쓴다

  • 반복 업무를 줄이는 소규모 도구를 빠르게 만들 때
  • 용역 없이 작은 수정을 계속해야 할 때
  • 유형 8 취합·변환 자동화

이럴 때는 쓰지 않는다

  • P2 이상 시스템 쓰기·처분이 걸려 보안 검토·통제 부품이 먼저 필요한데 이를 갖출 수 없을 때
  • 라이선스·저장소·인수인계를 정할 수 없어 전이가 불가능할 때(X9 위험)

얻는 것

  • 제작 속도와 현장 적합성
  • 내부 유지보수 역량 축적
  • 무예산·소예산 제작

점검표

  • 라이선스가 명시되어 있는가
  • 저장소가 개인 PC가 아닌 공유 위치에 있는가
  • 담당자가 바뀌어도 고칠 수 있는 문서·설정 분리가 있는가
  • 실사용 지표가 있는가

구조 — 참여 부품

  • 업무 담당자 — 요구를 알고 직접 만드는 제작자
  • AI 코딩 에이전트·저작도구 — 코드·화면·워크플로 생성
  • A3 공공 깃랩·자료실 — 등재처 — 담당자 이동 후에도 이어지게
  • A9 업무 규범 스킬 — 제작 규범·지시서를 재사용 가능한 형태로

변형

  • 비개발자 바이브코딩: 교육 후 비개발 직원이 AI 코딩으로 웹앱을 만들고 실사용 지표까지 잰다.
  • 용역 탈피 단계형: 1단계는 전문기업과, 2단계는 직원이 도구를 대여해 라벨링·학습·개발을 직접 한다.
  • 오픈소스 조립형: n8n·FastAPI·Qdrant·LM Studio 등 오픈소스로 워크플로를 직접 조립하고 설정을 공유한다.
  • 사람+에이전트 작업 단위형: 작업 지시서를 코딩 에이전트 입력 프롬프트로 설계해 '사람 1인 + 에이전트 1세션' 단위로 일한다.

X1 AI 스티커 안티패턴

기존 화면에 요약·챗봇 버튼만 붙이고 업무 순서와 사람·AI의 역할 분담은 그대로 두어, AI가 있어도 업무 산출물이 바뀌지 않는 함정이다.

맥락

기존 행정정보시스템·업무 포털에 AI 기능을 추가하는 과제, 특히 성과 지표가 'AI 기능 탑재 여부'나 호출 수로 잡힌 과제. R24에 따라 AI 런타임이 전혀 없는 순수 행정정보시스템도 이 태그(AI 무관)로 표기한다.

맞서는 힘(긴장)

  • 빠른 도입 실적 vs 업무 흐름 재설계 비용
  • 기존 시스템 무변경(안정성) vs 산출물 단위의 역할 분담
  • 'AI 탑재' 홍보 효과 vs 실제 처리시간·수정률 개선

해법

먼저 가치 흐름 규칙(R1)으로 사람 또는 국민이 최종으로 받는 핵심 산출물을 정하고, 그 산출물을 AI가 어떤 모양으로 분담할지 B 업무 컴포넌트를 하나 고른다(초안→사람 확정이면 B1, 근거 접지 답변이면 B3, 서류 추출이면 B4). 사람이 확정하는 지점은 C1 검토 큐로, 이용자가 고쳐 확정하는 면은 F2 편집 가능한 출력으로 명시한다. 흐름이 바뀌었는지는 C4 감사 로그·지표의 처리시간·수정률로 잰다. AI 런타임이 전혀 없는 행정정보시스템이라면 AI로 포장하지 말고 R24대로 B0·service_type 0·platform 공란·X1(AI 무관)으로 정직하게 분류한다.

이럴 때 쓴다

  • AI 기능이 추가됐다는 서술은 있으나 처리 단계 수·결재선·담당자 역할이 바뀌었다는 서술이 없다
  • 성과 지표가 AI 호출 수·이용 만족도뿐이고 처리시간·수정률 같은 산출물 지표가 없다
  • 챗봇이 기관 업무 데이터·시스템과 연결되지 않은 범용 대화에 머문다
  • AI 런타임이 전혀 없는 행정정보시스템이 AX 과제로 분류되어 있다(R24)

이럴 때는 쓰지 않는다

  • B1 코파일럿처럼 AI가 초안을 만들고 사람이 확정하는 역할 분담이 실제로 서술된 경우
  • B8 레거시 오버레이처럼 표준 시스템 위에 얹었지만 업무 산출물을 AI가 만들어 내는 경우
  • B0 결정적 도구가 반복 취합 업무를 실제로 줄이고 AI로 포장하지 않은 경우(Ready 부품으로 정직하게 분류된 경우)

얻는 것

  • 기존 시스템을 건드리지 않아 도입이 빠르고 장애 위험이 낮다
  • 'AI 탑재' 실적을 즉시 보고할 수 있다

점검표

  • AI 도입 전후 처리 단계·담당자 역할의 차이를 한 장으로 보여 줄 수 있는가
  • AI가 만드는 산출물과 사람이 확정하는 지점이 명시되어 있는가
  • 처리시간·수정률 같은 산출물 지표가 도입 전 기준선과 함께 있는가
  • AI 런타임이 없는데 AI 과제로 보고하고 있지 않은가

구조 — 참여 부품

  • 덧붙인 AI 기능 — 요약·대화 버튼. 업무 산출물 생산에 역할이 없음
  • B1 코파일럿 — 교정 후 초안→사람 확정으로 산출물 역할을 나누는 대체 부품
  • C1 검토 큐 — 교정 후 사람이 확정하는 지점을 명시
  • C4 감사 로그·지표 — 흐름이 실제로 바뀌었는지 처리시간·수정률로 측정

변형

  • 요약 버튼형: 기존 화면에 '요약' 버튼만 추가하고 결재·처리 단계는 그대로
  • 범용 챗봇 부착형: 업무 데이터와 연결되지 않은 범용 대화창을 포털에 부착
  • AI 무관 행정시스템(R24): AI 런타임이 전혀 없는 순수 행정정보시스템(예: 교육·인증 학습관리시스템). B0·service_type 0·platform 공란과 함께 X1(AI 무관)로 표기

X4 단일 모델 인질 안티패턴

상용 API 하나에 전 기능이 묶여 있어, 그 API가 멈추거나 바뀌면 무슨 일이 생기는지 아무도 답하지 못하는 함정이다.

맥락

E2가 해외 상용 API이고 B 부품이 그 API를 게이트웨이 없이 직접 호출하는 과제. 특히 대민 자동응답·상시 감지처럼 중단 비용이 큰 서비스.

맞서는 힘(긴장)

  • 최고 성능 단일 모델 vs 대체 경로 유지 비용
  • 빠른 시범 구축 vs 게이트웨이·폴백 설계
  • 모델 업데이트의 성능 향상 vs 예고 없는 동작 변화

해법

모델 호출을 A2 모델 서빙 계층 뒤로 숨겨 B 부품이 특정 벤더 API를 직접 부르지 않게 한다. 그 위에 C7 폴백 스위치로 재시도 → 기존 API → 대체 MCP → 대체 모델(A2.2 주권형 로컬 등) → 규칙 기반 축소 → 수동 전환의 경로를 정하고 전환 이력을 C4에 남긴다. 모델 교체가 실제로 안전한지는 C9 평가 세트로 재어 버전을 고정한다. 모델 중립(BYO) 배포라면 A9 스킬 형태로 배포해 모델 교체 가능성 자체를 폴백으로 삼는다.

이럴 때 쓴다

  • E2가 해외 상용 API인데 C7 폴백이 없다(분류기준 검증 경고 조건)
  • 'API가 멈추면 어떻게 되는가'에 대한 서술이 없다
  • 모델 버전 고정·교체 시험 기록이 없다
  • A2 게이트웨이 없이 B 부품이 벤더 API를 직접 호출한다

이럴 때는 쓰지 않는다

  • B0 결정적 도구처럼 런타임 AI가 없는 경우
  • 로컬 완결 도구로 외부 의존이 없는 경우
  • 모델 중립(BYO) 배포로 A9 스킬 형태라 이용자가 모델을 바꿀 수 있는 경우
  • 상용 API를 쓰되 A2 게이트웨이와 C7 대체 경로가 구현된 경우

얻는 것

  • 가장 성능 좋은 모델을 가장 빨리 쓴다
  • 게이트웨이·대체 모델 유지 비용이 없다

점검표

  • 모든 모델 호출이 A2 한 곳을 지나는가
  • 대체 경로가 하나 이상 구현되어 있는가
  • 대체 모델의 품질이 C9로 측정되어 있는가
  • 모델 버전이 고정되어 있고 교체가 릴리스처럼 관리되는가

구조 — 참여 부품

  • A2 모델 서빙 계층 — 벤더 API를 숨기는 끼울 자리
  • C7 폴백 스위치 — 장애 시 대체 경로로 전환
  • C9 평가 세트·회귀시험 — 대체 모델의 품질을 같은 자로 확인
  • 단일 상용 API — 모든 기능이 묶인 의존 대상

변형

  • 직접 호출형: 게이트웨이 없이 코드 곳곳에서 벤더 SDK를 직접 호출
  • 벤더 내장형: 벤더 제품 안에 모델이 박혀 교체 자체가 불가능(A2.6 블랙박스와 결합)
  • 버전 미고정형: 모델 버전을 고정하지 않아 업데이트가 예고 없이 동작을 바꿈

관련 부품

X10 평가 없는 RAG, RAG 없는 튜닝 안티패턴

평가 세트 없이 검색을 붙여 '좋아진 것 같다'로 배포하고, 검색으로 풀릴 문제를 파인튜닝으로 푸는, 진행 경로를 건너뛰는 함정이다.

맥락

B3 지식 접지·B1 코파일럿에 RAG를 붙이거나 A2.3 튜닝형 모델을 만드는 과제, 특히 규정·매뉴얼 기반 질의응답.

맞서는 힘(긴장)

  • 눈에 보이는 기술 성과 vs 지루한 평가 세트 구축
  • 빠른 배포 vs 변경마다 재는 자
  • 자체 모델 보유 인상 vs 검색으로 충분한 문제

해법

§7.2 진행 경로를 순서대로 밟는다. B1 직접 프롬프트에서 시작해 두 번째 단계에서 C9 평가 세트(업무 질문·정답·채점 기준)를 먼저 만들고, 이후 A9 규범 스킬·F4, B3 지식 접지(A1 데이터 자산), B3 검색 품질(Hybrid·Rewriting·Reranker), C5 가드레일·F1 순으로 붙이며 매 단계를 C9로 잰다. A2.3 튜닝은 진행 경로의 마지막 단계로, 검색·규범 스킬로 풀리지 않는다는 것이 C9 점수로 확인됐을 때만 한다. 모델·프롬프트·설정 조합은 릴리스처럼 버전 관리한다.

이럴 때 쓴다

  • RAG·튜닝을 도입했는데 업무 질문·정답·채점 기준 세트가 없다
  • '답변 품질 향상'을 수치 없이 서술하거나 단발 정확도만 보고한다
  • 자주 바뀌는 규정·매뉴얼 질의를 파인튜닝으로 풀었다
  • 검색 품질(재현율·리랭킹)을 재지 않고 튜닝으로 넘어갔다

이럴 때는 쓰지 않는다

  • C9 세트로 RAG 전후를 비교한 뒤 배포한 경우
  • 검색·스킬로 풀리지 않음을 C9 점수로 확인한 뒤 튜닝한 경우
  • B2·B4처럼 비LLM 학습 모델로 원래 학습이 해법인 경우(RAG가 대안이 아님)

얻는 것

  • RAG·튜닝이라는 눈에 보이는 기술 성과를 빨리 낸다
  • 평가 세트 구축에 현업 시간을 쓰지 않는다

점검표

  • 업무 질문·정답·채점 기준 세트가 있는가
  • RAG 전후 점수 비교가 있는가
  • 튜닝을 선택한 근거가 C9 점수로 설명되는가
  • 모델·프롬프트·설정 조합이 버전 관리되는가

구조 — 참여 부품

  • C9 평가 세트·회귀시험 — 빠진 부품. 모든 변경을 같은 자로 잼
  • B3 지식 접지 — 튜닝 전에 먼저 시도할 검색 기반 접지
  • A2.3 튜닝형 모델 — 진행 경로의 마지막 단계
  • A1 데이터 자산 서비스 — 정답 출처와 검색 코퍼스

변형

  • 평가 없는 RAG: 검색을 붙이고 몇 개 질문을 눈으로 보고 배포
  • RAG 없는 튜닝: 문서 검색으로 풀릴 최신 규정 질의를 파인튜닝으로 해결하려 함
  • 평가 없는 튜닝: 튜닝 전후를 같은 세트로 비교하지 않음

관련 부품
