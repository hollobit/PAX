# 도시 입체지도 — 서울·부산·대구·대전·인천·세종·광양·제주와 경기 31개 시·군

OpenStreetMap 건물·도로·물길과 실제 지형 표고로 세운 3차원 도시 지도. Three.js 정적 웹사이트이며 Claude sites(Artifact)로 배포한다.
주간·일몰·야간 세 가지 시간대를 고를 수 있고, 건물을 누르면 원본 높이·바닥면적·지면 표고를 보여 준다.

## 건물 위치·면적·높이 — 무엇이 원본이고 무엇이 추정인가

### 서울 — 국토교통부 GIS건물통합정보 (2026-10-08 시범)

서울은 OSM 대신 건축물대장과 연계된 국토교통부 GIS건물통합정보로 건물을 세운다(`scripts/city3d/vworld.py` → `gisbldg.py`).
OSM 16.7만 채 → 건물 82.1만 동(통합정보 80.6만 + OSM 보충 1.6만, 쪼갠 조각까지 상자 85.7만 개), 높이 추정(5m) 74% → **20%**.

| 높이를 정한 순서 | 건물 수 | 화면 |
|---|---|---|
| 1. 건축물대장 높이 — 층수와 맞을 때만(3층 이상은 층당 2~7m, 1~2층은 25m까지, 층수 없으면 60m까지) | 304,368 | 원본 값 |
| 2. 같은 자리 OSM 건물의 실제 높이(겹친 조각 중 가장 높은 것) | 27,000 | 원본 값 |
| 3. 지상층수(`grnd_flr`) × 3m — 80층 초과 층수는 오기로 보고 쓰지 않는다 | 320,327 | 원본 값(정보 창에 "지상층수 × 3m") |
| 4. 기본값 5m | 나머지 | 추정(회색) |
| OSM에만 있는 건물(통합정보 윤곽에 들지 않음) | 15,648 | OSM 규칙 그대로 |

- 2번을 3번보다 앞에 둔 이유: 초고층은 층수 환산이 크게 틀린다(롯데월드타워 123층 × 3m = 369m, OSM 실측 520m).
  대장 높이 오기 예(실측): 1층 305m·9층 283m·3층 123m, 116층 203㎡ — 층수와의 비율 검사로 걸렀다.
- **쪼갠 건물 8,288동**: 상자가 윤곽의 55% 미만만 채우고 한 변이 40m를 넘는 오목·길쭉한 윤곽(ㄷ자 아파트·긴 상가)은 상자 하나면
  마당·도로를 덮는 판이 되므로 건물 방향 25m 격자로 잘라 조각마다 상자를 세운다. 그런 판 1,005개 → 2개.
- **뺀 것**: 지상층 0·지하층만 있는 시설과 높이·층수 없이 이름이 지하 시설(지하상가·지하철역·지하차도·주차장)인 것 1,400건,
  높이·층수·OSM 대응이 모두 없는 2,000㎡ 넘는 판 116건(시청광장 지하쇼핑센터처럼 광장 위에 판으로 서는 지하 구조물).
- 레코드 플래그: 1 추정 · 2 보정(OSM) · **4 출처 = 건물통합정보** · **8 높이 = 층수 환산**. 회색 표시는 1·2만 본다.
- 인증키는 저장소에 두지 않는다(`~/.config/pax/vworld.env` 또는 환경변수 `VWORLD_KEY`, 빌드 때만 사용). 받은 원자료(약 630MB)는 `data/private/city3d/cache/vworld/`(비공개)에 둔다.
- 수치지형도(국토지리정보원) 등고선·표고는 VWorld API에 없어(2026-10-08 실측) 지형은 아직 SRTM 30m다.
- 측정(이 Mac, Chrome·Metal): 이전 OSM 판과 같은 시점·같은 예산(22만 상자)에서 시점 회전 중 프레임 중앙값 16.7ms·95% 16.8ms로 차이 없음.

### 그 밖의 도시 — OpenStreetMap

- **위치**: 원본 건물 윤곽(벡터 타일 폴리곤)의 최소 회전 직사각형 중심. 1m 단위로 저장.
- **바닥면적**: 원본 윤곽의 실제 면적(m²). 65,535m² 이상은 “65,535 ㎡ 이상”으로 표시.
- **모양**: 모든 건물을 **공유 상자 하나를 늘리고 돌린 것(최소 회전 직사각형)**으로 근사한다. 수십만 채를 InstancedMesh 한 번으로 그리기 위한 선택이다.
  서울 시청 일대 타일(3,651채)로 잰 근사 정도: 윤곽 면적 ÷ 직사각형 면적의 중앙값 0.87, 0.6 미만(ㄱ자·ㄷ자 등) 8%.
- **높이**: OpenMapTiles `render_height`(OSM `height`, 없으면 `building:levels × 3.66m`, 정수 반올림).
  - **추정(회색)**: `height`·`building:levels`가 모두 없어 OpenMapTiles 기본값 **5m**가 들어간 건물 — 전체의 77%.
  - **추정(보정)**: 시작 높이(`min_height`)만 있고 높이가 기본값이라 위아래가 뒤집힌 건물 5채 — 시작 높이 + 3m로 세웠다.
  - 층수 기반 값과 실측 높이는 타일 자료에서 구분할 수 없다(둘 다 “원본 값”으로 표시).
- 건물 높이는 **과장하지 않는다**.

## 지형 축척·과장

- 기본 **1× = 실제 축척**: 수평·수직 모두 같은 미터 단위.
- **2× 과장** 선택 시 지형 표고만 2배. 이유: 서울·대구 분지처럼 완만한 구릉과 하천 골짜기가 1×에선 잘 읽히지 않아서. 건물 높이는 그대로 두고, 화면에 배율과 이유를 함께 적는다.
- 격자: 표고 30m 격자(원자료 z13 ≈ 17~19m/px 쌍선형 재표본). 화면 메시는 데스크톱 60m, 모바일 120m로 성기게 만든다.

## 시간대·랜드마크 비행·물 가림 방지

**시간대(주간·일몰·야간)** — `js/modes.js`. 하늘·안개·반구광·해(고도·방위각)와 도시 재질을 함께 바꾼다. 야간에는 건물 벽에
셰이더로 창문 불빛을 그리고, 도로는 주황빛, **수면은 약하게 스스로 빛나** 어두운 땅과 섞여 강이 사라지지 않게 했다.
3D PAX에서는 도시 입체지도가 펼쳐졌을 때 지도 위 띠의 단추로 고른다(주간은 미니어처의 빛을 그대로 이어 쓴다).

**랜드마크 비행** — `js/flight.js`. 도시마다 표로 정한 랜드마크 중 **OSM에서 확인된 지점만** 가까운 순으로 이어 날아간다.
구간마다 먼 곳일수록 높이 솟았다 내려앉는 호를 그리고(3~9초), 도착하면 반지름 800m로 7초 동안 둘레를 돈다.
지도를 만지면(끌기·휠) 멈춘다. 독립 페이지는 "비행" 단추, 3D PAX는 도시 모드의 "✈ 랜드마크 비행".

랜드마크 찾기(`scripts/city3d/process.py find_landmark`): 이름이 정확히 같은 OSM 지점 중 **실제 위치 2km 안**만 쓰고,
여럿이면 지물다운 분류(명소·청사·봉우리·역·섬·호수) → 정류장·대여소 → 식당·가게 순, 그다음 가까운 것. 같은 이름 식당
(예: 마포의 '경복궁' 식당)이나 정류장에 끌려가지 않게 하려는 규칙이다. 찾지 못한 곳은 "대략 좌표(추정)"(점선 단추)로 두고 날지 않는다.

**숲이 산을 덮지 않게** — OSM 숲 다각형은 크고 오목해서 earcut 삼각형이 수 km짜리 평면이 되고, 꼭짓점 높이만 가진 그 판이
산등성이를 뚫거나 봉우리를 덮었다(봉우리 둘레의 부채꼴 판). `layers.js paintGreen`이 변 하나라도 150m보다 긴 숲·공원 삼각형을
표고 격자에 래스터화해 **지형 색으로 칠하고**, 작은 삼각형(도심 공원 등)만 얹는 면으로 남긴다. 숲은 이제 지형을 그대로 따른다.

**물 가림 방지** — 수면 삼각형은 강둑 꼭짓점의 표고만 가져, 강 가운데의 30m 표고가 수면보다 높으면 땅이 물을 덮는다.
`layers.js carveWater`가 수면 삼각형을 표고 격자에 래스터화해 그 칸의 땅을 수면보다 2.5m 아래로 깎는다(원본 표고는 그대로,
건물·도로 높이에는 쓰지 않음). 지형을 2~4칸마다 성기게 그릴 때 좁은 물길이 꼭짓점 사이로 빠지지 않도록, 꼭짓점 둘레에 물 칸이
있으면 그 물 칸의 가장 낮은 높이를 쓴다. 깎인 칸 수는 서울 27,036칸, 부산 198,741칸(낙동강 삼각주). 3D PAX에서는 도시 모드일 때
과장된 전국 지형·OSM 지도 타일을 걷어 내고 도시 전체를 시도 판 위 약 13m에 얹어, 물이 지도 바탕 아래로 들어가지 않는다.

육안 확인(2026-09-27, 로컬): 서울 한강(옥수·압구정·여의도·밤섬)·중랑천·안양천·경복궁 연못, 부산 낙동강·서낙동강·평강천,
대구 금호강·낙동강, 대전 갑천·대청호, 세종 금강, 광양 섬진강 — 주간·야간(서울)·일몰(서울 비행)에서 물이 땅·건물·지도 바탕에
가려진 곳을 찾지 못했다. 다리·고가도로·철도는 물 위로 지나간다.

## 바이너리 형식 (`<도시>/*.bin` — 공개본은 `site/city3d/data/<도시>/*.bin.gz.b64.txt`)

모든 파일 = 32바이트 헤더 + 본문. 헤더: `magic "C3D1"`, `kind`(BLDG/LINE/MESH/DEMG), `version=1`, `count`(레코드 수), `stride`(고정 길이 레코드 바이트, 가변이면 0), `length`(본문 바이트), `crc32`(본문), `extra`(종류별).
브라우저(`js/binary.js`)는 **헤더 magic·종류·버전, 본문 길이 = 파일 길이 − 32, count × stride = length, CRC32, meta.json의 파일 크기·CRC**를 모두 확인한 뒤에만 쓴다. 가변 길이 파일은 끝까지 읽은 바이트 수와 점 수(`extra`)도 대조한다.

| kind | 레코드 |
|---|---|
| BLDG | 16B: x,n(u16 m) · 너비·깊이(u16 0.1m) · 방향(u8, 0~π) · 플래그(u8: 1=기본값 높이, 2=보정) · 높이·시작 높이(u16 0.1m) · 바닥면적(u16 m²) |
| LINE | [class u8][flags u8(1=다리)][점 수 u16][x,n u16 × 점 수] (도로 class: 1 고속도로 … 7 진입로, 8 철도, 9 도시철도 / 하천: 1 강, 2 운하, 3 개천, 4 배수로) |
| MESH | [정점 수 u32][삼각형 수 u32][x,n u16…][class u8…(숲·공원만) + 4B 정렬][색인 u32…] — earcut 삼각분할 |
| DEMG | int16 × cols × rows(0.25m 단위, 행 0 = 북쪽, −32768 = 자료 없음) |

**배포 전송 인코딩**: Claude sites(Artifact)는 임의 바이너리 파일을 내보내지 않는다. 그래서 배포본은 각 `.bin`을 gzip 압축 후 base64 텍스트(`*.bin.gz.b64.txt`)로 싣고(`scripts/city3d/pack.py`), 브라우저가 base64 → gzip(`DecompressionStream`)을 되돌린 **원래 .bin 바이트**로 위 검증을 모두 한다. GitHub Pages 공개본(https://hollobit.github.io/PAX/city3d/)도 같은 전송본을 써서 두 배포처의 브라우저 코드·검증 경로가 같다. 원본 `.bin`과 타일 캐시는 비공개 빌드 폴더(`data/private/city3d/`)에만 둔다.

좌표는 도시 경계 상자 남서쪽 모서리 기준 로컬 미터(등장방형 근사, 50km 안 오차 0.1% 미만). 도시마다 `meta.json`에 원점 경위도·축척이 있다.

## 렌더링 — 구현한 최적화

- **공유 지오메트리 + InstancedMesh**: 건물 전부가 상자 지오메트리 하나를 공유한다. 건물 층은 드로 콜 1회(그림자 패스 별도).
- **표시 예산 선택**: 시점 중심에서 가까운 순(높은 건물 가산)으로 예산만큼만 인스턴스 행렬을 채운다. 히스토그램 선택이라 O(N), 시점이 충분히 움직일 때만 다시 고른다.
- **모바일 예산 분리**(굵은 포인터 또는 짧은 변 700px 미만): 픽셀 비율 1(데스크톱은 기기 값, 최대 2) · 그림자 1024px(데스크톱 4096px) · 표시 건물 최대 40,000채(데스크톱 220,000채) · 지형 120m 격자(데스크톱 60m) · 안티에일리어싱 끔.
- 도로·하천·수면·숲은 도시마다 병합된 메시 몇 개로 그린다. 그림자 카메라는 시점을 따라가며 범위를 시점 거리에 맞춘다. 원거리 정밀도를 위해 로그 깊이 버퍼를 쓴다.
- 밤 창문은 텍스처 없이 셰이더가 벽면 격자와 인스턴스 번호로 그린다(`gl_InstanceID`).

## 측정값(실측만)

- **렌더 시간**: Apple Silicon Mac + Chrome, 1673×1108 캔버스, 서울 전경(건물 167,255채 모두 표시, 삼각형 3,807,953개, 드로 콜 8회). 프레임마다 `readPixels`로 GPU 완료를 기다려 30프레임을 잰 결과 **평균 3.29ms · 중앙값 3.5ms · 상위 10% 4.2ms**. 화면 합성·표시 시간은 빠졌으므로 FPS로 환산해 주장하지 않는다.
- **FPS**: 자동화 브라우저 탭이 백그라운드 상태여서 실제 화면 FPS는 재지 못했다. 페이지의 FPS 칸은 보는 사람 기기에서 1초마다 실측해 보여 준다.
- **불러오기**: 서울 불러오기·검증·장면 구성 3.2~4.2초, 부산 3.1초(같은 Mac, 로컬 서버).

## 한계

- 건물은 직사각형 상자 근사다. ㄱ·ㄷ자·원형 건물, 지붕 모양, 층별 셋백은 재현하지 않는다.
- 서울 밖 도시는 높이의 대부분이 기본값 5m 추정이다(OSM에 높이·층수 태그가 없는 건물). 서울은 건물통합정보로 추정 20%까지 줄였다.
- 서울 밖 건물 수는 OSM에 그려진 건물 수다. 행정 건축물대장과 다르며 지역마다 수록률이 다르다.
- 서울의 층수 환산 높이(층당 3m)는 실제 층고(상가·공장은 더 높음)와 다를 수 있다.
- 도로·수면은 지형 격자 위에 얹은 평면이라 급경사에서 지형이 살짝 뚫고 나오거나 떠 보일 수 있다. 다리는 양끝 높이 + 8m 평면으로 단순화했다. 터널 구간은 뺐다.
- 랜드마크 25곳 중 6곳(금정산·금강보행교·동성로·팔공산·이순신대교·광양제철소)은 지도 자료에서 이름을 찾지 못해 대략 좌표를 썼고 화면에 점선으로 표시한다.
- 바다 수면은 해발 5m 미만을 0m로 평평하게 둔다.

## 다시 만들기 (PAX 저장소 루트에서)

```bash
uv run --with shapely python3 scripts/city3d/fetch.py          # 원자료 받기 → data/private/city3d/cache (캐시 재사용)
(cd scripts/city3d && uv run --with shapely python3 vworld.py seoul)   # 서울 건물통합정보(VWORLD_KEY 필요, 받은 칸은 건너뜀)
uv run --with mapbox-vector-tile --with shapely --with numpy --with mapbox-earcut --with pillow python3 scripts/city3d/process.py
uv run --with mapbox-vector-tile --with shapely python3 scripts/city3d/mapinfo.py   # 이름표·구 경계
python3 scripts/city3d/pack.py                                  # 전송본·JSON → site/city3d/data
PYTHONPATH=scripts python3 -m pytest tests/test_city3d.py -q    # 형식·자료·전송본·브라우저 읽기 코드·지도 정보 검증
```
도시 경계는 같은 저장소의 `site/data/korea-geo.json`·`korea-sgg.json`(SGIS 가공)에서 읽는다.

## 바깥에서 여는 주소

`city3d/?city=busan&lat=35.18&lon=129.075&label=이름&place=연제구&case=사례id`

- `city`: seoul·busan·sejong·daegu·gwangyang 중 하나(그 밖은 무시하고 서울).
- `lat`·`lon`: 한국 범위(위도 33~39·경도 124~132)의 숫자만. 도시 지도 범위 밖이면 알리고 무시한다.
- `place`: 시군구 이름 — 있으면 좌표 대신 그 시군구 청사(예: 광양시청) 이름표 자리로, 없으면 구 이름표 자리로 맞춘다.
- `label`(60자)·`case`(16진 id): 주황 기둥의 이름표와 "3D PAX로 돌아가기" 링크에 쓴다.

## 3D PAX 안에서 펼치기

3D PAX(`pax3d.html`)는 이 지도를 별도 창이 아니라 미니어처 지도 안에서 연다(`site/pax3d-city.js`).
목표점이 도시 범위(`data/cities.json`의 `bbox`) 안이고 카메라가 약 4.4 월드 단위(≈190km) 안으로 오면 자료를 미리 받고,
2.4 단위(≈100km) 안에서 도시 모드로 바꾼다(2.9 단위 밖으로 나가면 되돌림).

- 좌표: 도시 로컬 미터(x, n) → 미니어처 월드 `x0 + x·sx`, `z0 − n·sz`. `sx`·`sz`는 미니어처 투영의 경도·위도 1도 길이를
  이 도시의 1도 미터(`m_lon`·`m_lat`)로 나눈 값이라 두 등장방형 투영이 정확히 겹친다. 높이는 실제 축척(`sy = sz`).
- 미니어처 지형은 약 10배 과장이라 도시 모드에서는 걷어 내고(지도 타일·나무·시도/시군구 선도) 이 지형을 쓴다.
- 사례 자리: 기관 소재지 → 시군구 청사(`geo.js seatOf` — 이름이 같은 청사, 없으면 그 구 안에 있는 앞머리 같은 청사,
  그래도 없으면 구 이름표 자리) → 시청. 사례 탑의 크기(바닥 약 38m, 높이 약 80~220m)는 표지용이지 실제 건물이 아니다.
- 표시 예산: 데스크톱 건물 180,000채·지형 90m 격자, 모바일 30,000채·120m 격자.

독립 페이지 주소 인자(`?city=&lat=&lon=&label=&place=&case=`)는 그대로 쓸 수 있다.
