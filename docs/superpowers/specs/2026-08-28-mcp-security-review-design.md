# MCP 보안·안전 검증 리뷰 (MCP Security Review) 설계

날짜: 2026-08-28
상태: 사용자 승인 대기
선행: 관측소 MCP 현황·이슈 섹션, 2026-08-22 생태계 연결 관측 스펙(제도·표준 3공백 진단)

## 1. 목적

PAX에 등재된 MCP 사례들을 보안·안전 관점에서 **일관된 프레임으로 검증**하고,
그 결과를 전용 메뉴로 공개해 ① 도입 검토자에게 위험 신호를, ② 개발자에게 개선
방향을, ③ 정책 축(연결 관측의 '이행 공백' 진단)에 실측 데이터를 제공한다.

사용자 확정 사항:
- **깊이**: 정적 검사(전수) + 선별 동적 검사(MCP Inspector)
- **공개 수준**: 축별 등급·일반화 설명만 공개, 악용 가능 상세(재현 경로·PoC)는 비공개.
  심각 취약점은 개발자 통보 → 수정 후 공개(responsible disclosure)
- **주기**: 전수 백필 1회 → 신규 MCP 등재 시 정적 검사 자동 → 주간 점검(월)에서 CVE 재스캔

원칙: **미확인 원칙의 보안판** — "검증 안 됨"은 "위험함"이 아니다. 미검증·통과·주의를
명확히 구분하고, 모든 판정에 검사 도구·버전·일자를 남긴다.

## 2. 검사 프레임 — 6축

| # | 축 | 방법 | 판정 규칙 |
|---|---|---|---|
| 1 | **권한 표면** | 자동 — 저장소의 도구 선언(tool 정의)을 파싱해 파일시스템/셸 실행/네트워크/외부 API 도구 수를 센다 | 셸 실행 도구 존재=주의, 목적 대비 광범위 파일 접근=주의, 읽기 전용=통과 |
| 2 | **시크릿** | 자동 — 자체 정규식 스캔(API 키 패턴, PRIVATE KEY, 커밋된 .env, 하드코딩 토큰) | 실키 발견=심각(통보 대상), 예시·플레이스홀더만=통과 |
| 3 | **공급망** | 자동 — `npm audit`/`pip-audit`(생태계별), 락파일·버전 고정 여부 | Critical/High CVE=주의(개수 공개), 락파일 없음=주의, 클린=통과 |
| 4 | **입력 검증·인젝션** | LLM 감사 — 명령 주입(shell=True·문자열 조합 exec), 경로 탈출, 프롬프트 인젝션 취약 표면(외부 콘텐츠를 도구 설명·응답에 그대로 삽입) | 파일·행 근거 인용 필수. 근거 없는 판정 금지. 의심=주의 |
| 5 | **데이터 흐름** | LLM 감사 + README 교차 — 외부 전송 대상(원 API 외 제3자 전송 여부), 로컬 완결성 주장과 코드의 일치 | 명시되지 않은 제3자 전송=심각(통보), 원 API만 호출=통과 |
| 6 | **운영 위생** | 기존 필드 재사용 — license, maintenance, mcp_official + 인증·레이트리밋 문구 유무 | 라이선스 명시+활발=통과, 방치=주의 |

- 축별 판정: `통과 | 주의 | 심각(비공개 처리 중) | 미검증 | 해당 없음`
- **종합 등급**: 심각(공개 보류) > 주의 1개 이상 = "주의" > 전축 통과 = "양호" > 일부 미검증 = "부분 검증"
- 동적 검사(선별): MCP Inspector CLI(`npx @modelcontextprotocol/inspector-cli`)로
  `tools/list`를 호출해 **선언된 도구와 실제 노출 도구의 일치**를 대조. 대상 선별 기준:
  기관 제공(mcp_provider_agency 有) 또는 스타 30+ 또는 원격 MCP(설치 없이 접속되는 것).
  실행은 임시 디렉토리·해당 프로젝트 전용 환경에서만 하고 자격증명 없이 수행한다.

## 3. 데이터 모델 — data/mcp_reviews.json

```json
{"reviews": [{
  "case_id": "76f07692203606ad",
  "checked_at": "2026-08-29",
  "tools": {"pip_audit": "2.7.x", "inspector": "0.x", "llm": "세션 감사"},
  "axes": {
    "permission_surface": {"verdict": "통과", "note": "읽기 전용 조회 도구 8종, 셸·쓰기 없음"},
    "secrets": {"verdict": "통과", "note": "환경변수 주입 방식, 하드코딩 없음"},
    "supply_chain": {"verdict": "주의", "note": "High CVE 2건(전이 의존성), 락파일 있음"},
    "injection": {"verdict": "통과", "note": "파라미터화 호출, 셸 미사용 (src/api.ts 확인)"},
    "data_flow": {"verdict": "통과", "note": "원 API(공공데이터포털) 외 전송 없음"},
    "hygiene": {"verdict": "통과", "note": "MIT·활발"}
  },
  "dynamic": {"done": true, "note": "선언 15개 = 노출 15개 일치"},
  "overall": "주의",
  "disclosure": null
}]}
```

- `disclosure`: 심각 발견 시 `{"notified_at": "...", "channel": "...", "resolved": false}` —
  resolved 전에는 해당 축 note를 "비공개 처리 중(개발자 통보됨)"으로만 표기.
  **원장에도 악용 가능 상세는 적지 않는다**(공개 저장소이므로). 상세는 로컬
  `data/private/mcp_findings/`(gitignore)에만 둔다.
- 대상 정의: cases.json에서 `m축 평가가 M*` 또는 title/tags에 MCP가 있고 저장소가
  있는 사례. 저장소 없는 원격 MCP(팩트방망이 등)는 정적 축 중 1·4를 "해당 없음(코드 비공개)"로.

## 4. 화면 — site/mcp-review.html (신규 메뉴 "MCP 검증")

1. **방법론 헤더** — 6축 설명, 판정 의미("미검증≠위험"), responsible disclosure 정책,
   면책(참고 정보이며 도입 시 기관 자체 보안성 검토 필요 — awesome-mcp-korea 면책 문구 결)
2. **검증 매트릭스** — 행: MCP 사례(사례 페이지 링크), 열: 6축+동적+종합.
   셀은 판정 배지(색+아이콘, 색맹 대비 텍스트 병기). 정렬: 종합 등급→스타.
3. **요약 카드** — 검증 완료 n/전체, 양호·주의·심각 처리 중 개수, 최다 주의 축
   (= 연결 관측 '이행 공백' 진단의 실측 입력)
4. **사례 페이지 배지** — build_case_pages가 mcp_reviews를 읽어 해당 사례에
   "MCP 검증: 양호(2026-08-29)" 배지 + 메뉴 링크 표시
5. 표준 2줄 메뉴(내부 줄에 "MCP 검증" 추가)·80vw. 관측소 MCP 섹션에서 상호 링크.

## 5. 파이프라인·운영

- **scripts/check_mcp.py**: 대상 추출 → shallow clone(임시 디렉토리) → 축 1~3 자동 검사
  → 결과를 mcp_reviews.json에 병합(기존 LLM 감사 축은 보존). `--case <id>`로 단건 실행.
- **LLM 감사(축 4·5)**: 세션에서 코드 열람 후 근거 인용과 함께 원장에 기록 —
  백필 시 전수, 신규 등재 시 그 사례만.
- **build_mcp_review.py**: 원장 → site/data/mcp-review.json(공개 필드만 필터 —
  disclosure 미해결 상세 차단을 빌드에서 강제) → 페이지 렌더용.
- 수집 절차 편입: 신규 MCP 사례 등재 시 check_mcp+LLM 감사 수행. 주간 점검(월)에
  `check_mcp.py --audit-only`로 CVE 재스캔.
- 파이프라인 순서: build_eval_data 뒤에 build_mcp_review 삽입(사례 페이지 배지가 읽음).

## 6. 에러 처리·엣지

- clone 실패(비공개·삭제 저장소): 전축 "미검증(저장소 접근 불가)" + 사유 기록.
- audit 도구 부재(npm/pip 미설치 생태계): 해당 축 "미검증(도구 없음)" — 침묵 통과 금지.
- Inspector 실행 실패·타임아웃(120초): dynamic.done=false + 사유. 재시도 1회.
- 동적 검사는 자격증명·개인정보 없는 환경에서만 — API 키가 필수라 실행 불가면
  "미검증(자격증명 필요)"로 기록하고 실행하지 않는다.
- 검사 대상 저장소 코드는 검사 후 임시 디렉토리 삭제 — 로컬에 잔존 금지.

## 7. 테스트

- check_mcp: 픽스처 저장소(양성 시크릿/음성, 셸 도구 유/무, 락파일 유/무)로 축 1~3
  판정 검증. 병합 시 LLM 감사 축 보존 검증. clone 실패 경로 검증.
- build_mcp_review: disclosure 미해결 항목의 note가 공개 산출물에서 마스킹되는지 검증(핵심).
- 스키마: verdict 5종 외 거부, case_id가 실존 사례인지 검증.
- JS: node --check + 배포 검증 루프.

## 8. 범위

포함: 6축 프레임·원장·check_mcp.py(축 1~3 자동)·LLM 감사 절차·선별 동적 검사·
build_mcp_review·mcp-review 페이지·사례 배지·메뉴 추가·수집/주간 절차 편입·전수 백필.

제외(후속): 외부 전문 스캐너(mcp-scan·semgrep) 통합, 샌드박스 행위 관측(네트워크 후킹),
개발자 셀프 인증 제출 절차, 검증 이력 추이 화면.
