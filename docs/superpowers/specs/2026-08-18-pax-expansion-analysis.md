## 0. 핵심 진단 (Executive Summary)

1. **관측은 유일하지만 해석은 시작 단계다.** PAX는 "예산 없이 자생한 실무자 공공AX"를 관측하는 국내 유일 자산이다. 그러나 기관유형의 85%가 '기타', 지역 필드 부재, 라이선스 미표기로 인해 **정책·기관이 인용할 수 없는 데이터** 상태다.
2. **배관은 깔렸는데 물이 흐르지 않는다.** MCP 서버 55건이 폭증했지만 MCP∩공공데이터 31건 전부가 C0(기능 제공)이다. 소비(Client·Host 6건) 없는 공급, 폐쇄루프(C3) 1건, 권한·승인·감사 서술 사실상 0회 — Agentic 전환의 조건이 데이터에 통째로 비어 있다.
3. **First 이상은 개인이 만들 수 없다.** Ready 119/Enabled 46/First 1/Native 0의 분포는 bottom-up의 한계선을 보여준다. 유일한 First(광진구)는 개인 도구가 **기관 운영모델**(관리 원칙+전 직원 투입)로 전이된 사례다. 전이 경로의 제도화가 다음 단계의 전부다.
4. **챔피언은 조명되지만 보호받지 못한다.** 유지보수 책임의 개인 귀속, 사비·개인장비 개발, 교육·인증의 접근 장벽, 동의 없는 등재(opt-out조차 어려운 구조) — 확산 동기와 개인 부담이 충돌하고 있다.
5. **사이트의 다음 정체성은 "민간 관측소 + 전환 안내소"다.** 정부 공공 AX 포털(선정된 우수사례)과 경쟁하지 않고, 선정되지 않은 것·멈춘 것까지 기록하는 전수 관측과, 자가진단·체크리스트로 다음 단계를 안내하는 역할로 분화해야 한다.

## 3. 주제별 심층 분석

### 3.1 공공 AX 챔피언의 역할과 대우 — 비판적 현황 (커뮤니티 코퍼스 4,337건 근거)

**관찰된 현실**:
- **유지보수의 개인 귀속**: "안 되면 전화 오는 유지보수 책임 문제", "기존 업무 + 유지보수·설명 부담 증가". 커뮤니티 스스로 "지속가능한 AX의 필수요건은 기여자의 유지보수 하중을 줄이는 것"이라 정리함. 통합유지보수로 올리면 FP 기준 비용 폭증으로 반려.
- **자원의 사적 부담**: 범정부오피스는 "혼자서 예산 0원", 개발은 "거의 개인컴에서", 챔피언 사비 문제가 국가인공지능전략위 분과장을 통해 대통령·총리에게 직보될 정도의 의제.
- **인정 체계의 미스매치**: 교육 가면 "너만 받는 건 특혜" 눈치, 외부 강의 눈치, "하고 싶은 거 하지 말고 해야 할 일 먼저"라는 면박. AI 챔피언 인증 교육은 평일 09-18시 실시간 줌 3주 — 현업과 병행 불가한 설계. 반면 "챔피언 수를 경평지표로" 같은 왜곡 우려("하던 일에 AI 딱지 붙이고 에이전트 수 부풀릴 것")도 공존.
- **전이 성공 사례의 공통 패턴**: NIA(공유 변환기→API 제거→보안성검토→내부망 배포→기관장 품의→의무화→타 기관 공유), 광진구(도구 6종→4대 관리 원칙 공표→전 직원 투입→행안부 대회 선정). **개인의 헌신이 아니라 기관의 수용 절차가 성패를 갈랐다.**

**PAX가 할 수 있는 일**:
1. (상) **전이 플레이북 페이지**: NIA·광진구 패턴을 "개인 도구가 기관 공식이 되는 절차"(보안성검토→품의→배포→의무화)로 문서화, 각 단계에서 쓸 서식·근거 가이드라인 연결
2. (상) 챔피언 카드에 **유지보수 상태·후속자 모집** 표시 — 부담의 공론화이자 인수인계 채널
3. (중) **챔피언 카드 PDF 내보내기** — 사례·평가·인증을 담은 한 장, 성과 보고·인사 자료로 쓸 수 있는 현실적 '공식성'
4. (중) 인증 연동 확대(정부 챔피언 제도와 산출물 명단의 교차 — 정책연계 분석 참조) + 역할 인증(메인테이너/데이터 스튜어드/안전 검토자 — 미래 분석 참조)
5. (상·원칙) **등재 통지와 표시 수위 선택권** — 조명이 부담이 되지 않도록 (챔피언 관점 분석의 display_level)

### 3.2 공공 GitLab의 역할과 활용 이슈 — 비판적 현황

**관찰된 현실**:
- **성장**: 개설 한 달여 만에 가입 1,000명·프로젝트 405개, 행안부가 전 기관 공문으로 안내. PAX에도 공공 깃랩 사례 15건+ 등재, GitHub와의 미러링 시작(What-I-have-to-do, gonggong-ax-local-4).
- **마찰**: 가입 후 관리자 승인 지연(승인 메일 미도착 문의), 온AI 실험실은 "그냥 챗봇 — korea-law-mcp도 연결 못 하고 개발 시스템도 직관적이지 않다"는 실사용 평가, 행망에서 GitHub·Vercel·Netlify 차단이라는 근본 문제는 여전(github.io·파이어베이스 우회가 관행).
- **구조적 관찰**: 공공 깃랩 프로필은 "기관 실명"이 표준이라 신원·소속의 가장 신뢰할 수 있는 원천이 됨(PAX 챔피언 19명 실명·소속 확정의 근거). 반면 외부 생태계(GitHub 스타·이슈·PR 문화)와 단절되어 있어 반응·협업 신호가 약함.

**PAX가 할 수 있는 일**:
1. (상) **공공 GitLab ↔ GitHub 브릿지 페이지**: 미러 쌍 추적, "내부망산 도구의 외부 공개율"이라는 개방성 지표 산출 (정책연계 분석과 동일 제안 — 2개 관점 수렴)
2. (중) 공공 깃랩 신규 공개 프로젝트의 **정기 모니터링 수집원 승격** (현재는 수동 배치 위주 → explore API 주기 조회)
3. (중) 온AI 실험실·공공 깃랩 사용기 사례의 별도 태그화 — 실사용 마찰이 곧 개선 입력값
4. (하) 공공 깃랩 운영진(행안부 AI실험실 — 이미 챔피언으로 등재된 김기현·정준우 등)과 사례 상호 연계 제안

### 3.3 중앙-지방 격차와 교육 현장

**관찰된 현실**:
- **데이터의 침묵이 곧 격차다**: 지자체 명시 사례 7건 전원 수도권(서울·광진·화성·경기의회·남양주). 부산·대구·대전·호남·영남 기초지자체 사례 0건. 챔피언 소속도 행안부 4명 vs 기초지자체 4명(각 1명씩). 226개 기초지자체 중 관측된 곳 5곳 미만.
- **조직 내 격차**: "상위 1%는 날아다니고 기관 중앙값은 그대로", "MCP 설치가 일반 직원에겐 만만치 않다", "중앙부처 외에 지방직 최하위 기타공공기관까지 적용되게 해달라"는 직접 호소.
- **레거시 시스템의 벽**: 새올·이호조·에듀파인 등 지방·교육 행정 시스템은 API가 없어 "여비계산기도 이호조 미연동이라 반쪽", 화면 파싱의 기관승인 논쟁까지. 중앙(범정부 공통기반·온나라)과 지방(새올)의 인프라 격차가 도구 격차로 직결.
- **교육 현장**: 전북교육청 K뚝배기(공문 분류, 전국 최초 보도)·공식 배포 도구처럼 교육청 단위 성공 사례가 있으나, "학교 확대는 회의적" 담론, 가정통신문 다국어 번역 같은 학교 고유 수요는 미충족. 교육 org_type 사례 2건뿐.

**PAX가 할 수 있는 일**:
1. (상) region 필드 신설 후 **격차 지도/현황판** — "관측되지 않은 지역"을 회색으로 보여주는 것 자체가 정책 메시지
2. (중) **레거시 연동 수요 보드**: 새올·이호조·에듀파인 등 시스템별 "MCP/API가 있다면 만들 것" 수요 목록 — 그룹웨어 벤더·행안부에 전달할 실증 수요
3. (중) 교육 현장 트랙: 교육청 배포 도구·학교 수요 사례를 별도 큐레이션, 시도교육청 공공 깃랩·자료실 정기 수집원 추가
4. (하) 비수도권 커뮤니티 채널(지역 오픈채팅 등) 수집원 발굴 — 표본 편향의 실질 완화

### 3.4 Bottom-up 발굴 × 조직 차원 프로젝트의 연계 (4단계 AX 분석 기반)

**진단**: 4단계 분포(Ready 68%→Enabled 26%→First 0.6%→Native 0)는 실패가 아니라 **분업의 자연스러운 결과**다. bottom-up은 Ready·Enabled를 대량 생산하는 데 최적이고(개인이 만들 수 있는 것), First부터는 관문 자체가 조직 권한을 요구한다(역할 재설계, 예외처리 제도화, 운영 책임). 데이터가 보여주는 전이의 3가지 검증된 경로:

| 경로 | 사례 | 메커니즘 |
|---|---|---|
| **수용**(기관이 개인 도구를 공식화) | NIA 마크다운 의무화, 광진구 6종 투입 | 보안성검토→품의→배포→(의무화) |
| **탑재**(범정부 인프라에 올림) | 법제처 AI 법령비서(공무원 개발→온AI 실험실 탑재→전 공무원), 병무청 워크메이트 | 범정부 AI 공통기반이 배포 인프라 역할 |
| **개방**(공공 깃랩·GitHub 공개→타 기관 재사용) | gongedu, 전북교육청 도구, 미러링 사례들 | 코드 공유→각 기관 자체 수용 |

**연계 활성화 제안**:
1. (상) 사례에 `transition_stage` 필드: `개인 사용 → 부서 공유 → 기관 공식(보안검토·품의) → 타 기관 재사용 → 범정부 탑재` — 전이 단계별 현황판이 곧 "확산 퍼널"이 되고, 병목 구간이 정량화됨
2. (상) **전이 플레이북**(3.1과 동일 항목 — 두 분석이 같은 결론으로 수렴): 각 전이 단계의 절차·서식·가이드라인 연결
3. (중) `blocker` 필드(정책 관점 제안 수용): 전이가 멈춘 사유(보안검토/예산/담당자 이동/레거시 미연동/법적 근거/조직 저항)를 코딩 — "S3→S4로 못 가는 이유"의 실증 데이터
4. (중) 기관 담당자용 제보 양식: 개인 챔피언 창구와 별도로, 기관이 수용 사례(품의·보안검토 통과)를 등록하는 경로 — 도입 실행정보(예산·기간·조달·보안검토) 필드를 채울 유일한 현실적 수단
5. (하) First 후보군 트랙(C2 19건+C3 1건): 관문별 미충족 항목 추적, 발견된 제도 장애물을 규제 개선 과제로 축적

### 3.5 AI-native로 가는 길 — 무엇이 함께 고민되어야 하는가

Native 관문(핵심가치 결합+학습구조 C5+복원력)을 현재 데이터와 겹치면, **개인 개발로는 원리적으로 채울 수 없는 결손 조건** 4가지가 드러난다:

1. **폐쇄루프의 제도화** (C3+): 접수→처리→검증→종료 확인을 닫으려면 업무 시스템 쓰기 권한(P2+)이 필요한데, 권한 서술이 있는 사례가 0건. → **P축(권한 범위 P0~P4) 신설**과 P등급별 요구 통제(승인 게이트·감사 로그·킬스위치) 표준화가 선행 조건 (미래 분석 수용)
2. **평가 데이터화** (C5): 사용 결과가 평가셋으로 축적되는 사례 0건. 173건이 피드백 미확인. → 안전 프로필 6항목(권한/인간통제 4단계/승인 게이트/감사 로그/폴백/모델 의존)을 사례 표준 서술로 요구, '미확인 비율' 자체를 대시보드 KPI로
3. **복원력** (Native 관문): 모델 장애·가격 변동 대응이 서술된 사례가 부분확인 수준. 로컬 모델·독자 모델 흐름(내부망 10, 로컬 11, 독파모 연계)이 유일한 완화 경로 → model_dependency 필드로 국산/로컬/상용 의존을 관측
4. **실패의 기록**: Native로 가는 길은 성공 사례가 아니라 "왜 멈췄는가"에서 배운다. 현재 176건 전부 성공 편향. → 실패·중단 사례 트랙(익명 제출 허용)

**단계 이행 로드맵으로서의 사이트**: 자가진단(현재 6문항 인포그래픽 → C×H×P×R 좌표 판정 위저드) → 같은 좌표의 사례 3건 제시 → 다음 관문 체크리스트 → 전이 플레이북 연결. 이 4단 구조가 "관측 도구에서 안내 도구로"의 구체적 구현이다.

### 3.6 정부 정책 연계 (7대 정책 — 상세는 정책연계 분석 원문)

| 정책 | 핵심 연계 수단 | 우선순위 |
|---|---|---|
| 독자 파운데이션 모델(독파모) | `model_dependency` 필드 → "공공 사례의 국산 모델 채택률" 지표, 국산 모델 적합 업무(내부망·개인정보·C3+) 후보 리포트 | 상 |
| AI 메가 프로젝트 | **공공 AX 지수** 분기 공표(AX 분포·C축 평균 시계열) — 투입 지표뿐인 정책에 성과 관측 제공 | 상 |
| 특화 파운데이션 모델 | 도메인 클러스터 분석(법령 21·문서 19·조달 등) → **"행정·법령 특화 모델" 공모 공백 지적 제안서** | 상 |
| 공공 AX 챔피언 제도 | 이수 기반(정부) × 산출물 기반(PAX) 명단 교차, 인증 등급 상호참조(동의 기반), 우수과제 등재 트랙 | 중 |

**포지셔닝 원칙** (정책연계 분석 결론 수용): ① 민간 관측소 — 일관된 척도의 분기 반복 적용이 최우선 ② 피드백 루프 — 데이터를 문서로 만들어 NIA·NIPA·KISA 접점에 밀어 넣기 ③ 확산 채널 — 정부 포털과 경쟁이 아닌 계층 분리. **"정부가 자기 자료로 만들 수 없는 숫자를 여기서 인용하기 시작할 때" 인프라가 된다.**

### 3.7 공공데이터 활성화 × Agentic 전환 (미래 분석 요약)

- **공공데이터**: 풀뿌리 MCP화(62건)는 "AI가 쓰고 싶은 데이터" 수요 순위표(법령 14·서울시 9·DART 6·건축 5·조달 4...)다. 공식 MCP만 M4에 도달(HRDKorea 유일)한다는 관측 → **데이터 AI 접근성 관측소** 페이지(고가치 100종 × MCP 커버리지 매트릭스), **데이터 결함 리포트 루프**(개발자가 발견한 API 문제를 기관별 리포트로 환류, 해결 실적 우선 노출), 공식화 경로 배지(비공식→인지→공동 유지보수→공식), PAX 자체 MCP 서버(`pax-mcp`)
- **Agentic**: 국제 기준은 "만들 수 있는가"에서 "**한 일을 증명할 수 있는가**"로 이동(MCP의 리눅스재단 이관, A2A v1.0, NIST·IMDA 프레임워크). PAX의 위치: 배관(Server 55) 세계적 속도, 운영(C3 1건) 미시작, 거버넌스 서술 0. → P축 신설, 안전 프로필 6항목, Agentic 자가진단 페이지, 챔피언 역할 인증(메인테이너·데이터 스튜어드·안전 검토자), A2A 관측(현재 0건 자체가 관측 가치)

### 3.8 운영자 관점 — 자동화·지속가능성 (직접 분석)

- **파이프라인 취약점**: 세션 크론 7일 만료(8/15 실제 누락 발생), 카카오 수집이 Mac 앱 실행에 의존(2회 중단), Threads가 Chrome 확장 연결에 의존, 확장 출력 필터 우회 필요. → launchd+`claude -p` 항구 자동화 검증이 필요하고, 실패 시 알림(현재는 로그만) 추가
- **데이터 품질 부채**: evaluated_at 고정, 평가 기준서(엑셀)와 보충 파일(eval_additions 92건)의 이원 관리 — 보충이 본체를 넘어섬, 원 엑셀 재발행 또는 단일 소스화 필요. 태그 표기는 아직 흔들림 없음(검사 통과)
- **코드 부채**: app.js 966줄(800줄 규칙 초과) — 분리 후보: 북마크/내보내기/렌더러. style.css 1,900줄+
- **원문 보존**: 카카오 앱은 메시지 3개월 보관 — raw 파일은 로컬 보존 중이나 백업 정책 없음(비공개 유지 전제의 백업 필요)
- **개인 의존**: 큐레이터 1인 운영, 평가·연결·인증 판단이 세션 기억에 의존 — 판정 기준의 문서화(방법론 버전 태그)와 champion_links/certifications처럼 **근거를 데이터로 남기는 패턴**을 평가 전반으로 확장

### Phase 3 — 생태계 역할 (장기, 분기 단위)
- 정책 접점 정례화: NIA 공공AI사업지원센터·NIPA 특화모델·KISA N2SF에 분기 리포트 제출, 공공 AX 포털과 데이터 상호연계 제안
- 행정·법령 특화 파운데이션 모델 수요 제안서 발간, 도메인 평가셋 기여
- 실패·중단 사례 트랙(익명), First 후보군 추적 트랙
- 챔피언 역할 인증(메인테이너·스튜어드·안전 검토자) + 정부 인증 상호참조

### 관점 간 긴장(트레이드오프) — 설계 시 유의
1. **조명 vs 익명**: 챔피언 확산 동기와 개인 부담 — display_level과 통지 절차가 완충재. 전면 공개를 기본값으로 강제하지 않는다.
2. **전수 관측 vs 품질 신호**: 민간·아이디어 단계까지 담는 포용성과 결정권자용 신뢰성 — case_class 분리와 배지로 해결하되, 숫자(176건)를 마케팅하지 않는다.
3. **관측 vs 개입**: 결함 리포트·병목 데이터가 기관 비판이 되면 루프가 끊긴다 — 해결 실적 우선 노출 원칙.
4. **정부 연계 vs 독립성**: 관측소의 가치는 독립성에서 나온다 — 데이터 제공은 하되 판정 기준의 독립을 유지, 자금·운영 종속을 피한다.
