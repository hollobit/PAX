# 공공 AX의 AI 모델 사용 실태와 정책 과제

작성: 2026-08-29 · 근거: PAX 아카이브 235건 전수 실측(저장소 코드·설정 파일 수준 검증)
관련 화면: [관측소 — 모델 현황](https://hollobit.github.io/PAX/observatory.html#models)

---

## 요약

공공 AX 사례 235건의 런타임 모델 의존을 전수 조사한 결과, LLM을 런타임에 호출하는 52건 중
**국산 모델 채택은 3건(5.8%), 혼합 내 국산 병용까지 넓혀도 5건(9.6%)**이다. 해외 상용 API가
33건(63%)으로 지배적이고, 해외 오픈웨이트 로컬 실행이 9건(17%)이다. 그러나 이 수치의 이면에
세 가지 구조가 있다. 첫째, 사례의 22%(52건)는 **모델 중립(BYO)** 구조 — MCP 서버처럼 이용자의
클라이언트 모델 위에서 돌아 코드 수정 없이 국산 모델로 이식 가능한 층이다. 둘째, 비LLM 도구
65건을 포함한 거의 모든 사례가 **개발 단계에서는 해외 프론티어 모델**(Claude·Codex 등)로
만들어졌다 — 런타임 종속보다 깊은 개발 종속이다. 셋째, 범정부 AI 공통기반의 정부 전용 모델
**HCX-GOV-THINK-V1-32B**와 행안부의 **EXAONE 내부망 도입**이 코드·사례 수준에서 실측되어,
국산 전환의 인프라는 이미 가동을 시작했다. 결론적으로 국산 확산의 관건은 모델 성능 이전에
**클라이언트·에이전트 생태계, 접근성(API·크레딧), 그리고 무엇을 쓰는지 기록하는 관행(AI-BOM)**이다.

## 1. 조사 방법과 한계

- **대상**: PAX 등재 235건 전수. 판정 기준은 **런타임 의존** — 도구가 실행 중 호출하는 모델.
  "Claude Code로 개발했다"(바이브 코딩)는 런타임 의존으로 세지 않고 별도 층위로 분석했다.
- **방법**: ① 사례 요약·README 스캔 → ② 저장소 42곳 코드·설정 파일 클론 검사(모델 식별자·
  API 키 변수·엔드포인트) → ③ 오탐 행 단위 검증(`indexOf`→"exO", `ImageFilter.Gauss` 등 10여 건 배제).
- **한계**: 미확인 66건(28%)은 AI 기능은 있으나 코드 증거가 없는 사례다(폐쇄망 내부 도구·발표
  사례 다수). 이 결측 자체가 "모델 명시 관행 부재"라는 본 보고서의 문제의식 중 하나다.

## 2. 실측 현황

| 분류 | 건수 | 비중(전체) | 의미 |
|---|---|---|---|
| 해외 상용 API | 33 | 14.0% | GPT·Claude·Gemini 등 API/구독 호출 |
| 해외 오픈웨이트(로컬) | 9 | 3.8% | Gemma·Ollama 등 로컬 실행 — 데이터 미유출 |
| 혼합 | 7 | 3.0% | 상용+로컬, 국산+해외 병행 |
| **국산 독자모델** | **3** | 1.3% | HCX-GOV 2 · schift 자체 학습 2(사례 기준 3) |
| 모델 중립(BYO) | 52 | 22.1% | MCP 서버 등 — 클라이언트 모델 위 구동 |
| 없음(비LLM) | 65 | 27.7% | 규칙 기반 도구(개발에만 AI 활용) |
| 미확인 | 66 | 28.1% | AI 기능 있으나 모델 증거 미확보 |

구체 모델 상위: Claude/Codex 상용 에이전트 18 · GPT 계열 9 · Gemini 7 · Gemma 6 ·
로컬 서빙(Ollama·vLLM·LM Studio) 8 · HCX-GOV-THINK-V1-32B 2 · schift 2 · Qwen 1 · GLM 1 · EXAONE 1.

**특기 실측 3건**
1. **HCX-GOV-THINK-V1-32B** — 범정부 AI 공통기반의 정부 전용 하이퍼클로바 추론 모델(32B)이
   실전 도구 2건(온나라 AI 문서 분배기, 범정부 내부망 사이드바)의 기본 모델로 코드에 명시됨.
   멀티모달은 `LLM42-Gemma4`로 자동 전환하는 이중 구성까지 확인 — 정부 인프라의 모델 라인업이
   "국산 추론 + 오픈웨이트 멀티모달" 하이브리드임을 보여주는 첫 공개 관측.
2. **EXAONE** — 행안부가 엑사원·Gemma4를 행정 내부망에 도입(2026-08). 국산 오픈웨이트의
   기관 단위 채택 첫 사례.
3. **schift-ko-pii** — 한국어 개인정보 탐지 특화 자체 학습 모델. "대형 상용 대비 40배 작고
   성능 우위" 주장 — 태스크 특화 SLM의 국산 경로 실증.

## 3. 유형별 분석

### 3.1 해외 상용 모델 — 지배적이나 단일 아님
런타임 33건 + 스킬·에이전트류(상용 코딩 에이전트 구독 전제) 18건이 겹치며, GPT(GPTs·GEM 포함)·
Claude·Gemini가 삼분한다. 특징은 **구독 개인 부담** — "사비로 세 번째 충전, 이게 뭐하는 짓인가"라는
실무자 토로, 기관별 구독료 처리 방식(경상비·팀/개인 계정·한도) 제각각이라는 실측 담론이 병행한다.
비용 구조가 개인에게 전가된 채 해외 상용 의존이 형성되고 있다는 점이 문제의 핵심이다.

### 3.2 오픈웨이트 로컬 — '폐쇄망 대응'이 만든 자생 흐름
로컬 9건 + 혼합 내 로컬 병행을 합치면 LLM 사례의 약 4분의 1이 오픈웨이트를 로컬 실행한다.
동기가 뚜렷하다: 행정망·폐쇄망 제약과 개인정보 처리 — "자료가 PC 밖으로 나가지 않는다"가 공통
문구다. **Gemma 편중**(6건 — E2B/E4B 온디바이스 변형)이 특징으로, 9.6GB 모델을 원클릭 셋업으로
번들 배포하는 사례(공무원 워크플레이스)까지 나왔다. Llama·Mistral은 관측되지 않았다 — 한국어
성능과 경량 변형 가용성이 선택을 결정한다는 방증이다.

### 3.3 중국계 모델 — 실측 2건, 담론은 그 이상
- 실측: **Qwen**(공공기관 규정 MCP 생성기 — 로컬 RAG 챗), **GLM-5.3**(MoAI Cowork 에이전트
  레지스트리의 지원 모델). DeepSeek·Kimi(K2)는 코드 증거 0건.
- 담론: GPU 서버 구축 논의에서 "gpt-oss 120b·qwen·glm 서빙" 계획이 실무자 대화로 관측 —
  도입 후보군에는 이미 올라 있다.
- 이슈: 중국계 오픈웨이트는 로컬 실행 시 데이터 유출 리스크는 낮으나, ① 학습 데이터·정렬
  편향의 검증 부재, ② 공공 조달·보안 규정상 취급 기준 부재(현재 어떤 규정도 모델 원산지를
  다루지 않음), ③ 미국 수출통제·동맹 규제와의 정합성 문제가 남는다. **"금지"도 "방치"도 아닌
  판별 기준이 없다는 것**이 현재의 공백이다.

### 3.4 국내 모델·독자 파운데이션 — 인프라는 가동, 접점이 부족
국산 실측 5건(독자 3 + 혼합 병용 2)의 공통점은 **범정부 AI 공통기반이라는 공식 접점**을 통했다는
것이다(HCX-GOV 2건 모두). 반대로 개인 개발자가 시장에서 국산 모델 API를 선택한 사례는 schift
(자체 학습)를 제외하면 없다 — HyperCLOVA X·A.X·믿:음 등의 일반 API를 쓴 사례가 0건이다.
Solar(Upstage)·Kanana도 0건. **모두의AI(SK·KT·카카오 선정)** 담론이 커뮤니티에 돌지만 아직
도구 코드에는 닿지 않았다. 결론: 국산 모델의 문제는 인지도가 아니라 **개인 개발자 접근성**
(무료 티어·크레딧·문서·에이전트 클라이언트 지원)이다.

### 3.5 프론티어 모델 — 진짜 종속은 개발 단계에 있다
비LLM 65건을 포함한 사례 대부분이 Claude Code·Codex 등 **해외 프론티어 에이전트로 개발**됐다
(바이브 코딩). 커뮤니티 실측에서 실무자들은 최상위 모델을 한도 소진까지 쓴다("페이블 다 씀").
즉 런타임 국산화가 진전돼도 **생산 수단의 프론티어 종속**은 별개로 남는다. 이는 국산 프론티어
부재가 만드는 구조적 종속이며, 단기 대체가 불가능한 만큼 ① 개발 종속과 런타임 종속을 구분해
관리하고 ② 국산 모델이 잘하는 층(추론 경량 태스크·한국어 특화·문서 처리)부터 런타임을 확보하는
전략이 현실적이다.

### 3.6 SLM — 가장 유망한 국산 경로
schift-ko-pii(개인정보 탐지)와 Gemma E2B(요약·번역)의 실측은 같은 방향을 가리킨다:
**공공 업무의 상당수는 프론티어가 필요 없다.** 개인정보 마스킹·서식 변환·분류·요약 같은
반복 태스크는 태스크 특화 SLM으로 충분하며, 폐쇄망 PC에서 돌고, 데이터가 남지 않는다.
국산 모델이 프론티어 경쟁 대신 **공공 태스크 SLM 제품군**(마스킹·공문 요약·법령 검색 랭커·
STT)으로 진입하면 폐쇄망이라는 제약이 오히려 보호된 시장이 된다.

## 4. 이슈와 문제점

1. **3중 해외 종속**: 런타임(상용 API 63%) + 개발(프론티어 에이전트) + 플랫폼(GitHub·Vercel 등
   배포 인프라)의 서로 다른 종속이 겹쳐 있으나 정책은 런타임만 본다.
2. **비용의 개인 전가**: 구독·API 비용 사비 부담이 관행화 — 해외 상용 의존이 "개인의 선의"로
   보조되는 왜곡 구조.
3. **모델 명시 관행 부재**: 28%가 미확인. README에 모델·버전을 밝힌 사례는 소수이며,
   버전 고정(pinning)은 더 드물다. 재현성·보안 감사·교체 판단이 모두 불가능해진다.
4. **모델 원산지·거버넌스 기준 공백**: 중국계 포함 오픈웨이트의 공공 사용 판별 기준이 없다.
5. **폐쇄망-모델 미스매치**: 폐쇄망 수요는 로컬 모델을 강제하는데, 조달·보안성 검토는
   모델 단위가 아니라 시스템 단위라 로컬 모델 교체·업데이트 절차가 규정 밖에 있다.
6. **국산 모델의 개발자 접점 부재**: 공식 인프라(공통기반) 경유가 아니면 국산 모델을 만날
   경로가 사실상 없다.
7. **BYO 층의 방치**: 코드 수정 없이 국산 이식 가능한 52건(22%)이 있는데, 이 층을 공략하는
   국산 MCP 클라이언트·에이전트가 없다.

## 5. AI-BOM(AI 자재명세서) 적용의 필요성

소프트웨어의 SBOM처럼, 공공 AI 도구는 **무엇으로 돌아가는지의 명세**가 필요하다. 이번 조사가
코드를 일일이 뒤져야 했던 것 자체가 AI-BOM 부재의 증명이다. PAX의 `models_used`·
`model_dependency` 필드는 사실상의 원시적 AI-BOM이며, 이를 표준화하면 된다:

- **최소 명세(권장)**: 모델명·버전 | 호출 경로(API/로컬/BYO) | 데이터 흐름(전송 대상) |
  모델 라이선스 | 폴백·교체 가능성
- **적용 지점**: ① 공공 깃랩 저장소 메타데이터(README 표준 블록 또는 `ai-bom.json`),
  ② 보안성 검토 요청서 필수 항목(경기도 거버넌스 실험과 결합), ③ 정부 구매·확산 시 제출 서류.
- **효과**: 원산지·버전 리스크 일괄 조회, CVE형 모델 취약점 공지 대응, 국산 전환 대상 식별
  자동화. PAX 관측(사례 235건 실측)이 초기 레지스트리 역할을 할 수 있다.

## 6. 국내 개발 모델 확산을 위한 정책 요소

1. **BYO 층 공략이 최우선** — 모델보다 **국산 에이전트 클라이언트**(Claude Desktop·Cursor의
   국산 대응물, 공통기반 연동 MCP 호스트)에 투자. 52건의 모델 중립 도구가 즉시 국산 런타임이 된다.
2. **개인 개발자 크레딧** — 공무원·공공기관 개발자에게 국산 모델 API 무료 크레딧(모두의AI
   선정사 연계). "사비로 해외 상용"의 대체재를 먼저 쥐여줘야 한다.
3. **공통기반 API의 개방 반경 확대** — HCX-GOV를 내부망 공식 도구만이 아니라 공공 깃랩
   등재 개인 개발 도구에도 신청제로 개방(온나라 분배기·사이드바 모델이 이미 검증한 경로).
4. **공공 태스크 SLM 제품군 조달** — 마스킹·요약·분류 등 태스크별 국산 SLM을 카탈로그화하고
   조달 가점·수의계약 경로 부여. schift 사례가 보여준 시장이다.
5. **한국어 공공 벤치마크 공개** — 공문서·법령·민원 태스크 기준의 공개 리더보드. "국산이라서"가
   아니라 "이 태스크에 좋아서" 선택되게 하는 신뢰 장치.
6. **모델 원산지 거버넌스** — 오픈웨이트 사용 기준(허용 목록·검증 절차·업데이트 관리)을
   N2SF 등급 체계와 연동해 명문화. 중국계 모델을 판별 기준 없이 방치하지 않는다.
7. **AI-BOM 의무화와 인센티브 결합** — 명세 제출 도구에 보안성 검토 간소화 혜택(§5).

## 7. AI정부실험실에서 국내 모델 사용을 촉진하는 방법

AI정부실험실은 실험 단계 — 즉 **모델 선택이 아직 굳지 않은 지점**이라 개입 효과가 가장 크다.

1. **기본 제공 모델을 국산으로**: 실험실 환경(VM·개발존)에 HCX-GOV·EXAONE·공공 SLM을
   기본 탑재하고 해외 모델은 선택 설정으로 — 기본값(default)의 힘을 활용.
2. **국산 모델 실험 트랙 신설**: 같은 과제를 국산/해외 모델로 병렬 실험하고 결과를 공개
   비교하는 트랙 — 벤치마크(§6-5)의 실전 공급원이 된다.
3. **모델 스왑 챌린지**: 기존 BYO 도구(MCP 서버 52건)를 국산 클라이언트·모델로 구동하는
   검증 대회 — 이식 실적이 곧 국산 호환성 카탈로그가 된다.
4. **챔피언 크레딧 연계**: AI챔피언 인증자(데이터버스)에게 실험실 국산 모델 크레딧을 자동
   부여 — 교육(데이터버스)→실험(실험실)→확산(공공 깃랩)의 파이프라인에 국산 모델을 끼워 넣는다.
5. **실험 결과의 AI-BOM 자동 생성**: 실험실 산출물에 모델 명세를 자동 첨부해 관행을
   기본값으로 만든다 — 훗날 보안성 검토·구매 심사의 입력이 된다.
6. **성공 사례의 명시적 전시**: 온나라 분배기·사이드바처럼 공통기반 모델로 만든 도구를
   실험실 대표 사례로 내걸어 "국산으로 되는 일"의 목록을 늘린다.

## 8. 중국의 자국 모델 확산 정책 — 무엇을 참조할 수 있나

중국은 자국 모델 확산에서 가장 공격적인 성과를 낸 사례다. 검열 정합·강제 조달 같은 체제
종속적 요소를 걷어내고 **메커니즘만 추출**하면 참조 가치가 뚜렷하다. (아래 ①~③은 공개 정책,
④는 본 아카이브 커뮤니티에서 실무자 비교 관측으로 포착된 내용이다.)

### 8.1 그들이 한 것

1. **오픈웨이트를 생태계 무기로** — Qwen(알리바바)·GLM(즈푸)·DeepSeek가 경쟁적으로 가중치를
   공개해 전 세계 로컬 실행 생태계의 사실상 표준 후보가 됐다. 모델 판매가 아니라 **생태계
   기본값 장악**이 전략이며, 우리 실측에서도 중국계 모델이 서빙 후보 담론에 이미 올라 있다
   (§3.3). 국내 모델은 EXAONE 외 오픈웨이트 공개가 드물어 이 게임에 참전 자체를 안 한 상태다.
2. **지방정부 대량 배치의 물결 효과** — 2025년 DeepSeek 공개 직후 수십 개 지방정부가 정무
   시스템에 배치하며 "정부가 쓴다"는 신호 자체가 민간 확산을 견인했다. 채택이 채택을 부르는
   가시성 루프를 정부가 먼저 돌린 것이다.
3. **국가 컴퓨팅 + 바우처** — 동수서산(東數西算)류 국가 지능형 컴퓨팅 인프라에 지역별
   **컴퓨팅 바우처**를 얹어, 모델 사용의 한계비용을 정부가 흡수했다. "사비로 해외 상용"(§4-2)
   이라는 우리의 왜곡 구조와 정확히 대비된다.
4. **공무원 개발자 제도화 — 창객스타·5성 지능체** *(커뮤니티 실측 비교)* — 정부 전용 AI
   개발환경, 정부 구축 대모델·국산 컴퓨팅의 공무원 공동 사용, 행정문서·내부 지식베이스
   API 연계, 집중 실전교육, 공식 인증·포상, 우수 개발자의 시·구 지도부 성과 발표, 그리고
   **우수 모듈의 정부망 탑재와 타 부처 재사용**까지 — 개인의 개발이 제도의 자산이 되는
   전 경로가 설계돼 있다.
5. **모델 등록제(필링)** — 생성형 AI 서비스 등록제가 결과적으로 "공공에서 쓸 수 있는 모델
   목록"을 만들었다. 통제 목적을 걷어내면, 공공 사용 가능 모델의 **공식 카탈로그**라는
   기능이 남는다.

### 8.2 우리 정책 모델로 삼을 수 있는 부분

| 중국 메커니즘 | 한국형 번안 (기존 자산 활용) |
|---|---|
| 오픈웨이트 생태계 전략 | 국산 모델의 공공 태스크 특화판 오픈웨이트 공개를 R&D 지원 조건화 — EXAONE 선례 확장, 공공 SLM(§3.6)부터 |
| 지방정부 배치 물결 | 광역 1~2곳의 공통기반 모델 전면 배치 시범(경기도 거버넌스 실험과 결합) → 성과 공개로 가시성 루프 점화 |
| 컴퓨팅 바우처 | 국산 모델 API 크레딧(§6-2)을 챔피언 인증·공공 깃랩 등재와 연동 — "만들면 크레딧이 나온다" |
| 창객스타 인증·포상 | AI챔피언 제도에 등급별 실전 혜택(공통기반 접근권·크레딧·성과 발표 무대) 결합 — 커뮤니티가 이미 "모듈 1개 이상·공통 저장소" 개선안을 자생 논의 중 |
| 우수 모듈 정부망 탑재 | 공공 깃랩 → 검증(보안성 대행) → 정부망 모듈 마켓 승격 경로 제도화 — 국무회의 "정부 구매·확산" 지시와 접속 |
| 모델 필링 | 통제가 아닌 **공공 사용 가능 모델 카탈로그**(원산지·라이선스·검증 상태) — §4-4 거버넌스 공백을 목록으로 해소 |

### 8.3 참조하지 말아야 할 것

- **조달 강제·배제 목록**: WTO 정부조달협정·통상 마찰 리스크가 크고, 품질 신호를 왜곡해
  국산 모델의 실력 향상 유인을 죽인다. 기본값 설계와 크레딧으로 충분히 기울일 수 있다.
- **콘텐츠 정렬 심사**: 표현·학술 자유와 충돌하며 한국의 제도 정합성이 없다.
- **성과의 정치적 전시 과잉**: 발표 무대는 유효하나 실적 부풀리기 유인을 낳지 않도록
  실측 지표(PAX류 관측)와 결합해야 한다.

## 9. 에이전틱 AI 전환기의 소버린 전략 — 추가 고려 사항

에이전트 환경으로 넘어가면 종속의 단위가 바뀐다. 실측이 이미 보여준다: 스킬·에이전트형
사례 18건은 특정 모델이 아니라 **Claude Code·Codex라는 하네스(실행 환경)**에 묶여 있고,
정부 MCP/A2A 게이트웨이 구축 RFP가 관측됐으며, 커뮤니티는 멀티 에이전트 오케스트레이션을
일상 논의한다. 소버린 전략은 모델 확보를 넘어 다음을 다뤄야 한다.

1. **종속 단위의 재정의: 모델 → 에이전트 스택** — 모델·하네스·도구 호출(MCP)·메모리·스킬이
   한 덩어리로 종속된다. 모델을 국산으로 바꿔도 하네스가 해외면 스킬 생태계(우리 실측 18건)는
   그대로 해외에 남는다. **국산 에이전트 하네스**(MoAI Cowork 같은 국산 시도가 이미 실측됨)와
   공통기반 연동 MCP 호스트가 모델보다 빠른 승부처다(§6-1의 에이전트 판).
2. **게이트웨이 = 소버린 통제점** — 정부 MCP/A2A 게이트웨이는 단순 연동 인프라가 아니라
   자격증명 위임·감사 로그·정책 시행(어떤 에이전트가 어떤 도구·데이터에 접근했는가)의
   집행 지점이다. 여기의 표준과 로그 포맷을 국내 주도로 설계하면, 상부 모델이 무엇이든
   **행위 수준의 주권**을 확보한다. 반대로 이 층을 놓치면 모델 국산화도 공허해진다.
3. **에이전트 능력 벤치마크로 전환** — 에이전트 시대의 모델 선택 기준은 챗 품질이 아니라
   도구 호출 정확도·다단계 계획·한국어 문서 처리·긴 컨텍스트다. 국산 모델 확산을 원한다면
   §6-5의 공공 벤치마크를 **tool-use·에이전트 태스크 중심**으로 설계해야 한다. HCX-GOV가
   'THINK' 추론 모델로 배치된 것은 이 방향과 정합한다.
4. **에이전트 신원·권한의 제도화** — 공무원을 대리해 결재·조회·작성하는 에이전트는 인사·
   보안 체계상의 신원(누구의 위임인가), 권한 범위(N2SF 등급 연동), 책임 귀속(사고 시 면책
   기준 — 커뮤니티의 보안성 검토 담론과 동일 구조)이 필요하다. 이를 정의하지 않으면 에이전트
   도입 자체가 막히고, 정의하면 그 규격이 국산 스택의 홈그라운드가 된다.
5. **AI-BOM의 에이전트 확장** — §5의 명세에 에이전트 요소를 추가해야 한다: 사용 하네스,
   장착 스킬·MCP 목록, 도구 호출 권한 범위, 메모리 저장 위치. 에이전트는 실행 시점에 구성이
   바뀌므로 **정적 명세 + 런타임 로그**의 이중 구조가 필요하다.
6. **데이터 중력과 소버린 컴퓨트** — 에이전트 루프는 같은 데이터를 반복 왕복시킨다. 해외
   API 기반 에이전트는 반복 횟수만큼 데이터 유출 표면이 곱해지므로, 폐쇄망·로컬 에이전트
   런타임(오프라인 스택)은 공공 고유 수요이자 국산 생태계의 보호된 시장이다(§3.6과 동일 논리
   의 에이전트판). 국가 컴퓨팅 인프라는 학습용만이 아니라 **추론·에이전트 상주용**으로 설계돼야 한다.
7. **BYO에서 BYOA로** — 오늘의 모델 중립(BYO) 52건이 내일은 "Bring Your Own Agent"가 된다.
   도구 생태계를 에이전트 중립 표준(MCP 등)으로 유지하도록 공공 깃랩 등재 기준·검증(PAX MCP
   검증의 동적 대조 축)을 계속 표준 정합으로 끌고 가면, 어떤 국산 에이전트가 나와도 도구
   자산 전체를 즉시 물려받는다. **중립성 유지가 곧 국산의 진입로**라는 역설이 에이전틱
   소버린 전략의 핵심이다.

## 10. 독자 프론티어 모델의 공공 적용·확산 — 순환 구조 전략

국가가 지원하는 독자 파운데이션 모델(모두의AI 선정 SK·KT·카카오, 그리고 네이버 HyperCLOVA X·
LG EXAONE 등)이 프론티어급으로 개발되더라도, **공공 적용의 실측은 현재 HCX-GOV 파생 2건이
전부**다(§2). 프론티어를 만들었는데 쓰이는 경로가 없는 상태를 피하려면, 개발과 확산을 별개
사업이 아니라 **하나의 순환**으로 설계해야 한다. 중국 사례가 보여준 것이 바로 이 순환이다:
DeepSeek·Qwen은 프론티어를 오픈웨이트로 풀어 전 세계가 양자화·경량화·특화판을 만들게 했고,
그 파생 생태계의 기법·인재·평판이 다시 다음 프론티어에 환류됐다.

### 10.1 5단계 순환 구조

```
① 프론티어 개발 ──► ② 오픈웨이트 공개 ──► ③ 양자화·경량화 ──► ④ 공공 특화 파운데이션
        ▲                                                              │
        └────────────── ⑤ 기술·데이터·평가의 환류 ◄─────────────────────┘
```

**① 프론티어 개발 — 공공을 첫 시장이자 데이터 파트너로.**
국가 컴퓨팅으로 학습하되, 공공 워크로드(공문서·법령·민원·행정 데이터)를 개발 단계부터
목표 태스크로 삼는다. 실측이 보여주듯 커뮤니티는 이미 AI-ready 공공 코퍼스를 자발적으로
만들고 있다 — 세출예산서 마크다운 8,500건, 규정 구조화 DB, 법령 XML→MD 변환기, 국회 회의록
수집기. 이 자산을 학습·평가 데이터로 정식 공급하는 계약 구조(제공 기관·개발자에 대한 보상
포함)가 ①의 공공 기여 지점이다.

**② 오픈웨이트 공개 — 확산의 착화점.**
프론티어 원본이 아니어도 좋다. 직전 세대·중형 변형의 가중치 공개가 만드는 것은 매출 손실이
아니라 **검증 인력·파생 생태계·신뢰**다(DeepSeek 효과). 국내 모델 중 이 게임에 참전한 것은
EXAONE뿐이고, 그 EXAONE이 행안부 내부망 도입이라는 첫 기관 채택을 만들어냈다는 사실(§2)이
공개→채택 인과의 국내 실증이다. 정책 수단: 독자 파운데이션 R&D 지원에 **단계적 오픈웨이트
공개 조건**(직전 세대 또는 경량 변형)을 결합하고, 공개 모델에 공공 조달 가점을 부여한다.

**③ 양자화·경량화 — 폐쇄망 진입의 관문.**
공공 확산의 물리적 조건은 "행정망 PC에서 도는가"다. 실측의 Gemma E2B/E4B 사례(9.6GB 번들
원클릭 배포)가 증명하듯, 온디바이스 변형이 있어야 폐쇄망 사례가 나온다. 이 단계는 기업보다
**커뮤니티가 잘하는 일**이므로 정부는 판을 깔면 된다: AI정부실험실의 양자화 챌린지(국산
오픈웨이트를 GGUF·AWQ 등으로 경량화해 행정망 사양 PC에서 벤치마크), 공공 깃랩의 경량판
배포 채널화, 검증된 경량판의 공식 카탈로그 등재(§8-2 필링의 확장).

**④ 공공 특화 파운데이션 — 수요를 제품으로.**
범용 모델 위에 공문서·법령·민원·복무 코퍼스로 계속 학습(continual pretraining)하거나 태스크
특화 튜닝한 **공공 파생 모델**을 만드는 단계다. HCX-GOV-THINK-V1-32B가 정확히 이 계열의
첫 실물이며, schift-ko-pii는 개인도 이 단계에 진입할 수 있음을 보여줬다. 정책 수단: 공공
태스크 카탈로그(마스킹·공문 생성·법령 검색·민원 분류·STT)를 공식화하고 태스크별 특화 모델을
조달 대상으로 지정(§6-4), 특화 학습용 공공 코퍼스의 정제·제공을 국가데이터처 사업으로 편성.

**⑤ 환류 — 순환을 닫는 고리이자 가장 취약한 고리.**
공공 현장의 사용 로그·실패 사례·평가 결과·특화 기법이 다음 프론티어에 반영돼야 순환이
완성된다. 그러나 이 고리는 법·제도가 정의되지 않으면 절대 저절로 닫히지 않는다: 공공 데이터·
사용 기록의 학습 활용 근거(개인정보·기밀 분리 규정), 피드백 제공 기관의 권리와 보상, 개발사의
개선 반영 의무. 최소 실행판은 **AI정부실험실의 평가 결과·실패 리포트를 개발사에 정례
환류하는 공식 채널**(§7-2 병렬 실험 트랙의 산출물)이며, 완성판은 AI기본법 하위 규정에서
"공공 피드백 데이터 신탁" 같은 장치로 제도화하는 것이다.

### 10.2 순환을 끊는 병목 4가지와 대책

| 병목 | 왜 끊기나 | 대책 |
|---|---|---|
| 오픈웨이트 공개 유인 부족 | 개발사의 수익 잠식 우려 | 공개 조건부 R&D + 공개 모델 조달 가점 + 정부가 직전 세대 공개권을 구매하는 방식(공개 자체의 값을 지불) |
| 경량화·검증 인력 | 기업 우선순위 밖 | 실험실 챌린지·챔피언 크레딧으로 커뮤니티에 위임, 공공 깃랩을 배포 채널로 |
| 특화 코퍼스 접근 | 부처별 데이터 칸막이·비정형(HWP) | AI 친화 문서 정책과 연동한 코퍼스 정제 사업, 커뮤니티 변환 도구(실측 다수)의 공식 채택 |
| 환류의 법적 근거 | 학습 활용 규정 부재 | AI기본법 하위 규정 — 등급 분리(N2SF 연동)된 공공 피드백 데이터 신탁 |

### 10.3 순환의 관측 — PAX 지표화

전략은 관측 없이는 관리되지 않는다. 순환의 각 단계를 분기 지표로 추적할 수 있다:
① 공공 코퍼스 공급 사례 수 → ② 국산 오픈웨이트 모델 수(현재 EXAONE 계열 중심) →
③ 국산 경량 파생판의 공공 배포 수(현재 0 — Gemma가 채운 자리) → ④ 특화 모델의 공공 채택
수(현재 HCX-GOV 2·schift 2) → ⑤ 환류 사례 수(현재 0). 오늘 기준 순환은 ④에서 시작해
①②③⑤가 비어 있는 **부분 순환**이며, 이 결측 지도가 곧 정책 우선순위다.

## 11. 크리티컬 공공영역(국방·안보·보안·금융)의 국산 모델 적용·확산 전략

국방·안보·사이버보안·금융은 일반 행정과 요구 조건이 다르다: 에어갭·망분리가 전제이고,
데이터의 외부 반출이 원천 금지되며, 공급망(모델 가중치 자체)의 무결성 검증이 필요하고,
오작동 비용이 극단적이다. 이 조건들은 해외 상용 API를 **구조적으로 배제**한다 — 즉 크리티컬
영역은 국산 모델에게 보호된 시장이 아니라 **요구된 시장**이며, §10 순환 구조의 ③·④단계
(경량화·특화)가 가장 먼저 수익화되는 곳이다. 실측도 이를 예고한다: 폐쇄망 보안취약점 점검
도구(KODA)·SBOM 추적기가 이미 로컬 완결형으로 개발되고 있고, 방산 반입 기기 규정(완전 포맷·
전담부서 감독)이 커뮤니티에서 원문 인용될 만큼 현장 수요와 규제가 살아 있다.

### 11.1 영역별 전략

**국방 — 에어갭 온프레미스의 기준 시장.**
- 수요 태스크: 교범·정비 매뉴얼 QA, 정보 분석 보조, 군수·정비 기록 구조화, 지휘 보고 초안.
  전부 폐쇄 환경 온프레미스 추론이며 프론티어급이 필수가 아닌 특화 SLM 적합 태스크다.
- 전략: ① 국산 오픈웨이트의 **군 규격 경량판**(오프라인 설치·서명 배포판)을 순환 ③의 첫
  공식 수요처로 지정. ② **모델 형상관리**: 가중치 해시 서명·오프라인 업데이트 절차·롤백
  기준을 군수품 형상관리에 준해 제도화 — AI-BOM(§5)의 국방판. ③ 반입 절차(완전 포맷·전담
  감독)와 정합하는 "모델 반입 표준 절차"를 방사청·기무 계통과 공동 제정. ④ 국방 코퍼스는
  외부 위탁 학습이 불가하므로 **파인튜닝 역량의 부대 내재화**(도구·인력·저전력 학습 장비)가
  모델 조달만큼 중요하다.

**안보·정보 — 주권 모델의 최상위 등급판.**
- 이 영역은 모델 제공사조차 데이터를 볼 수 없어야 하므로, 상용 국산 모델도 API형은 부적합
  하다. HCX-GOV 계열의 상위 보안판 — **완전 온프레미스·제공사 접근 차단·감사 가능 추론
  로그**를 갖춘 정부 전용 인스턴스가 요구 사양이다.
- 추론 과정의 감사 가능성(무엇을 근거로 판단했는가)이 채택 조건이 되므로, 국산 추론
  모델(THINK 계열)의 로그·근거 표준을 이 영역 요구로 먼저 성숙시키면 일반 행정으로
  하방 전개된다 — 크리티컬이 표준의 시험대가 되는 구조.

**사이버보안 — 국산 보안 특화 SLM의 즉시 시장.**
- 수요 태스크: 로그 이상 탐지, 취약점 설명·우선순위화, 침해 보고서 초안, 보안 규정 QA.
  schift(PII 탐지)가 보여준 태스크 특화 경로의 보안판이며, KODA류 폐쇄망 도구의 실측이
  수요를 증명한다.
- 전략: ① 국정원·금보원 계열의 **모델 보안 인증**(CC 인증의 AI판 — 가중치 무결성·백도어
  검증·적대적 견고성)을 신설해 크리티컬 조달의 관문으로 삼는다. 인증 자체가 국산에 유리한
  게임이다(검증 협조·소스 접근이 가능한 쪽이 통과한다). ② 국가 적대적 테스트 체계(레드팀
  코퍼스·탈옥 벤치마크)를 공공 벤치마크(§6-5)의 보안 트랙으로 운영. ③ 보안관제(SIEM) 연동
  국산 SLM을 조달 카탈로그화.

**금융 — 규제 정합성이 만드는 국산 우위.**
- 망분리 규제 완화(샌드박스)와 CSAP 체계 아래에서, 규제 정합 비용은 해외 상용보다 국산이
  구조적으로 낮다. 실측된 금융 관련 사례(DART·ECOS MCP 다수)는 전부 모델 중립(BYO)이라
  국산 런타임 이식의 최적 후보군이기도 하다.
- 전략: ① 금융 특화 태스크(공시 분석·심사 보조·이상거래 설명·민원 응대)의 국산 특화 모델을
  금보원 검증과 묶은 **금융 모델 카탈로그**로 운영. ② 설명가능성·기록 보존(감독 규정) 요건을
  모델 요구 사양에 포함 — 이 역시 검증 협조가 가능한 국산에 유리. ③ 금융결제원·금보원의
  공동 온프레미스 추론 인프라로 중소 금융기관의 도입 비용을 공유화.

### 11.2 영역 공통 장치

1. **등급별 모델 티어 제도화** — N2SF와 연동해 C(기밀)·S(민감) 등급 업무는 온프레미스
   국산(또는 검증된 오픈웨이트)만, O(공개) 등급은 자율로 — 원산지 거버넌스(§6-6)의
   크리티컬 구체화. "국산 강제"가 아니라 **등급이 요구하는 조건을 국산이 가장 쉽게
   충족**하는 구조로 설계한다(§8.3의 강제 조달 회피 원칙과 정합).
2. **모델 공급망 인증 파이프라인** — 가중치 서명·재현 가능 빌드·AI-BOM 제출·적대적 테스트를
   통과한 모델만 크리티컬 카탈로그에 올린다. PAX MCP 검증의 6축 프레임이 도구 수준에서
   한 일을 모델 수준으로 올리는 것이다.
3. **크리티컬 → 일반의 하방 전개** — 크리티컬에서 성숙한 표준(감사 로그·형상관리·반입 절차)
   은 일반 행정에는 완화판으로 내려보낸다. 가장 엄격한 시장을 국산이 먼저 충족하면 나머지
   시장의 신뢰는 따라온다 — 이것이 크리티컬 영역을 국산 확산의 **교두보**로 삼는 논리다.
4. **인력 겸직 문제의 선결** — 실측 담론이 경고하듯 "챔피언이 개발자·운영자·개인정보 담당까지
   겸하는 구조는 오래 못 간다". 크리티컬 영역은 특히 전담 운영 주체(전문기관 대행 체계 —
   커뮤니티 제안과 동일 구조)를 전제로 설계해야 한다.

## 12. 결론

실측이 말하는 것은 "국산 채택률 5.8%"라는 숫자가 아니라 그 구조다. 해외 종속은 런타임보다
개발 단계에서 깊고, 국산의 접점은 공식 인프라(공통기반)에서만 열리고 있으며, 사례의 절반은
모델 중립이거나 비LLM이라 **전장은 모델 성능이 아니라 생태계 기본값**이다. BYO 층 공략, 개발자 크레딧, 태스크 SLM, AI-BOM, 실험실의 기본값 설계, 그리고 중국 사례가
보여준 가시성 루프·모듈 재사용 경로, 에이전틱 시대의 하네스·게이트웨이 주권, 그리고
프론티어→오픈웨이트→경량화→특화→환류의 순환 구조(현재는 ④만 있는 부분 순환),
그리고 크리티컬 영역을 '요구된 시장'이자 표준의 교두보로 삼는 전략 — 이것들이
실측 데이터가 가리키는 개입 지점이다. PAX는 이 지표(국산 채택률·로컬 실행률·BYO 비율·
모델 명시율)를 분기 스냅샷으로 계속 추적한다.
