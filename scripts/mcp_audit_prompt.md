# MCP LLM 감사 절차 (축 4 입력 검증·인젝션 / 축 5 데이터 흐름)

check_mcp.py의 자동 축과 짝을 이루는 세션 감사 절차. 신규 MCP 사례 등재 시와
전수 백필 시 수행한다. **근거 없는 판정 금지 — 모든 판정에 파일·행 인용 필수.**

## 검토 순서 (사례당 10~15분)
1. 저장소를 임시 디렉토리에 shallow clone (검사 후 삭제)
2. 도구 핸들러 파일부터: tool 등록부 → 파라미터가 흐르는 곳
3. 축 4 점검표:
   - 셸 호출에 사용자 입력이 문자열 조합으로 들어가는가 (`f"cmd {arg}"`·shell=True)
   - 파일 경로 파라미터에 `..` 정규화·화이트리스트가 있는가
   - 외부 콘텐츠(웹·API 응답)를 도구 설명/응답에 무가공 삽입하는가(프롬프트 인젝션 표면)
4. 축 5 점검표:
   - 네트워크 호출 대상 도메인 전수 나열 → README의 주장(로컬 완결 등)과 대조
   - 원 API(공공데이터포털 등) 외 제3자 전송이 있는가 — 텔레메트리·애널리틱스 포함
5. 판정 기록: data/mcp_reviews.json 해당 사례의 axes.injection / axes.data_flow
   - note 형식: "판정 요지 (근거: 파일:행)" — 공개 문서이므로 악용 상세는 쓰지 않는다
   - 취약점 재현 방법·페이로드는 data/private/mcp_findings/<case_id>.md 에만

## 심각(비공개 처리 중) 발동 조건
- 실키 유출, 명시되지 않은 제3자 전송, 원격 명령 실행 가능성
- 발동 시: ① verdict="심각(비공개 처리 중)" ② disclosure={"notified_at": null,
  "channel": null, "resolved": false} ③ **사용자에게 보고하고 승인 후에만 개발자 통보**
  (자동 발송 금지) ④ 통보 문안: "PAX 검증 과정에서 <일반화된 설명>이 확인되어 알려드립니다.
  수정되면 아카이브에 '수정 확인'으로 반영하겠습니다. 상세: <비공개 채널로>"
- 수정 확인 시: resolved=true, note를 "수정 확인(<요약>)"으로 갱신

## 판정 후
PYTHONPATH=scripts python3 scripts/build_mcp_review.py 로 공개본을 재생성하고
build_case_pages 재실행(배지 갱신).
